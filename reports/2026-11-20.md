## 1. Replication of Agentic Security Events: Audit and Investigation (ROGUE-AI)

**Topics:** LLM Agent Security, Agentic Incident Replication, AI Safety Evaluation, Multi-Agent Framework
**Authors:** Mengxiao Wang, Mahbub Alam, Kalyan Nakka, Nitesh Saxena
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.26553v1) | [PDF](http://arxiv.org/pdf/2611.26553v1.pdf) | [Code](https://rogue-ai.surge.sh)

### 1. 一句话结论

ROGUE-AI 通过受控复制实验验证媒体报道的智能体安全事件，在 108 个尝试复制中 89% 成功复现，且无攻击者的普通危险（如共享数据库）比提示注入造成更多危害。

### 2. 为什么重要

该工作首次系统性地将媒体报道的智能体安全事件转化为可重复的受控实验，不仅验证了事件真实性，还揭示了非攻击性危险是当前智能体失败的主要原因，为智能体安全审计和防御提供了新方向。

### 3. 研究问题

1. 媒体报道的智能体安全事件能否在离线环境中被复现？
2. 被归因的原因（如提示注入）是否真的是造成危害的必要条件？
3. 当前主流 LLM 智能体在真实事件场景中的失败率有多高？
4. 针对提示注入的防御是否适用于非攻击性危险？

### 4. 背景与问题设定

随着 LLM 智能体能够执行删除文件、支付等敏感操作，其安全事件频发。然而，现有事件目录仅收集报告，基准测试使用人工设计的攻击，缺乏对真实事件因果的验证。ROGUE-AI 旨在通过受控复制实验，测试事件报告中归因的原因是否确实导致危害。

### 5. 方法概览

- 任务 / 环境: 离线环境，包含事件报告中的任务 T、环境 E（含危险 H）和匹配的控制环境 E¬H（仅移除 H）。
- 变量 / 干预设计: 对每个事件，构建两个环境：事件环境（含危险）和控制环境（无危险），运行智能体多次，比较危害发生率。
- 评价指标: 危害发生率（harm rate），使用 Fisher 精确检验比较事件与控制组的差异，并校正多重比较。
- 模型比较: 测试了 GPT、Claude、Gemini 和 DeepSeek 的五个当前模型，比较它们在事件和控制条件下的表现。
- 我的理解: 该方法将事件报告视为因果假设，通过随机对照实验验证，类似于医学中的临床试验，但应用于智能体安全。

### 6. 关键发现

- 高复现率: 在 108 个尝试的复制中，89% 成功复现了报告中的危害，表明媒体报道的事件大多真实存在。
- 非攻击性危险更常见: 在 72 个真实世界危害事件中，62 个没有攻击者，而是由于普通危险（如共享数据库）导致，且这些事件造成的危害比提示注入更多。
- 防御措施不匹配: 针对提示注入的防御（如检测注入指令）无法防止非攻击性危险，因为后者不包含注入指令。
- 警告有效: 在工具输出后添加命名危险及其后果的警告，显著降低了所有模型的危害率（例如 Claude Sonnet 4.6 降至 2%）。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体系统应内置危险检测和警告机制，而不仅仅是防御提示注入。
- 对 Skill: 智能体需要具备识别环境危险（如共享数据库）的能力，并在行动前确认。
- 对 Memory: 记忆系统应记录危险环境特征，以便在类似场景中提前预警。
- 对评测: 评估智能体安全应包含真实事件复现，而不仅仅是人工攻击。

### 11. 局限性

- 复制实验基于公开报告，可能受报告偏差影响。
- 每个事件仅构建一个控制环境，可能未覆盖所有潜在混淆因素。
- 模型测试次数有限（15-30次），统计功效可能不足。
- 未考虑模型版本更新对结果的影响。

### 12. 我的看法 / 个人笔记

ROGUE-AI 是智能体安全评估的重要进步，它从被动记录转向主动验证，揭示了非攻击性危险的普遍性。警告机制简单有效，但实际部署需考虑用户确认的干扰。未来可扩展至更多事件类型和模型，并探索自动化构建控制环境。

## 2. ZeroVLN: Learning to Navigate without Supervised Fine-Tuning of the VLM Brain

**Topics:** 视觉语言导航, 具身智能, 强化学习
**Authors:** Zixuan Huang, Yang Zhou, Guli Zhang, Sunzhu Li, Hongyan Xie, Zehao Chen, Fuzhen Zhuang, Kaixuan Wang, Xiaozhi Chen, Yikun Ban, Deqing Wang
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.26414v1) | [PDF](http://arxiv.org/pdf/2611.26414v1.pdf) | [Code](https://github.com/hzx122/ZeroVLN)

### 1. 一句话结论

ZeroVLN 通过语义工具接口和闭环强化学习，在不微调 VLM 大脑的情况下实现了优于 SFT 方法的导航性能，同时保留了模型通用能力。

### 2. 为什么重要

传统 VLN 方法需要对 VLM 进行领域微调，导致通用能力下降。ZeroVLN 提出零微调范式，仅通过语义工具调用和强化学习优化决策与执行，为具身智能提供了一种更高效、更通用的训练范式。

### 3. 研究问题

1. 如何在不进行导航领域 SFT 的情况下，让 VLM 大脑做出有效的移动决策？
2. 如何通过闭环强化学习联合优化慢速决策策略和快速执行策略，以提升导航性能？

### 4. 背景与问题设定

视觉语言导航（VLN）要求智能体将移动决策与精确运动相结合。现有方法通常将 VLM 大脑与可学习的动作头耦合，并在导航数据上微调 VLM 以预测几何目标，但这会显著改变 VLM 权重并损害其通用视觉能力。受 DeepSeek-R1-Zero 启发，ZeroVLN 探索无需 SFT 的导航学习。

### 5. 方法概览

- 任务 / 环境: 连续环境下的视觉语言导航（VLN-CE），包括 SAGE-Bench、R2R-CE 和 RxR-CE 基准。
- 变量 / 干预设计: 引入语义工具调用接口，VLM 大脑通过自然语言发出移动请求（如 run_action_head），动作专家（流匹配模型）将其转化为连续动作。训练分为两阶段：先通过请求接地监督和前缀学习适配动作专家，再通过闭环智能体强化学习联合优化大脑和动作专家。
- 评价指标: 成功率（SR）、路径加权成功率（SPL）、导航误差（NE）、预言成功率（OSR）。
- 模型比较: 与直接工具使用、DualVLN、NaVILA 等 SFT 方法对比，ZeroVLN 在相同训练数据下取得最高 SR，且 VLM 权重变化极小（0.01497%）。
- 我的理解: ZeroVLN 的核心创新在于将决策与执行解耦，利用 VLM 的语义理解能力通过工具调用表达意图，而动作专家负责连续控制。通过轨迹级优势估计和过程奖励，强化学习能够有效协调两个策略，避免 SFT 带来的能力退化。

### 6. 关键发现

- 零 SFT 导航性能超越 SFT 方法: 在 SAGE-3D、R2R-CE 和 RxR-CE 上，ZeroVLN 的 SR 分别达到 51.3、66.7 和 64.6，均高于 DualVLN 和 NaVILA，且无需微调 VLM 大脑。
- VLM 通用能力得到保留: 与基线 DualVLN 相比，ZeroVLN 在多个视觉和空间基准上的性能下降极小，权重位移仅 0.01497%，验证了零 SFT 策略的有效性。
- 过程奖励缓解稀疏奖励问题: 通过距离进度和信息发现奖励，即使在所有 rollout 均失败的情况下，也能提供有效的学习信号，避免梯度退化。

## 3. Perfumer: A Large Language Model-based Agentic Framework Accelerating Structural Relaxation and Electronic Band Prediction for First-Principle Calculation

**Topics:** cond-mat.mtrl-sci, cs.LG
**Authors:** Zhiwei Li, Yuhao Zhou, Yikai Yang, Haonan Wang, Qing Ye, Jiancheng Lv, Kazunari Matsuda
**Venue / Year:** 
**Links:** [Abstract](http://arxiv.org/abs/2611.26349v1) | [PDF](http://arxiv.org/pdf/2611.26349v1.pdf)

### 1. 一句话结论

Perfumer 是一个基于大语言模型的智能体框架，通过预松弛和快速能带预测，将结构弛豫和电子能带计算加速了 2.75 倍，并在 2,607 种材料上实现了 0.157 eV 的中位能带误差。

### 2. 为什么重要

该工作将 LLM 智能体与专用数值模型结合，显著降低了第一性原理计算的门槛和成本，为材料筛选和自动化探索提供了高效的新范式。

### 3. 研究问题

1. 如何利用大语言模型智能体协调结构弛豫和电子能带计算，以降低计算成本？
2. 如何设计一个能带预测模型，在保持精度的同时避免显式构造哈密顿量？

### 4. 背景与问题设定

第一性原理计算（如 DFT）在材料科学中至关重要，但结构弛豫和能带计算通常需要大量计算资源和专业知识。现有机器学习方法分别加速了结构弛豫（如学习势）和电子结构预测（如 DeepH），但缺乏一个集成的工作流来协调这些步骤。大语言模型智能体提供了自动化任务规划和工具调用的可能性，但尚未与数值计算模型深度集成。

### 5. 方法概览

- 任务 / 环境: 材料科学中的结构弛豫和电子能带计算任务，涉及晶体结构、DFT 计算和能带路径。
- 变量 / 干预设计: Perfumer 框架包含三个核心组件：Perfumer-relax 模型（基于 MACE 的预松弛）、Quantum ESPRESSO（DFT 精修）和 Perfumer-band 模型（基于周期图神经网络和潜在厄米特谱头）。LLM 智能体负责解释自然语言请求、规划工作流、调用工具并总结结果。
- 评价指标: 结构弛豫速度提升倍数、能带预测的平均绝对误差（MAE）、计算时间（CPU 时间）以及最终结构的几何偏差。
- 模型比较: 与仅使用 QE 的基线相比，Perfumer 实现了 2.75 倍的整体加速；与 Fable 5.2 相比，Perfumer-band 模型在 WSe2 上的 MAE 降低了 72%，且预测速度更快。
- 我的理解: 该框架的核心创新在于将 LLM 智能体作为协调者，将预松弛模型和能带预测模型无缝集成到标准 DFT 工作流中，从而在保持精度的同时大幅减少计算时间。

### 6. 关键发现

- 结构弛豫加速 2.75 倍: 在 553 个测试结构上，使用 Perfumer-relax 预松弛后接 QE 精修，总计算时间从 277.8 小时降至 101.1 小时，加速 2.75 倍，且最终结构与纯 QE 结果高度一致（偏差小于 4.5×10⁻⁴ Å）。
- 能带预测精度与速度: Perfumer-band 模型在 2,607 种测试材料上达到 0.157 eV 的中位 MAE，涵盖镧系、锕系和磁性材料，预测时间中位数约 97 ms/材料，远快于 DFT。
- 端到端工作流自动化: LLM 智能体能够将自然语言请求转化为完整的弛豫-能带工作流，包括结构导入、候选材料生成、逐步弛豫和能带预测，并在约 15 分钟内完成新材料的筛选。

  与当前论文关系：Perfumer 进一步集成了预松弛和能带预测模型，超越了单纯的输入生成，实现了端到端的加速。
- MatSciAgent
  为什么重要：MatSciAgent 是一个多智能体系统，协调材料科学中的多种工具，与 Perfumer 的智能体架构类似。
  核心贡献：通过多个 LLM 智能体协作完成材料数据检索、结构生成和模拟。
  与当前论文关系：Perfumer 专注于弛豫和能带计算，并引入了专用数值模型，提高了计算效率。

### 14. 总结

Perfumer 是一个基于 LLM 的智能体框架，集成了预松弛模型和能带预测模型，将结构弛豫和电子能带计算加速 2.75 倍，并在 2,607 种材料上实现 0.157 eV 的中位误差。该框架支持自然语言交互，自动完成从结构到能带的完整工作流，为材料探索提供了高效工具。

## 4. Mind2Act World: A Diagnostic Benchmark for Embodied Mind, Physical Action, and Mind-Action Composition in Robotic Manipulation

**Topics:** 机器人操作, 具身智能, 基准测试, 多模态智能体, 视觉-语言-动作模型
**Authors:** Yuzhi Huang, Jie Wu, Fanding Huang, Junchao Lin, Weichen Zhang, Ziyi Xiong, Yang Li, Zhengwei Xie, Zhimin Wang, Zhen Liu, Jiazhen Huang, Yuzheng Zhang, Yuche Liu, Hongyi Yang, Chen Tang, Shixiang Tang, Hakan Aktas, Adam Wu, Duo Wu, Kangye Ji, Shuzhao Xie, Huanan Liu, Weijue Bu, Chenxin Li, Xinyuan Wang, Tianyi Bai, Yinan Mao, Jiawei Wang, Minglei Li, Heng Yu, Ehsan Adeli, Minchen Li, Yong-Lu Li, Cengiz Öztireli, Huazhe Xu, Chao Yu, Jing Zhang, Shanghang Zhang, Weitao Zhou, Wenwu Zhu, Cheng Chi, Jingyan Jiang, Zhi Wang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.26444v1) | [PDF](http://arxiv.org/pdf/2611.26444v1.pdf) | [Code](https://github.com)

### 1. 一句话结论

Mind2Act World 基准测试表明，现有具身智能系统在单独的记忆推理或物理执行上表现尚可，但在通过环境反馈将二者组合的闭环任务中成功率极低，组合能力是当前主要瓶颈。

### 2. 为什么重要

该基准首次将认知推理、物理执行及其组合能力在同一任务中分离评估，并提供了诊断工具，能精确定位失败环节，为具身智能系统的能力评估和后续改进提供了清晰方向。

### 3. 研究问题

1. 现有具身智能系统在记忆推理、物理执行和二者组合上的能力差距有多大？
2. 系统在 Mind2Act 任务中的失败主要源于推理、执行还是组合环节？

### 4. 背景与问题设定

具身智能要求机器人具备基于历史的认知推理、精确及时的物理执行以及通过环境反馈组合二者的能力。现有基准要么在同一任务中混合评估推理与执行，导致失败原因难以归因；要么分别评估但不测试组合能力。因此，需要一种能分离并组合评估这些能力的诊断基准。

### 5. 方法概览

- 任务 / 环境: 基于 Isaac Sim 的双臂 ARX X5 平台，包含 30 个模拟操作任务，覆盖 5 个真实世界应用领域，每个任务有 3 个难度等级和 2 种场景设置（Clean 和 Random），共 180 种配置。
- 变量 / 干预设计: 任务分为三个视图：Mind 视图测试基于历史观察的决策；Act 视图测试精确及时的物理执行；Mind2Act 视图测试闭环组合，其中动作结果影响后续决策。每个视图包含 10 个任务，通过保持其他能力简单来突出目标能力。
- 评价指标: 每个任务计算任务得分（0-100）和成功率，取 Clean 和 Random 场景的平均值；总体得分 = 0.25*Mind + 0.25*Act + 0.50*Mind2Act。
- 模型比较: 评估了多模态智能体（如 GPT-6 Astra）、视觉-语言-动作模型（VLA，如 InternW0）和世界-动作模型（WAM，如 FastWAM），并分别设置智能体和端到端策略排行榜。
- 我的理解: 该基准通过精心设计任务，使得每个视图只强调一种能力，从而能够独立评估和比较不同架构的系统在推理、执行和组合上的表现。

### 6. 关键发现

- 组合能力是主要瓶颈: 最强智能体在 Mind 任务中成功率达 52.7%，在 Act 任务中为 39.0%，但在 Mind2Act 任务中仅 12.0%，表明即使具备单项能力，组合能力也严重不足。
- 端到端策略在组合任务中表现极差: 所有端到端策略（VLA/WAM）在 Mind2Act 任务中成功率不超过 3.6%，远低于智能体，说明端到端方法难以处理需要记忆和反馈组合的长期任务。
- 场景随机化显著影响记忆能力: 在 Random 场景下，VLA 的记忆能力大幅下降，表明视觉变化会干扰历史信息的保持。

- 任务数量有限，可能无法覆盖所有操作场景。

Mind2Act World 提供了一个有价值的诊断框架，明确了具身智能的核心挑战在于组合能力。未来研究应聚焦于如何通过环境反馈有效整合记忆与动作，并开发更鲁棒的闭环学习算法。

## 5. How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents

**Topics:** LLM Agent, Agent Memory, Self-Distillation, Long-Horizon Tasks, Deployment
**Authors:** K. R. Jayaram, Vatche Isahagian, Aswath Vaithinathan Aravindan, Vinod Muthusamy, Punleuk Oum, Gaodan Fang, Michal Ulewicz, Gegi Thomas, Evelyn Duesterwald
**Venue / Year:** AAAI 2027
**Links:** [Abstract](http://arxiv.org/abs/2611.26361v1) | [PDF](http://arxiv.org/pdf/2611.26361v1.pdf) | [Code](https://github.com/AgentToolkit/altk-evolve)

### 1. 一句话结论

智能体记忆的最佳剂量取决于模型能力：强模型受益于全量指南，弱模型则更适合少量精选子集。

### 2. 为什么重要

该研究基于大规模生产环境的部署经验，揭示了记忆系统设计中容易被忽视的关键问题，如记忆压缩的代价、支持度不等于正确性、静默故障的危害等，为实际部署提供了可操作的指导。

### 3. 研究问题

1. 如何从智能体自身轨迹中自动提取并整合经验教训，以提升其在长时任务上的表现？
2. 记忆的剂量（即注入的指南数量）如何影响不同能力水平的模型？
3. 在记忆压缩和选择过程中，如何保持来源信息（provenance）的完整性？

### 4. 背景与问题设定

大语言模型智能体在长时任务中常出现重复的程序性错误，如错误分页、解析错误实体、未请求时返回答案等。现有方法如ExpeL、ACE等允许智能体从自身经验中学习，但缺乏对部署过程中实际问题的系统分析。本文基于IBM的CUGA智能体和watsonx Orchestrate平台，通过AppWorld基准测试，报告了构建、测量和产品化自蒸馏记忆管线的经验教训。

### 5. 方法概览

- 任务 / 环境: AppWorld基准测试，包含9个模拟应用、457个API和约100个模拟人物，共750个任务，分为train/dev/test三个子集。
- 变量 / 干预设计: 从智能体自身轨迹中提取1-3条经验教训（lessons），然后通过支持度守恒的整合（consolidation）将相似教训合并为指南（guidelines），最后在推理时注入全部或部分指南。
- 评价指标: 任务完成率（TGC）和场景完成率（SGC），以及每任务token消耗量。
- 模型比较: 对比了不同模型（DeepSeek-V3.2、gpt-oss-120b、GPT-5.5、GLM-5、Gemma-4-31B、Claude Opus 4.6）在不同指南注入量下的表现，并与ACE方法进行了比较。
- 我的理解: 该方法的核心在于从智能体自身经验中提取可复用的指导性知识，并通过支持度守恒的整合机制保持知识的可追溯性，从而在推理时灵活选择注入量，以适应不同模型的能力。

### 6. 关键发现

- 记忆的最佳剂量是模型能力的函数: 强模型（如DeepSeek-V3.2）随着注入指南数量的增加持续改进，全量191条指南带来+9.5 TGC和+16.1 SGC的提升；而弱模型（如gpt-oss-120b）从全量指南中获益有限，反而从约29条精选子集中获得最大提升（相对于基线+15.5 TGC，而全量集仅+11.3 TGC）。
- 不要过度压缩，价值在于长尾: 将指南压缩为12条精炼规则仅带来+2.9 TGC的提升，而保留全部191条（其中144条支持度为1）则带来+9.5 TGC，表明一次性、情境化的教训往往比通用规则更有价值。
- 选择需要来源信息，而来源信息容易丢失: 在整合过程中，支持度和来源任务信息可能被静默丢弃，导致后续选择无法进行。必须将来源信息作为不变量强制保留。
- 支持度是重复性，不是正确性: 一个高支持度的指南可能基于错误的假设（如分页大小），导致任务失败。支持度仅反映教训的普遍性，而非其正确性，需要额外的正确性或时效性信号。
- 测量噪声底线，避免误判: 相同配置的两次运行可能产生高达32个任务的结果翻转，因此小于5个任务的差异应视为噪声。
- 在固定框架上比较，并报告token消耗: 不同智能体框架的基线差异可能掩盖记忆方法的真实效果，应固定框架并报告token消耗，以便公平比较。
- 静默故障比建模问题更耗时: API错误被吞没、网络连接空闲断开、写入钩子未触发等问题导致整个运行失败，但日志看似正常。需要主动监控和断言。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体记忆系统应支持可配置的剂量，根据模型能力自动调整注入量，避免对弱模型造成负面影响。
- 对 Skill: 记忆应保留长尾的、情境化的教训，而非仅保留通用规则，以最大化对复杂任务的覆盖。
- 对 Memory: 记忆整合必须保持来源信息，支持度应作为选择依据，但需结合正确性信号，防止错误指南的传播。
- 对评测: 评估时应固定智能体框架，报告token消耗，并注意运行噪声，避免误判。

### 11. 局限性

- 仅基于AppWorld基准，可能无法完全代表真实世界的多样性。
- 记忆管线的效果依赖于模型能力，但未提供自动确定最佳剂量的方法。
- 未解决指南的正确性验证问题，高支持度错误指南可能未被发现。
- 运行次数有限，部分结论可能受噪声影响。

### 12. 我的看法 / 个人笔记

本文提供了宝贵的部署经验，强调了记忆系统的实用性和鲁棒性。核心发现“记忆剂量是模型能力的函数”具有重要指导意义，但如何自动确定最佳剂量仍待解决。此外，支持度与正确性的区分提醒我们，记忆系统需要更智能的验证机制。
