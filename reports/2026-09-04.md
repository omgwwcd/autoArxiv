## 1. Environment Evolution for Terminal Agents

**Topics:** 终端智能体, 强化学习, 环境缩放, 离线演化
**Authors:** Zhiyuan Fan, Tinghao Yu, Yuanjun Cai, Jiang Zhou, Jiangtao Guan, Jincheng Liu, Yun Yang, Dingxin Hu, Zhuo Han, Xing Wu, Feng Zhang, Lilin Wang
**Venue / Year:** arXiv 2609.04128v1, 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.04128v1) | [PDF](http://arxiv.org/pdf/2609.04128v1.pdf)

### 1. 一句话结论

提出环境演化方法，离线沿场景新颖性、技能稀有性和执行长度三个方向逐步增加终端环境难度，在Qwen3.6-27B和Qwen3.6-35B-A3B上经200步长时RL训练（GRPO算法，B=8, τ=6/8的演化谱系调度器），Terminal-Bench 2.1性能分别提升14.4和18.0个百分点。

### 2. 为什么重要

解决了现有环境合成方法对前沿模型（如Hy4 preview、Claude Opus 5、GPT-5.6 Sol）挑战不足、共演化方法依赖在线策略且泛化受限的问题，为终端智能体RL训练提供了可扩展的离线环境生成范式，确保持续有效的学习信号。

### 3. 研究问题

1. 如何在不依赖在线策略的情况下，持续生成对不断变强的模型仍有挑战性的终端环境？
2. 环境难度如何从多轮学习目标中形式化定义，并分解为可操作的因素？

### 4. 背景与问题设定

终端智能体通过命令行与计算系统交互完成长时任务。现有大规模环境合成方法（如SkillSynth）生成的场景对前沿模型不够困难，无法提供有效学习信号；共演化方法依赖在线策略，泛化性差且随模型变强信号减弱。因此需要一种离线、持续的环境难度提升方法。

### 5. 方法概览

- 任务 / 环境: 终端环境，每个包含指令、可执行环境和验证系统，智能体需通过多轮命令行交互完成任务。种子环境从47,678个中筛选出127个，再经SkillSynth补充至500个，确保质量和难度（Claude Opus 5通过率≤4/8，平均回合数≥30）。
- 变量 / 干预设计: 从多轮学习目标推导出三个影响难度的因素：场景新颖性（−log p_T(σ|g)）、技能稀有性（−log p_T(κ|σ,g)）和执行长度（L）。通过循环工程的多智能体框架（Proposer、Reviewer、Modifier、Verifier），每代沿一个方向增量修改环境，构建难度递增谱系。演化努力分低、高、最大三级，控制修改范围（低：修改一对(σ,κ)；高：修改连续片段；最大：修改任意部分）。演化谱系调度器（EL Scheduler）使用B=8次滚动和阈值τ=6/8，按代际顺序调度环境。
- 评价指标: 环境难度通过8次独立滚动的通过率衡量，并记录平均助手回合数；训练效果通过Terminal-Bench 2.1上的平均通过率评估（5次运行平均）。
- 模型比较: 在Qwen3.6-27B（27B密集模型）和Qwen3.6-35B-A3B（35B总参数、3B激活参数的MoE模型）上验证，与共演化和集成基线对比。难度评估使用Hy4 preview（高努力）、Claude Opus 5（x高努力）和GPT-5.6 Sol（x高努力）。
- 我的理解: 该方法将环境难度建模为场景新颖性、技能稀有性和执行长度的函数，通过离线演化独立于目标策略生成更难环境，再通过演化谱系调度器按代际顺序提供给训练，确保持续有效信号。

### 6. 关键发现

- 环境演化持续提升难度，高/最大努力下通过率单调降至零: 在Hy4 preview、Claude Opus 5和GPT-5.6 Sol上，高和最大演化努力下通过率随代际单调降至零，平均回合数从约60增至200；低努力下通过率波动但未归零。最大努力在第6-9代达到零通过率，高努力在第10-12代达到，低努力在15代后仍高于零。
- 长度方向单步难度变化最大，场景和技能方向增加回合数更多: 高努力下，长度方向单步通过率下降7.1个百分点（最大），但平均回合数增加较少（+9.4）；场景和技能方向通过率下降约4个百分点，但回合数增加更多（+13.5和+12.5）。15代平均效果：长度方向通过率下降4.8个百分点，场景和技能方向分别下降2.9和2.7个百分点。
- 训练性能显著提升，优于共演化和集成基线: 在Qwen3.6-27B和Qwen3.6-35B-A3B上，经200步长时RL训练（GRPO算法，B=8, τ=6/8的演化谱系调度器），Terminal-Bench 2.1性能分别提升14.4和18.0个百分点，优于共演化和集成基线。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 提供了一种可扩展的离线环境生成方法，使终端智能体能在持续变难的环境中训练，提升泛化能力，尤其适用于前沿模型。
- 对 Skill: 通过技能稀有性方向演化，可针对性训练智能体在罕见场景下应用特定技能，增强技能鲁棒性。
- 对 Memory: 长时任务中执行长度增加（平均回合数从60增至200），要求智能体具备更好的记忆和上下文管理能力（如256K上下文窗口和自动压缩）。
- 对评测: Terminal-Bench 2.1作为基准，环境演化可生成更难的测试集，推动评估标准提升，同时验证了基准的稳定性。

### 11. 局限性

- 演化谱系在通过率降至零后无法进一步评估难度，需结合其他指标（如平均回合数）。
- 种子环境筛选严格（从47,678个中仅保留127个，再补充至500个），可能限制多样性。
- 演化方向随机排序可能影响特定任务的优化效率，但论文中作为设计选择未深入探讨。
- 实验仅使用200步RL训练，更长训练步数下的效果未验证。

### 12. 我的看法 / 个人笔记

该工作巧妙地将环境难度分解为三个可操作因素，并通过离线演化避免了共演化的在线依赖，实验验证充分且跨模型一致。未来可探索更细粒度的难度控制（如连续演化努力）或结合在线反馈进行混合演化，以及验证更长训练步数下的效果。

## 2. InSituMeasure: Probing Situated Measurement Grounding in Industrial Scenes with Multimodal Large Language Models

**Topics:** Multimodal Large Language Models, Situated Measurement Grounding, Industrial Gauge Reading, Benchmark Evaluation
**Authors:** Chao Shen, Xinyuan Li, Yunfan Zhou, Jianguo Yao, Haibing Guan, Zhihai Wang, Xijun Li
**Venue / Year:** AAAI 2027
**Links:** [Abstract](http://arxiv.org/abs/2609.04014v1) | [PDF](http://arxiv.org/pdf/2609.04014v1.pdf)

### 1. 一句话结论

InSituMeasure 揭示，当前最先进的多模态大模型在真实工业场景中的仪表读数任务上表现极差，最佳模型联合数值-单位准确率仅 25.7%，远低于其在通用多模态基准上的表现。

### 2. 为什么重要

该工作首次将仪表读数定位为一项“情境化测量接地”任务，强调模型必须在真实工业噪声、多仪表场景和可回答性判断下进行精确的数值与单位联合预测。其发现对 MLLM 在安全攸关的工业部署中的可靠性提出了严峻挑战，并指明了模型在细粒度视觉测量、置信度校准和噪声鲁棒性方面的根本性缺陷。

### 3. 研究问题

1. 当前最先进的多模态大模型在真实、情境化的工业仪表读数任务上表现如何？
2. 模型在仪表读数中的失败根因是什么？是视觉感知、语言先验、还是置信度校准问题？

### 4. 背景与问题设定

尽管 MLLM 在通用多模态基准上表现优异，但在需要连续值预测的仪表读数任务上仍不可靠。现有基准（如 DialBench、MeasureBench）存在三大缺陷：缺乏情境上下文、部分依赖合成数据、缺少真实工业噪声和根因诊断标签。因此，现有评估无法反映模型在真实部署条件下的性能与失败模式。

### 5. 方法概览

- 任务 / 环境: 真实工业监控场景，包含 2,922 个任务，覆盖 8 类专业工程仪表（如数字指示器、压力表、油位计等），场景包含单/多仪表、不同视角、遮挡、光照变化、环境干扰等真实噪声。
- 变量 / 干预设计: 包含可回答与不可回答任务。不可回答任务通过反事实协议构造，包括五种噪声类型：软遮挡（部分隐藏证据）、视角偏移（扭曲指针或刻度几何）、环境噪声（雾、反射、强光）、指针状干扰（类似指针的结构误导）和硬遮挡（完全移除关键证据），以测试模型的弃权能力。
- 评价指标: 定义联合数值-单位准确率（Both）、数值准确率（Value）、单位准确率（Unit）、弃权与可靠性指标（覆盖率、选择性风险、过置信度、FPR）以及多目标准确率。
- 模型比较: 评估了 24 个最先进的 MLLM，包括 GPT-5、Gemini 2.5 Pro、Qwen3-VL 等，对比其在 InSituMeasure 上的性能。
- 我的理解: 该基准设计精巧，通过将仪表读数从孤立的视觉识别任务重新定义为情境化测量接地任务，并引入丰富的噪声标签和反事实协议，系统性地暴露了 MLLM 在真实世界部署中的关键弱点。评估指标不仅关注准确性，还强调置信度校准和弃权能力，这对于安全攸关的工业应用至关重要。

### 6. 关键发现

- MLLM 在情境化仪表读数上性能大幅下降，文本捷径和过自信响应是主要失败模式: 最佳模型（Gemini 2.5 Pro）的联合数值-单位准确率仅 25.7%，单位准确率 51.8%，数值准确率更低。分析发现，模型常依赖文本捷径（如输出无关字母‘M’、‘STOP’而非有效读数），且对不可回答任务给出过自信响应（如硬遮挡下仍预测数值），而非基于证据弃权。
- 模型置信度校准极差，存在严重的过置信与欠置信问题: 多数模型的正确预测（TP）比例很低，且存在大量高置信度的错误预测（FP）和低置信度的正确预测（FN）。例如，FP 表明模型在模糊证据或严重噪声下仍自信输出，FN 则显示正确读数未被充分信任，降低了可用预测数量。
- 失败根因多为复合噪声，视角偏移和环境噪声是主要单因素: 混合原因（37.1%）是最大的错误来源，其次是视角偏移（20.7% 值误差，24.3% 单位误差）和环境噪声（11.6% 值误差，14.4% 单位误差）。软遮挡和硬遮挡分别贡献 18.3% 和 5.7% 的值误差，表明真实世界的干扰是复合且相互作用的。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 当前 MLLM 驱动的智能体在需要精确数值感知的工业场景（如设备监控、巡检）中不可靠，必须结合专门的视觉测量模块或进行领域特定的微调与校准，并引入弃权机制以避免过自信错误。
- 对 Skill: 仪表读数是一项需要精细视觉定位、几何映射和语义理解的复合技能，MLLM 当前缺乏这种技能，需要发展新的训练范式，如结合结构化知识或强化学习，并减少对文本捷径的依赖。
- 对 Memory: 模型需要记忆不同仪表类型的刻度布局、单位语义和典型噪声模式，但当前工作表明模型倾向于依赖文本捷径而非真正的视觉接地，记忆机制需要改进以支持情境化推理。
- 对评测: 评估不应仅关注准确率，必须纳入置信度校准、弃权能力和对特定噪声类型的鲁棒性分析，以全面衡量模型在真实世界中的部署就绪度。

### 11. 局限性

- 数据集规模相对较小（2,922 个任务），可能无法完全覆盖所有工业仪表类型和噪声模式。
- 基准主要关注静态图像，未涉及视频流或动态测量场景。
- 根因分析依赖于人工标注的噪声标签，可能存在主观性，且未能完全建模噪声的交互效应。

### 12. 我的看法 / 个人笔记

该工作精准地指出了当前 MLLM 在细粒度、情境化、连续值预测任务上的核心短板，并通过精心设计的基准和深入的分析，为未来研究指明了方向。其价值不仅在于暴露问题，更在于提供了诊断工具和失败模式分类。未来工作应聚焦于如何将视觉感知、几何推理和不确定性估计更有效地整合到 MLLM 中，并探索在真实工业噪声下的鲁棒训练方法。

### 14. 总结

### 2. 为什么重要

## 4. FLY-EVAL++: An Evidence-Driven Evaluation Protocol for Safety-Constrained Flight Prediction with Large Language Models

**Topics:** GUI Agent
**Authors:** Yalun Wu, Junfeng Fang, Jiawei Wang, Haotian Liu, Qijun Yang, Minghan Yang, Hongcheng Guo, Zhoujun Li, Boyang Wang
**Venue / Year:** COLM 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.04021v1) | [PDF](http://arxiv.org/pdf/2609.04021v1.pdf)

### 1. 一句话结论

FLY-EVAL++ 提出了一种基于确定性验证的证据驱动评估协议，用于安全关键型飞行预测，发现安全合规性是区分大语言模型性能的最关键维度。

### 2. 为什么重要

该工作填补了现有评估协议无法可靠检测安全关键型物理环境中大语言模型输出违规的空白，强调了在安全关键领域必须显式测量约束满足和结构有效性，而非仅依赖准确性指标。

### 3. 研究问题

1. 在安全关键、物理约束的飞行预测任务中，现有基于准确性的评估指标是否足以衡量大语言模型的实际可用性和安全性？
2. 如何设计一个可复现、确定性、证据驱动的评估协议，以系统性地检测大语言模型在结构化输出中的协议合规性、物理可行性、安全约束违反等故障模式？

### 4. 背景与问题设定

大语言模型在安全关键、物理驱动的环境（如飞行轨迹与姿态预测）中，即使预测数值接近真实值，仍可能违反操作约束、产生物理不一致的字段组合或无法生成可用的结构化输出。现有评估协议主要依赖平均准确性指标，无法可靠测量这些故障模式。PilotBench 提供了 708 个真实通用航空飞行数据，但缺乏将安全和可行性要求操作化为可审计、可复现证据的评估方法。

### 5. 方法概览

- 任务 / 环境: 飞行轨迹与姿态预测（FTAP），基于 PilotBench 数据集，包含 708 个真实通用航空飞行段，9 个 FAA 对齐的飞行阶段，34 个标准化状态维度，10 Hz 采样率。
- 变量 / 干预设计: 设计了三个时间复杂度递增的任务：S1（单步预测）、M1（历史条件单步预测）、M3（历史条件多步滚动预测）。所有模型使用零温度、确定性解码和统一提示模板。
- 评价指标: FLY-EVAL++ 协议定义了五个维度：D1 协议与模式合规性、D2 字段有效性与局部动力学、D3 物理与跨字段一致性、D4 安全约束满足、D5 预测质量。每个维度通过确定性证据原子和严重性加权聚合计算得分。
- 模型比较: 筛选了 66 个大语言模型，其中 21 个满足 D1 合规性阈值（>90% 有效 JSON 和字段完整性）进行全面评估。安全得分标准差为 12.52，是物理维度（std=1.95）的 6.4 倍，是预测质量维度（std=1.35）的 9.3 倍。
- 我的理解: 该协议通过将评估分解为确定性证据提取和规则引导聚合两个阶段，避免了使用大语言模型评分带来的偏差和不一致性，使得评估结果完全可复现。其核心创新在于将安全约束和物理可行性作为显式评估维度，而非隐含在准确性指标中。

### 6. 关键发现

- 安全合规性是模型行为的最具区分度维度: 在 66 个大语言模型中，安全得分标准差为 12.52，是物理维度（1.95）的 6.4 倍，是预测质量维度（1.35）的 9.3 倍。具有可比预测性能的模型在安全得分上相差超过 28 分。
- 协议优先过滤大幅降低评估成本: D1 协议合规性过滤淘汰了 67% 的候选模型（45/66），这些模型无法生成有效 JSON 或缺少必需字段，从而避免了后续内容级验证的计算开销。
- 多步滚动预测暴露延迟安全故障: 在 M3 多步滚动任务中，模型表现出不稳定性和延迟的安全约束违反，这些故障在单步预测中不可见。安全维度在 M3 中重新成为主要区分器。

- 我的理解: 该方法巧妙地将扩散模型作为AR模型的并行草稿生成器，通过LoRA适配器保持参数高效，并利用总变差损失优化接受率，实现了无损且稳定的加速。

### 6. 关键发现

- Uno实现最大批量下2倍、小批量下3倍无损加速: 在最大批量下，Uno相比基础AR模型实现2倍加速（原文'up to 2× speedup at the largest batch size'），且加速比在所有批量下均保持，优于推测解码方法。例如，在批量大小1时加速比可达3倍。
- 8B Uno模型超越更大规模扩散LLM: 在agentic工具使用、编码和长上下文推理基准上，8B Uno优于26B DiffusionGemma和专有Mercury 2模型。具体地，在Tau2 Banking上Uno得分90 vs DiffusionGemma 58 vs Mercury 2 N/A；在SWE-bench Verified上Uno得分36 vs DiffusionGemma 20 vs Mercury 2 18。
- 加速在RL训练中保持，尽管AR权重更新而扩散权重未更新: RL训练仅更新AR权重，扩散权重（LoRA）保持冻结，但Uno的加速效果在RL rollout中依然保留，表明扩散权重与AR权重的耦合具有鲁棒性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Uno的加速能力可显著降低agentic工作负载的延迟，支持更复杂的多智能体协作和实时交互。
- 对 Skill: 通过加速RL rollout，Uno能更快地训练和优化技能，提升模型在工具使用和编码等任务上的能力。
- 对 Memory: LoRA扩散权重仅增加少量参数，内存开销低，适合资源受限的部署场景。
- 对评测: Uno提供了更高效的评估方式，可在相同时间内完成更多基准测试，加速模型迭代。

### 11. 局限性

- 扩散蒸馏阶段需要额外的训练步骤，虽然仅训练LoRA权重且开销小（论文称“negligible overhead”），但增加了训练复杂度。
- 加速效果依赖于扩散权重与AR权重的耦合，若AR权重大幅变化可能需重新蒸馏。
- 当前评估主要针对特定基准，在更广泛任务上的泛化性有待验证。

### 12. 我的看法 / 个人笔记

Uno提出了一种优雅且实用的方法，通过解耦质量与速度参数，在保持AR模型优势的同时实现无损加速。其兼容现有开源模型的特点降低了应用门槛，但长期稳定性（如RL训练后加速保持）仍需更多实证。
