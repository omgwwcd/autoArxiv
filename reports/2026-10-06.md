## 1. MemPilot: Orchestrating On-Demand Multimodal Memory Curation for LLM Agents

**Topics:** GUI Agent, LLM Agent, Memory, Reinforcement Learning
**Authors:** Haozhen Zhang, Haodong Yue, Quanyu Long, Jianzhu Bao, Qingyuan Liu, Tao Feng, Bohan Liu, Weida Liang, Wenya Wang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.06830v1) | [PDF](http://arxiv.org/pdf/2610.06830v1.pdf) | [Code](https://github.com/)

### 1. 一句话结论

MemPilot 通过强化学习训练的多步策略，在运行时按需编排多模态记忆策展，实现了性能-成本-延迟的可控权衡。

### 2. 为什么重要

现有智能体记忆系统多为查询无关的预构建，无法灵活适应查询需求，且缺乏对性能、成本、延迟的联合优化。MemPilot 首次将记忆策展建模为多步决策过程，通过强化学习实现细粒度的运行时资源分配，为构建高效、自适应的智能体记忆系统提供了新范式。

### 3. 研究问题

1. 如何设计一个灵活的框架，在运行时根据查询需求和优化偏好，自适应地编排多模态记忆策展？
2. 如何在性能、成本和延迟三个相互竞争的目标之间实现可控的权衡？

### 4. 背景与问题设定

LLM 智能体依赖记忆系统保留和复用交互历史。现有系统大多以查询无关的方式预先构建记忆，导致预处理成本高且可能丢失关键细节。近期研究转向运行时自适应，但通常局限于特定操作或固定流程，缺乏对性能、成本、延迟的灵活控制。MemPilot 旨在解决这一挑战，通过强化学习优化多步策略，在运行时动态决定检索、策展、模型选择和视觉访问，以平衡多个目标。

### 5. 方法概览

- 任务 / 环境: 多模态智能体记忆基准测试，包括 Mem-Gallery、WorldMemArena、H2HMem、MemEye 和 MemLens，其中后两个用于分布外评估。
- 变量 / 干预设计: MemPilot 维护查询无关的记忆库和原始多模态历史。策略在每个步骤选择 Retrieve 或 Curate 动作，并控制证据数量、策展指令、模型选择和视觉访问。通过强化学习（GRPO）优化策略，使用目标感知的优势解耦和前缀边际效用估计进行细粒度信用分配。
- 评价指标: F1 分数和 LLM 评判分数（L-J），以及总货币成本和延迟。
- 模型比较: 与文本中心记忆系统（A-MEM, SimpleMem）、训练型记忆方法（GAM, AgeMem, Mem-T）、多模态记忆系统（MIRIX, MemVerse, M2A）以及显式权衡方法（LightMem, BudgetMem, OmniSimpleMem）进行比较。
- 我的理解: MemPilot 的核心创新在于将记忆策展视为一个可学习的决策过程，通过强化学习让策略根据查询和偏好动态调整资源分配，而不是使用固定的流程或预算。这种灵活性使得系统能够在不同偏好下实现更优的权衡。

### 6. 关键发现

- 性能-成本-延迟权衡优势: 在五个基准上，MemPilot 在不同优化偏好下均取得了优于现有方法的权衡前沿，表明其能够根据偏好灵活调整资源分配。
- 自适应计算分配: 行为分析显示，MemPilot 会根据查询复杂度和偏好动态调整证据数量、模型选择和视觉访问，例如在低成本偏好下减少视觉使用和选择较小模型。
- 与现有记忆系统兼容: MemPilot 的查询无关记忆库可替换为任意现成记忆系统，且不影响运行时编排，展示了良好的兼容性。

## 2. Back to the Future: Rethinking EDA Infrastructure for Agentic Systems in Chip Design Verification

**Topics:** GUI Agent, Chip Design Verification, Electronic Design Automation, Large Language Models, Multi-Agent Systems
**Authors:** Je Yang, Ivan Lobov, Thomas Karpati
**Venue / Year:** NeurIPS 2026 Workshop: AI for Chip Design
**Links:** [Abstract](http://arxiv.org/abs/2610.06790v1) | [PDF](http://arxiv.org/pdf/2610.06790v1.pdf)

### 1. 一句话结论

BTTF通过将大规模波形数据转化为关系型SQLite数据库，并采用多智能体协作架构，实现了芯片验证中自然语言查询的高准确率执行（95.33%）。

### 2. 为什么重要

该研究填补了LLM在芯片验证中动态波形调试的空白，提出了一种可扩展的基础设施方案，有望显著减少人工验证负担，加速芯片设计周期。

### 3. 研究问题

1. 如何将非结构化的仿真波形数据转化为LLM可高效查询的结构化格式？
2. 多智能体协作架构能否在芯片验证任务中超越单一智能体，提升推理质量和准确性？

### 4. 背景与问题设定

现代芯片验证消耗超过70%的开发周期，但现有LLM辅助EDA研究主要集中于静态RTL代码生成，对动态波形调试和验证覆盖不足。原始波形文件（如VCD）体积巨大（如10GB以上），超出LLM上下文窗口，且缺乏结构化索引，导致智能体无法直接交互，形成'基础设施阻抗'（Infrastructural Impedance）。

### 5. 方法概览

- 任务 / 环境: 芯片设计验证中的动态波形调试，包括信号查询、事件检查、覆盖率分析、断言验证等任务。
- 变量 / 干预设计: 构建BTTF框架，包含离线波形预处理流水线（将VCD转换为SQLite数据库，采用时钟修剪、零翻转信号修剪和批量插入）和在线多智能体编排引擎（包括编排、分析、验证和评估智能体）。
- 评价指标: 执行准确率（150个查询的总体准确率）、推理质量评分（五维度评估：正确性、完整性、效率、模式遵循、上下文理解）、预处理性能（存储缩减、查询延迟、覆盖率）。
- 模型比较: 与单一智能体基线对比，BTTF在推理质量上提升17.3%，但延迟增加1.96倍。

### 6. 关键发现

- 预处理策略的权衡: 时钟修剪将存储占用减少66.20%，查询延迟降低3.28倍，同时保留98.51%的功能翻转覆盖率；进一步修剪未翻转信号可将存储减少72.18%，并保持100%的活跃信号覆盖率；而激进的平均以下修剪虽将存储减少86.97%，但覆盖率降至64.23%，表明存在安全缩减的边界。

## 3. MedPrune: Topology-Efficient Multimodal Multi-Agent Communication Evolution for Medical VQA Tasks

**Topics:** 多模态多智能体协作, 医学视觉问答, 图神经网络, 强化学习
**Authors:** Jiuheng Wan, Runze Li, Chen Chen, Tingyuan Hu, Daiyang Yu, Yimin Jing, Taolin Zhang, Richang Hong
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.06695v1) | [PDF](http://arxiv.org/pdf/2610.06695v1.pdf)

### 1. 一句话结论

MedPrune通过强化学习驱动的节点剪枝和核范数正则的边剪枝，动态演化医学多智能体通信拓扑，在提升VQA准确率的同时大幅降低token开销。

### 2. 为什么重要

现有医学多智能体系统常采用静态或全连接的通信拓扑，导致计算开销大且诊断性能受限。MedPrune首次在医学多模态场景中联合剪枝节点和边，实现了任务自适应的拓扑演化，为资源受限的临床环境提供了高效且鲁棒的解决方案。

### 3. 研究问题

1. 如何动态剪枝医学多智能体通信图中的冗余节点和边以提升推理效率？
2. 在医学VQA任务中，节点剪枝和边剪枝对诊断性能的贡献分别有多大？
3. MedPrune在对抗攻击下的鲁棒性如何？

### 4. 背景与问题设定

医学多模态大模型（Med-MLLMs）在视觉问答（VQA）中表现出色，但真实临床诊断需要多科室协作。现有方法要么采用静态模板（如固定流程），要么仅进行表面自适应，导致token开销大且性能受限。MedPrune将诊断过程建模为异构通信图，通过两阶段剪枝动态演化出紧凑高效的协作拓扑。

### 5. 方法概览

- 任务 / 环境: 医学视觉问答（VQA）任务，输入为医学图像和问题，输出为答案。
- 变量 / 干预设计: MedPrune包含两个阶段：1）异构节点剪枝：通过策略梯度优化软邻接矩阵，以任务性能为奖励，剪除低加权度的节点；2）异构边剪枝：在节点剪枝后的子图上，联合优化任务性能和核范数惩罚，并采用渐进式剪枝率衰减策略，逐步剪除低权重边。
- 评价指标: 准确率（Accuracy）和token效率（Token Efficiency）。
- 模型比较: 与训练无关方法（SP、CoT）、训练密集型方法（RAG、LoRA、GRPO）、静态多智能体方法（AdaCoMed、MedAgent-Pro）以及自适应方法（MMedAgent-RL、M3Prune、CARE、ARG-Designer）进行比较，骨干网络包括Qwen3-VL (8B)等。
- 我的理解: MedPrune的核心创新在于将多智能体通信视为可学习的图结构，通过两阶段剪枝实现任务自适应的拓扑演化，既保留了关键专家信息，又大幅减少了冗余计算。

### 6. 关键发现

- 性能提升: 在三个医学VQA基准上，MedPrune在Qwen3-VL (8B)骨干下平均准确率提升3.65%，token效率提升37.86%。
- 鲁棒性: 在对抗攻击设置下，性能仅下降3.1%，显示出强鲁棒性。
- 数据效率: 仅用10个样本的few-shot训练即可达到与全量训练相当的性能，表明其数据效率高。

- 对 Agent 系统: MedPrune为多智能体系统提供了一种动态拓扑演化范式，可推广到其他需要多专家协作的领域，如金融分析、法律咨询等。

- 对评测: token效率成为评估多智能体系统的重要指标，MedPrune提供了新的评估维度。

## 4. Can Agent Harnesses and Inference Engines Hear Each Other? The HEAR Protocol for Agentic LLM Serving

**Topics:** LLM Agent Serving, Harness-Engine Coordination, Cache-Aware Scheduling
**Authors:** Jiaqi Zhao, Haodong Chen, Jitai Hao, Wei Zhao, Jinghao Pang, Qiang Huang, Jun Yu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.06597v1) | [PDF](http://arxiv.org/pdf/2610.06597v1.pdf) | [Code](https://anonymous.4open.science/r/hear-3D1E/)

### 1. 一句话结论

HEAR 协议通过标准化智能体工作流与推理引擎之间的双向通信，实现缓存感知调度和负载感知执行模式选择，显著提升并发服务效率。

### 2. 为什么重要

该工作填补了智能体服务中工作流语义与运行时状态之间的系统级鸿沟，为构建可移植、可组合的跨层协调策略提供了通用协议基础，对提升复杂 LLM 应用的服务效率具有重要价值。

### 3. 研究问题

1. 如何标准化智能体工作流与推理引擎之间的跨层信息交换，以支持高效的协调决策？
2. 结合工作流意图与引擎状态，能否在内存受限的并发场景下显著提升服务吞吐和延迟表现？

### 4. 背景与问题设定

LLM 智能体执行多轮推理、工具调用和并行任务时，服务效率取决于智能体工作流（理解依赖、上下文生命周期）与推理引擎（掌握队列、KV 缓存、资源压力）的协同。然而现有接口缺乏系统性连接，导致工作流感知执行受限，例如引擎可能在上下文即将复用时驱逐 KV 缓存，或调度器忽略缓存命中而优先处理冷请求。

### 5. 方法概览

- 任务 / 环境: 内存受限的并发服务环境，涵盖 SCBench、Mooncake、BrowseComp-Plus 和 DeepResearchBench 等基准，模拟对话和科研智能体工作负载。
- 变量 / 干预设计: 实现 HEAR 协议，定义四种消息类别（执行描述与意图、执行需求与控制、状态与能力、执行结果），并区分意图与控制、偏好与需求、观察与保证、接受与完成。基于此，实例化两种策略：在线缓存感知运行时协调（结合等待约束和未来复用意图与 KV 驻留状态）和负载感知执行模式选择（根据工作负载特征配置推理模式）。
- 评价指标: 端到端速度提升、批处理吞吐量、中位数和 P95 首令牌延迟（TTFT）、任务质量（如准确率）等。
- 模型比较: 与未使用 HEAR 的基线（如仅依赖工作流或仅依赖引擎状态）对比，以及不同策略配置间的对比。
- 我的理解: HEAR 的核心在于提供一种语义清晰的通信契约，使工作流和引擎能够交换互补信息，而无需改变各自内部逻辑。通过分离协议语义与优化策略，它允许不同策略复用同一协议，实现灵活协调。

### 6. 关键发现

- 缓存感知协调显著提升并发服务效率: 在 SCBench 上，HEAR 实现 1.61 倍批处理加速，中位数 TTFT 降低 2.23 倍，P95 TTFT 降低 1.45 倍。
- 工作流意图与引擎状态互补: Mooncake 实验表明，未来复用意图可改善缓存保留，但需结合实时引擎状态以避免过载时性能下降。
- 负载感知配置带来端到端加速: 在 BrowseComp-Plus 和 DeepResearchBench 上，根据工作负载特性选择推理模式，分别获得 1.23 倍和 2.45 倍的端到端加速，且未观察到任务质量下降。

- 对 Memory: HEAR 的缓存感知协调优化了 KV 缓存的使用，减少不必要的驱逐和重新预填充，降低内存开销。
- 对评测: HEAR 提供了可量化的效率指标（如 TTFT、吞吐量），并强调任务质量不变，为评估智能体服务系统提供了新维度。

### 11. 局限性

HEAR 提出了一种优雅的协议抽象，解决了智能体服务中跨层信息不对称的关键问题。其分离协议与策略的设计具有前瞻性，有望成为未来智能体服务系统的基础组件。不过，实际部署中需考虑协议开销和兼容性，未来可探索自适应策略和更广泛的基准测试。

## 5. CLIFT: Conformal Self-Verification for Web Agent Training and Test-Time Scaling

**Topics:** GUI Agent, Web Agent, 强化学习, 测试时扩展, 共形预测
**Authors:** Yifan Zhang, Yutong Dai, Viraj Prabhu, Zhiyuan Hu, Ran Xu, Zeyuan Chen
**Venue / Year:** arXiv preprint arXiv:2610.06829v1
**Links:** [Abstract](http://arxiv.org/abs/2610.06829v1) | [PDF](http://arxiv.org/pdf/2610.06829v1.pdf)

### 1. 一句话结论

CLIFT 通过共形自验证将昂贵的裁判反馈转化为可复用的、经过认证的验证问题库，在训练时提供稠密奖励，在测试时实现无裁判的轨迹选择，从而显著提升开放 Web 智能体的性能。

### 2. 为什么重要

当前开放 Web 智能体的强化学习受限于稀疏的二元成功信号和昂贵的裁判模型，而 CLIFT 提供了一种无需外部裁判的测试时扩展方法，同时将裁判知识转化为可迁移的验证问题库，为训练和推理阶段提供了统一的解决方案，有望推动 Web 智能体在真实场景中的部署。

### 3. 研究问题

1. 如何将昂贵的裁判反馈转化为可复用的、经过认证的验证信号，以支持训练和测试时扩展？
2. CLIFT 的共形自验证机制能否在不同基准（WAI、VWA、OM2W）上提升开放 Web 智能体的性能，并实现跨模型迁移？

### 4. 背景与问题设定

开放 Web 智能体已能执行真实浏览器任务，但强化学习训练受限于弱监督：二元成功信号过于稀疏，导致信用分配困难；前沿语言模型裁判虽能提供丰富反馈，但成本高且部署时不可用。现有方法如 GRPO 依赖轨迹级奖励，无法提供细粒度指导。CLIFT 旨在通过共形自验证，将裁判反馈转化为可复用的验证问题库，在训练时提供稠密奖励，在测试时实现无裁判的轨迹选择。

### 5. 方法概览

- 任务 / 环境: 三个基准：WebArena Infinity (WAI) 用于训练和评估；VisualWebArena (VWA) 用于跨模型迁移测试；Online Mind2Web (OM2W) 用于零样本测试时扩展。
- 变量 / 干预设计: 训练阶段：CLIFT 使用共形认证的验证问题库，为每个 URL 状态生成验证分数，并作为非负奖励添加到裁判奖励之上，同时采用 URL 分层的优势估计。测试阶段：冻结验证问题库，通过共形轨迹选择（CTS）在多个候选轨迹中保守地选择更优者，无需外部裁判。
- 评价指标: 任务成功率（Success Rate），按基准的官方协议计算。
- 模型比较: 与多种基线比较：基础 Gemma-4、vanilla GRPO、以及公开的强基线（如 Gemini 3 Flash、Qwen 3.5、Kimi、Claude Opus 4.6 等）。
- 我的理解: CLIFT 的核心思想是将裁判的隐式知识显式化为可验证的问题，并通过共形预测保证其可靠性。训练时，这些验证信号提供稠密奖励，加速学习；测试时，它们作为无裁判的评估器，通过保守的多数投票机制选择更优轨迹，从而提升性能。

### 6. 关键发现

- WAI 上达到开放智能体最优性能: CLIFT 训练的 Gemma-4 模型在 WAI 的 9 个应用上达到 74.6% 的成功率，超过所有公开的开放智能体系统（如 Gemini 3 Flash、Qwen 3.5、Kimi），但未与封闭模型（如 Claude Opus 4.6）直接比较。CTS 无需外部裁判，且采用保守的多数投票规则，确保性能不退化。
- 验证问题库可跨模型迁移: 在 VWA 上，使用 Gemma-4 训练期间学习的验证问题库，应用于 GPT-5.5 的测试时选择，将平均成功率提升至 53.7%，超过 WALT 基线（52.9%），且所有三个环境（Classifieds、Shopping、Reddit）均有提升。
- 训练时奖励更稠密，加速收敛: CLIFT 的逐 URL 验证分数提供了比轨迹级奖励更稠密的信号，训练曲线显示 CLIFT 在相同裁判调用次数下比 vanilla GRPO 更快达到更高奖励。
