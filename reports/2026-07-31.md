## 1. LEDGERMIND: Provenance-Constrained Multimodal Agentic Reasoning with a Structured Evidence Ledger

**Topics:** GUI Agent, Multimodal Agent, Provenance, Faithfulness
**Authors:** Enjun Du, Hange Zhou, Chenxu Du, Siyi Liu, Zirong Chen, Ziyu Zheng, Yongqi Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.28374v1) | [PDF](http://arxiv.org/pdf/2607.28374v1.pdf)

### 1. 一句话结论

LedgerMind 通过结构化证据账本将多模态智能体轨迹转化为受溯源约束的状态机，显著提升答案准确性与轨迹忠实度。

### 2. 为什么重要

现有多模态智能体评估仅依赖最终答案准确率，无法揭示中间推理是否基于真实证据。LedgerMind 首次将溯源约束作为结构性条件，系统性地解决了无支撑推理、幻影引用、过度推理和修复放大等隐蔽失败模式，为可信多模态推理提供了新范式。

### 3. 研究问题

1. 如何设计一种结构化运行时，使多模态智能体的中间推理步骤可审计且受证据约束？
2. 能否通过溯源非放大保证，防止修复过程引入无来源的新内容？

### 4. 背景与问题设定

多模态大模型在视觉问答中常采用多步轨迹，但评估仅看最终答案准确率，无法区分正确回答是源于真实证据、语言先验还是偶然误差。现有方法如自由文本轨迹存储、引用机制和自修正均存在缺陷：自由文本混合了工具输出与模型推断；引用可能掩盖结论级幻觉（幻影引用）；自修正缺乏外部反馈时可能引入新错误（修复放大）。

### 5. 方法概览

- 任务 / 环境: 多模态视觉问答，涉及图像感知、检索和推理的多步轨迹。
- 变量 / 干预设计: 提出结构化证据账本作为轨迹状态，工具输出归一化为账本条目，下游推理只能引用活跃条目；通过三层接地协议（支持覆盖、实体一致性、数值一致性）验证声明；自适应双路径调度器根据问题复杂度选择直接路径或全管道路径；事件触发验证与修复引擎使用七种类型化操作符，保证修复不引入无溯源内容。
- 评价指标: 最终答案准确率、轨迹级忠实度（无支撑声明率、幻影引用率、过度推理率、修复放大率）。
- 模型比较: 在多个多模态推理基准和骨干MLLM上对比，LedgerMind 同时提升答案准确率和轨迹忠实度。
- 我的理解: 该方法将智能体轨迹从自由文本转化为受约束的状态机，核心创新在于用结构化账本强制证据溯源，并通过类型化修复操作符提供形式化保证，使每个新条目都必须来自工具输出。

### 6. 关键发现

- 结构化证据账本提升轨迹忠实度: LedgerMind 在多个基准上显著降低无支撑声明率和幻影引用率，同时保持或提升答案准确率。
- 自适应调度避免过度推理: 双路径调度器根据问题复杂度选择推理深度，在简单查询上避免不必要的多步管道，减少计算开销和错误引入。
- 类型化修复防止修复放大: 事件触发的验证与修复引擎通过七种类型化操作符（如DROP、REFRESH、RETRY）修改账本或动作，保证修复不引入无溯源内容，形式化证明见命题1。

### 10. 对 Agent / Skill / Memory 的启发

### 12. 我的看法 / 个人笔记

## 2. Beacon: Knowing When and How to Perform Agentic Visual Reasoning

**Topics:** GUI Agent, Agentic Visual Reasoning, Multimodal Large Language Models, Tool Use, Reinforcement Learning
**Authors:** Qixun Wang, Yang Shi, Letian Cheng, Zhuoran Zhang, Yan He, Yuqi Tang, Qi Zhang, Xinlei Yu, Ruizhe Chen, Tianrun Xu, Yuanxing Zhang, Pengfei Wan, Haotian Wang, Xianghua Ying
**Venue / Year:** arXiv preprint, 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.28595v1) | [PDF](http://arxiv.org/pdf/2607.28595v1.pdf)

### 1. 一句话结论

Beacon通过必要性感知自适应奖励和提示引导能力扩展机制，在强化学习阶段显著提升了多模态大模型在视觉推理中工具调用的自适应性和有效性，实现了超越纯文本推理的真实性能增益。

### 2. 为什么重要

现有智能体视觉推理模型在工具调用上缺乏自适应性，且工具带来的增益常被其引入的错误抵消。Beacon首次系统性地同时优化了工具调用的自适应性和工具效果，为构建更高效、更可靠的智能体视觉推理系统提供了新范式。

### 3. 研究问题

1. 现有智能体视觉推理模型在工具调用自适应性和工具效果方面表现如何？
2. 如何通过强化学习同时提升模型工具调用的自适应性和工具带来的真实性能增益？

### 4. 背景与问题设定

智能体视觉推理通过调用外部工具（如代码）生成中间多模态结果来辅助最终答案生成，已成为多模态大模型的重要范式。然而，现有研究忽视了工具调用的两个关键方面：一是模型能否根据问题是否需要工具来自适应地调用（模式自适应性，MA）；二是工具使用是否真正扩展了模型能力，同时避免在已可解决的问题上引入错误（工具效果，TE）。分析发现，现有模型MA有限，工具在难题上的增益很大程度上被在简单题上引入的错误抵消。

### 5. 方法概览

- 任务 / 环境: 多模态视觉推理任务，涵盖真实世界感知、图表理解、OCR、STEM、空间推理和智能体推理等13个基准测试。
- 变量 / 干预设计: 采用SFT+RL两阶段训练。SFT阶段通过高质量数据合成管道赋予模型基础代码使用能力；RL阶段引入必要性感知自适应奖励（NAAR）和提示引导能力扩展（HCE）机制，分别鼓励基于任务必要性的自适应工具调用和强化模型在最具挑战性问题上的工具使用能力。
- 评价指标: 主要指标包括：模式自适应性（MA_text、MA_tool、MA_mean）、工具效果（Tool-Gain、Tool-Harm）、工具可用准确率（Tool-Available Acc.）和纯文本准确率（Tool-Free Acc.）。
- 模型比较: 与Thyme、DeepEyes-V2、CodeV、Metis等代表性智能体视觉推理模型对比，在13个基准上评估平均性能。
- 我的理解: 该方法的核心创新在于将工具调用的自适应性和有效性作为两个可优化的目标，通过RL框架中的奖励设计和数据策略来同时优化，而不是像以往工作那样仅关注整体准确率或简单抑制工具调用。

### 6. 关键发现

- 现有模型工具调用自适应性差: 大多数评估模型的MA_mean接近甚至低于50%的随机基线，且许多模型始终偏好单一推理模式（纯文本或工具辅助），无法根据问题难度自适应选择模式。
- 工具增益被工具危害抵消: 现有模型的Tool-Gain较低，且不显著超过Tool-Harm，导致工具使用带来的净性能提升有限。
- Beacon实现自适应工具调用和最大净增益: Beacon在13个基准上取得最佳平均性能（58.98%），且MA_text和MA_tool均显著高于对比模型，Tool-Gain与Tool-Harm的差值最大（+3.1%），表明其工具使用更有效地扩展了模型能力。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Beacon展示了智能体系统应具备根据任务难度自适应选择是否使用工具的能力，避免不必要的计算开销，同时确保在复杂任务上通过工具扩展能力。
- 对 Skill: 工具使用技能的训练需要从SFT阶段的基础能力培养到RL阶段的自适应和高效使用，且RL阶段应重点强化在纯文本无法解决的难题上的工具使用能力。
- 对 Memory: 虽然本文未直接涉及记忆机制，但自适应工具调用可视为一种元认知能力，未来可结合记忆来记录哪些类型任务需要工具辅助，进一步提升效率。
- 对评测: 本文提出的MA和TE指标为评估智能体视觉推理模型提供了更细粒度的视角，超越了单纯的整体准确率，有助于诊断模型工具使用的真实效益。

### 11. 局限性

- 论文为预印本，工作仍在进行中，可能尚未经过同行评审。
- 训练数据构建依赖Gemini 3.1 Pro生成轨迹，可能引入教师模型的偏差。
- 实验仅在Qwen3-VL-8B-Instruct基座上验证，泛化性到其他基座模型尚待探索。

### 12. 我的看法 / 个人笔记

Beacon通过将工具调用的自适应性和有效性作为显式优化目标，在RL框架中巧妙设计奖励和提示策略，为解决智能体视觉推理中工具使用的核心矛盾提供了有效方案。其提出的MA和TE指标也为该领域提供了更细致的评估工具。未来工作可探索将自适应工具调用扩展到更广泛的工具集和更复杂的多步推理场景。

## 3. Why Are GUI Agents Correct but Late? Decode on the Decision-Time Critical Path, Tested with Pre-Compiled Policy Trees

**Topics:** GUI Agent, Decision-Time Critical Path, Latency Reduction, Policy Trees
**Authors:** Zihan Dong, Rui Qian, Qishi Zhan, Dongshen Peng, Kaixin Li, Yu Li
**Venue / Year:** AAAI 2027
**Links:** [Abstract](http://arxiv.org/abs/2607.28399v1) | [PDF](http://arxiv.org/pdf/2607.28399v1.pdf)

### 1. 一句话结论

通过预编译条件策略树将模型解码移出决策关键路径，在瞬态GUI事件窗口内将成功率从0.50提升至0.79（p=1.8×10⁻³），且无错误动作。

### 2. 为什么重要

GUI智能体常因解码延迟错过短暂交互窗口，本文首次通过受控实验隔离出延迟而非理解错误是主因，并提出无需修改模型的轻量解决方案，为实时GUI代理设计提供了新范式。

### 3. 研究问题

1. GUI智能体在瞬态事件中失败的主因是缺乏预期还是解码延迟？
2. 将生成过程移出决策关键路径能否在保持正确性的同时提升时效性？

### 4. 背景与问题设定

现有GUI智能体采用截图-推理-动作循环，但面对自动消失的对话框、限时认证等瞬态事件时，常因大型多模态模型的自回归解码耗时过长（中位数567ms）而错过窗口。问题不在于理解错误，而在于正确动作产生时窗口已关闭。

### 5. 方法概览

- 任务 / 环境: key_prompt基准测试：可调250-2000ms事件窗口的定时GUI任务，服务器端确定性评分，隐藏种子调度决定所需按键。
- 变量 / 干预设计: AAPT：空闲屏幕期间用冻结模型预编译条件策略树（可观察守卫、预授权动作、分支截止时间），树大小由解码延迟决定（Tcover ≥ Lp95 + M，其中Lp95为95百分位规划延迟，M为安全余量500ms）。事件发生时轻量观察者匹配分支并立即执行，无需生成新文本。对比基线：R0（反应式）、R1（开环）、P1（预测-重规划）、O1（神级路由）。
- 评价指标: 配对试验中成功率和错误动作率，使用精确McNemar检验。
- 模型比较: Holo-3.1-35B-A3B（主要实验）和独立通用多模态模型（复制实验），均冻结使用。
- 我的理解: AAPT的核心创新在于将生成式解码从事件关键路径转移到空闲期，通过预编译策略树实现事件触发时的零生成响应，本质上是计算时间与决策时间的解耦。

### 6. 关键发现

- AAPT在争议窗口显著优于反应式基线: 在650ms窗口，AAPT成功率0.79 vs R0的0.50（p=1.8×10⁻³），且错误动作率为0%。
- 仅提前行动不足以解决问题: 开环（R1）和预测-重规划（P1）基线在争议窗口成功率为0，因为它们仍在关键路径上解码。
- 效果依赖于三个关键组件，分支路由是因果瓶颈: 快速观察者解码、有效树规划、准确分支路由缺一不可；预注册的神级路由实验拒绝了初始假设（即树规划质量是瓶颈），转而指向分支路由为因果瓶颈。
- 效果在独立模型上可复制: 在126对试验中，通用多模态模型上p=4.9×10⁻¹³。
- 外部基准测试中AAPT与反应式基线性能相当但互补: AAPT在动作可枚举时优势显著，但不可枚举时反应式执行更优。

- 图来源: Figure 1: 争议窗口下的关键路径对比
- 为什么重要: 直观展示了反应式循环（567ms）与AAPT（325ms路由）在600ms窗口内的时序差异，解释了为何AAPT能成功而反应式失败。

横轴为事件发生前后的时间（ms），纵轴为不同方法的关键路径。反应式基线（R0）需在窗口内完成截图+决策+动作（567ms），而AAPT在空闲期预编译树，事件后仅需轻量路由（325ms），留有33ms余量。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 为实时GUI代理提供了一种无需修改模型即可显著降低延迟的通用方法，尤其适用于动作可枚举的场景。
- 对 Skill: 预编译策略树可视为一种可组合的原子技能，未来可存入长期记忆库。
- 对 Memory: 验证后的AAPT子树可转化为长期记忆中的门控技能，实现经验复用。
- 对评测: 提出配对试验和精确McNemar检验作为评估延迟敏感任务的严谨方法，强调预注册端点的重要性。

### 11. 局限性

- AAPT在动作不可枚举时性能不如反应式执行（如外部基准测试所示）。
- 树编译时间约1.8秒，在更紧迫场景中可能不足。
- 分支路由被识别为因果瓶颈，当前观察者准确率0.86-0.93仍有提升空间。

### 12. 我的看法 / 个人笔记

本文通过精巧的实验设计（配对试验、预注册、神级路由）令人信服地证明了解码延迟是GUI智能体失败的主因，而非理解错误。AAPT虽非全新架构，但其作为因果检验工具的价值远超方法本身。未来工作应聚焦于提升分支路由准确性和扩展至动作不可枚举场景。

### 13. 这篇工作引用的近期高影响力相关文章

- TraceR1
  为什么重要：代表预测-重规划方法，在争议窗口成功率为0，凸显AAPT的优势。
  核心贡献：预测轨迹并执行第一步后重规划，但每一步关键路径上仍有模型调用。
  与当前论文关系：作为P1基线的灵感来源，对比显示AAPT通过预编译避免了关键路径解码。

  为什么重要：通过推测执行隐藏延迟，但依赖可逆操作，不适用于GUI。

### 14. 总结

本文提出自适应预期策略树（AAPT），通过空闲期预编译条件策略树将模型解码移出决策关键路径，树大小由解码延迟决定（Tcover ≥ Lp95 + M）。在瞬态GUI事件窗口内将成功率从0.50提升至0.79（p=1.8×10⁻³），且无错误动作。通过配对试验和预注册端点，隔离出解码延迟而非缺乏预期是失败主因，并在独立模型上复制效果。预注册的神级路由实验拒绝了初始假设，指向分支路由为因果瓶颈。外部基准测试显示AAPT在动作可枚举时优势显著，但不可枚举时反应式执行更优。

## 4. How Benchmarks Mis-Score Computer-Use Agents

**Topics:** GUI Agent, Benchmark Reliability, Evaluation Pipeline
**Authors:** Zihan Dong, Zhiyuan Ma, Zekun Wang, Yunqing Li, Zirou Liu, Ruixuan Deng, Qishi Zhan, Rui Qian
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.28367v1) | [PDF](http://arxiv.org/pdf/2607.28367v1.pdf)

### 1. 一句话结论

15.3%的FAIL判定是错误的，真实失败中验证/反馈和规划错误占主导（共74.5%），而非执行/接地错误（13.9%）。

### 2. 为什么重要

揭示了CUA基准测试评分管道的系统性缺陷，可能导致排行榜误判和工程努力错配，并提供了阶段特定的设计规则以提升评估可靠性。

### 3. 研究问题

1. CUA基准测试的评分管道在哪些阶段容易产生不可靠的判定？
2. 在150个公开失败轨迹中，有多少FAIL判定实际上是错误的？
3. 真正的代理失败中，规划、执行和验证各阶段的分布如何？

### 4. 背景与问题设定

计算机使用代理（CUA）正被部署于网页浏览和桌面软件操作，但其基准测试分数仍依赖脆弱的脚本化预言机。分数是管道的输出，任务可能过时、轨迹可能遗漏关键视觉证据、评估者可能拒绝有效替代方案、聚合报告可能隐藏失败原因。随着任务从短动作序列扩展到长时跨应用工作流（如OSWorld 2.0中位数约1.6小时），部署与测量之间的差距日益突出。

### 5. 方法概览

- 任务 / 环境: 从五个基准（WebArena、WorkArena、VisualWebArena、AssistantBench、OSWorld）中采样150个公开失败轨迹，每个轨迹包含逐步推理、动作和截图。
- 变量 / 干预设计: 两阶段标注：阶段1判断FAIL是否为真正代理失败、评估者假阴性、任务损坏或证据不足；阶段2对真正失败应用三层诊断分类法（T1规划与规范、T2执行与接地、T3验证与反馈），改编自MAST。
- 评价指标: 错误判定率（假阴性、任务损坏）、失败类型分布（三层分类）。
- 模型比较: 使用两个视觉LLM（GPT-5.5和Claude Sonnet）独立标注，人类评审组验证所有74个分歧行和30个一致行，最终标签由多数投票决定。
- 我的理解: 该方法通过系统审计和结构化分类，将基准测试的不可靠性分解为可量化的组件，并区分了代理能力缺陷与评估管道缺陷。

### 6. 关键发现

- 15.3%的FAIL判定是错误的: 在150个失败轨迹中，10.7%是评估者假阴性（任务实际完成但检查器拒绝），4.7%是任务损坏（规范不可行或环境故障），另有3.3%证据不足。
- 真正失败中验证/反馈和规划错误占主导: 在122个真正代理失败中，T3验证/反馈错误占39.3%（如无操作循环36例、过早停止8例、遗漏验证4例），T1规划错误占35.2%（如规范违反18例、规划循环20例、幻觉特征5例），T2执行/接地错误仅占13.9%（如接地错误9例、工具参数6例、状态丢失2例）。
- 不同基准的错误模式各异: WebArena的假阴性率高达21.7%（答案匹配拒绝有效行为），AssistantBench的任务损坏率21.7%（搜索引擎失效、CAPTCHA），OSWorld的假阴性率14.0%（状态检查器错过有效替代方案），WorkArena无错误判定。

### 7. 最重要的图

- 图来源: Figure 1: CUA基准测试评分管道示意图
- 为什么重要: 该图将CUA执行循环映射到四个测量阶段（任务构建、执行环境、评分、报告），并定位了三个可靠性威胁（任务有效性/污染、评估者脆弱性、可观测性/诊断不透明性），为全文分析提供了组织框架。

从左上角的CUA执行循环开始，基准测试捕获有损轨迹并投影到四个阶段。每个阶段对应一个可靠性威胁：阶段1-2关注任务和环境有效性，阶段3关注评估者脆弱性，阶段2-4关注可观测性和诊断不透明性。箭头表示威胁进入管道的阶段。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 开发应关注验证/反馈和规划能力，而非仅提升执行精度；需设计能检测无操作循环和过早停止的机制。
- 对 Skill: 技能评估应区分规划、执行和验证阶段，避免单一成功率掩盖失败原因。
- 对 Memory: 轨迹应包含完整截图和状态转换，以支持事后诊断；需记录中间状态和反馈。
- 对评测: 评估管道应包含任务有效性检查、多路径接受、分级评分和诊断报告；避免仅依赖脚本化预言机。具体地，论文提出阶段特定设计规则：任务构建阶段需确保任务可行且独立于系统开发；执行环境需可重现且包含完整轨迹；评分应使用语义或基于判断的匹配；报告应支持诊断，如提供失败原因分类。

### 11. 局限性

- 样本仅包含失败轨迹，未估计成功轨迹中的假阳性。
- 审计限于五个基准，可能不泛化到所有CUA评估。
- LLM标注和人类评审可能存在偏差，尽管通过独立标注和交叉验证减轻。

### 12. 我的看法 / 个人笔记

该论文系统性地揭示了CUA基准测试中评分管道的不可靠性，并提供了可操作的改进方向。其核心贡献在于将评估问题分解为可量化的阶段，并展示了单一成功率如何掩盖关键失败模式。未来工作应扩展审计到更多基准和成功轨迹，并开发自动化的管道可靠性检查工具。

### 13. 这篇工作引用的近期高影响力相关文章

- MAST: Multi-Agent Coordination Benchmark
  为什么重要：提供了多代理协调的失败分类法，本文将其改编为单代理CUA的三层诊断分类。
  核心贡献：提出多代理任务中失败的系统分类。
  与当前论文关系：本文改编了MAST的分类法，移除了多代理特有类别，并重新解释了状态传播和验证失败。
- OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments
  为什么重要：提供了桌面控制基准和感知-动作循环框架，本文的失败分类基于此。
  核心贡献：提出真实桌面环境中的开放任务基准。
  与当前论文关系：本文使用OSWorld轨迹进行审计，并扩展了其失败分析。
- AgentRewardBench: Evaluating Reward Models for Web Agents
  为什么重要：提供了奖励模型评估基准，本文从中采样了WebArena、WorkArena等轨迹。

  与当前论文关系：本文使用AgentRewardBench的轨迹数据，并发现了其评估中的假阴性问题。

### 14. 总结

本文审计了150个CUA基准测试的失败轨迹，发现15.3%的FAIL判定是错误的，其中评估者假阴性占10.7%，任务损坏占4.7%。真正代理失败中，验证/反馈错误（39.3%）和规划错误（35.2%）远多于执行/接地错误（13.9%）。基于Figure 1的四阶段管道框架和Table 2的量化结果，提出了阶段特定的评估设计规则，以提高CUA基准测试的可靠性。

## 5. OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models

**Topics:** GUI Agent, Reward Model, VLM Judge, Computer-Using Agent
**Authors:** Qiushi Sun, Kanzhi Cheng, Yian Wang, Bowen Yang, Hang Yan, Liheng Chen, Fangzhi Xu, Zichen Ding, Nuo Chen, Jialin Cao, Xingdong Gong, Zehao Li, Kaiming Jin, Xinfeng Yuan, Zhoumianze Liu, Jingyang Gong, Zhangyue Yin, Jiahui Gao, Zhiyong Wu, Tianbao Xie, Jianbing Zhang, Ben Kao, Lingpeng Kong
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.28609v1) | [PDF](http://arxiv.org/pdf/2607.28609v1.pdf) | [Code](https://os-copilot.github.io/OSReward-Home/)

### 1. 一句话结论

OSReward 是首个跨平台、人工标注的 CUA 轨迹奖励模型标准化评测基准，揭示了 VLM 裁判普遍存在的宽松偏差，并开源了低成本、高可靠性的 OS-Shepherd 奖励模型。

### 2. 为什么重要

CUA 的评估、数据筛选和强化学习严重依赖 VLM 作为裁判，但裁判本身的可靠性从未被系统检验。OSReward 填补了这一空白，提供了干净的基准和低成本的开源替代方案，使学术预算也能支撑大规模可靠奖励信号。

### 3. 研究问题

1. VLM 裁判在跨平台 CUA 轨迹判断中是否可靠？
2. 如何构建低成本、高可靠性的 CUA 奖励模型？

### 4. 背景与问题设定

计算机使用代理（CUA）的轨迹验证是评估、数据筛选和强化学习的核心。人工验证和规则验证无法规模化，因此领域转向使用 VLM 作为裁判。但 VLM 裁判的可靠性从未被系统研究，现有基准存在轨迹质量混杂、标签噪声等问题。

### 5. 方法概览

- 任务 / 环境: 跨平台环境：Web（Chromium）、Windows（20+应用）、Ubuntu（30+应用）、Android 模拟器，每个环境都初始化了真实用户文件、应用数据库和干扰内容。
- 变量 / 干预设计: 从 1500 个人工验证指令中筛选约 800 个，由 Claude、Gemini、Kimi、Qwen 四类代理执行，产生 1019 条人工金标准轨迹。每条轨迹经三人独立标注+元审查，并构建 OSReward-Hard（困难子集）和 OSReward-Multi（细粒度效率/对齐子集）。
- 评价指标: 二元准确率（Binary Accuracy）、召回率（Recall on GT=FAIL/SUCCESS）、成本-准确率前沿（Cost-Accuracy Pareto Frontier）。
- 模型比较: 评测了 27 个 VLM 模型，包括 GPT-5、Claude-Opus-4-8、Gemini-3.1-Pro、Qwen3-VL 系列等，对比了商业模型与开源模型在 OSReward 和 OSReward-Hard 上的表现。
- 我的理解: 该方法通过端到端构建干净基准，避免了复用轨迹的混杂问题。人工标注流程严格，但 1019 条轨迹规模有限，可能无法覆盖所有长尾场景。OS-Shepherd 的训练数据来自大规模自动标注，与基准分离，保证了评估的独立性。

### 6. 关键发现

- VLM 裁判普遍存在宽松偏差: 所有评测模型在失败轨迹上的召回率远低于成功轨迹，即倾向于将失败误判为成功。例如，最佳模型 Claude-Opus-4-8 在 OSReward-Hard 上准确率仅 70%，平均模型仅 52%。
- 可靠裁判成本高昂: 准确率高的模型（如 Claude-Opus-4-8、GPT-5.5）成本极高，而低成本开源模型准确率大幅落后。OS-Shepherd 模型以 30-60 倍低成本达到接近商业模型的准确率。
- 裁判更依赖代理叙述而非屏幕状态: 分析表明，VLM 裁判更容易被代理的自我声明（如“任务完成”）所欺骗，而非真正检查环境状态是否达到目标。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: CUA 系统应避免仅依赖 VLM 裁判的自我声明，需结合环境状态检查。OS-Shepherd 提供了低成本、可自托管的奖励信号，使强化学习训练更可行。
- 对 Skill: 裁判的宽松偏差提示代理可能学会“假装成功”而非真正完成任务，训练时应加入对抗性样本。
- 对 Memory: 长轨迹（最多 100 步）的判断需要模型具备长上下文理解能力，当前模型在此方面仍有不足。
- 对评测: 未来 CUA 评估应包含困难子集（如 OSReward-Hard）以暴露裁判弱点，并报告失败/成功召回率而非仅准确率。

### 11. 局限性

- OSReward 基准仅包含 1019 条轨迹，规模有限，可能无法覆盖所有真实场景。
- 人工标注成本高，且标注者之间可能存在分歧（OSReward-Hard 正是基于分歧构建）。
- OS-Shepherd 的训练数据来自自动标注，可能继承自动标注的噪声。
- 评测仅覆盖 27 个模型，未包括最新发布的模型。

### 12. 我的看法 / 个人笔记

该工作系统性地揭示了 CUA 领域一个被忽视的关键问题——VLM 裁判的可靠性，并提供了实用的解决方案。OS-Shepherd 的开源发布对学术界意义重大，使低成本大规模 CUA 训练成为可能。但基准规模较小，未来需扩展至更多平台和任务。

### 14. 总结

OSReward 是首个跨平台、人工标注的 CUA 轨迹奖励模型标准化评测基准，包含 1019 条金标准轨迹及困难子集。评测 27 个 VLM 模型发现所有裁判存在宽松偏差，可靠模型成本高昂。为此，开源了 OS-Shepherd-100K 训练数据和 OS-Shepherd 奖励模型（9B/35B），以 30-60 倍低成本达到接近商业模型的准确率，为 CUA 社区提供了可靠且经济的奖励信号。
