## 1. GHOST-Q: Towards Studying Grounding Hallucinations Overlooked Under Same-score TradeOffs in Quantized VLMS

**Topics:** 视觉语言模型, 量化, 幻觉, 多模态可靠性
**Authors:** Saim Rehman, Muhammad Shafique
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.29999v1) | [PDF](http://arxiv.org/pdf/2609.29999v1.pdf)

### 1. 一句话结论

量化后的视觉语言模型即使保持总体准确率，也可能在细粒度视觉接地行为上发生显著且双向的预测翻转，且内存压缩并不必然带来推理延迟的降低。

### 2. 为什么重要

该研究揭示了量化评估中一个被忽视的关键问题：仅关注总体准确率可能掩盖模型在视觉接地可靠性上的退化，这对量化模型在安全关键场景中的部署具有重要意义。

### 3. 研究问题

1. 量化在保持总体任务准确率的同时，是否也保持了模型的视觉接地成功与失败模式？
2. 内存压缩是否必然带来推理延迟的降低？
3. 开放式生成评估中，固定生成预算是否会导致与架构和精度相关的审查偏差？

### 4. 背景与问题设定

视觉语言模型（VLM）的量化通常以总体任务准确率和内存节省作为评估标准，但总体分数的保持并不能保证视觉接地行为的保持。现有量化方法（如MBQ、VLMQ）主要验证多模态基准性能和压缩效率，而幻觉基准（如POPE、AMBER）则评估接地失败，但未研究压缩如何重新分配这些失败。因此，存在一个关键空白：量化模型可能保持总体效用分数，但改变其正确接地的具体样本。

### 5. 方法概览

- 任务 / 环境: 评估三个8B VLM家族（Qwen3-VL-8B、InternVL3-8B、Idefics3-8B）在FP16、INT8和NF4精度下的表现，使用MMStar、POPE、AMBER（存在性、属性、关系）和HallusionBench等基准。
- 变量 / 干预设计: 采用受控的跨精度评估协议，对每个模型-精度配置使用相同的示例、预处理、提示和解码条件。通过逐项配对分析，比较FP16和量化预测，统计有害（C→W）和有益（W→C）翻转，并使用bootstrap置信区间、精确McNemar检验和Benjamini-Hochberg校正。
- 评价指标: 总体准确率（MMStar、POPE、AMBER子集、HallusionBench）、配对效应（Δ）、翻转计数、匹配比值比（OR）、FDR校正p值、模型足迹、峰值内存、中位数/p95延迟、吞吐量。
- 模型比较: 比较三种架构（Qwen3-VL、InternVL3、Idefics3）在三种精度（FP16、INT8、NF4）下的表现，共9种配置。
- 我的理解: 该研究通过严格的配对统计方法，揭示了量化对模型行为的影响，超越了简单的准确率比较，为量化模型的可靠性评估提供了更全面的视角。

### 6. 关键发现

- 总体准确率保持但接地行为改变: 五个量化变体在MMStar上保持±2个百分点内的准确率，但36个配对比较中有10个在FDR校正后显著，其中9个在幻觉敏感条件下，且效应是双向的。
- 内存压缩不等于延迟降低: INT8和NF4分别减少模型足迹42.9-43.8%和64.3-65.7%，但在A100平台上，INT8的延迟增加43.5-280.4%，NF4增加2.2-69.6%，表明内存节省并未转化为速度提升。
- 生成预算审查: 在开放式AMBER生成中，88.28%的响应达到256 token上限，且审查程度因架构和精度而异，表明固定预算可能混淆幻觉比较。

### 11. 局限性

- 仅评估了三种8B模型家族和两种量化方法（bitsandbytes LLM.int8()和NF4），可能不适用于其他模型或量化方案。

- 开放式生成评估使用固定256 token预算，可能无法完全反映自然生成行为，尽管进行了更高预算的探测。

### 14. 总结

GHOST-Q通过受控跨精度评估，揭示了量化VLM在保持总体准确率的同时，可能在视觉接地行为上发生显著且双向的变化，且内存压缩并不保证延迟降低。研究建议对量化模型进行联合评估，包括效用、接地可靠性、生成行为和实际部署效率。

## 2. Agentic Detection of Online Conspiracies

**Topics:** cs.CL, cs.LG
**Authors:** Lior Biton, Oren Tsur
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.30250v1) | [PDF](http://arxiv.org/pdf/2609.30250v1.pdf)

### 1. 一句话结论

通过智能体框架按需检索社交上下文（用户资料、历史推文、社交网络），可将希伯来语推特阴谋论检测的F1从0.535提升至0.730，显著优于纯文本分类和预加载上下文方法。

### 2. 为什么重要

该研究首次将智能体框架应用于社交上下文检索的阴谋论检测，利用用户资料、历史推文和社交网络信息推断用户意图，解决了文本表面内容与真实意图不一致的难题，为在线虚假信息检测提供了新范式。

### 3. 研究问题

1. 如何利用社交上下文（如用户资料、历史推文、社交网络）来识别推文中的阴谋论意图？
2. 智能体框架相比纯文本分类和预加载上下文方法，在检测性能和效率上有何优势？

### 4. 背景与问题设定

社交媒体上的阴谋论话语常以隐晦方式表达，同一文本可能表示支持、质疑、讽刺或嘲笑，仅凭文本难以判断用户真实意图。现有检测方法多依赖文本特征，忽略了社交上下文。本文提出智能体框架，通过工具按需检索用户资料、历史推文和社交网络信息，以推断推文的言外之力。

### 5. 方法概览

- 任务 / 环境: 希伯来语推特数据集，覆盖2018年12月至2023年3月约80%-90%的公开希伯来语推文（约2.7亿条推文，330万用户），包含多个选举周期和新冠疫情时期。
- 变量 / 干预设计: 比较四种设置：纯文本LLM、推文+用户资料、推文+历史推文、推文+社交网络上下文，以及智能体框架（可自主选择工具）和双智能体辩论框架。
- 评价指标: F1分数，以及工具使用效率和token消耗分析。
- 模型比较: 使用GPT-5作为主模型，配备工具调用能力；基线包括纯文本LLM（如GPT-5和Gemini 3 Flash）和预加载上下文的非智能体模型。
- 我的理解: 该方法将阴谋论检测视为一个需要动态获取上下文信息的推理任务，智能体根据当前推理步骤决定调用哪些工具，从而避免无关上下文干扰，提高准确性和效率。

### 6. 关键发现

- 上下文感知显著提升检测性能: 智能体框架的F1分数达到0.730，远高于纯文本LLM的0.535，且优于预加载上下文的设置，表明按需检索上下文比一次性提供所有信息更有效。
- 工具使用具有选择性: 智能体并非总是使用所有工具，而是根据推文内容选择性地检索相关上下文，例如对于讽刺性推文，用户资料和历史推文比社交网络信息更有用。
- 双智能体辩论在部分案例中提高鲁棒性: 在部分案例中，双智能体辩论框架通过质疑和反驳，能更准确地识别出讽刺或模仿性推文，但token消耗更高。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体框架展示了在复杂社会语境中通过动态工具调用进行推理的潜力，可应用于其他需要上下文感知的文本分类任务。
- 对 Skill: 强调了选择性信息检索和推理能力的重要性，智能体需根据当前推理步骤决定获取哪些上下文，以提高效率和准确性。
- 对 Memory: 用户历史推文和社交网络信息作为外部记忆，为理解当前推文提供了关键背景，提示记忆机制在智能体设计中的价值。
- 对评测: F1分数和token消耗的权衡分析为评估智能体系统提供了参考，需同时考虑性能和效率。

### 11. 局限性

- 数据集仅限希伯来语，可能无法推广到其他语言和文化背景。
- 智能体框架依赖LLM的推理能力，在复杂讽刺或隐晦表达上仍可能出错。
- 工具调用增加了计算成本，token消耗较高，可能限制大规模应用。

### 12. 我的看法 / 个人笔记

本文提出的智能体框架为阴谋论检测提供了新思路，通过动态检索社交上下文有效解决了文本歧义问题。未来可探索多语言扩展和更高效的上下文选择策略，以降低计算成本。

### 14. 总结

本文提出一种智能体框架，通过按需调用工具检索用户资料、历史推文和社交网络信息，显著提升了希伯来语推特上阴谋论检测的F1分数（从0.535到0.730）。实验证明，上下文感知和选择性检索优于纯文本和预加载上下文方法，并分析了工具使用效率和双智能体辩论的潜力。

## 3. RAPID: Robot Agentic Programming from Demonstrations

**Topics:** 机器人操作, 智能体编程, 非抓取操作, 演示学习
**Authors:** Yuyao Liu, Jiayuan Mao, David Hsu, Leslie Pack Kaelbling, Tomás Lozano-Pérez
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.30249v1) | [PDF](http://arxiv.org/pdf/2609.30249v1.pdf)

### 1. 一句话结论

RAPID 从单个视觉演示中自动生成、验证并精炼机器人程序，利用对象中心的关系表示实现跨场景泛化。

### 2. 为什么重要

现有机器人编程智能体通常需要预定义的任务规格、人工设计的原语或可重置环境，而 RAPID 直接从演示中推断这些要素，从而在非抓取操作等复杂接触丰富的任务中实现自动化编程，显著降低工程负担并提升泛化能力。

### 3. 研究问题

1. 如何从单个视觉演示中自动生成可泛化的机器人操作程序？
2. 如何在不依赖预定义成功信号、人工原语或可重置环境的情况下，闭合智能体编程循环？

### 4. 背景与问题设定

编码智能体在复杂编程任务中表现出色，但将其应用于机器人系统时，通常需要预先提供任务规格、操作原语和验证环境。RAPID 旨在利用演示作为编程接口，自动推断这些要素，从而在非抓取操作等接触丰富的任务中实现程序生成、验证和精炼。非抓取操作涉及广泛的几何和接触相关交互，难以用固定原语库覆盖，因此是检验自动原语构建能力的理想测试平台。

### 5. 方法概览

- 任务 / 环境: 仿真环境（包括八个接触丰富的非抓取操作任务和 LIBERO-Pro 基准）以及真实 Franka 机械臂。
- 变量 / 干预设计: 从单个视觉演示中，RAPID 自动推断任务规格、构建操作原语（作为局部轨迹优化程序）并通过关系约束组合成策略，同时重建交互式仿真环境用于验证和精炼。
- 评价指标: 任务成功率，以及泛化到不同物体姿态、形状、材质和场景配置的能力。
- 模型比较: 与基线方法（如直接行为克隆、固定原语库等）进行比较，RAPID 在泛化性和成功率上表现更优。
- 我的理解: RAPID 的核心在于将操作程序表示为对象中心的关系程序，原语是局部轨迹优化问题，通过关系约束组合，从而在运行时适应场景几何和物理属性，实现跨场景泛化。

### 6. 关键发现

- 从单次演示生成可泛化程序: RAPID 能够从单个视觉演示中自动生成、验证和精炼机器人程序，无需预定义成功信号或人工原语。
- 对象中心关系表示提升泛化: 通过将原语表示为局部轨迹优化程序并通过关系约束组合，RAPID 在物体姿态、形状、材质和场景配置变化下表现出强泛化能力。
- 在非抓取和抓取任务中均有效: 在八个接触丰富的非抓取操作任务和 LIBERO-Pro 基准上，RAPID 均取得优于基线的性能，并在真实 Franka 机械臂上成功部署。

RAPID 提出了一种新颖的框架，将演示转化为可泛化的操作程序，通过对象中心的关系表示和轨迹优化原语，实现了在接触丰富任务中的自动化编程。其亮点在于闭环验证和泛化能力，但未来工作可探索更复杂的场景和物体类型，以及提高仿真重建的精度。

## 4. SemMSA: Latent Semantic-Aided Robust Multimodal Sentiment Analysis with Incomplete Data

**Topics:** 多模态情感分析, 不完整数据, 大语言模型, 谱对齐
**Authors:** Wenhao Li, Zhibin Wu, Chong Xiao, Qiangchang Wang
**Venue / Year:** NeurIPS 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.30238v1) | [PDF](http://arxiv.org/pdf/2609.30238v1.pdf)

### 1. 一句话结论

SemMSA通过大语言模型生成潜在语义，并利用无锚点谱对齐，在不完整多模态数据下显著提升情感分析鲁棒性。

### 2. 为什么重要

现实场景中多模态数据常因噪声、遮挡或传感器故障而不完整，现有方法易产生虚假生成或噪声引导。SemMSA首次将LLM潜在语义用于补偿不完整数据，并通过谱对齐实现全局非线性对齐，为鲁棒多模态分析提供了新范式。

### 3. 研究问题

1. 如何在不完整多模态数据下利用LLM提供高层语义补偿？
2. 如何设计无锚点对齐机制以同时整合多个模态并避免模态缺失带来的不稳定？

### 4. 背景与问题设定

多模态情感分析（MSA）旨在融合语言、视觉和音频信息推断情感，但实际中模态常不完整。现有方法分为重建和融合两类：重建方法恢复低层特征但缺乏语义，融合方法依赖复杂交互且易受噪声影响。本文提出SemMSA，利用LLM生成潜在语义补偿，并通过谱对齐实现全局一致性。

### 5. 方法概览

- 任务 / 环境: 三个标准MSA基准：MOSI、MOSEI（英文）和SIMS（中文），输入为不完整的多模态序列（语言、视觉、音频），输出情感分数。
- 变量 / 干预设计: 训练时以50%概率保持完整，其余样本随机掩蔽各模态；测试时缺失率从0到0.9变化。SemMSA包含两个核心模块：跨模态语义精炼（CSR）和跨模态谱对齐（CSA）。
- 评价指标: 使用Acc-2、F1、Acc-5、Acc-7、MAE和相关系数（Corr）评估，缺失率从0到0.9平均结果。
- 模型比较: 与MISA、Self-MM、MMIM、TETFN、TFR-Net、ALMT、LNLN、P-RMF、TF-Mamba等基线比较。
- 我的理解: SemMSA的核心创新在于：1）通过可学习的适配器将视觉和音频特征映射到冻结LLM的嵌入空间，并迭代精炼潜在语义状态；2）通过核Gram矩阵的谱增强实现无锚点对齐，同时加入实例级分离正则化防止表示坍缩。

### 6. 关键发现

- SOTA性能: 在MOSI、MOSEI和SIMS上，SemMSA在多种缺失率下均取得最佳结果，平均准确率提升1.4%。
- 鲁棒性提升: 随着缺失率增加，SemMSA性能下降更平缓，表明其语义补偿和谱对齐机制有效抵抗模态缺失。

- 为什么重要: 直观展示了SemMSA与现有方法的根本区别：通过LLM精炼语义并全局对齐，而非简单重建或融合。

对比三种框架：重建方法试图恢复缺失特征，融合方法直接整合可用模态，而SemMSA利用LLM生成潜在语义，并通过谱对齐将所有模态对齐到共同方向，从而避免虚假生成和噪声引导。

- 为什么也重要: 图3展示了不同缺失率下的性能趋势，证明SemMSA的稳定性优于基线。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 为多模态感知智能体提供鲁棒情感理解能力，尤其在传感器故障或数据缺失时仍能保持性能。
- 对 Skill: 展示了如何利用LLM的语义知识增强低层特征，可迁移至其他多模态任务。
- 对 Memory: 潜在语义状态可视为压缩的记忆表示，有助于长期交互中的情感状态跟踪。
- 对评测: 提出了在缺失数据下评估多模态模型的新基准，强调鲁棒性指标。

### 11. 局限性

- 依赖LLM的嵌入空间，可能受限于LLM的语义覆盖范围。
- 谱对齐计算复杂度较高，可能限制大规模应用。

### 12. 我的看法 / 个人笔记

SemMSA巧妙地将LLM的语义能力与谱理论结合，解决了不完整多模态数据的核心挑战。其无锚点对齐思想具有普适性，未来可扩展到更多模态和任务。

## 5. Coding Agents for Generalized Task and Motion Planning Problems

**Topics:** 任务与运动规划, 编码智能体, 通用化规划
**Authors:** Matteo Merler, Bowen Li, Josh Roy, Yichao Liang, Qianwei Wang, Yixuan Huang, Tom Silver
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.30233v1) | [PDF](http://arxiv.org/pdf/2609.30233v1.pdf) | [Code](https://github.com/)

### 1. 一句话结论

编码智能体通过交互式程序合成，在广义任务与运动规划中显著超越手工规划器，成功率更高且计算开销低一个数量级。

### 2. 为什么重要

该研究首次大规模验证了编码智能体在广义TAMP中的有效性，表明其能自动化发现跨实例规律，减少领域特定工程，为机器人规划提供强基线。

### 3. 研究问题

1. 编码智能体能否为广义TAMP问题合成可泛化的程序？
2. 编码智能体发现的策略与手工设计有何不同？
3. 交互式合成相比一次性生成和LLM基线的优势有多大？
4. 合成的程序在计算效率上是否优于传统规划器？
5. 访问环境源代码是否进一步提升性能？

### 4. 背景与问题设定

任务与运动规划（TAMP）问题即使在完全可观测和以对象为中心的状态下仍然困难，因为离散决策与几何、运动学和动力学约束紧密耦合。广义TAMP通过利用跨实例的规律性来减少新实例的规划开销，但现有方法需要大量TAMP特定工程。本文探索编码智能体能否自动化这一过程，仅通过任务描述和模拟器访问来合成可泛化的程序。

### 5. 方法概览

- 任务 / 环境: 28个模拟环境，来自KinDER基准（包括Kinematic2D、Dynamic2D、Kinematic3D、Dynamic3D）和3个PDDLStream领域（Packing、Blocked、Rovers）。
- 变量 / 干预设计: 编码智能体（Claude Code with Opus 5, Codex with GPT-5.6 Sol和GPT-6 Astra）在固定预算内通过交互式探索（运行模拟、测试程序）合成程序。主设置不提供环境源代码，+source设置提供源代码。
- 评价指标: 成功率（在100个未见实例上的平均成功率）和每个实例的计算时间（秒）。
- 模型比较: 与手工设计的TAMP规划器（16个环境可用）、一次性生成（LLM直接生成程序）和LLM基线的LLMGenPlan进行比较。
- 我的理解: 该方法将广义TAMP视为程序合成问题，利用编码智能体的交互能力，通过试错和调试来生成策略，而非依赖预定义的抽象。

### 6. 关键发现

- 编码智能体超越手工规划器: 在所有三个智能体配置中，平均成功率（56%-95%）显著高于手工规划器（47%），在16个可用规划器的环境中，Astra在15个环境中胜出。
- 交互式合成优于一次性生成: AgenticGenPlan的成功率远高于一次性生成（One-shot）和LLMGenPlan，表明交互式探索和调试对生成有效程序至关重要。
- 源代码访问进一步提升性能: 在+source设置中，Opus和Astra的成功率进一步提升，尤其是在动态3D环境中，表明源代码信息有助于处理复杂物理交互。
- 计算效率显著提升: 合成的程序在测试时每个实例的计算时间比规划器低一个数量级，且随着对象数量增加，规划器时间增长而智能体程序保持稳定。
- 发现意外策略: 智能体发现了非抓取操作、利用工具长边推动、旋转重抓等新颖策略，这些策略未出现在先前文献中，表明其具备创造性物理推理能力。

该研究令人信服地展示了编码智能体在广义TAMP中的潜力，其交互式合成范式可能成为未来机器人规划的重要方向。然而，对模拟器的依赖和动态环境的挑战提示我们，结合物理先验或学习组件可能进一步提升性能。
