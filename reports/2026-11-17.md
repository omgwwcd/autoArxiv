## 1. WeVisForensics: Self-Evolving Agent for Omni AI-Generated Video Detection

**Topics:** AI生成视频检测, 智能体, 多模态大模型, 强化学习
**Authors:** Yipeng Du, Yuxi Li, Ying Zhang, Chong Sun, Chen Li, Jing Lyu, Ying Tai
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.21373v1) | [PDF](http://arxiv.org/pdf/2611.21373v1.pdf) | [Code](https://github.com/Tencent/WeVisForensics)

### 1. 一句话结论

WeVisForensics通过双时间尺度策略优化（DTPO）实现调查智能体与检查子智能体的协同进化，在AI生成视频检测中达到95.2%的准确率，比最强基线高9.0%。

### 2. 为什么重要

该工作首次将智能体自适应调查与子智能体自我进化结合，解决了现有方法在局部伪影检测和策略优化上的局限，为AI生成视频取证提供了可解释且可扩展的新范式。

### 3. 研究问题

1. 如何让检测系统自适应地选择最相关的取证检查，而不是依赖固定流程或单次推理？
2. 如何让检查子智能体从调查智能体的交互中持续改进，而无需额外标注？

### 4. 背景与问题设定

现有AI生成视频检测方法主要依赖单次链式推理或预定义多智能体流程，难以捕捉短暂或局部伪影，且固定专家限制了检测能力的提升。本文提出智能体框架，通过调查智能体协调可进化的检查子智能体库，实现自适应证据收集和持续进化。

### 5. 方法概览

- 任务 / 环境: AI生成视频检测，输入为视频（含音频），输出为真实/伪造判定及证据链。
- 变量 / 干预设计: 调查智能体（πθ）在每轮选择检查子智能体（s）和时间窗口（u），或终止并给出判定；检查子智能体返回结构化报告（z）。训练采用DTPO：调查智能体使用GRPO快速更新，检查子智能体通过慢速蒸馏和技能卡修订进化。
- 评价指标: 检测准确率（Accuracy）和调用相关子智能体的精确率（call precision）。
- 模型比较: 与通用MLLM（如Gemini-3.1-Pro）、AIGC检测器（如BusterX++、ARGUS）及智能体方法（如GenBuster、MintVid）对比。
- 我的理解: 该方法将检测分解为规划（调查）和感知（检查）两个层次，通过强化学习优化调查策略，同时利用交互数据蒸馏提升检查子智能体，形成闭环进化。

### 6. 关键发现

- 自适应调查优于固定流程: 调查智能体能够根据视频内容动态选择检查类型和时间窗口，相比预定义流程，在局部伪影检测上更有效。
- 子智能体进化提升检测能力: 通过DTPO，检查子智能体在调查智能体的调用中不断改进，能够识别更细微的伪影，整体准确率提升9.0%。
- 角色分解证据增强可解释性: 每个检查子智能体专注于单一取证维度（如外观、物理、常识、OCR、音频），生成的证据链更清晰，便于审计。

## 2. Turing Agent: Agentic Formal Verification for Mathematical Research

**Topics:** AI Agent, Formal Verification, Mathematical Research, Theorem Proving, Lean
**Authors:** Yang Chen, Qianyi Wang, Ronghui Yang, Zhanhao Li, Yu Cong, Chen Zhang, Hangfan Zhang, Shao Zhang, Shuai Li, Toru Takisaka, Chao Xu, Yi Zhou, Zhihao Tang, Xiao Wang, Bo Zhang, Shuyue Hu
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.21299v1) | [PDF](http://arxiv.org/pdf/2611.21299v1.pdf) | [Code](https://wangqy031216-cloud.github.io/turing-agent)

### 1. 一句话结论

Turing Agent 是一个双尺度智能体框架，通过定理形式化与证明形式化的协同，实现了研究级数学的端到端形式化验证，并在 TCS 领域取得了显著成果。

### 2. 为什么重要

随着 LLM 生成数学证明的规模激增，如何确保这些证明的正确性成为关键瓶颈。Turing Agent 提供了一种系统化的智能体方案，将非正式数学研究转化为机器可验证的 Lean 证明，不仅提升了验证效率，还能发现更简单的替代证明并生成可复用的数学知识，为数学研究的可信化和自动化开辟了新路径。

### 3. 研究问题

1. 如何自动化地将研究级数学命题（如 TCS 中的复杂定理）形式化为忠实于原意的 Lean 语句？
2. 如何通过智能体协调，高效地构建完整、无漏洞的 Lean 证明，并处理长距离依赖和复杂分解？

### 4. 背景与问题设定

LLM 在数学发现中展现出巨大潜力，但 AI 生成的证明数量激增，其正确性难以保证。形式化验证（如使用 Lean）是确保正确性的可靠途径，但现有系统多聚焦于给定形式化语句后的证明搜索，缺乏对研究级命题的完整形式化支持。TCS 领域因其复杂的量词结构、依赖关系和严格的语义要求，成为检验形式化验证能力的理想试金石。

### 5. 方法概览

- 任务 / 环境: 研究级数学命题的形式化验证，重点评估 TCS 领域，使用 Lean 证明助手和 Mathlib/CSLib 库。
- 变量 / 干预设计: Turing Agent 采用双尺度架构：定理形式化（TF）智能体负责将非正式命题转化为忠实的 Lean 语句，证明形式化（PF）智能体负责构建证明。通过递归 DAG 分解、并行证明、经验池复用和选择性语义审查，实现端到端验证。
- 评价指标: 形式化成功率和 pass@1 指标，具体包括 Formal TCS Bench 上的忠实形式化成功率（约57-62%）和 RLMEval TCS 子集上的整体 pass@1（约83%）。
- 模型比较: 与直接生成、Codex CLI 和 Claude Code 等通用编码智能体进行对比，Turing Agent 在形式化成功率和证明完成率上显著领先。
- 我的理解: Turing Agent 的核心创新在于将形式化验证视为一个智能体协调问题，而非单纯的证明搜索。通过分离定理形式化与证明形式化，并引入 DAG 分解和经验复用，它能够处理研究级命题的复杂性和长距离依赖，同时通过语义审查确保形式化语句的忠实性。

### 6. 关键发现

- 显著超越基线: 在 Formal TCS Bench 上，Turing Agent 实现了约57-62%的忠实形式化成功率，远超最强基线；在 RLMEval TCS 子集上达到约83%的 pass@1。
- 完成未解决的研究级验证: Turing Agent 成功完成了 OpenAI 2026 年 10 月集合中三个此前未解决的 TCS 任务的形式化验证，其中一个问题需要约一百个辅助引理。
- 发现替代证明并生成可复用知识: 在验证过程中，智能体可能选择不同的数学构造（如用 C=A+B+1 代替 C=max(A,B)）以简化后续推理，并生成可复用的辅助引理，作为验证的副产品。

图中展示了从自然语言命题到 Lean 证明的流程，并标注了三个关键检查点：1) 形式化语句是否忠实于原命题；2) 代码是否通过语法和类型检查；3) 证明是否无未解决的缺口（如 sorry）。每个检查点对应一个挑战，Turing Agent 的设计旨在同时满足这三个要求。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Turing Agent 展示了智能体协调在复杂任务中的潜力，特别是通过 DAG 分解和并行执行来管理长流程，为其他领域（如代码生成、科学发现）的智能体设计提供了参考。
- 对 Skill: 形式化验证需要多种技能（如定理形式化、证明分解、语义审查），Turing Agent 通过分工和协作，将复杂技能模块化，有助于构建更强大的专业智能体。
- 对 Memory: 经验池的引入使得智能体能够积累和复用证明经验，类似于记忆机制，这对于处理相似问题或长流程任务至关重要。
- 对评测: 该工作强调了超越编译成功的评估标准，提出了忠实性、有效性和完整性等多维度评估，为智能体系统的评估提供了新视角。

### 11. 局限性

- 评估集中在 TCS 领域，可能无法完全代表其他数学分支的挑战。
- 依赖 Mathlib 和 CSLib 等现有库，对于库覆盖不足的领域，形式化可能受限。
- 语义审查依赖 LLM 判断，可能存在误判风险，需要人工复核。

### 12. 我的看法 / 个人笔记

Turing Agent 是形式化验证领域的重要进展，它巧妙地将智能体协调与数学形式化结合，解决了研究级命题验证的瓶颈。其双尺度架构和 DAG 分解策略具有通用性，未来可扩展到更多数学领域。不过，语义审查的可靠性仍需提升，且对库的依赖可能限制其应用范围。总体而言，这项工作为 AI 驱动的数学研究可信化奠定了坚实基础。

## 3. Agent-Native by Design: A Programming Language for Agentic Applications

**Topics:** Agentic AI, 编程语言, LLM 应用开发
**Authors:** Jayanaka Dantanarayana, Savini Kashmira, Xiaoyu Ma, Malitha, Malitha Prabhashana, Lingjia Tang, Jason Mars
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.21298v1) | [PDF](http://arxiv.org/pdf/2611.21298v1.pdf)

### 1. 一句话结论

提出 Agent-Native 编程范式，通过语言级原语统一 LLM 操作、工作流状态与模型路由，显著减少集成代码并支持自动优化。

### 2. 为什么重要

当前构建 Agent 应用需在 SDK/框架与业务代码间编写大量胶水代码，且编译器无法全局优化。Jac 语言将模型调用、工作流和路由显式化，为 Agent 开发提供更高效、可优化的新范式。

### 3. 研究问题

1. 如何简化 Agentic 工作流的构建，同时暴露自动优化所需的信息？
2. 统一模型操作、工作流结构和模型路由的编程语言能否减少开发工作量并提升性能？

### 4. 背景与问题设定

Agentic 应用结合 LLM 操作、工作流结构和模型路由。现有 SDK 和框架需要大量支持代码来准备输入、传播状态和调度步骤，且编译器缺乏全局视图，难以自动优化。

### 5. 方法概览

- 任务 / 环境: 五个 Agentic 应用基准，涵盖代码修复、信息检索等任务，使用多种 LLM 模型。
- 变量 / 干预设计: 对比 Jac 与 OpenAI SDK、LangGraph、CrewAI、DSPy 和 NOOA 的实现，测量代码量、任务质量和开发效率。
- 评价指标: AI 集成代码量（行数）、任务成功率、开发 token 消耗、路由决策延迟。
- 模型比较: Jac 与五种基线（SDK 和框架）对比，同时评估不同 LLM 家族（如 GPT、Claude）下的表现。
- 我的理解: Jac 通过语言原语（by llm()、visit ... by llm()）将模型调用和路由内建，编译器可分析依赖并自动优化，如推测执行。

### 6. 关键发现

- 代码量显著减少: Jac 相比 OpenAI SDK 减少 1.8–8.7 倍 AI 集成代码，相比框架也有明显优势。
- 开发效率提升: 使用编码 Agent 构建时，Jac 比 SDK 节省 48%（Claude Code）和 51%（Codex）的 token 消耗。
- 任务质量保持竞争力: 在五个基准上，Jac 的任务成功率与基线相当，未因简化而损失性能。
- 自动优化有效: 推测执行将路由决策延迟降低 29%–39%（中位数），服务划分通过配置实现且保持正确性。

## 4. RESILAGENT: A Three-Pillar Architecture for Cyber-Physical Resilience in Electrical Power and Energy Systems

**Topics:** 智能电网安全, 网络物理系统韧性, 智能体AI, 数字孪生, 区块链
**Authors:** Nikolaos Kekatos, Georgios Koutidis, Konstantinos Antonakopoulos, Stylianos Basagiannis, Sokratis Katsikas, Georgios Kavallieratos, Alexios Lekidis, Tom Nianios, Elpiniki Papageorgiou
**Venue / Year:** 2026 IEEE International Conference on Cyber Security and Resilience (IEEE CSR 2026)
**Links:** [Abstract](http://arxiv.org/abs/2611.21480v1) | [PDF](http://arxiv.org/pdf/2611.21480v1.pdf)

### 1. 一句话结论

RESILAGENT提出一种三支柱架构，将多模态智能体检测、数字孪生仿真与区块链证据锚定相结合，以应对电力能源系统中的混合威胁。

### 2. 为什么重要

电力能源系统面临网络攻击、物理破坏和气候压力的复合威胁，而现有监控系统相互孤立，导致检测和响应延迟。RESILAGENT通过闭环的检测-仿真-决策-签署流程，整合智能体AI、数字孪生和区块链，为关键基础设施提供了一种可操作、可验证的韧性框架，符合CER/NIS2合规要求。

### 3. 研究问题

1. 如何整合多模态数据（网络、物理、环境）以检测混合威胁？
2. 数字孪生如何支持实时应急分析和决策？
3. 区块链如何确保威胁情报和证据的完整性与可追溯性？

### 4. 背景与问题设定

电力能源系统（EPES）面临日益严重的混合威胁，如网络入侵、物理破坏和气候压力。现有监控系统（SIEM、IDS、CCTV等）相互孤立，导致检测和响应延迟。欧盟CER/NIS2指令要求关键实体具备韧性并保留证据，但现有方法缺乏集成和自动化。RESILAGENT旨在通过三支柱架构解决这些问题。

### 5. 方法概览

- 任务 / 环境: 电力传输和配电系统，包括IEEE 14/30/118节点测试网络，模拟网络攻击（FDIA）、物理破坏和环境压力（热浪、风暴）。
- 变量 / 干预设计: 三支柱架构：P1感知与数据智能（多模态智能体检测）、P2韧性分析与报告（数字孪生仿真）、P3事件响应与恢复（SOAR剧本和区块链锚定）。闭环流程包含八个阶段：观察、检测、融合、仿真、决策、行动、签署、学习。
- 评价指标: 检测AUC、推理延迟、N-1应急筛查时间、区块链锚定成本、端到端流水线延迟。
- 模型比较: 比较了隔离森林（无监督）、逻辑回归（基于残差统计）和MLP（原始测量向量）在FDIA检测上的性能。
- 我的理解: 该架构强调人机协同，高影响操作需人工确认，数字孪生作为安全过滤器，区块链提供不可篡改的证据链。

### 6. 关键发现

- 物理感知检测优于特征盲模型: 在IEEE 14节点测试中，基于残差的逻辑回归AUC为0.82，隔离森林为0.75，而MLP仅0.61，表明物理信息（残差）对检测至关重要。
- 融合提升检测稳定性: 结合网络特征（SCADA写入率）和物理特征，融合AUC为0.838，比纯物理高3.1个百分点，比纯网络高16.3个百分点，且方差降低一个数量级。
- 数字孪生应急筛查高效: 在IEEE 14节点上，N-1应急筛查约250毫秒完成，满足实时控制需求。
- 区块链锚定成本极低: 锚定2万事件，每个事件成本低于微秒，远低于检测延迟，适合实际部署。

## 5. ViRA: Toward Ultra-High-Resolution Visual Agents via Cross-Input Relative Policy Optimization

**Topics:** 视觉智能体, 超高分辨率图像理解, 强化学习, 对比集
**Authors:** Huawei Lin, Jinting Liu, Tongyan Wang, Xuyang Chen, Ruihua Shi, Zhichao Xu, Jiaxin Qin, Guoshenghui Zhao, Baijian Yang, Yingjie Victor Chen, Tan Yu, Weijie Zhao
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.21605v1) | [PDF](http://arxiv.org/pdf/2611.21605v1.pdf) | [Code](github.com/huawei-lin/ViRA)

### 1. 一句话结论

提出跨输入相对策略优化（CrossRPO），通过对比集训练视觉智能体，使其在超高分辨率图像中真正阅读证据而非依赖常识猜测，显著提升集准确率。

### 2. 为什么重要

现有视觉智能体在超高分辨率图像上常凭常识作答而非读取细节，且强化学习无法纠正这一捷径。CrossRPO通过对比集设计，使模型必须阅读证据才能获得奖励，为高分辨率视觉推理提供了新的训练范式，并开源了数据集和模型。

### 3. 研究问题

1. 如何设计训练信号，使视觉智能体在超高分辨率图像中真正阅读证据而非依赖常识猜测？
2. CrossRPO相比GRPO等现有方法，在集准确率上能带来多大提升？
3. CrossRPO的理论保证（如无偏性、GRPO为特例）如何成立？

### 4. 背景与问题设定

超高分辨率图像（如21-120MP）细节丰富，但超出模型输入限制，视觉智能体需通过缩放查看相关区域。然而，现有智能体常凭常识回答，即使有缩放工具也不阅读证据。强化学习（如GRPO）在单张图像上无法区分猜测与阅读，因为两者奖励相同。

### 5. 方法概览

- 任务 / 环境: 视觉问答任务，输入为超高分辨率图像（21-120MP），智能体可调用缩放工具查看局部区域，最终给出答案。
- 变量 / 干预设计: 构建对比集：同一问题对应多个图像版本，仅小区域证据不同，答案不同。训练时，智能体需同时处理所有版本，只有全部答对才获得高奖励。CrossRPO在每个版本内计算优势，并乘以跨输入权重（基于其他版本的正确率），从而强化解决整个集合的行为。
- 评价指标: 集准确率（set accuracy）：一个集合中所有版本均答对的比例。
- 模型比较: 与GRPO（逐版本训练）、池化GRPO（跨版本比较）、以及逐版本训练（无跨输入权重）对比，同时与Claude Haiku 5.5、GPT-6-Luna等闭源模型比较。
- 我的理解: CrossRPO的核心思想是通过对比集将“阅读证据”转化为可优化的目标。它避免了池化GRPO中猜测获得正奖励的问题，同时通过跨输入权重放大解决整个集合的梯度信号，使模型学会真正读取细节。

### 6. 关键发现

- CrossRPO显著提升集准确率: 在ViRA-Bench最大分辨率下，CrossRPO达到63.3%集准确率，高于GRPO的59.3%和池化GRPO的52.6%。
- ViRA模型超越闭源模型: ViRA-27B在多数基准上优于Claude Haiku 5.5和GPT-6-Luna（最高思考级别），且ViRA-9B在10个基准中的9个上优于同尺寸开源模型。
- CrossRPO不奖励常识猜测: 理论证明，对于仅凭常识回答的集合，CrossRPO的优势为零，而池化GRPO会给予正奖励。
- ViRA-Bench-Real验证了泛化性: 在真实拍摄的ViRA-Bench-Real上，ViRA模型同样表现优异，排除了编辑痕迹的影响。

- 对 Skill: 训练出的智能体更擅长定位和阅读图像中的微小细节，适用于医疗影像、卫星图像分析等需要高精度视觉推理的场景。

### 11. 局限性

- 对比集构建依赖人工编辑或生成，成本较高，且仅适用于可编辑的图像类型。

本文提出CrossRPO，一种用于训练超高分辨率视觉智能体的强化学习算法。通过构建对比集（同一问题对应多个仅证据区域不同的图像版本），CrossRPO奖励解决整个集合的行为，从而避免模型依赖常识猜测。实验表明，CrossRPO训练的ViRA模型在ViRA-Bench上显著优于GRPO和闭源模型，且理论证明其不会强化猜测行为。数据和代码已开源。
