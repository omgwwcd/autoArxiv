## 1. MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory

**Topics:** LLM Agent Memory, Memory Poisoning, Prompt Injection, Agent Security
**Authors:** David H. Yang, Blake Bullwinkel, Amanda Minnich, Mohammad Mohammadi Amiri, Giorgio Severi
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.09721v1) | [PDF](http://arxiv.org/pdf/2611.09721v1.pdf)

### 1. 一句话结论

MemoryDojo 基准测试揭示了不同 LLM 智能体记忆系统对投毒攻击的脆弱性差异，并提出了一种记忆感知的投毒优化方法，可显著提高攻击成功率。

### 2. 为什么重要

随着 LLM 智能体在长期任务中依赖记忆系统，记忆投毒成为新的安全威胁。该工作首次系统比较了多种记忆架构在投毒攻击下的表现，为设计更安全的智能体记忆系统提供了关键评估工具和见解。

### 3. 研究问题

1. 不同记忆系统如何影响投毒信息的持久性、传播性和最终行为影响？
2. 记忆感知的投毒优化能否显著提高攻击成功率，并揭示不同记忆架构的脆弱性差异？

### 4. 背景与问题设定

LLM 智能体使用记忆系统来提升长期多会话任务的性能，但记忆也引入了新的攻击面：恶意指令可能在一个会话中被注入，随后被存储、检索并在后续会话中执行。由于不同记忆系统在信息处理、存储和检索机制上存在差异，投毒的影响可能因系统而异。现有基准测试（如 AgentDojo）主要关注单会话的提示注入，而缺乏对跨会话记忆投毒的系统性评估。

### 5. 方法概览

- 任务 / 环境: 基于 AgentDojo 的四个领域（Workspace、Travel、Banking、Slack）构建多会话轨迹，并可选添加 LongMemEval-S 的对话历史作为记忆压力。
- 变量 / 干预设计: 在轨迹的某个会话中，将投毒提示附加到一个工具观察结果上，然后继续执行后续任务，观察投毒信息在记忆中的写入、检索和行为影响。
- 评价指标: 插入成功率（ISR）、检索成功率（RSR）、行为覆盖（BR）、任务级行为覆盖（BRT），以及任务效用和记忆效用。
- 模型比较: 比较五种开源记忆系统：A-MEM、Graphiti、Letta、Mem0、Memora，使用 GPT-5.6-Luna 作为任务智能体，并评估跨模型迁移性。
- 我的理解: 该方法通过标准化的多会话轨迹和统一的记忆接口，实现了对不同记忆系统的公平比较，并引入了记忆感知的投毒优化，以模拟更强大的攻击者。

### 6. 关键发现

- 所有记忆系统均易受投毒攻击，但影响差异显著: 在未优化的投毒下，所有系统的行为覆盖（BR）均大于零，但不同系统的 BR 差异较大，表明记忆架构对投毒传播有显著影响。
- 记忆感知优化显著提升攻击成功率: 通过迭代优化投毒提示，攻击成功率（BRT）提升约 2% 至 31%，且不同系统的提升幅度不同，揭示了架构的脆弱性差异。
- 投毒信息在记忆中的持久性和传播性因系统而异: 例如，Letta 的持久性较高，而 A-MEM 的传播性较强，这影响了投毒在后续会话中的检索和利用。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 记忆系统设计者应考虑投毒攻击的威胁，在记忆写入和检索环节增加安全过滤和验证机制。
- 对 Skill: 智能体技能（如工具调用）可能被投毒指令劫持，需要开发更鲁棒的指令遵循机制。
- 对 Memory: 记忆的持久性和传播性直接影响投毒效果，设计时应权衡信息保留与安全风险。
- 对评测: 评估智能体安全性时，应包含跨会话的记忆投毒场景，而不仅仅是单会话的提示注入。

### 11. 局限性

- 仅评估了五种记忆系统，可能无法覆盖所有架构。
- 投毒优化仅在合成轨迹上进行，真实环境中的效果可能不同。
- 评估依赖于 LLM 判断，可能存在主观偏差。

### 12. 我的看法 / 个人笔记

该工作填补了记忆投毒评估的空白，提供了实用的基准和优化方法。未来研究可探索防御机制，如记忆内容过滤、异常检测和访问控制。

MemoryDojo 是一个用于评估 LLM 智能体记忆投毒攻击的基准，包含 155 条多会话轨迹和五种记忆系统。研究发现所有系统均易受攻击，且记忆感知优化可显著提高攻击成功率。该基准为理解和缓解智能体记忆风险提供了重要工具。

## 2. AnimWeb-Bench: Benchmarking Animated Webpage Code Generation from Videos

**Topics:** GUI Agent, 多模态大语言模型, 代码生成, 网页动画
**Authors:** Zhongyi Zhang, Jingyu Xiao, Shuqing Li, Michael R. Lyu
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.09769v1) | [PDF](http://arxiv.org/pdf/2611.09769v1.pdf) | [Code](https://starry1001.github.io/AnimWeb-Bench-website/)

### 1. 一句话结论

AnimWeb-Bench 是首个从视频生成完整动画网页代码的基准，包含124个真实网页和33种动画类型，评估发现动画重建难度远高于静态外观，且快速连续变化最难复现。

### 2. 为什么重要

现有网页代码生成基准仅评估静态截图或离散交互，忽略了网页中普遍存在的连续动画。AnimWeb-Bench 填补了这一空白，首次系统评估 MLLM 和编码代理从视频重建完整动画网页的能力，为多模态理解和代码生成研究提供了新方向。

### 3. 研究问题

1. 多模态大语言模型和编码代理能否从视频中重建完整动画网页的静态外观和动态行为？
2. 哪些因素（如动画类型、模型规模、反馈机制）影响动画重建质量？

### 4. 背景与问题设定

动画在网页中无处不在，但现有基准（如 Design2Code、WebSight）仅关注静态截图或用户触发的离散交互，无法评估连续时间动态。Animation2Code 虽涉及视频到动画代码，但仅限孤立图形。真实网页包含布局、文本、媒体与多种动画组合，重建需推断运动轨迹、时序、缓动和同步，评估也需细粒度追踪组件运动。

### 5. 方法概览

- 任务 / 环境: 124 个真实网页，覆盖 7 个应用领域和 33 种动画类型，每个任务提供参考视频和静态资源，模型需生成单个 HTML 文件（内嵌 CSS/JS），在浏览器中渲染并录制生成视频。
- 变量 / 干预设计: 评估协议分为两个维度：静态外观保真度（结构、文本、颜色、视觉相似度）和动画保真度（位置、大小、速度、外观）。关键帧通过视频帧间相似度曲线提取，组件轨迹通过检测器跨帧关联，跨视频轨迹匹配结合文本和几何特征。
- 评价指标: 静态外观：结构相似度（IoU、中心、面积、宽高比加权）、文本相似度（Levenshtein）、颜色相似度（CIEDE2000）、视觉相似度（CLIP）。动画：位置、大小、速度相似度（基于轨迹的归一化差异）和 CLIP 外观相似度。所有指标与人类判断相关性 Spearman ρ=0.67–0.74。
- 模型比较: 评估了 14 个 MLLM（如 GPT-4o、Claude 3.5 Sonnet、Gemini 1.5 Pro 等）和 3 个编码代理（基于 GPT-4o 等），比较了不同模型规模和代理策略（如是否使用帧检查、渲染反馈）。
- 我的理解: 该基准将网页动画重建分解为静态外观和动态行为两个可量化的维度，通过关键帧对齐和组件轨迹匹配实现细粒度评估，避免了帧级相似度的模糊性。

### 6. 关键发现

- 动画重建显著难于静态外观: 所有模型在动画保真度上的得分远低于静态外观保真度，表明当前系统对时间动态的理解和生成能力不足。
- 编码代理通过帧检查和渲染反馈提升质量: 显式帧检查和渲染反馈能显著提高编码代理的重建质量，尤其是动画部分，但提升幅度有限。
- 快速连续变化最难复现: 分析显示，快速、连续的动画（如背景过渡、遮罩）比离散状态转换更难正确重建，模型倾向于简化或忽略这些动态。

## 3. What to Delegate, What to Preserve: Human Preferences for Agentic AI Across Everyday Life and Work

**Topics:** Agentic AI, Human-AI collaboration, Task delegation, Automation preferences, Human-computer interaction
**Authors:** Sarah Wheeler, Veronica Rammouz, Yaoyao Qian, Zexuan Liu, Mengyi Wei, Anthony Rios, Tianzhi He, Kyrie Zhou
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.09730v1) | [PDF](http://arxiv.org/pdf/2611.09730v1.pdf)

### 1. 一句话结论

用户对AI代理的自动化偏好因任务领域而异，且倾向于“有界自主”：AI可执行大量任务，但人类希望保留监督和最终决策权。

### 2. 为什么重要

该研究首次系统比较了同一用户在工作与日常生活中的AI代理自动化偏好，揭示了“委托”不仅是任务执行，更是执行、协作、领导与权威的配置，为设计符合用户期望的代理系统提供了实证基础。

### 3. 研究问题

1. AI自动化偏好如何在不同日常与工作领域变化？哪些任务层面和用户层面因素与更高的委托意愿相关？
2. 人们如何比较AI代理、人类工作者和人机团队的可信度？协作偏好和AI领导力偏好如何与期望的自动化水平相关？
3. 当人们愿意委托任务时，他们希望如何配置AI参与（执行、协作、监督、决策权）？

### 4. 背景与问题设定

随着LLM代理能够自主执行多步骤任务，用户对委托的边界尚不明确。现有研究多聚焦单一领域或职业任务，缺乏跨领域、同一用户内的系统比较。此外，隐私、经济价值、信任等因素常被分开研究，而委托决策是这些因素的综合考量。

### 5. 方法概览

- 任务 / 环境: 基于场景的在线调查，覆盖美国289名有AI经验的成年人，涉及9个生活领域的45个用例。
- 变量 / 干预设计: 每位参与者随机评估每个领域中的一个场景（共9个），采用重复测量设计，测量自动化偏好、信任、协作、AI领导力、隐私关注和支付意愿等。
- 评价指标: 自动化偏好（主要结果）、信任（AI代理、人类工作者、人机团队）、协作需求、AI领导力偏好、隐私关注、支付意愿、预期节省/支出。
- 模型比较: 使用广义估计方程（GEE）模型分析自动化偏好的关联因素，并辅以开放式问题的定性分析。
- 我的理解: 该研究通过场景调查，让用户对具体任务进行评价，从而捕捉任务层面的差异。重复测量设计允许控制个体差异，GEE模型处理了重复测量的相关性。定性分析补充了定量结果，揭示了“有界自主”的偏好。

### 6. 关键发现

- 自动化偏好因领域而异: 沟通和旅行领域的委托意愿较高，而心理健康、身体健康和职业领域的意愿较低。
- 信任、领导力和先前使用是关键因素: 对AI代理的信任、期望AI领导以及先前任务特定AI使用与更高的自动化偏好相关。
- 隐私关注并非独立关联因素: 隐私关注在不同领域差异显著，但在调整其他因素后，与自动化偏好无独立关联。
- 人们偏好有界自主: 开放式回答显示，参与者希望AI执行大量任务，但保留人类监督和最终决策权。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 设计代理系统时应考虑任务领域差异，提供可调节的自动化水平，并支持人类监督和最终决策权。

## 4. On Agentic Manipulation Policies

**Topics:** 机器人操作, 智能体策略, 通用AI模型, 具身智能
**Authors:** Chen Chen, Omid Bagherieh, Naveen Nikamanth Appiah Balaji, Jesse T. Gonzalez, Negin Heravi, Fahad Islam, Xueting Li, Jean-Baptiste Regli, Kejia Ren, Petr Švec, David J. Yoon, Matthias Müller, Vladlen Koltun
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.09892v1) | [PDF](http://arxiv.org/pdf/2611.09892v1.pdf)

### 1. 一句话结论

通用AI模型直接控制机械臂的智能体操作策略（AMP1）在零样本条件下显著超越专用策略（如VLA和WAM），并展现出涌现的复杂行为。

### 2. 为什么重要

该研究挑战了机器人操作领域依赖专用策略和演示学习的传统范式，证明通用AI模型能够直接控制机械臂，无需任务特定训练即可实现高成功率，为通用机器人操作提供了新方向。

### 3. 研究问题

1. 通用AI模型能否直接控制机械臂并超越专用策略？
2. 智能体操作策略（AMP）在不同任务和硬件上的泛化能力如何？
3. 持久记忆能否让智能体从自身经验中学习并提升性能？

### 4. 背景与问题设定

现有机器人操作策略多为专用模型，依赖大量演示数据，泛化能力有限。通用AI模型虽在语言和视觉任务中表现优异，但其直接控制机械臂的潜力尚未充分探索。本文提出智能体操作策略（AMP），让通用模型在闭环中直接命令机械臂，适应任务进展。

### 5. 方法概览

- 任务 / 环境: 仿真基准：RoboLab-120、LIBERO-PRO、robosuite、BEHAVIOR-1K；真实世界：12个任务，使用Franka Research 3机械臂和Robotiq夹爪。
- 变量 / 干预设计: AMP1作为参考框架，提供视觉观察、代码执行和直接运动控制。对比基线包括VLA（π0.5）和WAM（FLUX 3 Action）。
- 评价指标: 成功率（任务完成比例），以及平均成功时间（真实世界）。
- 模型比较: 在RoboLab-120上，AMP1（Gemini 4 Argon）成功率85.6%，远超VLA（49.2%）和WAM（42.9%）；在真实世界任务中，AMP1成功率96.3%，而FLUX为45.4%，π0.5为27.8%。
- 我的理解: AMP1的核心在于利用通用AI模型的推理和规划能力，通过视觉反馈和代码执行直接控制机械臂，无需预定义技能或微调。其成功依赖于模型的空间认知和问题解决能力，且能通过记忆机制持续学习。

### 6. 关键发现

- 零样本性能显著优于专用策略: 在RoboLab-120上，AMP1（Gemini 4 Argon）零样本成功率85.6%，而最强的VLA和WAM分别为49.2%和42.9%。在真实世界任务中，AMP1成功率96.3%，而FLUX为45.4%，π0.5为27.8%。
- 涌现复杂行为: AMP1能自发产生策略，如将平放的书推到桌边以抓取、移动遮挡物寻找隐藏物体、用叉车方式抬起过宽物体等，这些行为未在提示或技能中指定。
- 持久记忆提升学习能力: 加入持久记忆后，AMP1在RoboDojo双机械臂任务上，通过练习将成功率从26.4%提升至84.1%，且跨任务学习使成功率翻倍至57.6%，同时减少35%的模型调用。

## 5. CPU-ARC: Agentic Reasoning Caching for on-CPU Reasoning Reuse

**Topics:** AI Agent, Reasoning Caching, LLM Efficiency
**Authors:** Peter Belcak, Greg Heinrich, Saurav Muralidharan, Shizhe Diao, Pavlo Molchanov
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.09891v1) | [PDF](http://arxiv.org/pdf/2611.09891v1.pdf)

### 1. 一句话结论

提出一种将LLM推理轨迹转化为模块化、CPU可执行的代码缓存（ARC）的方法，在MATH-500和SciBench等基准上性能与GPT-4等前沿模型相当，但调用成本降低16-291倍。

### 2. 为什么重要

该方法显著降低了大模型在重复性任务上的推理成本，使得在边缘设备上部署高性能AI成为可能，同时保持可解释性和可校正性，为构建高效、可持续的智能体系统提供了新思路。

### 3. 研究问题

1. 如何将LLM的推理过程转化为可复用的、CPU可执行的代码模块？
2. 这种转化后的代码缓存能否在保持性能的同时，大幅降低推理成本？

### 4. 背景与问题设定

大语言模型在解决每个问题时都从零开始推理，即使面对大量重复或参数化变体的问题，也造成了巨大的计算浪费。现有的系统级缓存方法要么不鲁棒，要么成本高，难以在边缘设备上部署。

### 5. 方法概览

- 任务 / 环境: 数学和科学推理任务，包括MATH-500和SciBench等基准测试。
- 变量 / 干预设计: 从源LLM的推理轨迹中，通过构建者模型提取逻辑步骤，生成模块化的语义函数，并组合成可执行程序。程序使用小语言模型处理语义搜索和值提取，主要逻辑在CPU上执行。
- 评价指标: 性能（准确率）、成本（调用成本倍数）、鲁棒性（对输入扰动的稳定性）。
- 模型比较: 与前沿LLM（如GPT-4）进行性能对比，并比较不同构建者模型（如GPT-4o、Llama-3.1-70B）生成的缓存效果。
- 我的理解: 该方法将LLM的推理能力“编译”为轻量级代码，通过参数化实现泛化，从而在CPU上高效执行，实现了推理的复用。

### 6. 关键发现

- 性能与前沿模型相当: 在MATH-500和SciBench等基准上，ARC的准确率与GPT-4等前沿模型持平或略高，但成本降低16-291倍。
- 成本大幅降低: ARC的调用成本仅为源模型的1/16至1/291，且主要依赖CPU执行，适合边缘部署。
- 鲁棒性和可解释性: ARC对输入扰动具有鲁棒性，且代码形式完全可解释，便于人工审查和校正。
