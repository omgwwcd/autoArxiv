## 1. Chronicle: Cut-Point Replay for Regression Testing of LLM Agents

**Topics:** LLM Agent, 回归测试, 记录与重放, 非确定性
**Authors:** Tisha Chawla, Susheem Koul
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.20625v1) | [PDF](http://arxiv.org/pdf/2609.20625v1.pdf) | [Code](https://github.com/theagentplane/chronicle)

### 1. 一句话结论

Chronicle 通过记录 LLM 代理运行时的非确定性边界，并支持在任意子集上运行新代码的“切点重放”，将事故转化为可重复的回归测试，且录制开销极低。

### 2. 为什么重要

LLM 代理的失败难以复现，导致回归测试困难。Chronicle 提供了一种轻量级、确定性的方法，使开发者能够针对特定代码变更进行测试，而无需重放整个轨迹，显著提升代理系统的可靠性和可维护性。

### 3. 研究问题

1. 如何将 LLM 代理的失败记录转化为可重复的回归测试？
2. 如何在重放时仅运行部分代码（切点）而保持其余部分确定性？
3. Chronicle 的录制开销和重放确定性如何？

### 4. 背景与问题设定

LLM 代理的响应是非确定性的，失败依赖于不可复现的推理、变化的工具状态和多步轨迹，导致重跑难以复现。现有工具仅记录轨迹用于追踪或评分，不支持针对代码变更的测试。Chronicle 旨在通过记录非确定性边界（模型调用、工具调用、路由决策）为不可变信封，并支持切点重放，从而将事故转化为回归测试。

### 5. 方法概览

- 任务 / 环境: 6 个记录的事故，每个包含小型代理（模型-工具-模型），涉及退款、发票、交易、邮件、支付和删除等不安全操作。所有代理使用模拟边界，不调用真实 LLM 提供者。
- 变量 / 干预设计: 开发者用 @boundary 注解标记边界；录制时保存每次跨越的输入输出为信封；重放时，切点重放允许选择部分边界运行新代码，其余从记录中提供。
- 评价指标: 故障检测率（未防护代码失败，防护和良性修改通过）、重放确定性（20 次重复零差异）、录制开销（每跨越微秒数）、提供者调用次数和成本、套件运行时间、边界注解覆盖率、突变杀死率。
- 模型比较: 与全桩基线（所有边界都从记录中提供）对比，全桩基线无法检测工具代码中的故障，因为工具从不执行。
- 我的理解: Chronicle 的核心思想是将代理运行视为一系列边界跨越，通过记录这些边界，可以在重放时灵活地选择哪些边界执行新代码，哪些使用记录，从而隔离测试特定组件。

### 6. 关键发现

- 录制开销极低: 内存录制每跨越仅增加 23 微秒（中位数），相当于假设 300 毫秒模型调用的 0.008%，且存储每跨越不超过 1.44 KB。在真实 Qwen3.5 4B 模型上，录制开启与关闭的平均延迟差异为 91 毫秒，95% 置信区间包含零，统计上不显著。
- 全重放完全确定: 20 次重复运行零差异，且不调用任何模型，成本为零。
- 切点测试有效检测故障: 在 6 个事故上，切点测试对未防护代码全部失败，对防护修复和良性修改全部通过，并容忍 30 个无关改写。
- 突变测试显示切点优于全桩: 切点测试杀死 51/192 个突变体，而全桩基线杀死 0 个，因为工具代码从未执行。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Chronicle 提供了一种将生产事故转化为回归测试的机制，使代理系统能够持续集成和部署，同时确保安全关键操作得到验证。
- 对 Skill: 开发者需要学习如何标记边界和编写切点计划，这要求对代理架构有深入理解。
- 对 Memory: 录制信封存储了输入输出，可作为代理行为的记忆，但当前实现不涉及长期记忆。
- 对评测: Chronicle 提供了一种新的评估方法：通过重放历史事故来评估代码变更，补充了基于模拟环境的评估。

### 11. 局限性

- 基准仅包含 6 个小型事故，缺乏真实世界的复杂性和规模。
- 模型边界是模拟的，未在真实 LLM 提供者上验证。
- 未处理流式响应和并发工具调用。
- 重放时若边界读取隐藏状态（如时钟、数据库），可能不准确。
- 突变体杀死率仅 62%（行为改变突变体），部分突变体无法被杀死。

### 12. 我的看法 / 个人笔记

Chronicle 提出了一种实用且优雅的解决方案，将 LLM 代理的测试问题转化为记录与重放问题。其切点重放概念灵活，允许针对特定组件进行测试，且开销极低。尽管基准较小，但方法具有推广潜力。未来工作应扩展至真实 LLM 提供者、处理更复杂的代理拓扑，并探索自动选择切点。

### 14. 总结

Chronicle 通过记录 LLM 代理的非确定性边界并支持切点重放，将事故转化为回归测试。实验表明，录制开销极低（23 微秒/跨越），全重放确定性高，切点测试能有效检测故障，而全桩基线无法检测。该方法为代理系统的可靠测试提供了新途径。

## 2. RetireOPD: Self-Retiring On-Policy Distillation for Agentic Reinforcement Learning

**Topics:** Agentic RL, Text-based Agent, 知识蒸馏
**Authors:** Yan Yu, Zhengxi Lu, Yizhou Liu, Yichen Pan, Aozhe Wang, Qipeng Chen, Hua Yang, Wenqi Zhang, Weiming Lu, Qianglong Chen, Yongliang Shen
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.20784v1) | [PDF](http://arxiv.org/pdf/2609.20784v1.pdf) | [Code](https://github.com/ZJU-REAL/SDAR)

### 1. 一句话结论

RetireOPD通过先优化技能条件化教师，再在训练中自适应退出教师蒸馏，解决了特权信息蒸馏中教师不可靠和阶段依赖的问题，显著提升了智能体强化学习的性能。

### 2. 为什么重要

该工作揭示了多轮智能体强化学习中教师蒸馏的两个关键失败模式，并提出了一种在线自适应退出机制，为智能体训练提供了更高效、更稳健的方法，具有重要的理论和实践意义。

### 3. 研究问题

1. 在智能体强化学习中，特权信息蒸馏的教师是否总是可靠的？
2. 教师监督的收益是否在整个训练过程中持续存在？
3. 如何自适应地决定何时移除教师蒸馏以避免其限制后续的奖励优化？

### 4. 背景与问题设定

多轮智能体强化学习通常只获得每个轨迹的单一标量奖励，导致中间决策缺乏监督。自蒸馏（OPD）通过教师提供密集的token级监督来补充稀疏奖励，但教师通常基于特权信息（如技能）进行条件化。然而，现有方法假设教师始终可靠且监督始终有益，但实验发现这两个假设在智能体任务中均不成立：特权信息本身不足以使教师可靠（例如，7B模型即使有技能提示，ALFWorld成功率仅23.4%），且教师监督的收益随训练阶段变化。因此，需要一种自适应机制来决定何时移除教师。

### 5. 方法概览

- 任务 / 环境: ALFWorld（文本交互的具身环境）和WebShop（模拟在线购物环境），两者均需要多步决策和交互。
- 变量 / 干预设计: 首先，独立训练一个技能条件化的教师（使用环境奖励优化），然后联合训练一个无技能的学生，同时使用GRPO和OPD损失。在训练过程中，通过监控教师-学生差异和学生的相对能力，当差异停止缩小（ρ≥δ，δ=0）且学生达到教师成功率的设定比例（η≥γ，γ=0.9）时，自动退出教师蒸馏，之后仅使用GRPO继续训练。
- 评价指标: ALFWorld的成功率（Success Rate）和WebShop的准确率（Accuracy）。
- 模型比较: 与多种基线比较：无训练（Vanilla, Skill-Prompt）、纯RL（GRPO, GiGPO, PPO, RLOO）、纯蒸馏（OPD, OPSD）、混合（GRPO+OPD, GRPO+OPSD）以及RetireOPD。
- 我的理解: 该方法的核心在于将教师蒸馏视为一种临时的脚手架，通过在线监测训练信号（差异和相对能力）来决定何时移除，从而避免教师限制学生的进一步优化。

### 6. 关键发现

- RetireOPD显著提升性能: 在ALFWorld上，RetireOPD相比GRPO基线，成功率提升14.1%-18.8%（例如3B模型从75.0%提升至93.8%）；在WebShop上，准确率提升11.8%-19.0%（例如1.5B模型从56.8%提升至75.8%）。
- 教师必须经过优化: 直接使用技能条件化的教师（未经过环境奖励优化）效果不佳，而经过环境奖励优化的教师能提供更可靠的监督信号。
- 自适应退出优于固定调度: RetireOPD的自适应退出机制优于固定调度或全程保留教师，表明教师监督在后期可能阻碍奖励优化。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 该方法为智能体训练提供了一种更高效的范式，通过自适应退出教师，可以避免教师限制，同时利用其早期引导，有望应用于更复杂的多轮交互任务。
- 对 Skill: 强调了技能条件化教师需要经过环境奖励优化才能有效，提示技能本身并不直接带来优势，需要与任务目标对齐。
- 对 Memory: 虽然本文未直接涉及记忆机制，但教师蒸馏可视为一种知识迁移，类似于将外部知识内化到学生模型中，未来可探索与记忆系统的结合。
- 对评测: 提出了基于训练动态的在线评估指标（差异和相对能力），为智能体训练中的教师退出提供了可量化的标准。

### 11. 局限性

- 方法依赖于技能库的可用性，在缺乏技能库的任务中可能无法应用。
- 自适应退出阈值（δ=0和γ=0.9）需要手动设置，可能在不同任务或模型上需要调整。
- 实验仅在两个基准上验证，泛化性有待进一步测试。
- 使用采样近似KL可能引入计算开销，但论文未详细讨论其效率影响。

### 12. 我的看法 / 个人笔记

该工作为解决智能体强化学习中的稀疏奖励问题提供了新思路，通过自适应退出教师蒸馏，平衡了早期引导和后期优化。其核心洞察在于教师监督的收益是动态的，需要在线监测。未来可探索更复杂的退出策略，如基于梯度冲突的检测，或扩展到多教师场景。

### 14. 总结

RetireOPD提出了一种自退出的在线蒸馏方法，用于智能体强化学习。它首先用环境奖励优化技能条件化的教师，然后联合训练学生，并通过监测教师-学生差异和相对能力，在差异停止缩小且学生达到教师成功率的90%时自动退出教师。实验表明，该方法在ALFWorld和WebShop上显著优于现有基线，验证了其有效性。

## 3. CoRef-GS: Cooperative Referring Gaussian Splatting for Multi-Agent Scene Understanding

**Topics:** 3D Gaussian Splatting, 多智能体场景理解, 指代表达分割, 跨智能体配准
**Authors:** Zhikun Zhou, Kunyu Peng, Runyi Yang, Junhao Cai, Di Wen, Ruiping Liu, Danda Pani Paudel, Yi Zhou, Luc Van Gool, Kailun Yang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.20586v1) | [PDF](http://arxiv.org/pdf/2609.20586v1.pdf) | [Code](https://github.com/ruojiruoli17/CoRef-GS.git)

### 1. 一句话结论

CoRef-GS通过跨智能体Sim(3)配准与实例融合，在无需联合训练的情况下，实现了对融合后高斯地图的视角条件指代表达理解。

### 2. 为什么重要

该工作首次系统研究了多智能体协作场景下的指代性场景理解问题，解决了独立构建的语义高斯地图在融合后语言查询能力退化的问题，为具身智能体的协作感知与语言交互提供了新思路。

### 3. 研究问题

1. 如何使独立构建的语义高斯地图在跨智能体对齐和融合后仍保持语言查询能力？
2. 如何在融合地图上从查询智能体的视角进行关系感知的指代表达分割？

### 4. 背景与问题设定

具身智能体需要从指定视角理解自然语言指代表达，但单智能体观测受限。多智能体协作可提供互补视角，但独立重建的地图在融合后需保持几何可对齐性、实例级语义可比性和视角条件关系推理能力。现有语言感知高斯方法仅支持单地图查询，而高斯配准方法忽略语义兼容性。

### 5. 方法概览

- 任务 / 环境: 双四足机器人（CoQuad-Ref基准）在真实和仿真室内场景中，从不同区域观测同一静态场景，构建部分重叠的局部语义高斯地图。
- 变量 / 干预设计: 每个智能体独立构建实例感知的语义高斯地图（基于OpenGaussian），然后通过图像辅助的粗到细Sim(3)配准对齐，再通过几何和语义一致性进行跨智能体实例关联与融合。查询时，从查询视角渲染实例掩码，构建视角条件掩码关系图，进行关系推理。
- 评价指标: 指代表达分割的mIoU（真实场景），以及配准的旋转误差（仿真场景）。
- 模型比较: 与ReferSplat（单地图方法）对比，CoRef-GS在真实场景mIoU上从52.6%提升至68.8%；在仿真场景中，旋转误差从粗配准后的2.58°降至0.15°。
- 我的理解: CoRef-GS的核心在于解耦地图构建与查询推理：利用CLIP语义空间的共享性保证跨智能体语义可比性，通过几何配准和实例关联实现融合，而查询时仅基于渲染掩码进行关系推理，避免了联合训练的开销。

### 6. 关键发现

- 跨智能体配准精度显著提升: 在仿真场景中，CoRef-GS将旋转误差从粗配准后的2.58°降至0.15°，表明图像辅助的粗到细Sim(3)配准能有效对齐独立构建的地图。
- 融合地图上的指代分割性能大幅提升: 在真实场景中，CoRef-GS的指代mIoU达到68.8%，相比单地图方法ReferSplat的52.6%提升了16.2个百分点，验证了跨智能体融合对语言查询的增益。

## 4. SAFARI: An Industrial Benchmark for LLM-Assisted Hazard Analysis and Risk Assessment

**Topics:** LLM, 功能安全, ISO 26262, 危险分析与风险评估, 基准测试
**Authors:** Chenxi Wu, Zimu Wang, Haiyang Zhang, Wei Wang, Zhijie Xu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.20584v1) | [PDF](http://arxiv.org/pdf/2609.20584v1.pdf) | [Code](https://github.com/xixi47520-hash/HARA)

### 1. 一句话结论

SAFARI 基准测试表明，前沿 LLM 在生成看似合理的危险描述方面表现良好，但在 ISO 26262 风险分类（尤其是 ASIL 分配）上能力薄弱，最佳 ASIL macro-F1 仅 0.261，且 CoT 提示通常无益甚至有害。

### 2. 为什么重要

这是首个针对汽车功能安全中 HARA 流程的工业级 LLM 基准，揭示了 LLM 在安全关键工程中的能力边界，为在受监管环境中安全部署 LLM 提供了重要参考，并指出了需要人工监督的关键环节。

### 3. 研究问题

1. LLM 在 ISO 26262 框架下的 HARA 任务中表现如何？
2. CoT 提示能否提升 LLM 在 HARA 中的风险分类能力？
3. LLM 在 HARA 中的主要失败模式是什么？

### 4. 背景与问题设定

现代汽车软件定义功能日益复杂，安全评估需考虑组件失效与操作场景的交互。ISO 26262 要求进行 HARA，包括识别危险事件、评估严重度（S）、暴露度（E）、可控性（C）并推导 ASIL。HARA 结合了开放式危险推理和标准约束的风险分类，对 LLM 构成挑战。现有 LLM 安全基准多关注通用安全，缺乏对 HARA 这类受监管工程流程的评估。

### 5. 方法概览

- 任务 / 环境: SAFARI 基准包含 3,000 个去标识化的工业 HARA 案例，聚焦于非预期驱动力或扭矩输出这一高关键性故障，并变化操作场景（如机动、道路布局、天气、交通参与者等）。数据集划分为 1,600 训练、400 验证、1,000 测试。
- 变量 / 干预设计: 任务分为两个连续子任务：任务1（危险分析）要求生成危险事件、危险和风险人群；任务2（风险评估）要求推断 E/S/C、ASIL、安全目标和 FTTI。评估采用自动指标（准确率、macro-F1、MAE）和参考锚定的 LLM-as-a-judge 协议，后者从四个维度（HLM、PCC、RCC、SGA）评分。
- 评价指标: 任务1使用参考锚定的 LLM-as-a-judge 评分（HLM、PCC、RCC、SGA），任务2使用准确率和 macro-F1 评估 E/S/C/ASIL，FTTI 使用 MAE。
- 模型比较: 评估了九个前沿 LLM（GPT-5.5、GPT-5.4-mini、Gemini-3.5-Flash、DeepSeek-V4-Pro、DeepSeek-V4-Flash、Qwen3.5-397B-A17B、Qwen3.5-122B-A10B、GLM-5.1、MiniMax-M2.7），在少样本（FS）和链式思考（CoT）两种提示策略下进行。
- 我的理解: 该基准设计精巧，将 HARA 分解为两个耦合任务，既评估开放式生成能力，又评估标准约束的分类能力，并通过参考锚定的 LLM-as-a-judge 协议解决了开放式文本评估难题。

### 6. 关键发现

- LLM 在危险生成上表现良好，但在风险分类上表现不佳: 模型在任务1（危险事件生成）上得分较高，但在任务2的 E/S/C 预测和 ASIL 分配上表现较差，最佳 ASIL macro-F1 仅为 0.261，表明生成流畅文本与准确风险评估之间存在显著差距。
- CoT 提示通常无益甚至有害: CoT 在多数任务上降低了性能（如 HLM、PCC、严重度、可控性、ASIL），但一致改善了 FTTI 估计，提示其效果因任务而异。
- 主要失败模式：场景上下文遗漏和可控性误判: 错误分析显示，模型在生成危险事件时经常遗漏关键场景上下文，且在评估可控性时存在系统性误判，导致将高 ASIL 案例错误分配为 QM（质量管理）级别。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: LLM 代理在安全关键工程中应仅作为辅助工具，需在关键决策点（如 ASIL 分配）引入人工审核，并利用 LLM 生成初稿以提高效率。
- 对 Skill: 需要开发专门的技能或微调模型以提升风险分类能力，例如通过领域特定训练或外部知识库增强可控性评估。
- 对 Memory: 模型需要更好地利用场景上下文，可能通过结构化记忆或检索增强来减少上下文遗漏。
- 对评测: 参考锚定的 LLM-as-a-judge 协议为评估开放式安全工件提供了有效方法，但需注意模型家族偏好，建议使用多个评判者交叉验证。

### 11. 局限性

- 基准仅覆盖单一故障类型（非预期驱动力），可能无法泛化到其他安全关键场景。
- LLM-as-a-judge 协议虽与专家相关性高，但可能仍存在偏差，且未完全消除模型家族偏好。
- 实验仅评估了九个模型，可能未涵盖所有前沿 LLM。

### 12. 我的看法 / 个人笔记

该基准填补了 LLM 在功能安全领域评估的空白，结果令人警醒：LLM 的流畅生成能力可能掩盖其在标准分类上的不足。未来工作应探索如何将领域知识注入模型，并开发更可靠的评估协议。

### 14. 总结

SAFARI 是首个针对汽车 HARA 的工业级 LLM 基准，包含 3,000 个案例，评估了九个前沿模型。结果显示，LLM 在危险生成上表现良好，但在风险分类上能力薄弱，最佳 ASIL macro-F1 仅 0.261，且 CoT 提示通常无益。主要失败模式是场景上下文遗漏和可控性误判，导致高 ASIL 案例被错误降级。该基准为 LLM 在安全关键工程中的应用提供了重要评估工具，并强调了人工监督的必要性。

## 5. DocAttriBench: Benchmarking Answer Grounding in Document Visual Question Answering

**Topics:** Document VQA, Visual Answer Grounding, Multimodal Large Language Models, Benchmark
**Authors:** Luca De Grandis, Silvia Cappelletti, William Raccagni, Marcella Cornia, Lorenzo Baraldi, Rita Cucchiara
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.20574v1) | [PDF](http://arxiv.org/pdf/2609.20574v1.pdf) | [Code](https://aimagelab.github.io/DocAttriBench/)

### 1. 一句话结论

DocAttriBench 是一个大规模文档 VQA 基准，通过基于掩码困惑度的自动标注方法 MAPPET 为答案提供细粒度的元素级证据定位，并发现现有 MLLM 的零样本定位能力普遍较弱。

### 2. 为什么重要

该工作解决了文档 VQA 中答案定位标注稀缺且质量不高的问题，提供了一个大规模、多样化的基准数据集，能够有效评估和训练多模态大模型的视觉定位能力，推动更可靠、可验证的文档理解系统的发展。

### 3. 研究问题

1. 如何自动为文档 VQA 答案生成高质量的元素级视觉定位标注？
2. 现有 MLLM 在文档 VQA 中的答案定位能力如何？

### 4. 背景与问题设定

文档视觉问答（Document VQA）要求模型根据文档图像回答自然语言问题，而答案定位（Answer Grounding）则要求模型指出支持答案的具体视觉区域（如文本块、表格、图片）。然而，现有基准要么缺乏定位标注，要么标注质量有限，且人工标注成本高昂。因此，构建大规模、高质量的定位基准是当前挑战。

### 5. 方法概览

- 任务 / 环境: 文档图像上的视觉问答任务，模型需输出答案文本和对应的边界框（证据区域）。
- 变量 / 干预设计: 提出 MAPPET 方法，通过掩码文档布局元素并计算困惑度变化来评估每个元素对答案生成的贡献，从而自动选择最相关的元素作为证据。同时设置阈值过滤低质量或模糊样本。
- 评价指标: 答案准确率（Answer Accuracy）、定位准确率（Attribution Accuracy）以及整体答案质量（Overall Answer Quality）。
- 模型比较: 评估了 16 种多模态大语言模型（MLLM），包括不同规模（≤3B, 7B-8B, 32B-38B）的模型，比较其零样本和微调后的性能。
- 我的理解: MAPPET 的核心思想是利用语言模型对答案生成的置信度（困惑度）来反向推断哪些视觉区域对答案最关键。通过掩码操作，可以量化每个区域的信息量，从而实现自动定位。这种方法避免了人工标注，且能处理多种文档类型。

### 6. 关键发现

- 零样本定位能力普遍较弱: 即使最大的模型（>30B）在零样本情况下的定位准确率也极少超过 35%，而小模型（≤3B）通常低于 10%。
- 微调显著提升定位性能: 在 DocAttriBench 上微调的 7B-8B 模型在定位准确率上比零样本版本提升超过 20 个百分点，甚至超过更大的通用模型。
- MAPPET 生成高质量标注: 通过人工评估，MAPPET 生成的定位标注准确率超过 95%，验证了其自动标注的可靠性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 对于基于文档的智能体系统，该基准可帮助评估和提升其证据定位能力，从而增强系统的可解释性和可信度。
- 对 Skill: 文档 VQA 中的定位能力可视为一种关键技能，DocAttriBench 可用于训练和评估该技能。

- 对评测: 该基准提供了标准化的评估协议，可促进文档 VQA 定位任务的公平比较。

### 11. 局限性

- 基准主要基于现有数据集聚合，可能无法完全覆盖所有文档类型和问题形式。
- 评估的模型数量有限，且未涵盖所有最新模型。

### 12. 我的看法 / 个人笔记

该工作通过自动标注方法解决了文档 VQA 中定位数据稀缺的问题，构建了大规模基准，并揭示了现有模型的不足。未来可进一步探索更高效的定位方法，以及将定位能力融入更复杂的文档理解任务中。
