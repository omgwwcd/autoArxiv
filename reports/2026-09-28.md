## 1. Structured Reasoning Agentic Framework for Interpretable Critical View of Safety Assessment

**Topics:** 计算机视觉, 手术场景理解, 智能体推理, 可解释人工智能
**Authors:** Qing Xu, Yuxiang Luo, Zhen Chen
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.31524v1) | [PDF](http://arxiv.org/pdf/2609.31524v1.pdf)

### 1. 一句话结论

ReasonCVS 通过将 CVS 评估分解为基于解剖场景图的子标准验证，并利用经过 rationale 蒸馏微调的 LLM 智能体进行可解释推理，在 Endoscapes-CVS201 上达到 68.1% mAP，优于现有方法。

### 2. 为什么重要

该工作首次将结构化推理智能体框架应用于手术安全评估，解决了现有黑盒模型缺乏可解释性和组合泛化能力的问题，为计算机辅助干预中的高风险决策提供了可追溯的临床推理依据，有望提升手术安全性和人机协作信任度。

### 3. 研究问题

1. 如何将 CVS 评估从整体预测分解为可验证的细粒度解剖子标准？
2. 如何利用视觉-语言模型和 LLM 智能体实现可解释的、符合临床逻辑的 CVS 推理？

### 4. 背景与问题设定

腹腔镜胆囊切除术中，肝胆囊三角区域解剖复杂，胆管损伤风险高。自动 CVS 评估是降低风险的关键。现有方法多为端到端黑盒模型，直接映射视觉特征到标准标签，缺乏对解剖关系的显式推理，导致可解释性差、组合泛化能力不足。

### 5. 方法概览

- 任务 / 环境: Endoscapes-CVS201 基准，包含 11,090 帧图像级标注和 493 帧像素级分割掩码，评估三个 CVS 标准：C1（两个结构）、C2（肝胆囊三角解剖）、C3（胆囊板）。
- 变量 / 干预设计: ReasonCVS 包含三个模块：1) ASGA 构建解剖场景图，将分割掩码转化为节点和边；2) VLM 驱动的子标准验证器，针对每个子标准生成判断、置信度和解释；3) 基于 Qwen-3 32B 的 rationale 感知推理智能体，通过 rationale 蒸馏微调，综合子标准证据输出最终判定和临床推理。
- 评价指标: 平均精度（mAP）和平衡准确率（BAcc），并进行了消融实验和临床专家评估（1-5 分 Likert 量表，评估临床合理性、可信度和清晰度）。
- 模型比较: 与 ResNet50、SurgVLP-vision、HecVL-vision、PeskaVLP-vision、CVS-AdaptNet、LayoutCVS、ResNet50-DetInit、LG-CVS、DeepCVS、STRG、SV2LSTG 等方法比较。
- 我的理解: 该方法的核心创新在于将 CVS 评估转化为结构化图验证问题，通过子标准分解和智能体推理实现可解释性。ASGA 提供了结构化的视觉表示，VLM 验证器提供细粒度证据，而 rationale 蒸馏则让 LLM 智能体学会权衡证据、解决冲突，从而生成符合临床逻辑的推理。

### 6. 关键发现

- ReasonCVS 在 Endoscapes-CVS201 上达到 SOTA 性能: ReasonCVS 取得 68.1% mAP，比最佳现有方法 SV2LSTG 高 3.8%，尤其在 C2 标准上提升显著（62.9% vs 56.4%），表明结构化图推理对复杂解剖区域有效。
- 消融实验验证各模块贡献: ASGA 带来 10.6% mAP 提升，VLM 子标准验证器带来 6.1% 提升，而 rationale 感知推理智能体带来最大提升（7.8% mAP），说明 rationale 蒸馏对证据综合至关重要。
- 临床专家评估显示 ReasonCVS 推理质量更高: 在临床合理性、可信度和清晰度三个维度上，ReasonCVS 的评分分布更集中且更高，而 Vanilla Agent 评分分散且偏低，证明 rationale 蒸馏能产生更符合临床逻辑的推理。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 展示了 LLM 智能体在医疗视觉任务中作为中央决策者的潜力，通过工具调用（VLM 验证器）和证据综合实现可解释决策，可推广到其他需要可追溯推理的智能体系统。
- 对 Skill: 提出了 rationale 蒸馏方法，通过教师模型生成推理链来微调学生模型，提升了模型在复杂证据综合上的能力，可应用于其他需要复杂推理的技能学习。
- 对 Memory: ASGA 构建的场景图可视为一种结构化记忆，存储解剖实体及其关系，为推理提供全局上下文，类似记忆增强机制。
- 对评测: 引入了临床专家评估维度（合理性、可信度、清晰度），为可解释 AI 系统的评估提供了参考框架。

### 11. 局限性

- 依赖分割掩码的准确性，ASGA 的性能受限于 SAM-3 的分割质量，在低质量图像或罕见解剖变异下可能出错。
- 子标准验证器使用 VLM 提示，可能受限于 VLM 的视觉理解能力，且未进行微调，可能在某些复杂场景下产生误判。
- rationale 蒸馏依赖教师模型（Gemini-3-pro）生成的推理质量，若教师推理有误，可能误导学生模型。
- 实验仅在单一基准（Endoscapes-CVS201）上验证，泛化性有待进一步测试。

该工作将智能体推理与结构化场景图结合，为手术安全评估提供了新范式，其可解释性设计值得借鉴。但实际部署中需考虑分割误差和 VLM 可靠性，未来可探索端到端训练验证器或引入不确定性量化。

## 3. DeepEdu-v1: Efficient and Scalable Agentic LLMs for Vietnamese Education

**Topics:** AI教育, 长上下文推理, 智能体系统, 低资源语言, 数据主权
**Authors:** Quang Nguyen, Hieu Nguyen, Hien Hoang, Toan Pham, Cong Tran, Nam Vu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.31568v1) | [PDF](http://arxiv.org/pdf/2609.31568v1.pdf)

### 1. 一句话结论

DeepEdu-v1 通过相似性分块滚动和自改进智能体层，在越南教育场景中实现了高效、可扩展且符合数据主权的 AI 辅导系统。

### 2. 为什么重要

该工作解决了在资源受限地区部署 AI 辅导系统的两大核心难题：数据主权合规（本地部署）和长上下文推理效率，同时通过自改进机制减少对主流语言先验的依赖，为本地化教育 AI 提供了可复制的框架。

### 3. 研究问题

1. 如何在不进行昂贵微调的情况下，让 LLM 在长上下文推理中保持高效并减少幻觉？
2. 如何构建一个自改进的智能体系统，使其能够持续积累本地化知识并提升复杂任务表现？

### 4. 背景与问题设定

在越南等发展中地区，AI 辅导有潜力显著提升学习效果，但云助手（如 ChatGPT）存在数据主权违规和本地知识不足的问题，而本地部署则面临 KV 缓存内存溢出和预填充延迟高以及幻觉问题。现有方法如量化、稀疏注意力和智能体上下文工程分别解决部分问题，但缺乏综合方案。

### 5. 方法概览

- 任务 / 环境: 越南教育场景，包括金融推理和交互式智能体基准测试，运行在消费级 GPU 上。
- 变量 / 干预设计: 提出 SCALE 框架，包含两个核心创新：1) 相似性分块滚动（Similarity Chunk Rolling）推理引擎，将 token 选择从子块级别提升到簇级别，减少检索调用；2) 自改进智能体层，通过查询感知上下文工程持续策划验证过的 playbook，而非微调。
- 评价指标: TTFT（首 token 延迟）、检索调用次数、任务准确率（agentic accuracy）。
- 模型比较: 与 TokenSelect 基线（选择性注意力）和标准 vLLM 服务进行比较。
- 我的理解: 该方法通过聚类相似查询块来减少注意力计算，同时利用智能体交互积累的验证知识来增强模型表现，是一种结合推理优化和知识管理的混合策略。

### 6. 关键发现

- 推理效率显著提升: 相似性分块滚动将检索调用减少 7.7 倍，预填充延迟（TTFT）降低约 35%，同时保持或提升任务准确率。

TemplateCraft 通过规划-评估循环和记忆机制，将自然语言指令自动转换为可复用的视觉模板，显著提升了模板生成的成功率和跨输入的一致性。

### 2. 为什么重要

该工作首次系统性地解决了可复用视觉模板的自动生成问题，将多智能体协作、执行反馈和记忆机制引入模板生成流程，大幅降低了人工成本，为短视频等场景的一键式内容创作提供了新范式。

### 3. 研究问题

1. 生成的模板能否满足创意要求并适应不同用户输入？
2. TemplateCraft 是否能在较小开源模型上提升模板生成成功率？
3. 要求使用持久资产是否能提高模板的可复用性？

### 4. 背景与问题设定

短视频的流行推动了一键式内容创作的需求。视觉模板通过预设效果将用户上传的图像转化为个性化内容，但可复用模板的生成仍需要大量人工准备素材和编排工具。现有大语言模型代理（如 HuggingGPT、ComfyUI-Copilot）主要面向一次性内容生成，缺乏对可复用模板生成的支持。因此，本文提出 TemplateCraft，一个多智能体系统，将自然语言指令转化为客户端可执行的模板，通过规划、素材生成、效果工作流生成和协议编译四个阶段实现自动化。

### 5. 方法概览

- 任务 / 环境: 模板生成任务，输入为自然语言创意指令，输出为可复用的视觉模板（图像或视频）。模板需包含可替换的用户输入槽和持久资产，并能在不同输入下保持风格一致。
- 变量 / 干预设计: 系统包含四个阶段：模板规划、素材生成、效果工作流生成和协议编译。前三个阶段由规划器-评估器循环控制，评估器根据执行反馈和候选输出进行路由决策（REVISE_PLAN、REVISE_MATERIAL、REVISE_EFFECT_WORKFLOW、FINISH），并利用阶段子记忆和长期记忆进行定向修订，无需更新模型参数。
- 评价指标: 模板生成成功率（SRc）、模板遵循度（TA）、模板可复用性（TR）、图像质量（IQ）和美学质量（AQ）。
- 模型比较: 与 Planner-only、Planner-CoT、Planner-Evaluator、UniV A 以及直接生成基线（Wan2.6、Seed）进行比较，所有变体使用 Qwen3-VL-30B-A3B-Instruct 作为规划器和评估器，图像和视频生成分别使用 Seedream 4.0 和 Seedance 1.5 Pro。
- 我的理解: TemplateCraft 的核心创新在于将执行反馈和记忆机制引入模板生成流程，通过评估器诊断问题并定向回滚到最早需要修改的阶段，同时利用长期记忆跨任务复用经验，从而在较小模型上实现了更高的生成成功率和模板遵循度。

### 6. 关键发现

- TemplateCraft 显著提升模板生成成功率: 在图像和视频模板任务上，TemplateCraft 的 SRc 分别达到 66.7% 和 50.0%，相比 Planner-only 的 56.7% 和 30.0% 有显著提升，视频任务提升幅度更大（20个百分点）。
- 执行反馈和记忆机制是关键: 消融实验显示，Planner-CoT 仅提升视频 SRc 至 43.3%，而 Planner-Evaluator 将图像 SRc 提升至 63.3%，加入长期记忆后进一步达到 66.7%/50.0%，表明执行反馈、定向回滚和历史经验共同作用。
- 持久资产提升模板可复用性: 要求使用持久资产时，模板可复用性（TR）显著提高，跨输入的风格一致性更好，验证了持久资产在模板复用中的重要性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 展示了多智能体系统在复杂内容生成任务中的潜力，通过执行反馈和记忆机制可显著提升小模型的性能，为构建更可靠的自动化内容创作系统提供了新思路。
- 对 Skill: 强调了技能库和持久资产在模板复用中的重要性，提示技能设计需考虑可复用性和跨输入一致性。
- 对 Memory: 验证了阶段子记忆和长期记忆在定向修订和跨任务经验复用中的有效性，为代理系统的记忆设计提供了实证支持。
- 对评测: 提出了 TemplateBench 基准，包含真实模板任务和评分规则，为可复用模板生成提供了标准化的评估方法。

### 11. 局限性

- TemplateBench 仅包含 60 个模板任务，规模有限，可能不足以全面评估系统泛化能力。
- 评估依赖 VLM 评分，尽管与人类评分相关性较高，但仍可能存在偏差。
- 系统依赖特定生成模型（Seedream、Seedance），其性能可能影响最终模板质量。
- 未探讨模板在不同客户端或不同生成模型上的迁移性。

### 12. 我的看法 / 个人笔记

TemplateCraft 是视觉模板生成领域的重要进展，其多智能体架构和记忆机制设计巧妙，有效解决了小模型在复杂任务中的可靠性问题。未来可进一步扩展模板类型和评估维度，并探索跨平台部署。

## 5. Resource-Optimized and Energy-Aware Agentic AI Framework Anchored on Blockchain for Secure Software Supply Chains

**Topics:** 软件供应链安全, 智能体AI, 区块链, SDLC
**Authors:** Toqeer Ali Syed, Asadullah Abdullah Khan
**Venue / Year:** International Journal of Energy, Environment, and Economics
**Links:** [Abstract](http://arxiv.org/abs/2609.31282v1) | [PDF](http://arxiv.org/pdf/2609.31282v1.pdf)

### 1. 一句话结论

提出一个基于区块链的智能体安全框架，通过加密签名的证明和链上发布策略，确保软件供应链全生命周期的安全与可信。

### 2. 为什么重要

该框架将智能体AI与区块链结合，不仅保护软件供应链，还确保智能体自身的安全与可信，解决了现有方法缺乏自主性和动态适应性的问题。

### 3. 研究问题

1. 如何利用智能体AI实现软件供应链的主动、实时安全防护？
2. 如何通过区块链确保智能体行为的可验证性和不可篡改性？
3. 如何将智能体AI与区块链集成以支持可执行的发布决策？

### 4. 背景与问题设定

现代软件供应链复杂且攻击面广，传统安全措施多为被动，缺乏自主性。智能体AI可提供自主防御，但其自身可信性需保障。区块链提供不可篡改的账本，可确保智能体证明的可验证性。

### 5. 方法概览

- 任务 / 环境: 软件供应链全生命周期，包括源代码、依赖、CI/CD、制品和运行时环境。
- 变量 / 干预设计: 部署多个专用安全智能体（如源代码完整性、依赖与SBOM分析、CI配置审计、制品验证、运行时策略评估），每个智能体由LLM支持，生成结构化安全报告并产生加密签名的证明。
- 评价指标: 未明确给出具体指标，但通过用例和序列流程展示智能体分析、链上证明和发布决策的流程。
- 模型比较: 与SLSA、in-toto、OpenSSF Scorecard、ARGO-SLSA等框架对比，强调本框架的自主性、智能体身份注册和链上发布策略。
- 我的理解: 该框架将智能体AI的推理能力与区块链的不可篡改性结合，通过智能体注册、证明日志和发布策略智能合约，实现安全分析的自动化与可验证性。

### 6. 关键发现

- 智能体证明与链上发布策略: 每个智能体生成加密签名的证明，记录在区块链上，通过智能合约评估证明以决定是否允许部署，确保决策的可验证性和不可篡改性。
- 智能体身份注册与安全通信: 通过区块链上的智能体注册表和CA签发的证书，确保智能体身份可信，通信采用mTLS，防止中间人攻击。
- 覆盖全生命周期的安全监控: 框架覆盖源代码、依赖、CI配置、制品和运行时，提供持续的安全保障，弥补现有方法仅关注单一阶段的不足。
