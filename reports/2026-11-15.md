## 1. Discovering Effective Agent Memory Designs through Program Evolution

**Topics:** Agent Memory, Program Evolution, LLM Agents
**Authors:** Xinheng Ding, Seyyed Saeid Cheshmi, Ziyang Zhang, Tairan Chen, Wenya Xie, Yu Hou, Rui Zhang, Zirui Liu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.17068v1) | [PDF](http://arxiv.org/pdf/2611.17068v1.pdf) | [Code](https://github.com/ash-ding/MAPE)

### 1. 一句话结论

通过程序进化自动发现高效智能体记忆设计，在LoCoMo和LongMemEval上以更低成本实现更高准确率，并揭示保留原始对话与按查询意图组合证据的有效模式。

### 2. 为什么重要

智能体记忆设计长期依赖人工经验，缺乏系统性探索。该工作首次将整个记忆程序作为进化对象，从极简种子出发自动发现超越人工设计的方案，并揭示可迁移的设计原则，为记忆系统自动化设计开辟新路径。

### 3. 研究问题

1. 从极简种子出发，程序进化能发现哪些有效的记忆系统设计？
2. 不同优化目标（仅准确率 vs 准确率+成本）如何影响进化过程和最终设计？

### 4. 背景与问题设定

大语言模型智能体（如个人助理）依赖持久记忆维持多轮对话连续性。现有记忆系统（如Mem0、A-Mem等）由人工设计，组件间协调复杂，且优化目标单一（仅准确率）。本文提出MAPE框架，将记忆系统视为可编程程序，通过进化自动搜索设计空间，同时考虑准确率与推理成本。

### 5. 方法概览

- 任务 / 环境: 两个基准：LoCoMo（长对话问答）和LongMemEval-S（长程记忆评估），均按20%/80%划分搜索集和评估集。
- 变量 / 干预设计: 进化从极简种子（如不存储记忆）开始，通过迭代诊断-提议循环生成新程序。每个候选程序在固定搜索集上评估准确率和成本，并记录执行轨迹供诊断。
- 评价指标: 准确率（LLM裁判按基准rubric判定）和生命周期服务成本（美元/千查询，基于token价格）。
- 模型比较: 与Full Context、RAG及五种人工设计记忆系统（Mem0、A-Mem、LightMem、SimpleMem、Zep）对比。
- 我的理解: MAPE将记忆系统抽象为四个阶段（构建、检索、组合、回答），进化可修改前三阶段代码。通过LLM提议者基于历史候选和诊断生成新程序，形成闭环优化。

### 6. 关键发现

- 进化程序全面超越人工设计: 在LoCoMo上，MAPE-ALCM准确率达87.94%，比最佳人工基线SimpleMem（80.80%）高7.14%；在LongMemEval上，MAPE-ALME达77.00%，比最强基线RAG（66.00%）高11.00%。
- 联合优化准确率与成本可大幅降低推理开销: MAPE-PLCM在LoCoMo上以2.03美元/千查询的成本达到85.18%准确率，成本仅为MAPE-ALCM的28%；在LongMemEval上，MAPE-PLME成本为5.76美元/千查询，准确率72.25%，成本比MAPE-ALME（52.84美元/千查询）降低约89%。
- 两个可迁移设计模式：保留原始对话与按查询意图组合: 进化程序普遍保留原始对话作为可检索证据，避免提取摘要丢失细节；同时根据查询意图（如时间、多跳）动态组合证据，提升回答质量。
- 跨骨干和跨基准迁移性良好: 在LoCoMo上进化出的程序换用Qwen3-30B-A3B-Instruct-2507后仍保持高准确率（MAPE-PLCM 81.33%），且跨基准迁移到LongMemEval时，MAPE-ALCM和MAPE-PLCM分别达到65.50%和64.25%，优于部分人工系统，但略低于RAG（66.00%）。

## 2. AURA 2.0: From User-Driven Responses to Model-Initiated Conversations in Streaming Video

**Topics:** 流式视频理解, 多模态大语言模型, 模型主动对话, 工具调用, 视觉定位
**Authors:** Shuhan Li, Huankang Guan, Xintong Guo, Yang Bo, Yuyang He, Dunyuan Xu, Jingyan Chen, Fang Liu, Tsz Kin Wan, Jinpeng Chen, Zhenqi He, Yuxuan Hu, Wenbo Li, Han Gao, Qijun Li, Long Chen, Hongsheng Li, Rui Liu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.17048v1) | [PDF](http://arxiv.org/pdf/2611.17048v1.pdf) | [Code](https://github.com)

### 1. 一句话结论

AURA 2.0 通过模型主动对话（MIC）、流式感知工具调用（SATC）和交互式视觉定位（IVG）三大升级，使流式视频大模型能够主动发起对话、调用工具并精准定位目标，显著提升了交互的主动性和实用性。

### 2. 为什么重要

现有AI助手大多被动响应，无法在视频流中主动发现并利用对话机会。AURA 2.0 首次实现了模型主动发起对话的能力，结合工具调用和视觉定位，使流式视频交互从“用户驱动”迈向“模型主动”，为实时视频理解、监控、辅助决策等应用开辟了新可能。

### 3. 研究问题

1. 如何让流式视频大模型在无用户查询时主动识别值得讨论的话题并适时发起对话？
2. 如何将工具调用和视觉定位能力无缝集成到流式交互框架中，同时保持低延迟和上下文连续性？

### 4. 背景与问题设定

流式视频大语言模型（VideoLLMs）旨在在线处理视频流并实时响应，但现有系统大多依赖用户查询或预设指令，缺乏主动发起对话的能力。AURA 2.0 在 AURA 的基础上，引入模型主动对话（MIC）、流式感知工具调用（SATC）和交互式视觉定位（IVG），并构建了大规模训练数据集和高效推理框架，以支持更自然、主动的流式交互。

### 5. 方法概览

- 任务 / 环境: 流式视频交互环境，模型逐块处理视频帧，结合用户输入和历史对话，决定保持沉默或生成响应（文本或工具调用）。
- 变量 / 干预设计: 引入三种新能力：MIC（模型主动发起对话）、SATC（基于视觉和对话上下文调用外部工具）、IVG（支持用户标记和模型输出边界框）。训练数据通过MLLM合成，包含约114亿token、5400小时视频和4000万帧。
- 评价指标: 在公开基准（PhoStream、ProactiveVideoQA、IPIBench、StreamArena）上评估整体性能，并针对MIC、SATC、IVG进行专项评估，包括对话发起时机、工具调用准确性、定位精度等。
- 模型比较: 与AURA、MMDuet2、MOSS-VL-Realtime、JoyAI-VL-Interaction等模型对比，AURA 2.0在支持MIC、SATC、IVG方面具有独特优势，且在公开基准上达到领先水平。
- 我的理解: AURA 2.0 的核心创新在于将“主动对话”作为一等公民，通过统一的响应控制机制（<|silent|>/<|respond|>）管理所有交互行为，并利用长时交互记忆（LHIM）保持上下文连续性，使模型能在长时间视频流中做出适时、相关的主动响应。

### 6. 关键发现

- 模型主动对话（MIC）有效提升交互主动性: AURA 2.0 能够在无用户查询时，基于视频内容主动发起有意义的对话，且能避免重复或无关的打扰，在ProactiveVideoQA等基准上表现优异。
- 流式感知工具调用（SATC）扩展了模型能力边界: 模型能根据视频和对话上下文自动决定是否调用外部工具（如计算器、搜索），并将结果融入后续响应，在StreamArena工具使用任务上显著优于不支持工具调用的模型。
- 交互式视觉定位（IVG）实现精准目标关联: 模型能理解用户标记并输出帧对齐的边界框，支持多候选消歧、目标切换等复杂场景，在MeViS等数据集上验证了有效性。

### 11. 局限性

## 3. AgentSSL: Can MLE Agents Leverage Unlabeled Data?

**Topics:** MLE Agent, Semi-Supervised Learning, Program Selection
**Authors:** Ethan Lin, Akanksha Sarkar, Ziang Liu, Kristin Branson, Jennifer J. Sun
**Venue / Year:** NeurIPS 2026 (arXiv preprint)
**Links:** [Abstract](http://arxiv.org/abs/2611.17323v1) | [PDF](http://arxiv.org/pdf/2611.17323v1.pdf) | [Code](https://codiscovery.ai/AgentSSL)

### 1. 一句话结论

MLE agents can discover effective semi-supervised learning programs under weak feedback, outperforming human baselines in 8/12 settings, but program selection remains a critical bottleneck.

### 2. 为什么重要

This work extends MLE agents to realistic data-scarce regimes, showing they can reduce both annotation and engineering costs, and introduces a large-scale benchmark for program selection.

### 3. 研究问题

1. Can MLE agents effectively leverage unlabeled data in semi-supervised learning settings?
2. How does agent-discovered SSL performance compare to human-engineered baselines under limited supervision?
3. What are the bottlenecks in selecting the best program from agent-discovered candidates without a large labeled validation set?

### 4. 背景与问题设定

Machine learning deployment requires labeled data and human engineering. MLE agents automate pipeline design but are typically studied in fully supervised settings. SSL reduces annotation cost but requires human engineering. AgentSSL aims to reduce both costs by framing SSL as a program search problem.

### 5. 方法概览

- 任务 / 环境: Image classification across six datasets (DTD, SUN397, RESISC45, Retinopathy, CLEVR, KITTI) with limited labeled data (e.g., 3-80 examples per class) and abundant unlabeled data.
- 变量 / 干预设计: Agents generate SSL programs using feedback from either noisy validation (N) or unsupervised metrics (U). Search strategies include greedy, evolutionary, and MCTS. Baselines include supervised, FixMatch, SoftMatch, FineSSL, PET, V-PET.
- 评价指标: Oracle test performance (best program in pool) and selection regret (difference between oracle and selected program).
- 模型比较: AgentSSL with unsupervised feedback (AgentSSL_U) and noisy validation (AgentSSL_N) compared to human baselines.
- 我的理解: The method treats SSL as a program search where an LLM agent iteratively proposes and refines code, using feedback from either a small labeled validation set or unsupervised metrics. The key innovation is applying MLE agents to SSL, and the benchmark ProgramSelectBench for studying selection.

### 6. 关键发现

- AgentSSL outperforms human baselines in 8/12 settings: The best agent-generated program (Abest) exceeded the strongest human-engineered SSL baseline by up to +21.8% in 8 of 12 settings, demonstrating that agents can discover effective SSL strategies.
- Program selection is a critical bottleneck: Selecting the best program based on the agent's feedback metric can lead to performance drops of up to 47%, highlighting the difficulty of model selection without a large labeled validation set.
- Unsupervised feedback can guide effective search: Even when unsupervised metrics are weakly or negatively correlated with final accuracy, agents can still discover competitive programs, suggesting that weak feedback is sufficient for exploration.

## 4. Metal Sandbox: Isolated Execution and Command Scheduling for GPU Coding Agents on Apple Silicon

**Topics:** GPU Coding Agents, Apple Silicon, Metal, Command Scheduling, Isolated Execution
**Authors:** Haozhe Wang, Lina Chen, Fanqi Wan, Qi Han, Yinmin Zhang, Zheng Ge, Daxin Jiang, Junchi Yan
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.17294v1) | [PDF](http://arxiv.org/pdf/2611.17294v1.pdf) | [Code](github.com/WangHaoZhe/metal-sandbox, github.com/WangHaoZhe/harbor)

### 1. 一句话结论

Metal Sandbox 通过受限文件访问和跨 Mac 命令调度，将 GPU 编码代理的吞吐量提升 1.68–2.05 倍，并减少 18.8% 的工具等待时间。

### 2. 为什么重要

该工作为在 Apple Silicon 上高效训练和评估生成 Metal kernel 的模型提供了基础设施，解决了并发代理会话中 GPU 空闲和队列不平衡的问题，对端侧推理优化具有重要意义。

### 3. 研究问题

1. 如何在不牺牲安全性的前提下，为 GPU 编码代理提供原生 macOS 执行环境？
2. 如何通过跨节点命令调度提高多代理会话的 GPU 利用率和吞吐量？

### 4. 背景与问题设定

端侧推理需要高效利用本地加速器，而生成 Apple Metal kernel 的模型训练和评估需要原生 macOS 工具和并发代理会话。然而，代理会话在模型请求、开发命令和 GPU 执行之间交替，导致 GPU 大量空闲。现有方案如 Docker 容器或 macOS 虚拟机无法提供原生 GPU 访问或文件隔离。

### 5. 方法概览

- 任务 / 环境: 四个 Mac mini M4 节点（32GB 内存，macOS 27.0.1），通过千兆以太网互联，共享工作区使用 SMB 挂载。

## 5. Programming Quantum Circuit Parameters with Large Language Models

**Topics:** 量子计算, 大语言模型, 变分量子算法
**Authors:** Tiago de Souza Farias, Caio Moraes Porto, Matheus da Silva Fonseca, Nicolas Armando Cabrera Carpi, Anderson de Araujo Oliveira, Celso Jorge Villas-Boas
**Venue / Year:** arXiv:2611.17246v1 [quant-ph] 12 Nov 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.17246v1) | [PDF](http://arxiv.org/pdf/2611.17246v1.pdf)

### 1. 一句话结论

冻结的通用大语言模型能够为结构化哈密顿量生成有希望的变分量子电路参数，但在一般哈密顿量上不如传统优化方法，且迭代反馈改进有限。

### 2. 为什么重要

这项工作探索了利用大语言模型直接生成量子电路参数的可能性，为减少量子计算中的优化开销提供了新思路，并揭示了问题结构对LLM性能的关键影响，对量子计算与AI交叉领域具有重要意义。

### 3. 研究问题

1. 在什么条件下，冻结的通用大语言模型能够有效生成变分量子电路的参数？
2. 迭代能量反馈能否显著改善LLM生成的参数质量？
3. LLM能否从符号表示中盲解释量子电路的行为和输出？

### 4. 背景与问题设定

变分量子算法（VQA）结合参数化量子电路与经典优化器，但传统优化需要大量量子评估。近年来，大语言模型（LLM）被用于直接生成电路参数，但有效性条件不明。本文研究冻结的通用LLM（GPT-6 Astra）在无任务特定训练下，从电路和哈密顿量的符号描述生成完整参数向量，并评估其在一般随机哈密顿量、结构化父哈密顿量和分子系统上的表现，同时探索LLM对量子电路的盲解释能力。

### 5. 方法概览

- 任务 / 环境: 量子电路参数优化任务，涉及一般随机哈密顿量、结构化父哈密顿量和分子系统；电路以OpenQASM 3描述，哈密顿量以泡利分解表示。
- 变量 / 干预设计: 使用冻结的GPT-6 Astra作为语言模型优化器（LMO），输入电路和哈密顿量描述，生成完整参数向量；可选迭代能量反馈（将先前参数和能量作为上下文）。对比基线为Adam优化器。盲解释任务中，输入电路表示（逻辑、原生、混淆），要求模型描述行为、预测输出。
- 评价指标: 能量误差（相对于已知基态能量）、能量期望值、算法识别准确率、输出位串预测准确率。
- 模型比较: LMO与Adam优化器在参数质量上对比；盲解释任务中评估LLM在不同电路表示下的表现。
- 我的理解: 该方法将LLM视为参数生成器，利用其从符号描述中推断参数，而非传统优化。关键在于问题结构：结构化哈密顿量（如父哈密顿量）具有可识别的物理模式，LLM能利用这些模式；而一般随机哈密顿量缺乏结构，LLM难以有效推断。迭代反馈可能帮助有限，因为LLM的生成过程可能不依赖于梯度信息。

### 6. 关键发现

- 一般哈密顿量上LLM不如Adam: 对于一般随机哈密顿量，LLM生成的参数能量误差大于Adam优化，且额外反馈改进有限。
- 结构化哈密顿量上LLM表现良好: 对于父哈密顿量和分子系统，LLM能生成低能量参数配置，表明物理和数学结构有助于参数推断。
- 迭代反馈改进有限: 连续LLM提议通常比初始配置改进有限，但在某些分子实验中观察到能量显著降低，但无法区分反馈与额外生成的影响。
- LLM可盲解释电路: LLM能识别某些量子算法（包括混淆电路），即使算法识别失败，有时也能正确预测测量位串。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: LLM可作为智能体直接生成量子电路参数，减少对经典优化器的依赖，但需注意问题结构匹配。
- 对 Skill: LLM的量子参数生成能力可视为一种技能，适用于结构化问题，但需结合验证机制。
- 对 Memory: LLM可能利用训练数据中的物理知识，但记忆可能不足以处理一般问题，需外部反馈。
- 对评测: 评估LLM生成参数的质量需独立验证物理可实现性，避免直接预测能量导致的错误。

### 11. 局限性

- 仅使用GPT-6 Astra，未测试其他LLM，泛化性未知。
- 迭代反馈实验未隔离反馈与额外生成的影响，无法确定反馈的具体贡献。
- 盲解释任务仅覆盖三种算法，且混淆程度有限，可能低估实际复杂性。

这项工作系统地评估了LLM在量子参数生成中的能力，揭示了结构的重要性。未来可探索结合少量梯度信息或混合优化策略，以提升一般问题的性能。盲解释能力也值得进一步研究，可能用于量子电路验证。
