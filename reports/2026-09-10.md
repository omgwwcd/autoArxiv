## 1. JarvisGUI: Towards Cross-Device GUI Agents with Dynamic Task Composition

**Topics:** GUI Agent, Cross-Device Benchmark, Task Composition
**Authors:** Zixiang Chen, Yuheng Lu, Zihao Cheng, Zeming Liu, Jizeng Bai, Ziye Huang, Zhiyin Lin, Zihan Li, Yuhang Guo, Yunhong Wang, Haifeng Wang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.10451v1) | [PDF](http://arxiv.org/pdf/2609.10451v1.pdf) | [Code](JarvisGUI)

### 1. 一句话结论

JarvisGUI 是一个跨设备 GUI 代理基准，通过类型系统动态组合任务，揭示现有代理在状态转移和跨平台推理上的严重不足。

### 2. 为什么重要

现有 GUI 基准仅评估单设备静态任务，忽略了真实世界中跨设备协作的需求，导致对代理能力的过度乐观估计。JarvisGUI 填补了这一空白，为评估代理在异构环境中的实际可用性提供了关键工具。

### 3. 研究问题

1. 现有 GUI 代理在跨设备工作流中的表现如何？
2. 如何系统性地构建和评估跨设备 GUI 任务？

### 4. 背景与问题设定

真实 GUI 使用常涉及多设备工作流，需要跨平台传输中间结果、维护共享状态和协调操作。然而，现有基准仅评估单设备静态任务，忽略了跨设备能力，导致对代理实际部署准备度的评估过于乐观。

### 5. 方法概览

- 任务 / 环境: 基于 Docker 的虚拟化环境，包含 Android、Windows 和 Ubuntu 三个平台，支持高吞吐并行执行和多设备协作。
- 变量 / 干预设计: 采用 Planner-Grounder 两阶段架构，将自然语言指令转换为跨平台可执行动作序列。任务通过类型系统动态组合，确保数据流兼容性。
- 评价指标: 基于最终环境状态的确定性评估函数，检查文件内容或 DOM 元素等可观察工件，确保评估对随机界面变化具有鲁棒性。
- 模型比较: 评估了多个开源 GUI 代理（如 Bai et al., 2025a; Zhou et al., 2025 等），比较其在单设备与跨设备任务上的表现差异。
- 我的理解: 该方法通过形式化任务定义为输入-输出转换，利用类型系统自动组合跨设备工作流，并采用动态评估机制，使得大规模、可复现的跨设备代理评估成为可能。

### 6. 关键发现

- 跨设备任务显著降低代理成功率: 现有开源 GUI 代理在跨设备工作流中表现不佳，暴露出状态转移意识、跨平台上下文推理和长程依赖管理方面的关键能力差距。
- 单设备能力与跨设备能力存在巨大差异: 代理在单设备任务上表现良好，但在需要跨设备协调的任务中性能大幅下降，表明现有基准高估了代理的实际可用性。

### 14. 总结

JarvisGUI 是一个跨设备 GUI 代理基准，通过类型系统动态组合任务，在 Android、Windows 和 Ubuntu 虚拟环境中评估代理。实验表明，现有开源代理在跨设备任务中表现不佳，暴露出状态转移和跨平台推理的关键差距，为 GUI 代理的实际部署提供了重要洞察。

## 2. TRACE: Trajectory-robust Admission with Evidence Ordering for Efficient GUI Agents

**Topics:** GUI Agent, Visual Token Pruning, Efficient Inference, Multimodal Large Language Model
**Authors:** Yuhao Wang, Mu Qiao, Xindong Zhang, Yunzhi Zhuge, Lei Zhang, Huchuan Lu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.10297v1) | [PDF](http://arxiv.org/pdf/2609.10297v1.pdf)

### 1. 一句话结论

TRACE 提出训练无关框架，通过布局先验、嵌套排序和覆盖修复，在多步 GUI 代理中实现视觉令牌的不可逆提交与单调收缩，显著降低延迟和内存占用。

### 2. 为什么重要

GUI 代理在多步交互中累积高分辨率截图，导致推理延迟和内存激增。TRACE 首次将视觉令牌剪枝形式化为轨迹不确定下的写入时证据提交问题，并设计生命周期感知方案，在保持性能的同时大幅提升效率，为实际部署提供可行路径。

### 3. 研究问题

1. 在多步 GUI 交互中，当视觉状态可复用且未来目标未知时，如何做出不可逆的视觉令牌提交决策？
2. 如何在严格预算下同时保持对可操作区域的空间覆盖，避免剪枝偏向少数显著区域？

### 4. 背景与问题设定

多步 GUI 代理每步处理高分辨率截图，历史帧通过缓存复用避免重复编码，但缓存一旦写入，丢弃的令牌无法恢复。因此，视觉令牌剪枝从可重选的在线选择变为不可逆的写入时提交，且后续收缩必须保持嵌套关系（历史保留集是当前保留集的子集）。现有方法（如 FastV、CDPruner）在单步中有效，但在多步场景下因重选导致频繁重编码，且偏向显著区域导致空间覆盖缺失。

### 5. 方法概览

- 任务 / 环境: 多步 GUI 交互任务，代理每步观察截图并执行动作，历史帧通过缓存复用。
- 变量 / 干预设计: TRACE 包含四个组件：布局派生交互先验（LIP）利用 OmniParser 检测 UI 元素，计算交互能量 E = H + C + G + R（熵、对比度、包含度、共振度），生成每令牌密度 ρ = E/n，再通过软质量 m_j = 1 + αNp_j 形成偏置；嵌套证据排序（NEO）融合布局先验、指令相关性（通过余弦相似度 a_j = softmax(zscore(max cos(z_j, U)))）和特征新颖性（通过贪心残差选择 d_j^2(S) = ||ψ_j - Π_S ψ_j||_2^2），生成嵌套顺序 π；原生令牌覆盖修复（NCR）为当前帧用步长采样（步长 s = ceil(|U_c|/g_c)）修复空间覆盖，为历史帧用 medoid 选择（最小化区域内特征距离平方和）修复；单调 KV 收缩（MKC）在帧退休时截断缓存至历史预算，仅编码新帧。
- 评价指标: 单步任务：ScreenSpot-v2、ScreenSpot-Pro、MMBench-GUI 的准确率；多步任务：OmniGUI、Mind2Web、AndroidControl 的步骤成功率（Step SR）。
- 模型比较: 基于 GUI-Owl-1.5-8B 模型，与 Random、Uniform、DivPrune、CDPruner、VisPruner、PruMerge+、TRIM、FastV、VisionTrim、ZOO-Prune、PruneSID 等 11 种方法对比，在宽松预算（单步 r=10%，多步 c=50%, h=10%）和严格预算（单步 r=5%，多步 c=25%, h=5%）下均取得最佳或次佳平均性能。
- 我的理解: TRACE 的核心洞察是将剪枝决策从每步重选改为一次性提交，并通过布局先验和覆盖修复解决未来目标未知和空间覆盖缺失两个挑战。嵌套顺序和单调收缩的设计使得历史帧无需重编码，从而在保持性能的同时大幅降低计算开销。

### 6. 关键发现

- TRACE 在严格预算下显著优于现有方法: 在单步任务中，TRACE 在 5% 令牌预算下达到 73.90% 准确率（ScreenSpot-v2），远超第二名 VisionTrim 的 58.65%；在多步任务中，TRACE 在 50% 当前帧和 10% 历史帧预算下平均步骤成功率 78.7%，比最佳基线高 6.3 个百分点。
- 嵌套顺序无需重选即可保持性能: 实验表明，强制嵌套顺序（历史保留集是当前保留集的子集）与独立重选相比，准确率差异在 ±2% 以内，说明嵌套顺序不会带来性能损失，同时避免了重编码开销。
- 布局先验和覆盖修复是性能提升的关键: 消融实验显示，移除布局先验（LIP）后，ScreenSpot-v2 准确率下降约 10 个百分点；移除覆盖修复（NCR）后，在严格预算下准确率下降约 15 个百分点，验证了这两个组件对轨迹鲁棒性和空间覆盖的重要性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: TRACE 提供即插即用的效率提升方案，无需训练即可显著降低 GUI 代理的推理延迟和内存占用，特别适合资源受限的移动端或实时交互场景。
- 对 Skill: 布局先验的引入使代理更关注可操作区域（如按钮、文本框），可能提升动作定位的准确性，尤其在复杂界面中。
- 对 Memory: 单调 KV 收缩机制将历史帧的缓存管理简化为索引截断，避免了重复编码和剪枝，为长轨迹交互提供了可扩展的内存方案。
- 对评测: TRACE 在多个基准上验证了有效性，但现有评估多基于固定预算，未来可探索动态预算分配或与任务难度自适应结合。

### 11. 局限性

- TRACE 依赖 OmniParser 进行布局检测，增加了预处理开销，且布局检测的准确性可能影响先验质量。OmniParser 本身需要额外计算，在资源受限场景下可能成为瓶颈。
- 当前方法在极低预算（如 1%）下性能下降明显，空间覆盖修复的步长采样和 medoid 选择可能仍不足以保留关键信息，尤其是在界面元素密集时。
- 实验仅基于 GUI-Owl-1.5-8B 模型，跨模型族（如 Qwen-VL、LLaVA）的泛化性尚未充分验证，且未在更大规模模型（如 13B 以上）上测试。

### 12. 我的看法 / 个人笔记

TRACE 将视觉令牌剪枝问题重新定义为生命周期管理，思路新颖且实用。布局先验和覆盖修复的设计巧妙解决了多步场景下的两个核心挑战，实验充分。未来可探索布局检测的轻量化替代（如基于视觉特征的隐式先验），以及动态预算分配以进一步提升效率。此外，TRACE 对 OmniParser 的依赖可能限制其通用性，值得关注。

### 13. 这篇工作引用的近期高影响力相关文章

- FastV: Fast Visual Token Pruning for Large Language Models
  为什么重要：FastV 是视觉令牌剪枝的早期工作，通过注意力分布剪枝冗余令牌，但未考虑多步场景下的不可逆提交问题。
  核心贡献：提出基于注意力统计的令牌排序和剪枝方法，在单步任务中有效。
  与当前论文关系：TRACE 指出 FastV 在多步场景下因重选导致重编码，并在此基础上引入布局先验和嵌套顺序。
- CDPruner: Context-Diverse Pruning for Vision-Language Models
  为什么重要：CDPruner 结合指令相关性和特征多样性进行剪枝，是当前最先进的训练无关方法之一。
  核心贡献：同时考虑指令相关性和特征多样性，选择信息量最大的令牌。
  与当前论文关系：TRACE 发现 CDPruner 在多步场景下因缺乏布局先验而丢失后续目标，且空间覆盖不足。
- PruMerge+: Efficient Visual Token Merging for Multimodal LLMs
  为什么重要：PruMerge+ 通过合并冗余令牌生成合成摘要，是令牌合并的代表性工作。
  核心贡献：将剪枝与合并结合，自适应调整令牌数量。
  与当前论文关系：TRACE 坚持保留原生令牌（不合并），因为合并后的合成令牌无法在缓存中逐行丢弃，与单调收缩不兼容。

### 14. 总结

TRACE 提出训练无关框架，通过布局派生交互先验（LIP）、嵌套证据排序（NEO）、原生令牌覆盖修复（NCR）和单调 KV 收缩（MKC），实现了 GUI 代理中视觉令牌的不可逆提交与单调收缩。在六个基准上的实验表明，TRACE 在严格预算下显著优于现有方法，同时降低了 58% 的首令牌延迟和 59% 的 KV 缓存占用，为高效 GUI 代理提供了实用解决方案。

## 3. The Answer Path and the Grounding Instruction in LLM Question Answering over Knowledge Graphs

**Topics:** GraphRAG, LLM, Knowledge Graph Question Answering
**Authors:** Arquimedes Canedo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.10237v1) | [PDF](http://arxiv.org/pdf/2609.10237v1.pdf)

### 1. 一句话结论

在GraphRAG中，保留答案路径（链式三元组）至关重要，而提高上下文精度、序列化格式、三元组顺序和子图大小对多跳推理准确率无显著影响；接地指令（严格提示）在无上下文时导致F1下降8.63倍，但该效应属于评估伪影，不应归因于图上下文。

### 2. 为什么重要

该研究系统解构了GraphRAG流水线的四个设计选择，揭示了哪些因素真正影响LLM在知识图谱问答中的表现，纠正了先前研究中因实验设计缺陷（如提示词不一致）导致的误导性结论，为实际系统优化提供了明确方向：优先保证召回率而非精确率，并谨慎处理接地指令以避免评估偏差。

### 3. 研究问题

1. 在GraphRAG中，检索子图的哪些属性（如是否包含答案路径、上下文精确率、序列化格式、三元组顺序、子图大小）对LLM的答案准确率有显著影响？
2. 接地指令（如“仅使用提供的事实回答”）在有无上下文时如何影响模型表现，以及如何避免因提示词不一致导致的实验伪影？

### 4. 背景与问题设定

GraphRAG流水线需要决定将哪些三元组放入提示、如何序列化、如何排序以及如何指示模型使用它们。先前研究对这些设计选择的影响缺乏系统比较，且存在实验设计缺陷（如提示词不一致）导致误导性结论。本研究通过控制变量法，在六个LLM和两个KGQA基准上评估这四个选择，以确定哪些对答案准确率有实际影响。

### 5. 方法概览

- 任务 / 环境: 知识图谱问答任务，使用125个来自LC-QuAD 2.0（1-2跳）和QALD（3-4跳）的Wikidata问题，每个问题有金标准SPARQL查询和50个三元组的Oracle子图（包含答案路径和干扰项）。
- 变量 / 干预设计: 正交实验设计，分别改变检索精确率（用无关实体三元组替换非链三元组）、接地指令（严格 vs 宽松提示）、序列化格式（7种）、三元组顺序（5种）和子图大小（0-200三元组），同时保持其他变量固定。
- 评价指标: 答案F1（token级匹配，多答案使用最优二分匹配）和证据忠实度（三元组引用检查）。
- 模型比较: 六个模型：Claude Sonnet 4.6、Haiku 4.5、GPT-5、GPT-5 Mini、Gemini 2.5 Pro、Gemini 2.5 Flash，温度=0。
- 我的理解: 该实验设计非常严谨，通过正交控制变量分离了每个因素的影响，并特别关注了实验伪影（如提示词不一致）。关键创新在于区分了“答案路径”和“干扰项”的不同作用，以及揭示了接地指令在无上下文时的巨大效应实际上是评估伪影。

### 6. 关键发现

- 答案路径是检索质量的关键: 保持50个三元组不变，将非链三元组替换为无关实体三元组（精确率从1.00降至0.51）仅导致F1变化+0.003（p=0.812）；而移除答案路径（链式三元组）导致F1从0.627降至0.231（宽松提示）或0.005（严格提示）。因此，检索预算应优先保证召回率，精确率在测试范围内无价值。
- 接地指令在无上下文时产生巨大伪影: 在无事实的提示中，严格指令（“仅使用提供的事实”）导致F1从0.299降至0.035（下降8.63倍）。但该效应仅出现在无上下文条件下，不代表工作流水线。若上下文臂使用严格指令而基线使用不同指令，会错误地将组合效应归因于图上下文（作者因此撤回了一个早期结果）。
- 序列化格式、三元组顺序和子图大小无显著影响: 在多跳推理中，七种序列化格式的F1差异从1跳的0.234降至3跳的0.036；五种三元组顺序的F1变化仅+0.006；子图大小从仅链式到200个三元组无显著差异。这些因素仅在1跳解析时略有影响，且与谓词标签可读性混淆。
- 错误子图对参数知识的抑制效应被高估: 将正确子图替换为无关子图使F1从0.627降至0.231，但相对于无上下文基线，实际抑制效应仅为-0.068 F1，且6个模型中有2个无抑制。剩余性能来自模型参数知识，而图模型无此储备。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Agent系统若使用GraphRAG，应优先保证检索召回率（确保答案路径存在），而非追求精确率；同时需注意接地指令的设计，避免因提示词不一致导致评估偏差。
- 对 Skill: 技能设计应关注如何高效获取答案路径，而非优化序列化格式或三元组顺序；多跳推理中这些因素无影响，可简化实现。
- 对 Memory: 记忆系统存储子图时，应确保答案路径的完整性；无关上下文对性能影响有限，但错误子图可能抑制参数知识，需谨慎处理。
- 对评测: 评估GraphRAG时，必须保持提示词一致（匹配提示），否则会引入伪影；接地指令的效应在无上下文时巨大，但不应归因于图上下文。

### 11. 局限性

- 子图来自金标准SPARQL，而非真实检索器，因此精确率实验反映的是上下文构建属性而非系统设置。
- 深度与基准完全混淆（LC-QuAD vs QALD），深度分层结果无法区分深度效应与数据集差异。
- 序列化格式与谓词标签可读性混淆，无法分离语法和命名的影响。
- 严格与宽松提示的对比因响应格式不同而无法用格式敏感评分器测量，报告为开放对比而非数值。

### 12. 我的看法 / 个人笔记

该研究通过严谨的实验设计揭示了GraphRAG中常被忽视的细节：答案路径的保留是性能的关键，而许多常见优化（如提高精确率、调整格式）对多跳推理无效。特别重要的是，它指出了实验伪影的普遍性——接地指令在无上下文时的巨大效应常被误归因于图上下文，这提醒我们在评估RAG系统时必须谨慎控制提示词一致性。实际应用中，应优先保证检索召回率，并避免在无上下文时使用严格指令。

## 4. Show-Harness: Just a VLM Agent Can Play Robots

**Topics:** 机器人操控, 视觉语言模型, 具身智能
**Authors:** Yanzhe Chen, Zechen Bai, Zhijun Cao, Wenzheng Zeng, Kevin Qinghong Lin, Yiqi Lin, Guoqiang Liang, Kevin Yuchen Ma, Qiming Huang, Mike Zheng Shou
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.10522v1) | [PDF](http://arxiv.org/pdf/2609.10522v1.pdf) | [Code](https://showlab.github.io/Show-Harness)

### 1. 一句话结论

Show-Harness通过离散语义动作接口，使VLM无需微调即可零样本操控机器人，或通过少量微调实现低成本部署。

### 2. 为什么重要

该工作提出了一种模型无关的具身操控框架，将VLM的语义理解直接转化为精细的物理动作，无需昂贵的预训练或专用遥操作硬件，为机器人操控的泛化性和可扩展性提供了新路径。

### 3. 研究问题

1. 如何设计一个语义上有意义且足够精细的动作接口，使VLM能直接进行物理控制？
2. 该接口能否同时支持闭源前沿VLM的零样本操控和开源小模型的低成本微调部署？

### 4. 背景与问题设定

现有VLM虽具备丰富的世界知识，但将其转化为机器人控制仍面临挑战：VLA模型将语义压缩为连续动作，需大量数据适配；层次化系统则通过中间抽象削弱了语义与物理的直接联系。Show-Harness旨在通过紧凑的语义动作接口弥合这一鸿沟。

### 5. 方法概览

- 任务 / 环境: 多种机器人平台（如Franka、AgileX）及仿真环境，涵盖桌面操作、折叠衣物、切蛋糕等多样化任务。
- 变量 / 干预设计: 提出离散语义动作单元（如MV_FWD、GRASP等），通过具身解释器确定性地映射为机器人运动；并设计GUMI图形界面，支持人类、智能体及人机协作收集演示数据。
- 评价指标: 任务成功率、跨任务/跨平台/跨环境泛化能力、零样本性能、微调效率（GPU小时数）。
- 模型比较: 与代表性智能体框架（如SayCan、RT-2）及VLA范式（如Octo、OpenVLA）对比，Show-Harness在泛化性和效率上均更优。
- 我的理解: Show-Harness的核心创新在于将机器人控制抽象为VLM可自然推理的离散语义动作，同时通过确定性解释器保持物理精度，从而在语义与物理之间建立直接、透明的桥梁。

### 6. 关键发现

- 零样本操控能力: 闭源前沿VLM（如GPT-4V）通过Show-Harness可直接零样本操控机器人，在多种任务和平台上优于代表性智能体框架。
- 轻量级微调高效部署: 2B规模的开源VLM仅需数GPU小时微调即可在相同动作空间内操控机器人，泛化性和仿真到现实迁移能力优于VLA范式。
- 跨任务、跨平台、跨环境泛化: Show-Harness装备的VLM智能体在多种任务、机器人平台和环境中均表现出鲁棒的泛化能力。

## 5. Multi-Agent Reinforcement Learning for Autonomous UAV Exploration in Wildfire Response

**Topics:** Multi-Agent Reinforcement Learning, UAV Navigation, Wildfire Monitoring
**Authors:** Caden Chandra, Jerry Ng
**Venue / Year:** arXiv:2609.10433v1, September 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.10433v1) | [PDF](http://arxiv.org/pdf/2609.10433v1.pdf)

### 1. 一句话结论

多智能体深度强化学习框架使无人机在模拟野火环境中学会稳定追踪火线并自适应调整位置，平均距离从7.5降至1.0单位，成功率稳定在100%，演员损失从10⁻¹降至10⁻⁴。

### 2. 为什么重要

野火响应中传统方法（如MPC）计算成本高且难以适应动态火势，而该工作展示了DRL在实时自适应监控中的潜力，为自主应急系统提供了可扩展的解决方案。

### 3. 研究问题

1. 奖励塑形和环境复杂性如何共同影响多智能体UAV的收敛行为和自适应导航性能？
2. 不同火势场景下，各奖励组件对策略稳定性和探索效率的相对贡献是什么？

### 4. 背景与问题设定

2025年洛杉矶野火暴露了传统响应中的通信中断、资源限制和人力疲劳问题。现有UAV依赖人工操作，可扩展性差；MPC需为每个火场景重新求解，实时性不足。因此，需要一种能适应动态火势、平衡安全与探索的自主导航方法。

### 5. 方法概览

- 任务 / 环境: 3D仿真空间（20×10×10单位），包含6种火场景（静态火、扩散火、火线、随机火、火墙+随机坠毁、中心大火）。无人机为半径0.25单位的球体，火为高10单位的圆柱体。
- 变量 / 干预设计: 多智能体actor-critic架构，使用TD3和APE2生成候选动作；课程学习逐步缩小安全裕度（5级）；奖励包含接近度、探索、能量、边缘、移动、发现等10个组件，经Welford在线归一化后加权求和。
- 评价指标: 演员损失、评论家损失、回合长度、成功率、平均奖励、平均距离、火检测数、访问网格数。
- 模型比较: 通过消融研究比较11种奖励配置（基线及逐一移除各组件）在6种场景下的性能，但所有结果基于单一训练运行（n=1）。
- 我的理解: 该方法通过多组件奖励和课程学习引导无人机从边界徘徊逐步过渡到火线跟踪，消融实验揭示了不同场景下关键奖励组件的差异，例如发现奖励在静态火中降低火检测但增加覆盖。

### 6. 关键发现

- 训练收敛与性能提升: 演员损失从10⁻¹降至10⁻⁴，评论家损失稳定在6×10⁻²；平均奖励升至约250,000；成功率在400集后稳定在100%；平均距离从7.5降至1.0单位。
- 自适应导航行为涌现: 无人机学会火线跟踪和自适应重定位，轨迹从早期短促不规则变为后期长弧线绕火巡逻，课程学习减少了早期碰撞。
- 奖励组件贡献因场景而异: 基线在多数场景中火检测数最高（如场景2约1.8火/集）；探索奖励在扩散火中覆盖最广（150格，超过基线60格）；发现奖励在静态火中降低火检测（0.6 vs 基线1.0）但增加覆盖（200格）；边缘惩罚在随机火中覆盖最大（150格 vs 基线110格）。

- 对 Memory: 经验回放和在线归一化对稳定训练至关重要，但未显式建模长期记忆；未来可引入记忆增强策略处理部分可观测性，如火势历史。
- 对评测: 消融研究是理解组件贡献的关键，但需注意单一训练运行（n=1）的统计可靠性；建议多次运行报告置信区间，并与其他基线方法（如MPC）定量比较。

### 11. 局限性

- 所有结果基于单一训练运行（n=1），缺乏统计可靠性，无法评估策略的变异性。
- 仿真环境简化了火势传播和无人机动力学，未考虑真实传感器噪声、通信延迟和风场影响。
- 未与基线方法（如MPC、人工驾驶）进行定量比较，仅通过消融评估自身组件，无法判断绝对性能优势。

### 12. 我的看法 / 个人笔记

该工作系统性地探索了奖励设计对多智能体UAV导航的影响，消融实验提供了有价值的见解，但单一运行和简化环境限制了结论的泛化性。未来应增加多次运行、引入真实传感器模型，并与其他方法对比，以验证DRL在实际部署中的优势。
