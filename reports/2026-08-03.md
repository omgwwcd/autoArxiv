## 1. SeekBrain: An Autonomous Multi-Agent System for Accelerating Neuroscience Discovery

**Topics:** Multi-Agent System, Neuroscience, LLM Agent, Automated Data Analysis
**Authors:** Jiamin Wu, Peishan Xiang, Jingyang Chen, Yuqing Zhu, Yuxi Li, Ling Luo, Qihao Zheng, Jialiang Zu, Yongchao Wu, Mindong Liu, Haitao Wu, Chaofan Hu, Yijie Sun, Yuqi Hang, Yu Zhu, Shuo Li, Yue Fan, Shiyang Feng, Wanghan Xu, Tianlei Zhang, Jie Zhang, Wenlong Zhang, Bo Zhang, Kai Wang, Lei Bai, Mianxin Liu, Wanli Ouyang, Jiulin Du, Chunfeng Song
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.29347v1) | [PDF](http://arxiv.org/pdf/2607.29347v1.pdf) | [Code](https://github.com/AI4NeuroLab/SeekBrain)

### 1. 一句话结论

SeekBrain 是一个自主多智能体框架，通过神经科学分析配方库和双引擎架构，在 BrainArena 基准上平均得分 75.8，分别比 Claude Code 和 Codex 高 11.7% 和 17.7%。

### 2. 为什么重要

神经科学数据分析高度异构且工作流碎片化，SeekBrain 通过自动从论文-代码对中构建分析配方库，并结合分层规划与执行引擎，实现了跨模态数据的高效分析，在真实研究中揭示了斑马鱼和小鼠的神经表征规律，有望加速数据驱动的科学发现。

### 3. 研究问题

1. 如何构建一个能够自动处理多尺度、多模态神经科学数据的智能体系统？
2. SeekBrain 在真实研究场景中能否揭示新的神经表征规律？

### 4. 背景与问题设定

现代神经科学依赖整合多尺度、多模态数据集来揭示神经原理，但数据高度异质和工作流碎片化严重制约了发现。现有 LLM 智能体在生物信息学等领域取得进展，但难以直接迁移到神经科学，因为神经科学缺乏统一的数据表示和标准化流程，领域知识分散在论文和代码中。

### 5. 方法概览

- 任务 / 环境: 神经科学数据分析任务，涵盖行为、神经活动、结构、分子等多种模态，涉及小鼠、斑马鱼、线虫等模式生物。BrainArena 基准包含 32 个专家标注任务，其中 59% 为双模态任务，行为与神经活动组合占 53%。
- 变量 / 干预设计: SeekBrain 包含两个核心引擎：研究规划引擎（通过 Orchestrator 和 Reviewer 辩论生成树状研究计划）和分析执行引擎（Formulation、Code、Validation、Interpretation 四阶段循环）。系统维护一个神经科学分析配方库，初始包含 68 个配方，从论文-代码对中自动提取并支持研究者反馈更新。
- 评价指标: 在 BrainArena 基准上使用专家标注的评分标准，总分 100 分，评估方法正确性、图形保真度和解释有效性三个维度，包含超过 700 个扣分细项。
- 模型比较: 与 Claude Code（Claude Opus 4.7）和 Codex（GPT-5.5）对比，SeekBrain 平均得分 75.8，显著高于 Claude Code 的 64.1 和 Codex 的 58.1（Friedman 检验 P<0.0001，Dunn 事后检验均显著）。在困难任务上优势更大，且在所有 7 种分析类型上均取得最高分。
- 我的理解: SeekBrain 的核心创新在于将分散的领域知识编码为可复用的分析配方，并通过分层规划和执行引擎实现自动化分析。配方库的消融实验（Wilcoxon 符号秩检验 P<0.0001）证实其对性能提升至关重要。研究者反馈机制允许用户注入反馈并蒸馏为新的配方，使系统能够持续进化。

### 6. 关键发现

- SeekBrain 在 BrainArena 上全面超越基线: 在 32 个专家标注任务上，SeekBrain 平均得分 75.8，比 Claude Code 高 11.7 分，比 Codex 高 17.7 分。在全部 7 种分析类型上均取得最高分，其中神经解码和脑网络与解剖映射的提升最大（分别比 Codex 高 28.7 和 28.5 分）。
- 配方库对性能提升至关重要: 消融实验表明，使用神经科学分析配方库后，系统性能显著提升（Wilcoxon 符号秩检验，P<0.0001）。配方库初始包含 68 个配方，覆盖预处理到建模的各个阶段，并支持通过用户交互痕迹持续更新。
- 真实研究场景中的发现能力: 在斑马鱼自由运动数据中，SeekBrain 揭示了行为的低维神经表征和结构化流形几何；在小鼠决策任务中，它发现了跨五个解码器图的共享低秩解码强度轴，且在回归掉速度和速度后，刺激、选择和反馈图仍保留空间变异。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: SeekBrain 展示了将领域知识编码为可复用配方对提升智能体在专业领域性能的重要性，为构建领域专用智能体提供了范式。
- 对 Skill: 系统通过配方库和研究者反馈实现技能的持续积累和泛化，表明智能体可以通过经验学习不断扩展能力边界。
- 对 Memory: 配方库作为长期记忆存储领域知识，而执行过程中的用户交互痕迹可被蒸馏为新的配方，实现记忆的动态更新。
- 对评测: BrainArena 基准提供了多维度、专家标注的评估框架，为神经科学数据分析智能体的标准化评测奠定了基础。

### 11. 局限性

- 当前配方库仅包含 68 个初始配方，覆盖范围有限，可能无法处理所有神经科学分析场景。
- 系统依赖底层 LLM（如 Claude Opus 4.7）的性能，LLM 的幻觉问题可能影响分析结果的可靠性。
- 研究规划引擎在基准测试中被消融，其实际贡献尚未充分验证。

### 12. 我的看法 / 个人笔记

SeekBrain 通过将分散的领域知识系统化为可复用的分析配方，有效解决了神经科学数据分析中的碎片化问题，其分层规划和研究者反馈机制为构建可进化的科学智能体提供了可行路径。未来工作可进一步扩展配方库覆盖范围并增强跨领域迁移能力。

## 2. ExtractBench: A Benchmark for Schema-Guided Enterprise Document Extraction

**Topics:** GUI Agent, Document Extraction, Benchmark
**Authors:** Boyang Zhang, Adrian Lyjak, Eli Stewart, Zhaoqi Li, Simon Suo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.29677v1) | [PDF](http://arxiv.org/pdf/2607.29677v1.pdf) | [Code](https://github.com/run-llama/ExtractBench)

### 1. 一句话结论

ExtractBench 是首个联合评估模式引导文档提取中值准确性、记录完整性、溯源能力和成本的基准，涵盖 370 份企业文档（4869 页），并发现 LlamaExtract Agentic Plus 在值 F1、词级溯源 F1 和页级溯源 F1 上均排名第一，成本仅 8.1 美分/页，远低于编码代理的 27.8 美分/页。

### 2. 为什么重要

企业文档提取工作流日益依赖 AI 代理，但现有基准要么忽略用户自定义模式，要么不评估溯源或成本。ExtractBench 填补了这一空白，提供了覆盖 8 个领域、67 种文档类型、13 个挑战标签的标准化评估框架，有助于推动可靠且经济可行的文档提取系统发展。

### 3. 研究问题

1. 如何构建一个能同时评估值准确性、记录完整性、溯源能力和成本的文档提取基准？
2. 现有前沿模型（商业 VLM、编码代理、专用 API）在模式引导提取任务上的表现与成本权衡如何？

### 4. 背景与问题设定

企业文档提取传统上由人工完成，但 LLM 和自主代理的发展催生了自动化需求。模式引导提取要求代理根据用户定义的 JSON Schema 从文档中提取结构化数据，并提供溯源证据。现有基准（如 SROIE、DocILE）不支持用户自定义模式，而较新的基准（如 Contextual EB、LongArray）仅覆盖部分维度，缺乏对长文档记录完整性、手写/扫描文档、溯源和成本的联合评估。

### 5. 方法概览

- 任务 / 环境: 370 份企业文档（4869 页），涵盖 8 个业务领域（金融 145 份、能源 98 份、政府 49 份、汽车 27 份、供应链 20 份、医疗 15 份、法律 10 份、房地产 6 份）和 67 种文档类型，每份文档带有任务挑战（T1 长列表完整性 154 份、T2 大海捞针 39 份、T3 密集文档 214 份）、感知挑战（P1 旋转/仅图像 38 份、P2 扫描 134 份、P3 手写 55 份）、表格结构（S1 合并表头 35 份、S2 表头不在顶部 42 份、S3 跨页表格 91 份、S4 超大表格 12 份、S5 单元格内表格 30 份）、长度（L1 短 ≤10 页 252 份、L2 中 11-50 页 98 份、L3 长 >50 页 20 份）和领域标签。
- 变量 / 干预设计: 基准包含三种来源的文档，真值构建方法各异：真实文档（通过多模型共识+人工审核，仅争议字段由人裁决，无词级边界框）、合成长列表（程序化生成，值在渲染前已知，词级边界框从渲染读取，经模型池审计）、扫描表单（人工逐字段验证值和边界框，169 份文档，84% 的字段有人工放置的边界框）。每个文档类型共享一个 JSON Schema。
- 评价指标: 值准确性：顺序无关的值 F1；溯源能力：词级 F1 和页级 F1（仅在有边界框的字段上计算）；成本：每页美分（范围 0.2 美分到 34 美分）。
- 模型比较: 评估了 14 个系统，包括商业 VLM（Gemini 3.5 Flash、GPT-4o 等）、开源提取管道、编码代理（Codex GPT-5.5）和专用 API（LlamaExtract Agentic Plus）。
- 我的理解: 该基准通过精心设计的真值构建管道（多模型共识、程序化生成、人工验证）解决了大规模标注的难题，并引入多维度标签支持细粒度分析，使得不同挑战场景下的性能差异可解释。

### 6. 关键发现

- 商业 VLM 在短文档上表现良好，但在长文档上性能急剧下降: Gemini 3.5 Flash 在短文档（≤10 页）上值 F1 为 87.9%，但在长文档（>50 页）上降至 27.9%，主要原因是记录列表截断。GPT-4o 在短文档上值 F1 为 91.2%，长文档降至 45.3%。相比之下，LlamaExtract Agentic Plus 在短文档上值 F1 为 96.6%，长文档为 94.4%，性能一致性显著优于商业 VLM。
- 编码代理准确性高但成本昂贵: Codex GPT-5.5 整体值 F1 为 93.6%，但每页成本 27.8 美分，是 LlamaExtract Agentic Plus（8.1 美分/页）的 3 倍以上。编码代理在长文档上表现更稳定（值 F1 91.8%），但成本随文档长度线性增长。
- LlamaExtract Agentic Plus 在准确性与成本间取得最佳平衡: 该专用 API 在值 F1（95.6%）、词级溯源 F1 和页级溯源 F1 上均排名第一，且成本仅为编码代理的约 1/3。在短文档上值 F1 为 96.6%，长文档上为 94.4%，性能一致性显著优于商业 VLM。
- 感知挑战显著影响性能，手写文档是最大难点: 在手写文档（P3）上，所有系统的平均值 F1 下降约 15-20 个百分点。例如，LlamaExtract Agentic Plus 在扫描文档（P2）上值 F1 为 94.2%，在手写文档上降至 82.1%。商业 VLM 在手写文档上表现更差，Gemini 3.5 Flash 仅 61.3%。
- 13 个挑战标签揭示系统在不同场景下的差异化表现: 长列表完整性（T1）是最大挑战，所有系统在 T1 文档上的平均值 F1 比非 T1 文档低 12 个百分点。密集文档（T3）中，系统常犯过度提取错误（将空白字段填充为值）。表格结构标签中，跨页表格（S3）和超大表格（S4）导致记录丢失或结构错乱。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 代理系统在处理长文档时需特别注意记录完整性，避免截断；同时应提供词级溯源证据以支持人工审核。手写和扫描文档需要专门的预处理或增强模型。
- 对 Skill: 模式引导提取技能需兼顾值准确性、记录完整性和溯源能力，且需在不同文档长度和挑战场景下保持稳健。密集文档中需避免过度提取空白字段。
- 对 Memory: 长文档提取对代理的上下文窗口和记忆机制提出挑战，可能需要分页处理或外部记忆来维持长列表的完整性。超大表格（S4）和跨页表格（S3）需要特殊处理策略。
- 对评测: 评估应超越单一聚合分数，采用多维度标签（如任务挑战、感知挑战、长度）进行细粒度分析，并纳入成本指标（范围 0.2-34 美分/页）以反映实际部署可行性。

### 11. 局限性

- 基准文档数量（370 份）相对有限，可能无法完全代表企业文档的多样性，尤其是长文档（>50 页）仅 20 份。
- 合成长列表虽保证了真值准确性，但其布局与真实文档的差异可能影响泛化性，且仅覆盖 T1 挑战。
- 人工验证仅覆盖扫描表单（169 份），其他文档的真值依赖模型共识，可能存在系统性偏差；真实文档无词级边界框，因此溯源评估仅适用于扫描表单和合成长列表。
- 成本指标仅考虑 API 调用费用，未包含延迟、人工审核成本或基础设施开销。

### 12. 我的看法 / 个人笔记

ExtractBench 是文档提取评估领域的重要进步，其多维度标签和成本-质量权衡分析为企业选择提取系统提供了实用指导。未来工作可扩展文档规模和领域，增加更多真实手写文档，并探索更高效的溯源评估方法。

## 4. AMTFV: Agentic Mathematical Tool-Flow Verification for LLM Self-Correction

**Topics:** LLM数学推理, 自校正, 工具增强推理, 智能体系统
**Authors:** Rui Zou, Yutao Zhu, Mengqi Wei, Ji-Rong Wen
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.29549v1) | [PDF](http://arxiv.org/pdf/2607.29549v1.pdf) | [Code](https://github.com/TicusFFF/mathematical-self-correction/tree/main/S2-1_AMTFV)

### 1. 一句话结论

AMTFV通过数学工具流（MTF）接口将验证建模与底层执行解耦，在多个数学推理数据集上显著提升了LLM的自校正准确性。

### 2. 为什么重要

该工作解决了LLM数学验证中自然语言反思缺乏精确计算、代码验证过早耦合建模与实现的核心矛盾，为构建可靠数学推理系统提供了新范式。

### 3. 研究问题

1. 如何设计一个接口，使LLM在数学验证中能够专注于高层建模而避免过早陷入底层代码实现？
2. 与自然语言反思和直接代码验证相比，基于MTF的验证框架能否更有效地提升LLM的最终答案准确性？

### 4. 背景与问题设定

LLM在数学推理中虽表现强劲，但其答案常因计算错误、符号推导缺陷、约束遗漏等不可靠。现有后向验证方法主要分为两类：自然语言反思（缺乏精确计算支持）和直接代码验证（过早耦合数学建模与实现细节，导致错误难以定位且依赖模型代码生成能力）。AMTFV旨在通过引入中间接口MTF，分离验证建模与具体执行，实现更可靠的验证与自校正。

### 5. 方法概览

- 任务 / 环境: 五个高难度数学推理数据集（AIME 2024/2025、BRUMO 2025、HMMT February 2025、AMO Bench），共170个问题；使用DeepSeek、GPT、Gemini系列共7种模型配置。
- 变量 / 干预设计: AMTFV包含三个智能体：验证智能体（A_ver）、答案修正智能体（A_ans）和工作流修正智能体（A_flow）。核心是MTF接口，采用中断-执行-恢复模式：LLM发出计算请求后暂停，等待数学工具箱智能体（A_tool）解析请求、生成可执行调用并返回结果，然后LLM基于结果继续推理。
- 评价指标: 最终答案准确性（final-answer accuracy），按数据集大小加权平均。
- 模型比较: 与自然语言校正（reflex、Self-Refine、Self-Reflection、CheckList）、推理增强（CoT-Tool）和验证增强（ProgCo、ProgCo-Py）方法对比。
- 我的理解: AMTFV的核心创新在于MTF接口，它像是一个“数学计算抽象层”，让LLM只需描述“要算什么”（数学对象和计算意图），而无需关心“怎么算”（具体代码）。这类似于高级语言与汇编的分离，提高了验证的可靠性和可维护性。

### 6. 关键发现

- AMTFV在多个模型上取得最高平均准确率: 在DeepSeek-Flash、DeepSeek-Flash-Think和DeepSeek-Pro三种设置下，AMTFV的平均准确率均高于所有对比方法。在DeepSeek-Flash上，从初始44.1%提升至61.2%，提升17.1个百分点；在DeepSeek-Pro上从38.8%提升至57.1%，提升18.3个百分点。
- AMTFV在中高验证复杂度样本上增益更大: 进一步分析表明，AMTFV在中等和高验证复杂度的样本上相比最强基线（ProgCo-Py）提升更显著，说明其解耦设计在处理复杂验证任务时优势更突出。
- MTF接口减少了局部检查通过但最终答案错误的情况: AMTFV通过MTF使验证目标显式化（如符号化简、全局最优、约束可满足性），避免了仅检查局部一致性的问题，从而更可靠地识别错误答案。

  与当前论文关系：AMTFV与之对比，证明了在数学任务上引入精确工具计算优于纯语言反思。
- ToRA: Integrating Natural Language Reasoning with Tool Calls for Mathematical Problem Solving
  为什么重要：ToRA是工具增强数学推理的经典工作，展示了将推理与工具调用结合的有效性。
  核心贡献：在数学问题求解中交错自然语言推理与工具调用。
  与当前论文关系：AMTFV借鉴了工具增强思路，但聚焦于验证阶段，并通过MTF实现更结构化的工具交互。

### 14. 总结

AMTFV提出数学工具流（MTF）作为中间接口，将LLM数学验证中的高层建模与底层执行解耦，通过验证智能体、答案修正智能体和工作流修正智能体的协作，在五个高难度数据集上显著优于自然语言反思和直接代码验证方法，最高提升8.3个百分点，尤其在中高验证复杂度样本上增益明显。

## 5. Beyond Component Testing: Validating Agentic AI Systems

**Topics:** GUI Agent, Agentic AI, Validation, Software Engineering, Runtime Monitoring
**Authors:** Fabio Orazio Mirto, Luca D'Agati, Giuseppe Tricomi, Stefano Silvestri, Francesco Longo, Antonio Puliafito, Giovanni Merlino
**Venue / Year:** arXiv preprint, 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.29405v1) | [PDF](http://arxiv.org/pdf/2607.29405v1.pdf)

### 1. 一句话结论

Agentic AI系统的验证必须从组件测试转向轨迹级、上下文相关的验证，并建立覆盖行为、安全、时间、监管和多智能体五个维度的生命周期证据框架。

### 2. 为什么重要

该综述系统性地识别了现有验证方法在时间有效性、运行时证据维护、监管可读性和开放多智能体系统保障方面的结构性缺口，为安全关键领域（如医疗、工业、智能交通）的Agent部署提供了可操作的研究路线图。

### 3. 研究问题

1. 哪些经典软件测试假设在Agentic系统中失效？
2. 一个全面的验证框架必须覆盖哪些维度？
3. 现有方法如何分布在这些维度上？
4. 从剩余缺口出发，应优先推进哪些研究方向？

### 4. 背景与问题设定

Agentic AI系统通过多步轨迹（规划、工具使用、记忆、交互、适应）追求目标，其行为依赖于时间展开和环境变化，超出了传统组件测试和单次输入-输出评估的能力。现有软件工程测试方法（单元测试、集成测试、规范验证）基于确定性、可分解性、明确规范、稳定环境和部署前正确性假设，而Agent系统在这些方面均存在根本性不匹配。

### 5. 方法概览

- 任务 / 环境: 综述基于PRISMA方法筛选257篇论文，覆盖2019-2026年文献，包括经典软件工程测试、Agent框架评估、信息物理系统验证、运行时保障和监管指南五个领域。
- 变量 / 干预设计: 提出五维度分类法（行为、安全、时间、监管、多智能体），对每篇论文编码主维度、方法族和领域背景，并通过Cohen's κ=0.759的独立评审验证分类可靠性。
- 评价指标: 通过覆盖矩阵量化各方法族与验证维度的配对成熟度，并采用对抗敏感性分析验证方向性结论的稳健性。
- 模型比较: 与现有Agent综述（如Yehudai 2025, Luo 2025）对比，指出它们在时间有效性和监管可读性维度上的缺失。
- 我的理解: 该方法论的核心创新在于将时间有效性和监管可读性提升为独立的一级维度，而非作为能力评估的附属注释，从而暴露了现有文献的结构性盲区。

### 6. 关键发现

- 行为评估相对成熟，但时间、监管和多智能体维度严重不足: 在257篇论文中，行为维度占27.6%（71篇），时间维度24.1%（62篇），多智能体19.5%（50篇），安全16.3%（42篇），监管12.5%（32篇）。行为评估方法（如基准测试、轨迹一致性检查）较为丰富，而时间有效性（如概念漂移、证据新鲜度）、监管可读性（如保证案例、上市后监督）和开放多智能体系统保障仍处于早期阶段。
- 经典测试假设的五种不匹配: 确定性不匹配：随机推理导致相同初始状态产生不同轨迹；分解不匹配：正确组件组合可能因编排失败；规范不匹配：目标如“有帮助地行动”难以形式化为输入-输出属性；环境不匹配：动态环境无法被稳定测试夹具捕获；时间不匹配：行为在部署后可能因记忆、更新而漂移。
- 跨领域案例验证了五维度分类法的实用性: 在医疗、工业运营和智能交通三个安全关键领域，五维度分类法能够系统性地映射失败模式，并揭示现有验证方法在时间有效性和监管可读性上的共同缺口。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: Agent系统需要内置可验证性设计，包括轨迹日志、决策可追溯性和运行时监控接口。
- 对 Skill: 技能验证应从单次调用正确性转向轨迹级行为一致性，并考虑技能组合的涌现效应。
- 对 Memory: 记忆系统需要验证其长期一致性、漂移鲁棒性和对决策轨迹的影响。
- 对评测: 评估必须从静态基准转向动态、对抗性轨迹生成，并建立证据新鲜度维护机制。

### 11. 局限性

- IEEE Xplore占单源记录的64%，可能存在数据库偏差。
- 分类法依赖单篇论文的主维度分配，可能忽略跨维度贡献。
- 综述未覆盖硬件可靠性或传感器容错等非软件层面。

### 12. 我的看法 / 个人笔记

该综述的价值在于将验证问题从技术细节提升到系统性的生命周期框架，特别是将监管可读性作为独立维度，回应了FDA和MDCG等监管机构的实际需求。其提出的四方向研究议程（有限自主规范、对抗轨迹生成、运行时监控、审计就绪证据）为后续工作提供了清晰路线图。但分类法的粒度较粗，例如时间维度下概念漂移和证据新鲜度可能需要更细分的子维度。

### 13. 这篇工作引用的近期高影响力相关文章

- A Survey on LLM-based Autonomous Agents (Luo et al. 2025)
  为什么重要：系统梳理了Agent架构、能力和基准，是当前Agent综述的代表作。
  核心贡献：按能力维度组织Agent评估，但未将时间有效性和监管可读性作为独立维度。
  与当前论文关系：本文指出其缺失的两个维度，并以此作为分类法创新的动机。
- Agent Evaluation: A Survey (Yehudai et al. 2025)
  为什么重要：专注于Agent评估方法，与本文验证主题直接相关。
  核心贡献：提供了评估方法的分类，但缺乏对生命周期证据和监管要求的系统整合。
  与当前论文关系：本文在其基础上扩展了验证维度，并引入监管和生命周期视角。
- Runtime Assurance for Autonomous Systems (Collaco et al. 2026)
  为什么重要：聚焦运行时保障，是信息物理系统验证领域的关键参考。
  核心贡献：提出了运行时监控和保障框架，但未覆盖Agent特有的轨迹级行为。
  与当前论文关系：本文将其方法纳入五维度分类法中的安全维度，并指出需要扩展到Agent轨迹。

### 14. 总结

该综述通过系统筛选257篇论文，提出Agentic AI系统验证的五维度分类法（行为、安全、时间、监管、多智能体），揭示了行为评估相对成熟而时间有效性、监管可读性和开放多智能体系统保障存在结构性缺口。基于跨领域案例（医疗、工业、智能交通），论文主张验证必须从组件测试转向轨迹级、上下文相关的生命周期证据框架，并提出了有限自主规范、对抗轨迹生成、运行时监控和审计就绪证据四个研究方向。
