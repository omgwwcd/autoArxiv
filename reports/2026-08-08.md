## 1. Benchmarking and Enhancing LLMs for Rule-Intensive Review of National Standard Documents

**Topics:** LLM, Document Review, Benchmark, Multi-Agent System
**Authors:** Tao Wang, Qihao Yang, Rongjiao Liang, Lianghong Lin, Haitao Wang, Xinyu Cao, Tianyong Hao
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.06312v1) | [PDF](http://arxiv.org/pdf/2608.06312v1.pdf)

### 1. 一句话结论

GB/T-Bench 和 GB/T-Reviewer 分别作为首个国家标准文档审查基准和多智能体审查框架，揭示了当前 LLM 在规则密集型文档审查中与人类专家的显著差距，并通过结构化技能协调有效提升了审查性能。

### 2. 为什么重要

该工作填补了 LLM 在规则密集型专业文档审查领域的评估空白，提出了首个系统化的基准和增强框架，为高可靠性文档审查的 AI 应用奠定了基础，对标准化及其他高风险文档领域具有重要参考价值。

### 3. 研究问题

1. 如何系统评估 LLM 在规则密集型国家标准文档审查中的能力？
2. 如何通过多智能体框架提升 LLM 在文档审查中的可靠性和准确性？

### 4. 背景与问题设定

现有 LLM 基准主要关注领域知识和问答，缺乏对专业文档内在质量审查的评估。国家标准文档（如中国 GB/T 标准）具有篇幅长、高度结构化、受明确规则约束的特点，其审查依赖人工专家，成本高且难以规模化。因此，需要建立专门的基准和增强方法。

### 5. 方法概览

- 任务 / 环境: 审查完整的国家标准文档（GB/T），要求 LLM 输出结构化的诊断结果，包括缺陷位置、审查维度、细粒度错误类型和描述。
- 变量 / 干预设计: 提出 GB/T-Bench 基准，包含 GB/T 审查分类法（5 个审查维度：结构、范围、规范性情态、术语、参考文献，细分为 25 个错误类型）、可控反例生成机制（结合确定性规则和受限 LLM 重写，处理 488 篇文档生成 7306 个可追溯错误实例）和面向诊断的评估协议（要求错误位置、审查维度、错误类型精确匹配）。同时提出 GB/T-Reviewer 多智能体框架，包括解析模块（将文档解析为节序列）、专家审查模块（含全局审查器、维度专家代理、错误类型代理和规则扫描器）和预测模块（验证、融合、去重、扩展）。
- 评价指标: 使用 CMCS（综合匹配得分，要求错误位置、审查维度、错误类型三者完全匹配）和 DMTR_k（前 k 个诊断的匹配率，如 DMTR_8、DMTR_9、DMTR_10）等指标。
- 模型比较: 评估了 14 个主流 LLM（包括闭源：GPT-5.6-sol、GPT-5.5、GPT-5.4、GPT-5.4-mini、GPT-5.3、Claude-Opus-4.8、Claude-Fable-5、Gemini-3.5-Flash、Qwen3.7-Plus；开源：DeepSeek-v4-Pro、DeepSeek-v4-Flash、MiniMax-M2.7、Qwen2.5-VL-72B-Instruct、Qwen3-235B-A22B-Instruct-2507），并与人类专家（2 名专家和 3 名研究生）进行对比。
- 我的理解: 该方法通过构建结构化的审查分类法和可控反例生成，解决了审查任务中数据稀缺和评估困难的问题；多智能体框架通过分解审查知识为专门技能并协调协作，提升了 LLM 在复杂规则下的诊断能力。

### 6. 关键发现

- 人类与 LLM 存在显著差距: 最强 LLM（GPT-5.6-sol）的 CMCS 仅为 0.3280，而人类专家达到 0.6640，表明当前 LLM 在规则密集型文档审查中远未达到人类水平。
- GB/T-Reviewer 显著提升审查性能: GB/T-Reviewer 将最佳 CMCS 提升至 0.5094（基于 GPT-5.5），相比直接使用 LLM 提升了 0.1909，验证了结构化技能协调的有效性。
- LLM 在结构性和范围错误上表现较好，在规范性判断和术语一致性上较弱: 模型在检测显式结构和范围错误方面相对有效，但在规范性情态动词判断、术语对齐和跨节一致性验证方面存在明显局限。
- GB/T-Reviewer 在不同维度上提升不均: 在 DMTR_8 指标上，GB/T-Reviewer 将 GPT-5.5 从 0.5410 提升至 0.9026，但在 DMTR_10 上提升较小（从 0.2439 至 0.7860），表明对低排名错误的改善有限。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 多智能体框架通过分解审查知识为专门技能并协调协作，可显著提升 LLM 在复杂规则任务中的表现，为构建高可靠性专业智能体提供了范例。
- 对 Skill: 将领域知识转化为可组合的专门技能（如维度专家、错误类型代理）是提升模型在特定任务上性能的有效策略。
- 对 Memory: 解析模块保留文档层次结构和位置信息，使模型判断可定位到具体节，增强了可解释性和准确性。
- 对评测: 面向诊断的评估协议（要求精确匹配位置、维度、类型）为规则密集型任务提供了更严格的评价标准，有助于发现模型细粒度能力的不足。

### 11. 局限性

- GB/T-Bench 仅覆盖中国国家标准，可能不直接适用于其他国家的标准文档。
- 反例生成机制依赖 LLM 重写，可能引入偏差或遗漏某些错误类型。
- GB/T-Reviewer 的计算开销较大，可能限制其在资源受限场景下的应用。

该工作系统性地解决了 LLM 在规则密集型文档审查中的评估和增强问题，提出的基准和框架具有实用价值。未来可扩展至更多类型的专业文档，并探索更高效的智能体协作机制。

## 2. TRAJDEBUG: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories

**Topics:** GUI Agent, LLM Agent, Error Detection, Debugging, Long-Horizon Trajectory
**Authors:** Yunjia Qi, Zehua Yin, Xintong Shi, Hao Peng, Songyuanyi Lu, Yixian Liu, Richeng Xuan, Yuhong Liu, Zhichao Hu, Xiaozhi Wang, Lei Hou, Bin Xu, Juanzi Li
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.06346v1) | [PDF](http://arxiv.org/pdf/2608.06346v1.pdf) | [Code](https://github.com/THU-KEG/TrajDebug)

### 1. 一句话结论

TRAJDEBUG通过错误生命周期追踪，将长轨迹中的关键错误检测分解为证据驱动的触发检测、状态分类和因果归因，显著提升了定位准确率。

### 2. 为什么重要

长轨迹中错误级联和调试困难是LLM智能体落地的核心瓶颈。TRAJDEBUG不仅提供了可审计的归因方法，还展示了诊断结果可直接用于提升下游任务成功率，为智能体自我改进和鲁棒性分析提供了实用接口。

### 3. 研究问题

1. 如何在长轨迹中准确识别单个错误步骤，尤其是当证据分散在远距离指令、观察和上下文时？
2. 如何从多个共存且下游影响不同的局部错误中，区分出对最终失败负责的关键错误？

### 4. 背景与问题设定

LLM智能体在复杂任务中常产生数百步的轨迹，最终失败可能源于早期错误并级联传播。现有方法要么依赖整体判断（易受多错误干扰），要么建模因果依赖（但无法处理后续修复对错误影响的改变）。关键错误检测旨在定位最早且因果导致失败的错误步骤，但面临长上下文证据分散和多错误动态演化的双重挑战。

### 5. 方法概览

- 任务 / 环境: 多领域智能体基准，包括工具使用（τ²-Bench）、软件工程（SWE-Bench Pro）、网页导航（WebShop）、具身任务（ALFWorld）等，轨迹长度从8.72到119.7步不等。
- 变量 / 干预设计: TRAJDEBUG框架包含三个阶段：1) 错误触发检测：基于多粒度历史压缩，逐步骤提取与指令、历史、环境或自身推理冲突的原子错误触发；2) 错误状态分类：将相关触发聚合成实例，判断其是否已解决及是否留下终端足迹（不可逆状态变化、语义残留或预算债务），筛选出终端相关候选；3) 候选集引导的因果归因：LLM基于候选实例的首步、状态标签和证据选择关键错误。
- 评价指标: 精确关键步骤准确率（exact critical-step accuracy），即预测步骤与人工标注完全匹配的比例。
- 模型比较: 与7种直接提示的先进LLM（GLM-5.1、Gemini-3.1-Pro等）以及3种多智能体诊断系统（AgentDebugger、CHIEF、AgentRX）对比，在5个基准（AgentDebugBench、WhoAndWhen、TRAJERRBENCH）上评估。
- 我的理解: 该方法的核心创新在于将端到端的关键错误判断分解为三个可审计的子任务：先通过证据约束找到所有可能的错误，再通过生命周期状态过滤掉已修复或无害的错误，最后仅对少量候选进行因果归因。这种分解降低了长上下文和错误级联带来的模糊性。

### 6. 关键发现

- TRAJDEBUG在多个基准上取得最佳整体性能: 在AgentDebugBench、WhoAndWhen和TRAJERRBENCH上，TRAJDEBUG的平均准确率（34.98%）显著优于最佳直接提示模型Claude Opus 4.6（29.40%）和最佳多智能体系统AgentDebugger（23.72%）。
- 长轨迹下鲁棒性更强: 长度分析显示，随着轨迹长度增加，直接提示模型的准确率急剧下降，而TRAJDEBUG的下降幅度更小，表明其多粒度压缩和分阶段处理有效缓解了长上下文负担。
- 诊断结果可提升下游任务成功率: 将诊断转化为针对性指导后，重新执行相同任务的成功率平均提升10.80%；将历史失败诊断聚合为可复用记忆并迁移到新任务，成功率平均提升5.70%。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: TRAJDEBUG可作为智能体系统的内置调试模块，在失败后自动定位关键错误，为自我修复或人类干预提供精确指导。
- 对 Skill: 诊断结果可转化为具体技能改进建议，例如避免违反特定约束或改进信息收集策略。
- 对 Memory: 历史失败诊断可聚合为结构化失败记忆，在新任务中主动避免类似错误，实现经验迁移。
- 对评测: 关键错误检测准确率可作为智能体鲁棒性的新评估维度，补充传统任务成功率。

### 11. 局限性

- 依赖LLM进行多阶段推理，计算开销较大，可能不适合实时调试场景。
- 错误状态分类中的预算债务阈值（k=50%）是启发式设定，可能不适用于所有任务。
- 当前仅支持单步关键错误定位，未处理多个关键错误共同导致失败的情况。

### 12. 我的看法 / 个人笔记

TRAJDEBUG通过将关键错误检测分解为证据驱动的子任务，优雅地解决了长轨迹中错误级联和多错误共存的难题。其最大亮点是诊断结果可直接用于提升下游任务性能，证明了可解释诊断的实用价值。未来工作可探索更高效的实现方式（如专用小模型替代LLM）和扩展到多关键错误场景。

## 3. Tracing the Heart: An Evidence-Linked Pipeline for Heart-Failure Feature Engineering

**Topics:** EHR Feature Engineering, Heart Failure, Multi-Agent System, Clinical AI
**Authors:** Soorya Ram Shimgekar, Michelle Hu, Dorisa Shehi, Daniel Kang, Roy Ka-Wei Lee, Koustuv Saha, Christian Poellabauer, Christopher Lee, Sajeev Singh, Piyum Zonooz, Navin Kumar, Zeeshan Ahmed, Priyadarshini Kachroo
**Venue / Year:** ML4H 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.06366v1) | [PDF](http://arxiv.org/pdf/2608.06366v1.pdf)

### 1. 一句话结论

nMAS 自动化心衰特征工程，生成可审计特征，将 HFrEF 表型 AUROC 从 0.895 提升至 0.963。

### 2. 为什么重要

EHR 特征工程占数据科学家 39-45% 工作量，nMAS 首次实现基于指南、可追溯的自动化特征生成，有望大幅降低心血管研究数据准备成本。

### 3. 研究问题

1. 能否构建一个证据可追溯、基于评分规则的自动化心衰特征工程流水线？
2. 自动生成的特征在结构完整性、规则合规性和下游表型预测上是否优于仅清洗的 EHR 变量？

### 4. 背景与问题设定

EHR 特征工程是临床研究和 AI 的主要瓶颈，尤其在心力衰竭（影响 670 万美国成年人）中，需要整合分散的 EHR 数据并应用基于指南的临床推理。现有基于规则和 LLM 的方法仅提供部分自动化，且可维护性和证据可追溯性有限。

### 5. 方法概览

- 任务 / 环境: 500 个模拟心衰患者记录，来自 9 个 EHR 源表（人口统计、诊断、用药、超声心动图等）。
- 变量 / 干预设计: nMAS 多智能体系统：先通过可达性智能体检查数据支持性，再经特征提取和特征工程流水线，生成结构化特征和基于评分规则的复合特征，最后经 LLM 审计。
- 评价指标: 结构完整性、规则合规性、证据可追溯性、独立 LLM 评分（81.5% 最高分）、下游 XGBoost 分类 AUROC。
- 模型比较: 基线为仅清洗的 EHR 变量（无聚合特征），对比添加 nMAS 生成特征后的 XGBoost 模型。
- 我的理解: nMAS 的核心创新在于将临床指南编码为版本化的评分规则，每个特征都链接到源数据和指南文献，并通过受限 LLM 审计确保合理性，从而在自动化和可解释性之间取得平衡。

### 6. 关键发现

- nMAS 生成 202 个特征，结构完整且规则合规: 生成 132 个结构化特征和 70 个基于评分规则的聚合特征，通过自动化验证工具确认结构完整性、规则合规性和证据可追溯性。
- 聚合特征显著提升表型预测性能: 添加聚合特征后，HFrEF 表型 AUROC 从 0.895 提升至 0.963，HFpEF 从 0.870 提升至 0.910。
- 独立 LLM 评估确认特征质量: 基于 LLM 的评分规则评估（证据支持和方法学合理性）得分为最高分的 81.5%。

## 4. Benchmarking the Benchmarks: Evaluating Benchmarks for Conversational Agents

**Topics:** Conversational Agents, Benchmark Evaluation, LLM-as-Judge
**Authors:** Noam Koren, Roy Bar-Haim, Abigail Goldsteen
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.06329v1) | [PDF](http://arxiv.org/pdf/2608.06329v1.pdf)

### 1. 一句话结论

提出无参考框架，利用LLM裁判评估对话代理基准测试的一致性、复杂性和策略覆盖率，并通过合成基准生成和受控扰动实验验证其有效性。

### 2. 为什么重要

对话代理基准测试的质量很少被评估，低质量基准可能导致不可靠的代理评估。该框架提供系统化、可操作的方法诊断基准缺陷，适用于合成和人工构建的基准，填补了策略导向评估的空白。

### 3. 研究问题

1. 如何系统评估对话代理基准测试的质量？
2. LLM裁判能否可靠衡量基准的一致性、复杂性和策略覆盖率？
3. 基准质量差异能否通过生成模型能力和受控扰动有效区分？

### 4. 背景与问题设定

任务导向对话代理通过基准测试评估，但基准质量（如一致性、复杂性、策略覆盖率）很少被审查。合成基准可能包含不一致任务或简单场景，人工基准也存在构造效度问题。现有研究缺乏针对对话代理基准的策略导向评估，尤其是政策违规场景的覆盖。

### 5. 方法概览

- 任务 / 环境: 基于τ-bench的Airline和Retail领域，包含工具、数据库和领域策略，每个任务由描述、期望行为和初始数据库状态组成。
- 变量 / 干预设计: 使用INTELLAGENT生成合成基准，替换不同能力LLM（GPT-5.4、Claude-4.5-Sonnet、Llama-3.3-70B、Llama-3.1-8B、Llama-3.2-1B）作为生成器；另通过交换期望行为（20%-80%任务）或跨域策略交换进行受控扰动。
- 评价指标: 四个指标：描述-期望行为对齐、策略-期望行为对齐（一致性）；策略违规次数（复杂性）；策略违规覆盖率（覆盖率，阈值K=3）。
- 模型比较: 使用GPT-5.4、Claude-4.5-Sonnet、Gemini-2-Flash作为LLM裁判，比较不同裁判下指标区分基准质量的能力，并通过Benchmark Ordering Score量化排序一致性。
- 我的理解: 该方法通过LLM裁判对任务组件（描述、期望行为、策略）进行对齐评分，并统计策略违规情况，从而量化基准质量。指标设计兼顾任务级和基准级，提供可操作诊断。

### 6. 关键发现

- 指标能区分不同质量基准: 在Airline领域所有指标达到完美排序（Benchmark Ordering Score=1.0），Retail领域平均0.92；策略违规次数在所有裁判和领域下均完美排序，表明指标可靠捕捉质量差异。
- 指标对受控质量退化敏感: 期望行为交换导致描述-期望行为对齐分数持续下降（0%-80%扰动）；跨域策略交换使所有策略相关指标显著降低，证明指标对任务一致性和策略匹配敏感。
- LLM裁判与人类评估中等至强相关: Kendall's τb在0.32-0.67之间，所有相关性显著（p<0.05），策略违规次数一致性最强（0.55-0.67），验证了LLM裁判的可靠性。
- 定性分析揭示五种常见基准缺陷: 通过分析低分任务，识别出：1) 幻觉工作流阶段或未支持动作；2) 缺失必要信息收集；3) 缺失操作前明确确认；4) 错误补偿处理；5) 禁止动作。这些类别展示了指标的诊断价值。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 提供基准质量评估工具，帮助选择可靠基准以评估代理能力，避免因低质量基准导致误导性结论。

该工作填补了对话代理基准质量评估的空白，方法实用且验证充分（合成基准、受控扰动、人类评估）。未来可扩展至更多领域和基准类型，探索自动化策略提取和阈值优化。定性分析的五种缺陷类型为基准改进提供了具体方向。

## 5. HarnessOpt-Bench: Evaluating LLMs at Harness Optimization

**Topics:** LLM评估, 智能体系统, 自动化框架优化
**Authors:** Varun Ursekar, Apaar Shanker, Yash Maurya, Shehab Yasser, Vijay S. Kalmath, Veronica Chatrath, Yuan Xue
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.06301v1) | [PDF](http://arxiv.org/pdf/2608.06301v1.pdf)

### 1. 一句话结论

HarnessOpt-Bench通过受控协议证明，在框架优化任务中，优化器模型的选择对性能的影响大于编码框架的选择，且原生框架并无一致优势；干预广度与增益正相关，而详细失败轨迹检查很少使用且与增益无正相关。

### 2. 为什么重要

随着LLM在智能体系统中的部署日益增多，其能力不仅取决于模型权重，还取决于周围的框架（提示、工具、控制流、记忆等）。自动化框架优化是提升AI系统的重要途径，但缺乏统一的评估协议。该基准填补了这一空白，为衡量和开发能够改进AI智能体的系统提供了可复现的评估目标，并揭示了模型选择的关键作用。

### 3. 研究问题

1. 前沿LLM在框架优化任务中能否被有效区分？
2. 优化器模型和其编码框架各自对性能的贡献有多大？
3. 不同任务和种子设置下，框架优化的增益如何变化？

### 4. 背景与问题设定

LLM在智能体系统中的能力受框架（提示、工具、控制流、记忆和编排代码）影响显著。框架优化——在固定预算下迭代改进框架以提升测量结果——是构建强大AI系统的关键部分。然而，现有方法使用各自的目标智能体、种子、预算和评分协议，导致结果混淆了优化器模型、编码框架、目标智能体和协议的影响。需要一个受控的基准来分离这些因素。

### 5. 方法概览

- 任务 / 环境: 四个下游任务：OfficeQA、BrowseComp-Plus、Terminal-Bench和GAIA。每个任务有固定的目标模型、环境和验证器。任务数据分为开发集（20例）、验证集（40例）和测试集（40例），测试集在搜索过程中完全不可访问。GAIA的种子是非功能存根（得分为0），与其他任务的种子性质不同。
- 变量 / 干预设计: 优化器（LLM与编码框架配对）接收目标智能体的种子框架、分级评估反馈（开发集显示详细轨迹，验证集仅显示聚合指标）和固定目标评估预算（最多100次评估调用，4次完整案例通过）。优化器可以编辑框架并提名最终候选，最终候选在保留的测试集上评分。评估环境是可信执行环境，强制执行预算、隔离保留状态并记录每个候选版本。
- 评价指标: 归一化增益：g = (Eθ(H+) - Eθ(H0)) / (1 - Eθ(H0))，表示优化器捕获的相对于种子的改进比例。还定义了任务特定的分辨率带（resolution band），用于判断差异是否显著：OfficeQA ±0.045，BrowseComp-Plus ±0.066，Terminal-Bench ±0.054，GAIA ±0.035。差异小于分辨率带时视为未解决。
- 模型比较: 评估了5个前沿LLM（claude-opus-5、claude-sonnet-5、gpt-5.6-sol、gpt-5.6-terra、kimi-k3），每个模型与共享编码框架（opencode）和各自原生框架（claude-code、codex、kimi-cli）配对，共10个配置，进行了111次评分运行。
- 我的理解: 该基准通过固定目标模型、环境和验证器，并保持测试集不可访问，来隔离优化器模型和编码框架的影响。使用可信执行环境确保预算执行和数据隔离。归一化增益使得不同任务间的性能可比，而分辨率带提供了判断差异是否显著的阈值。GAIA任务因其种子特殊性，增益衡量的是构建工作智能体而非改进现有智能体，因此与其他任务的可比性有限。

### 6. 关键发现

- 模型选择比编码框架选择影响更大: 固定任务和框架时，改变优化器模型平均移动增益0.142；固定任务和模型时，改变框架平均移动增益0.079。模型效应大于框架效应。LSS-λ（任务调整后的模型平均性能）进一步量化了模型间的差异。
- 原生框架并不一致地优于共享框架: 在共享框架和原生框架之间，没有一致的性能优势。例如，claude-opus-5在opencode上表现更好（0.63 vs 0.59），而gpt-5.6-sol在codex上表现更好（0.49 vs 0.29）。
- 干预广度与增益正相关，而详细轨迹检查使用有限: 在OfficeQA、BrowseComp-Plus和Terminal-Bench上，干预广度（探索的预注册杠杆比例）与归一化增益呈强正相关（ρ分别为0.88、0.88、0.65），而GAIA上相关性较弱（ρ=0.34）。详细失败轨迹检查很少被使用，且与增益无正相关。
- 增益在不同任务和种子设置间差异显著: 例如，OfficeQA上最佳增益达0.63，而Terminal-Bench上最高仅0.29。GAIA任务中，种子是非功能存根（得分为0），增益衡量的是构建工作智能体而非改进现有智能体，因此与其他任务的可比性有限。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 框架优化是提升智能体系统性能的关键途径，自动化此过程可以显著减少人工调优工作。
- 对 Skill: 优化器需要诊断失败、实施系统级更改、在有限预算下区分真实改进和噪声，这要求高级推理能力。
- 对 Memory: 框架中的记忆组件（如上下文管理）是优化的重要方面，优化器需要有效管理记忆以提升性能。
- 对评测: 需要受控的评估协议来分离优化器模型、框架和任务的影响，HarnessOpt-Bench提供了这样的协议，包括分辨率带用于判断差异显著性。

### 11. 局限性

- 优化器模型的推理未被限制，结果可能高估了在推理资源受限情况下的性能。
- 仅评估了5个模型和4个任务，可能无法泛化到其他模型和任务。
- GAIA任务的种子是非功能存根（得分为0），与其他任务的种子性质不同，限制了跨任务比较的可靠性。

### 12. 我的看法 / 个人笔记

该基准为框架优化提供了急需的标准化评估，实验设计严谨，结果清晰。模型选择比框架选择更重要的发现具有实际意义，表明提升优化器模型本身比改进编码框架更有效。分辨率带的引入增强了结果解读的严谨性。干预广度与增益正相关的发现提示，优化器应更广泛地探索修改空间。未来工作可以探索更多任务和模型，以及限制推理资源下的性能。

### 14. 总结

HarnessOpt-Bench是一个用于评估LLM在框架优化任务中能力的基准，通过受控协议分离优化器模型和编码框架的影响。实验表明，模型选择对性能影响大于框架选择，原生框架并不一致优于共享框架，干预广度与增益正相关，且增益在不同任务间差异显著。该基准为衡量和开发能够改进AI智能体的系统提供了可复现的评估目标。
