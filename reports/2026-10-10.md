## 1. Can AI Agents Learn Their Way to the Top? Evaluating Heuristic Learning in a Long-Running Game Agent Competition

**Topics:** GUI Agent, Adversarial Games, Heuristic Learning
**Authors:** Kaisen Yang, Qingle Liu, Kejin Wang, Yicheng Zhao, Jieming Li, Shenghan Zheng, Ruize Yang, Bojun Yang, Heng Gong, Xiang Gao, Lanyue Zhang, Kaiyu Zhong, Zhuo Liu, Shaoxuan Li, Chengxi Li, Yong Yan, Weixuan Zhang, Tianwei Luo, Situ Wang, Youjie Zheng, Sihan Zhao, Shengyuan Wang, Huan-ang Gao, Jiazheng Xu, Xiaohui Xie, Wentao Han, Hongning Wang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.12341v1) | [PDF](http://arxiv.org/pdf/2610.12341v1.pdf) | [Code](https://github.com/THU-CST-SAST/AAArena)

### 1. 一句话结论

AI代理通过启发式学习在对抗性游戏中能获得部分金牌，但在复杂规则游戏和长期策略开发上仍面临挑战。

### 2. 为什么重要

该研究提出了一种新的学习范式——对抗性启发式学习（AHL），利用AI代理作为学习引擎，在固定模型权重下通过修改代码策略来提升游戏表现，为AI在复杂对抗环境中的自适应学习提供了新思路。

### 3. 研究问题

1. AI代理能否通过启发式学习在长期运行的对抗性游戏竞赛中达到顶尖水平？
2. 不同的模型和工具配置在AAArena基准上的表现如何？
3. 对手选择和反馈密度如何影响策略改进？
4. 代理能否从自身对局（on-policy）和他人对局（off-policy）的重放中学习？

### 4. 背景与问题设定

对抗性游戏一直是AI研究的试验场，从启发式搜索到强化学习，但有限样本下的学习和适应仍然困难。AI代理能够将游戏经验转化为可执行策略的修订，这为启发式学习提供了可能。本文形式化了对抗性启发式学习（AHL），并构建了包含12个真实对抗性游戏和1920个存档人类程序的基准AAArena，模拟真实游戏竞赛的评估协议。

### 5. 方法概览

- 任务 / 环境: AAArena基准包含12个对抗性游戏，每个游戏有存档的人类程序作为对手，代理需要在固定的比赛和评估预算内，通过选择对手、分析重放、修订代码策略来提升排名。
- 变量 / 干预设计: 评估了7种模型和工具配置，包括Opus5.5与Claude Code的组合，以及其他配置。代理遵循原则：不进行互联网搜索、不阅读对手代码，保持代码可解释和可编辑。
- 评价指标: 主要指标是代理在游戏排行榜上的最终排名，以及获得的奖牌数（金牌表示第一名）。
- 模型比较: 比较了不同模型和工具配置的性能，发现Opus5.5与Claude Code的组合表现最佳，获得6枚金牌，但没有任何配置能在所有游戏中登顶。
- 我的理解: 该方法将AI代理视为学习引擎，通过迭代循环（读取规则、选择对手、分析重放、修改代码）来优化策略，类似于人类玩家通过复盘来提升水平。

### 6. 关键发现

- 最佳配置获得6枚金牌: Opus5.5与Claude Code的组合在12个游戏中获得6个第一名，但其余6个游戏的人类排行榜未被超越。
- 复杂规则游戏表现较弱: 在规则说明更复杂的游戏中，代理的性能普遍较差，表明游戏理解是主要瓶颈。
- 对手选择和密集反馈有助于策略改进: 实验表明，选择适当的对手和提供密集的反馈（如小规模比赛中的详细结果）能显著提升策略改进效果。
- 代理能从自身和他人的重放中学习: 代理既可以从自己比赛的重放（on-policy）中学习，也可以从其他玩家比赛的重放（off-policy）中学习，这扩展了学习数据的来源。

- 对评测: AAArena提供了一个标准化的评估协议，模拟真实竞赛，可用于衡量代理在对抗性环境中的学习能力，促进该领域的可复现研究。

### 11. 局限性

- 代理在规则复杂的游戏中表现不佳，游戏理解能力有待提升。
- 没有任何配置能在所有游戏中登顶，表明通用性不足。
- 评估预算和比赛预算固定，可能限制了代理的探索空间。

本文提出的AHL范式很有前景，通过代码修订实现策略学习，避免了大规模参数更新，但当前代理在复杂游戏中的表现仍有限，未来可结合更强大的推理模型和更有效的对手选择策略来提升。

## 2. Is In-Domain Training Enough for Fine-Grained Industrial Anomaly Understanding?

**Topics:** 多模态大语言模型, 工业异常检测, 多智能体系统
**Authors:** Xingwu Zhang, Duanyang Du, Huiling Zhu, Jiayue Dai, Yixiao Liu, Guozhi Liu, Zhihan Zhang, Zijun Long
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.12310v1) | [PDF](http://arxiv.org/pdf/2610.12310v1.pdf)

### 1. 一句话结论

领域内训练不足以解决细粒度工业异常理解中的感知缺陷，而结合异构MLLM与专用视觉缺陷专家的多智能体框架SiGMA可显著提升性能。

### 2. 为什么重要

该研究挑战了领域内训练是提升工业异常理解关键的传统观点，提出了一种无需训练的多智能体协作方案，为工业质检中MLLM的应用提供了新思路。

### 3. 研究问题

1. 领域内训练是否足以让单个MLLM在细粒度工业异常理解的所有任务上表现优异？
2. 如何通过多智能体协作和外部视觉专家弥补MLLM在细粒度感知上的不足？

### 4. 背景与问题设定

多模态工业异常理解（MM-IAU）要求同时完成缺陷检测、定位、描述和推理，但单个MLLM难以在所有任务上表现优异。现有方法多依赖领域内训练，但训练后的模型在细粒度感知上仍有明显短板。本文基于MMAD基准（39,670个问题）分析，发现训练后的专家模型在缺陷定位上准确率最高仅75.5%，远低于人类专家的92.3%，且检测能力甚至不如未训练的基座模型。

### 5. 方法概览

- 任务 / 环境: MMAD基准，包含七种工业异常理解任务，如异常检测、缺陷分类、缺陷定位、缺陷描述、缺陷分析、物体分类和物体分析。
- 变量 / 干预设计: 提出SiGMA框架，采用搜索-推理-定位-聚合流程：多模态搜索器检索工业知识和正常参考图像；异构MLLM智能体独立回答；视觉缺陷专家通过参考对比生成校准的异常图；可靠性控制器根据任务能力和证据质量加权聚合。
- 评价指标: 各任务上的准确率（%），并与人类专家、大型MLLM、训练方法和优化方法对比。
- 模型比较: 对比了InternVL2-76B、GPT-4o、GPT-5-mini、Gemini-2.5-Flash/Pro等大型MLLM，以及AnomalyGPT、AnomalyR1、OmniAD、JUDO等训练方法，和Reason-IAD优化方法。
- 我的理解: SiGMA的核心在于将感知任务从MLLM中分离，交给专门的视觉缺陷专家，并通过校准和可靠性控制来整合异构智能体的优势，避免了单一模型的瓶颈。

### 6. 关键发现

- 领域内训练不足以解决细粒度感知缺陷: 训练后的专家模型在缺陷定位上最高仅75.5%准确率，远低于人类92.3%，且异常检测能力甚至低于未训练的基座模型。
- SiGMA显著提升性能: SiGMA在MMAD上平均准确率达85.2%，比最强训练专家和Gemini-2.5-Pro高4.0%，接近人类水平（86.7%），且无需训练。具体地，SiGMA在缺陷定位上达到79.6%准确率，比最强训练专家高4.1%。
- 多智能体互补性有限: 不同MLLM在任务上各有优势，但细粒度感知是共同弱点，仅组合模型无法解决。

## 3. From What to Which: Decoding Modifier Grounding in Frozen MLLMs

**Topics:** Multimodal Large Language Models, Visual Grounding, Optimal Transport
**Authors:** Barbara Toniella Corradini, Caterina Gallegati, Ludovica Genovese, Vittorio Murino
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.12305v1) | [PDF](http://arxiv.org/pdf/2610.12305v1.pdf)

### 1. 一句话结论

冻结的MLLM表示中，修饰词（如属性、空间词）也包含可解码的实例级视觉定位信息，可通过轻量级最优传输探针OTTER提取。

### 2. 为什么重要

现有视觉定位方法主要关注名词（what），忽略了修饰词（which）对区分实例的关键作用。该工作首次系统研究修饰词级别的定位，为多实例场景下的细粒度视觉理解提供了新思路，且无需修改模型参数，具有即插即用性。

### 3. 研究问题

1. 冻结的MLLM表示中，修饰词（如属性、空间词）是否包含可解码的实例级视觉定位信息？
2. 这些信息是集中在特定修饰词类型，还是分布在整个上下文化token表示中？
3. 通过最优传输学习的定位映射能否泛化到自由生成和跨数据集场景？

### 4. 背景与问题设定

多模态大语言模型（MLLM）在生成复杂场景描述时，token级视觉定位至关重要。然而，现有方法主要关注名词（what），忽略了修饰词（如“黄色”、“左边”）对区分实例（which）的作用。该工作提出“what-to-which”问题，即从对象级定位转向实例级定位，并探索冻结MLLM表示中是否已包含可解码的修饰词定位信息。

### 5. 方法概览

- 任务 / 环境: 使用RefCOCO数据集进行受控实验，COCO Caption和OpenPSG用于自由生成评估，RefCOCOg用于跨数据集迁移测试。
- 变量 / 干预设计: 设计七个引导问题（Q1-Q7）系统评估：Q1比较完整短语与仅名词的定位效果；Q2按token类型（空间、属性、关系/动作、名词、功能词）分组分析；Q3通过反事实对和扰动测试检验信息分布；Q4对比随机/中心/注意力基线验证映射有效性；Q5通过删除/插入扰动验证区域相关性；Q6测试自由生成泛化；Q7测试跨数据集迁移。
- 评价指标: 使用Pointing、Energy-in-GT、Soft-IoU、阈值IoU、熵等指标评估定位精度，并计算保留率（retention ratio）衡量上下文依赖性。
- 模型比较: 与TAM（Token Activation Maps）和注意力图基线比较，同时设置随机、中心、注意力等基线。
- 我的理解: OTTER通过最优传输将生成的token与视觉patch对齐，学习一个轻量级映射头（约550k参数），在冻结的MLLM表示上训练，无需修改模型。其核心创新在于将定位问题形式化为最优传输问题，并引入dustbin机制处理不可对齐的token或patch。

### 6. 关键发现

- 修饰词包含实例级定位信息: 在RefCOCO上，完整短语的定位效果显著优于仅名词，表明修饰词（如空间词、属性）确实携带了区分实例的视觉信息。
- 空间词定位信号最强: 在RefCOCO-MOD中，空间修饰词的定位精度最高，属性次之，关系/动作词也有一定效果，而功能词几乎无定位能力。
- 信息分布广泛且上下文相关: 通过反事实对和扰动测试，发现实例级信息不仅存在于修饰词，也存在于上下文化的名词表示中，但修饰词对上下文变化的依赖性更强。
- OTTER优于基线且泛化良好: OTTER在受控实验和自由生成中均优于TAM和注意力基线，且跨数据集迁移（RefCOCO到RefCOCOg）保持性能。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 该工作表明，智能体系统可以利用修饰词定位来更精确地理解用户指令中的属性或空间关系，从而提升在复杂场景中的操作准确性。
- 对 Skill: 修饰词定位能力可增强技能学习中的视觉理解，例如机器人抓取时区分“红色杯子”与“蓝色杯子”。
- 对 Memory: 通过定位修饰词，系统可以更有效地存储和检索与特定实例相关的记忆，提升长期交互中的上下文理解。
- 对评测: 该工作提供了新的评估协议（如反事实对、扰动测试），可用于更严格地评估视觉定位方法的实例级区分能力。

### 11. 局限性

- 实验主要基于Qwen2.5-VL，其他MLLM的泛化性未充分验证。
- 训练数据规模较小（2500张图像），可能限制复杂场景下的性能。
- 对关系/动作词的定位效果相对较弱，可能需要更复杂的建模。

### 12. 我的看法 / 个人笔记

该工作创新性地将视觉定位从名词扩展到修饰词，并通过最优传输实现了轻量级、可迁移的定位探针。其受控实验设计严谨，为后续研究提供了新范式。未来可探索更大规模训练、多模态融合以及与其他任务（如视觉问答）的结合。

## 4. Unlocking the Regulatory Genome by ARGUS: An Evidence-Constrained Agentic Framework for Interpreting Single Nucleotide Variants

**Topics:** 基因组学, 智能体, 变异解读
**Authors:** Pratik Dutta, Matthew B. Obusan, Max Chao, Rekha Sathian, Nimisha Papineni, Ramana V. Davuluri
**Venue / Year:** NeurIPS 2026 Workshop: Agentic AI for Biological Discovery
**Links:** [Abstract](http://arxiv.org/abs/2610.12281v1) | [PDF](http://arxiv.org/pdf/2610.12281v1.pdf) | [Code](https://github.com/duttaprat/ARGUS)

### 1. 一句话结论

ARGUS通过将确定性生物计算与LLM推理严格分离，并采用观察驱动的调查循环，实现了对非编码单核苷酸变异的功能解读，避免了LLM的幻觉。

### 2. 为什么重要

超过90%的疾病相关变异位于非编码调控区，其功能解读是基因组医学的核心难题。ARGUS提供了一种可审计、证据约束的智能体框架，能够区分预测与证据，减少LLM幻觉，为精准医学提供可靠工具。

### 3. 研究问题

1. 如何利用智能体框架整合多种证据源，对非编码SNV进行可靠的功能解读？
2. 如何通过确定性计算约束LLM推理，避免幻觉并提高变异解读的可信度？

### 4. 背景与问题设定

全基因组关联研究（GWAS）发现的大多数疾病相关变异位于非编码调控区，但解读其功能影响仍具挑战。现有预测模型（如DNABERT）可预测变异对转录因子结合的影响，但预测不等于证据。LLM在解读时容易产生幻觉，如虚构实验支持或夸大统计信号。例如，早期原型中Qwen模型将rs6983267的SP1结合误报为'gain in binding with log_odds_ratio of 3.02'，而实际两个等位基因的结合概率均低于0.5，无结合事件。因此，需要一种框架，将预测与独立证据整合，并诚实评估不确定性。

### 5. 方法概览

- 任务 / 环境: 针对非编码SNV（如rs6983267）的功能解读，涉及转录因子结合变化的预测与验证。
- 变量 / 干预设计: ARGUS包含预测阶段（DNABERT模型）和调查阶段（智能体循环）。预测阶段对每个TF模型输出结合概率，并分类为LOF/GOF、增强/减弱、保留或无结合，同时标记饱和状态。调查阶段中，规划器选择证据源（ADASTRA、JASPAR、ENCODE cCRE），验证器确定性解释结果，更新假设状态，直至达到终止条件。核心设计原则是“确定性科学，智能体推理”：所有生物学分类由规则代码执行，LLM仅负责选择行动或撰写报告，不能改变证据或结论。验证器对ADASTRA结果实施10分支决策树，例如：显著ASB且与预测方向一致则支持；显著ASB但方向不一致则矛盾；非显著但功效不足则保持活跃；非显著且功效充足则对差异预测矛盾、对非差异预测中性。
- 评价指标: 最终状态（如rescued、abstained）、工具调用次数、与独立模型（AlphaGenome Atlas）的一致性。
- 模型比较: 比较固定优先级规划器与LLM规划器（Claude Sonnet 4.6）在相同证据快照下的决策和工具调用效率。
- 我的理解: ARGUS的核心是“确定性科学，智能体推理”：所有生物学分类由规则代码执行，LLM仅负责选择行动或撰写报告，不能改变证据或结论。这种设计确保了可审计性和可靠性。

### 6. 关键发现

- 同一变异产生不同轨迹: 在rs6983267上，四个转录因子（FOXA1、KLF6、RAD21、SP1）产生不同调查轨迹：FOXA1被ADASTRA数据拯救（FDR=0.030，15个实验，475个reads），KLF6因混合证据弃权（JASPAR Δ=-0.147，cCRE支持），RAD21因无显著结果弃权（FDR=0.65，5个实验，104个reads），SP1因缺乏直接证据弃权。
- LLM规划器更高效: LLM规划器在相同结论下使用更少的工具调用（9次 vs 13次），通过跳过无法解决假设的证据源，提高了效率。
- 与AlphaGenome Atlas一致性: AlphaGenome Atlas的预测与ARGUS的结论部分一致，如FOXA1的显著变化，但该模型被排除在决策之外，因其变异级评分无法提供转录因子特异性方向。

## 5. HarnessSQL: Harness-Native Training for SQL Agents in Realistic Database Environments

**Topics:** Text-to-SQL, SQL Agent, Harness-Native Training, Reinforcement Learning
**Authors:** Haolin Yang, Jipeng Zhang, Jian Xie, Shuaishuai Gong, Sirui Han, Yike Guo
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.12274v1) | [PDF](http://arxiv.org/pdf/2610.12274v1.pdf) | [Code](https://github.com/YangHaolin0526/HarnessSQL)

### 1. 一句话结论

通过在真实执行环境中进行全轨迹SFT和RL训练，HarnessSQL显著提升了紧凑型SQL智能体在复杂数据库任务上的执行准确率。

### 2. 为什么重要

传统Text-to-SQL模型训练与部署存在严重不匹配：训练时只学习静态查询生成，部署时却需要与环境交互。HarnessSQL首次将执行环境融入训练全过程，使模型学会探索、执行、纠错和提交，大幅提升实际数据库场景下的表现，为构建真正可用的数据库智能体提供了新范式。

### 3. 研究问题

1. 如何弥合Text-to-SQL模型训练与部署之间的环境交互不匹配？
2. 在真实执行环境中进行全轨迹训练能否显著提升SQL智能体的执行准确率？
3. Harness-native训练是否能够泛化到未见过的交互基准？

### 4. 背景与问题设定

现有Text-to-SQL模型通常被训练为直接从问题映射到静态SQL查询，而真实数据库智能体需要多轮交互：检查模式、执行试探查询、诊断错误并修正假设。这种训练与部署的差异导致模型在推理时无法有效处理执行反馈。我们提出HARNESSSQL，一种harness-native后训练框架，通过构建可执行数据库环境、设计SQL专用工具接口，并采用全轨迹SFT和RL，使模型学习完整的交互策略。

### 5. 方法概览

- 任务 / 环境: 使用容器化沙箱，包含真实数据库（SQLite），提供只读执行、查询结果和错误反馈，并设置隐藏的执行验证器。
- 变量 / 干预设计: 设计SQL专用harness，提供四个工具：sql_list_tables、sql_schema、sql_exec、sql_submit，并限制其他无关工具。训练分为两个阶段：先由专家教师生成验证过的轨迹进行全轨迹SFT，再使用DAPO算法进行强化学习，奖励基于执行结果和协议合规性。
- 评价指标: 执行准确率（Execution Accuracy），即提交的SQL与隐藏验证器结果一致的比例。
- 模型比较: 对比了通用模型（Qwen2.5-Coder-32B）、SQL专用模型（OmniSQL、Arctic-Text2SQL）以及多智能体系统（MARS-SQL），并报告了模型规模、是否智能体、是否推理、是否harness训练等属性。
- 我的理解: 该方法的核心在于将训练环境与部署环境对齐，让模型在训练时就能接触到真实的执行反馈，从而学会如何探索数据库、处理错误并最终提交正确查询。通过SFT提供基础能力，再通过RL进一步优化探索策略，使得紧凑模型也能达到甚至超越大型模型的效果。

### 6. 关键发现

- Harness-native训练大幅提升执行准确率: 在Spider 2.0-SQLite上，Qwen3-8B从15.5%提升至45.2%，Qwen3-14B从22.2%提升至54.8%，远超32B规模的基线模型。
- 跨域泛化能力强: 在BIRD-Interact Mini和LiveSQLBench Base-Lite上，HarnessSQL模型分别达到9.0%/11.3%和24.8%/28.5%，显著优于现有基线，表明学到的交互策略具有通用性。
- SFT是RL的基础: 直接应用RL仅带来小幅提升（+4.5点），而先进行SFT再RL则能大幅提升（+29.7点），说明全轨迹SFT为模型提供了必要的交互基础。

- 图来源: Figure 1: 从一次性Text-to-SQL到harness交互式数据库智能体的对比图
- 为什么重要: 该图直观展示了传统方法（一次性生成、无环境反馈）与HarnessSQL方法（沙箱+交互工具+执行反馈）的核心差异，强调了训练与部署环境对齐的重要性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 训练智能体时，应尽可能模拟真实部署环境，包括工具接口、反馈机制和约束条件，以减少训练与部署的差距。
- 对 Skill: 智能体需要学习探索、错误恢复和策略调整等技能，而不仅仅是生成最终答案。
- 对 Memory: 在长轨迹交互中，模型需要有效管理上下文，harness中的上下文压缩机制有助于处理长序列。
- 对评测: 评估应基于执行结果而非表面匹配，并考虑协议合规性，以更真实地反映智能体能力。

### 11. 局限性

- 训练数据仅来自Spider 2.0-Lite和DBT，可能无法覆盖所有真实数据库场景。
- 实验仅验证了紧凑模型（8B/14B），更大规模模型的效果未知。
- 跨域基准的绝对准确率仍较低（如BIRD-Interact Mini约10%），说明复杂交互任务仍有很大提升空间。

### 12. 我的看法 / 个人笔记

HarnessSQL通过将训练与部署环境对齐，显著提升了SQL智能体的实际表现，这一思路对于其他工具使用型智能体（如代码生成、网页操作）也有借鉴意义。未来工作可以探索更丰富的工具集、更复杂的任务，以及如何将harness-native训练扩展到更大模型。
