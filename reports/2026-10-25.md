## 1. An Empirical Study of Recent Large Language Models for Knowledge Graph to Text Generation on Standard Benchmarks

**Topics:** 知识图谱到文本生成, 大语言模型评估, 自然语言生成
**Authors:** Priyanka, Renaud Delbru, Souhail Bakkali, Mickaël Coustaty, Antoine Doucet
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.31529v1) | [PDF](http://arxiv.org/pdf/2610.31529v1.pdf)

### 1. 一句话结论

近期大语言模型（如GPT-5-mini、Gemma-4-31B等）在知识图谱到文本生成任务上已大幅缩小与微调模型的差距，但在忠实度上存在不同类型的错误，且参考指标与LLM评判捕捉不同质量维度。

### 2. 为什么重要

该研究在统一评估协议下系统比较了多种最新LLM与微调模型在三个标准基准上的性能，揭示了不同评估指标间的差异，为知识图谱到文本生成领域提供了全面的性能参考和评估方法指导。

### 3. 研究问题

1. 在统一评估协议下，近期大语言模型（GPT-5-mini、Gemma-4-31B、Granite-4.2-30B、Nemotron-3-Ultra）与微调模型（T5-large、T5-Gemma2）在多个数据集上的性能对比如何？
2. 基于参考的指标族与基于图源的LLM评判之间的一致性如何？
3. LLM评判在知识图谱到文本输出上测量了什么，两个不同LLM评判与人类标注的一致性如何？
4. 微调模型和提示模型在错误类型上是否存在差异？

### 4. 背景与问题设定

知识图谱到文本生成是将知识图谱三元组转化为自然语言描述的任务。传统上，微调的编码器-解码器模型是标准方法，但近期大语言模型（LLM）的零样本性能显著提升。然而，现有评估多采用不同指标和协议，难以直接比较。本文旨在统一评估框架下，对比多种最新LLM与微调模型，并分析不同评估指标的相关性及LLM评判的可靠性。

### 5. 方法概览

- 任务 / 环境: 使用三个标准数据集：WebNLG17、WebNLG20（英文子集）和DART，涵盖不同领域和三元组规模。
- 变量 / 干预设计: 比较五类模型：微调的T5-large、LoRA适配的T5-Gemma2、提示的Gemma-4-31B、Granite-4.2-30B、Nemotron-3-Ultra-550B-A55B以及GPT-5-mini。所有提示模型使用少样本设置，并采用余弦相似度检索示例。
- 评价指标: 使用八种基于参考的指标（BLEU、METEOR、ChrF++、ROUGE-L、BLEURT、BERTScore、BARTScore、PARENT）和两种基于图源的LLM评判（BinEval和GPTScore），并针对220个人类标注输出进行验证。
- 模型比较: 在统一评估协议下，比较各模型在三个数据集上的性能，并分析不同指标间的相关性及LLM评判与人类标注的一致性。
- 我的理解: 该研究通过统一评估协议，全面比较了多种模型，并引入LLM评判来评估忠实度、覆盖率和流畅度，揭示了不同评估维度的重要性。

### 6. 关键发现

- LLM缩小了与微调模型的差距: 在WebNLG17上，T5-large的BLEU为58.57，而GPT-5-mini为51.94，Gemma-4-31B为53.74，差距从过去的数十点缩小到几个点；在神经指标（如BLEURT）上达到持平，但微调模型在BLEU、BARTScore和PARENT上仍保持领先。

## 2. Parameter-Efficient Adaptation of Large Language Models to a Low-Resource Agglutinative Language: A Corpus, Datasets, and a Reproducible Benchmark for the Bashkir Language

**Topics:** 低资源语言, 参数高效微调, 文本分类, 大语言模型
**Authors:** Mullosharaf K. Arabov, Svetlana S. Khaybullina
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.31397v1) | [PDF](http://arxiv.org/pdf/2610.31397v1.pdf)

### 1. 一句话结论

QLoRA适配的生成式大模型在巴什基尔语二分类任务上优于编码器模型，且持续预训练效果因模型而异。

### 2. 为什么重要

为巴什基尔语这一低资源黏着语提供了首个开放语料库、数据集和可复现基准，系统比较了多种适配方法，为低资源语言的大模型适配提供了实践指导。

### 3. 研究问题

1. QLoRA适配的生成式模型（3.8-8B）与编码器模型（mBERT、XLM-R）在巴什基尔语文本分类任务上的性能对比如何？
2. 持续预训练（CPT）能否在困惑度和下游任务上带来可测量的提升，且效果是否因基础模型而异？
3. 分词器生育率与适配质量有何关系，能否解释西里尔分词器与BPE分词器之间的性能差距？
4. LLM评委能否复现巴什基尔语母语者的评分，哪些生成质量指标无法自动评估？

### 4. 背景与问题设定

巴什基尔语是低资源黏着语，使用西里尔字母，在现有大语言模型中代表性不足。现有语料库规模小、来源单一，缺乏系统性的适配方法比较。本研究旨在构建开放资源套件，并系统评估多种适配策略，以推动该语言的自然语言处理研究。

### 5. 方法概览

- 任务 / 环境: 文本分类任务（二分类、多分类）和语言建模，使用巴什基尔语网络语料库（71,567篇文档，46.9M tokens）和三个标注数据集（二分类16,994篇、多分类17,897篇、多标签22,318篇）。
- 变量 / 干预设计: 比较三种适配策略：全量微调（编码器模型）、QLoRA（生成式模型）、上下文学习（零样本和少样本）；并评估持续预训练（CPT）的影响。
- 评价指标: 宏F1、困惑度（BPB）、分词器生育率、人工评分（语法、连贯性、语言正确性）及LLM评委评分。
- 模型比较: 八种架构：DistilGPT2、GPT-2 base/medium、Phi-3-mini、Mistral-7B、YandexGPT-5-Lite-8B、mBERT、XLM-R。
- 我的理解: 该研究通过系统对比不同规模、不同类型的模型和适配方法，揭示了在低资源黏着语上，生成式模型结合QLoRA可能优于传统编码器微调，且分词器设计对性能有显著影响。

### 6. 关键发现

- QLoRA适配的生成式模型在二分类上优于编码器模型: YandexGPT-5-Lite-8B（8B）在二分类任务上达到宏F1 0.748，显著高于XLM-R（0.653）和mBERT（0.650），差异经Holm校正后显著（p<0.001）。
- 持续预训练效果因模型而异: CPT对Phi-3-mini和YandexGPT-5-Lite-8B的困惑度有改善（Δ=+0.58和+0.33），但对Mistral-7B反而恶化（Δ=-1.15，p<0.001）；在二分类任务上，CPT对Mistral-7B提升最大（+4.0宏F1）。
- 分词器生育率与适配质量相关: 西里尔分词器（如YandexGPT-5-Lite-8B）生育率较低（2.92），适配质量更高；BPE分词器生育率较高（最高7.80），性能较差。困惑度在不同分词器间不可直接比较。
- LLM评委无法完全替代人工评估: LLM评委在语法和连贯性上与母语者评分相关性较高（rho=0.33-0.46），但在语言正确性上相关性低（rho=0.16，p=0.11），因此人工评估仍不可替代。

## 3. Certified Execution Harness for Agentic AI: Safe and Least-Intrusive Petri-Net Supervisory Control Between Reasoning and Action

**Topics:** LLM Agent, Petri Net, Supervisory Control, Prompt Injection, Safe Tool Execution
**Authors:** Chao Gu, Quanyan Zhu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.31376v1) | [PDF](http://arxiv.org/pdf/2610.31376v1.pdf)

### 1. 一句话结论

本文提出用Petri网对LLM代理的工具执行进行监督控制，通过合成最小侵入监督器，在提示注入下保证安全，并证明传统最大许可监督器在重规划闭环中可能任意更侵入，而更严格的监督器反而更优。

### 2. 为什么重要

该研究为LLM代理的安全工具执行提供了形式化且可证明的保障，不同于依赖提示词或内容过滤的软性防御，它通过状态感知的监督控制，从机制上阻止不合规操作，尤其针对提示注入攻击。这为构建可信赖的自主代理系统提供了新思路。

### 3. 研究问题

1. 如何形式化LLM代理的执行框架，使其在提示注入下仍能保证安全？
2. 在代理可重新提议的闭环中，如何设计监督器以最小化干预（即最少拒绝次数）？

### 4. 背景与问题设定

LLM代理能够调用工具执行操作，但可能受到提示注入攻击，导致执行未授权或不合规的操作。现有防御如提示词策略、内容过滤器、访问控制等，均无法跟踪操作状态（如已消耗的授权或预算），因此无法防止重复使用或越权操作。本文提出将执行框架建模为Petri网，通过监督控制理论合成安全监督器，在运行时决定是否允许每个提议的工具调用。

### 5. 方法概览

- 任务 / 环境: LLM代理与外部环境（工具、人类、其他代理）交互，代理提出工具调用，执行框架决定是否执行。环境可能包含恶意内容（提示注入），代理本身不可信。
- 变量 / 干预设计: 定义代理执行Petri网（AEPN），其中标记表示能力、批准、预算等资源，变迁表示工具调用。执行框架包括接口、验证器、Petri网内核和监督器。提议的工具调用只有在通过四个检查后才执行：解析成功、验证器通过、变迁使能、监督器允许。监督器基于状态反馈，可禁用可控变迁。
- 评价指标: 安全性（不进入禁止状态）、非阻塞性（总能完成）、最少干预性（拒绝次数最少，即最小侵入性）。
- 模型比较: 比较了传统最大许可监督器（MP）与提出的最小侵入监督器（LI）。MP在每一步允许尽可能多的变迁，但可能导致更多拒绝；LI通过考虑代理重新提议的概率，优化长期拒绝次数。
- 我的理解: 该方法将安全约束编码为Petri网的结构，通过监督控制理论合成监督器。关键创新在于引入重规划闭环，即代理在被拒绝后可以重新提议，而每次拒绝都消耗推理成本。因此，监督器的目标不仅是安全，还要最小化预期拒绝次数。

### 6. 关键发现

- 传统最大许可监督器可能任意更侵入: 在重规划闭环中，传统最大许可监督器（MP）虽然允许更多变迁，但可能导致代理反复提议被拒绝的操作，从而增加拒绝次数。文中证明存在场景，MP的干预程度可以任意大于更严格的监督器（如最小侵入监督器）。
- 最小侵入监督器的特征化: 对于给定的提议模型，最小侵入监督器是传统最大许可监督器的值阈值细化：它只拒绝那些从当前状态出发，预期成本超过阈值的变迁。该阈值由提议概率和状态价值决定。
- 安全部署需要可拒绝的步骤: 在自主发布代理的案例中，综合结果表明，安全部署要求监督器在发布开始后仍能拒绝某个步骤（如发布后的验证），否则无法保证安全。

## 4. Automating Feature Flag Cleanup at Scale with Multi-Agent LLM Systems: An Industrial Experience at DoorDash

**Topics:** 软件工程, 多智能体系统, LLM应用, 技术债务管理
**Authors:** Atharv Chandratre, Jai Datar
**Venue / Year:** 2026 IEEE International Conference on Software Maintenance and Evolution (ICSME), Industry Track
**Links:** [Abstract](http://arxiv.org/abs/2610.31351v1) | [PDF](http://arxiv.org/pdf/2610.31351v1.pdf)

### 1. 一句话结论

DoorDash 使用多智能体 LLM 系统自动化清理过期功能开关，在 50 个案例中实现了 90% 的成功率，平均耗时 13.8 分钟，成本 4.79 美元。

### 2. 为什么重要

该工作展示了 LLM 多智能体系统在工业级代码清理任务中的实际应用，解决了传统规则工具无法处理的语义复杂性问题，为大规模技术债务自动化管理提供了可行方案和实证数据。

### 3. 研究问题

1. RQ1: 部署的系统多久能生成工程师可直接合并或稍作修改的 PR？
2. RQ2: 哪些功能开关特征能预测系统能否一次性生成可合并的清理结果？
3. RQ3: 系统在实际运行中的时间和成本特性如何？能否大规模运行？

### 4. 背景与问题设定

功能开关（feature flags）用于渐进式发布和实验，但一旦功能完全上线，开关及其条件代码成为技术债务，并可能带来操作风险。DoorDash 拥有超过 56,000 个动态值（DVs，即功能开关），其中 1,659 个已过期，手动清理每个需 1-2 小时。现有规则工具（如 Piranha）因 DoorDash 的依赖注入包装模式、非布尔开关和跨文件清理需求而无法适用。

### 5. 方法概览

- 任务 / 环境: DoorDash 的 Kotlin 代码库，包含 623 个仓库，使用动态值（DV）作为功能开关抽象，涉及三层访问模式：字符串常量、包装函数和业务逻辑。
- 变量 / 干预设计: 两阶段架构：阶段一由编排代理（Claude Sonnet 4.6）分析过期 DV，查询实验平台（通过 MCP）获取实时状态，生成报告；人工确认目标值后，阶段二为每个 DV 启动专用移除代理（Claude Opus 4.6）在隔离的 git worktree 中并行执行清理，包括代码修改、测试更新、构建验证、覆盖率检查（≥95%）和静态分析。
- 评价指标: 成功指标：PR 是否被接受（直接接受、接受但需修改、失败）；时间（平均/中位数）；成本（平均/中位数 LLM API 费用）；CI 首次通过率。
- 模型比较: 未与其他 LLM 系统直接比较，但与规则工具 Piranha 进行了对比，指出其不适用性；与行业报告（如 Google、Duolingo）相比，本文提供了定量评估。
- 我的理解: 该系统通过将任务分解为分析和执行两个阶段，利用不同模型的能力特点，并通过人工检查点确保安全性，同时使用隔离工作区和确定性验证门控保证并行执行的可靠性。

### 6. 关键发现

- 高成功率: 在 50 个过期 DV 中，62% 一次性成功，28% 需少量修改，10% 失败，总体清理率 90%。
- 复杂性与可靠性边界: 简单 DV 100% 一次性成功；中等复杂度 94% 清理率；复杂 DV 85% 清理率，失败案例主要涉及跨接口参数传递的深层调用链。
- 成本效益显著: 平均每个 DV 清理耗时 13.8 分钟，成本 4.79 美元，相比手动 1-2 小时大幅节省。

## 5. AgenticEvolve: Evolutionary Program Search with Persistent Language Model Agents that Design and Run Experiments

**Topics:** 进化程序搜索, 大语言模型智能体, 自主实验, 启发式设计, 符号回归
**Authors:** Ze-Yu Peng, Qing-Yu Lan, Zhan-He Wang, Jun Zhang, Yun-Song Piao
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.31326v1) | [PDF](http://arxiv.org/pdf/2610.31326v1.pdf) | [Code](https://github.com/pengzy-cosmo/AgenticEvolve)

### 1. 一句话结论

AgenticEvolve 通过让持久化 LLM 智能体在正式评估之间自主设计和运行实验，显著提升了进化程序搜索的质量，且评估次数更少、成本相当。

### 2. 为什么重要

该工作首次系统性地量化了进化程序搜索中智能体自主实验的贡献，展示了将 LLM 从单一变异算子升级为主动实验者的潜力，为未来结合外部工具与进化算法的研究提供了新范式。

### 3. 研究问题

1. 在进化程序搜索中，智能体自主设计的实验对程序质量有何贡献？
2. 这些实验带来的收益和成本如何随任务和模型变化？

### 4. 背景与问题设定

传统的基于 LLM 的进化程序搜索（如 FunSearch、AlphaEvolve）将 LLM 作为变异算子，在生成候选程序时无法执行代码或进行实验，只能依赖形式化评估。这限制了模型对程序行为的深入理解。AgenticEvolve 提出让每个岛屿由持久化 LLM 智能体运行，智能体可以在提交候选程序前编写并执行分析脚本，从而进行自主实验，以改进程序。

### 5. 方法概览

- 任务 / 环境: 两个启发式设计任务：在线装箱（OBP）和动态作业车间调度（DJSS）；以及十二个来自 LLM-SRBench 的方程发现问题。
- 变量 / 干预设计: 对比 AgenticEvolve（启用实验工具）与 No-analysis（禁用实验工具，其余配置相同）以及基线 OpenEvolve。
- 评价指标: 对于启发式设计，使用质量指标（OBP 的装箱超额百分比，DJSS 的归一化平均延迟）；对于方程发现，使用结构恢复成功率。同时报告评估次数和估计的 LLM 成本。
- 模型比较: 使用三种 LLM：DeepSeek-V4.1-Flash、GLM-5.3-Flash 和 Qwen3.8-Flash。
- 我的理解: 该方法的核心在于赋予智能体在正式评估之间进行实验的能力，使其能够主动探索程序行为、生成测试实例、调整参数，从而更有效地改进程序。No-analysis 对照实验隔离了实验的贡献，使得收益可归因于自主实验。

### 6. 关键发现

- AgenticEvolve 在启发式设计任务上优于基线和 No-analysis: 在 OBP 和 DJSS 任务上，AgenticEvolve 在隐藏和未见实例上均达到最佳平均最终质量，且使用更少的评估次数达到基线的最终质量。
- 自主实验显著提升方程发现能力: 在十二个方程发现问题中，AgenticEvolve 恢复了更多真实结构，优于 No-analysis 和现有 LLM 及遗传编程基线。
- 成本优势取决于模型和预算: AgenticEvolve 的 LLM 成本有时高于 No-analysis，但在相同预算下通常能达到更好的质量，且评估次数更少。
