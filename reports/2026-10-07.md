## 1. ScienceClaw: Benchmarking Continual Self-Evolution of AI-for-Science Agents Across the Natural and Social Sciences

**Topics:** AI for Science, Agent Self-Evolution, Benchmark
**Authors:** Mingda Zhang, Wenjin Liu, Tiesunlong Shen, Zikai Xiao, Zhenghong Lin, Qing Xu, Erik Cambria, Xiaoying Tang, Haoran Luo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.08691v1) | [PDF](http://arxiv.org/pdf/2610.08691v1.pdf) | [Code](https://github.com/beita6969/ScienceClaw)

### 1. 一句话结论

ScienceClaw 提出并验证了固定参数的程序级自我进化框架，使 AI-for-Science 智能体在跨 23 个学科的任务流中持续积累可迁移的 Skill 和 Operator，显著提升跨数据集性能。

### 2. 为什么重要

该工作首次将智能体的自我进化从通用任务扩展到自然科学和社会科学的 23 个学科，通过严格的验证机制和独立评估，证明了无需更新模型参数即可实现持续、可迁移的科学能力提升，为科学自动化提供了新范式。

### 3. 研究问题

1. 如何将已验证的科学执行转化为持久的程序级改进？
2. 在跨学科任务流中，程序自我进化能否带来可靠的性能提升和跨数据集迁移？

### 4. 背景与问题设定

大型语言模型智能体在科学自动化中展现出潜力，但已验证的执行结果很少能成为持久的程序级改进，且现有评估未覆盖自然科学和社会科学的连续任务。ScienceClaw 将程序自我进化形式化为固定参数下的任务求解、科学验证和程序更新，并构建了涵盖 23 个学科的基准，以评估进化增益、保持性和跨数据集迁移。

### 5. 方法概览

- 任务 / 环境: 23 个学科的任务流，每个学科包含 64 个 IID 和 64 个 OOD 实例，任务具有明确目标、可访问输入和可验证输出，并配有隔离环境和任务特定评估器。
- 变量 / 干预设计: 对比冻结基线（不进化）与多种进化方法（SkillOpt、TTE、AHE、EvoMaster、EvoScientist），以及 ScienceClaw 的两种变体（RuleEvo 和 Qwen-only 进化）。所有系统共享相同的初始程序、工具、源任务顺序和预算。
- 评价指标: 主要指标为 MacroSR（学科级成功率的宏平均），同时报告任务原生指标、进化增益、保持性、跨数据集迁移和成本。
- 模型比较: ScienceClaw 在所有 23 个学科的两个分割上均优于所有基线，平均相对优势在 IID 上为 2.58%，在 OOD 上为 4.19%。
- 我的理解: ScienceClaw 的核心在于将修复轨迹转化为可复用的 Skill 和 Operator，并通过源任务重放和独立验证确保更新有效，从而在不改变模型参数的情况下实现持续进化。

### 6. 关键发现

- 持续程序进化显著提升跨数据集性能: ScienceClaw 在所有 23 个学科上均取得最佳结果，平均相对优势在 IID 上为 2.58%，在 OOD 上为 4.19%，且每个学科均为正收益。
- 进化收益在 OOD 上更大: 跨数据集迁移的改进幅度大于同分布数据，表明进化出的 Skill 和 Operator 具有更好的泛化能力。
- 规则进化与 Qwen-only 变体也有效: RuleEvo 和 Qwen-only 进化虽然性能略低于完整版，但仍优于所有基线，说明进化机制本身的有效性。

- 对 Agent 系统: ScienceClaw 提供了一种无需训练即可持续改进智能体的方法，可应用于其他需要长期自主进化的智能体系统。

## 2. Agentic AutoRAG: RAG Pipeline Optimization through Reasoning-Driven Agents

**Topics:** 检索增强生成, 超参数优化, 智能体, 多目标优化
**Authors:** Lasse B. Strand, Robert Jakob, Kevin O'Sullivan, Markus Kreft
**Venue / Year:** EMNLP 2026 REALM Workshop / NeurIPS 2026 ML4Sys Workshop
**Links:** [Abstract](http://arxiv.org/abs/2610.08452v1) | [PDF](http://arxiv.org/pdf/2610.08452v1.pdf) | [Code](https://github.com/Agentic-Systems-Lab/Agentic-AutoRAG)

### 1. 一句话结论

Agentic AutoRAG 通过诊断-提议循环和知识库引导的智能体，在少量试验内高效优化 RAG 流水线，实现更高的准确率和更低的成本。

### 2. 为什么重要

RAG 流水线配置涉及大量相互作用的超参数，传统优化方法效率低且缺乏可解释性。Agentic AutoRAG 利用 LLM 智能体进行推理驱动的优化，不仅提升了性能，还提供了可解释的优化轨迹，为 RAG 系统的自动化调优提供了新范式。

### 3. 研究问题

1. 如何利用检索与生成失败的归因信息来指导 RAG 流水线的超参数优化？
2. 如何将模型知识库和定价信息融入优化过程，以实现成本感知的多目标优化？

### 4. 背景与问题设定

RAG 流水线配置是一个昂贵的超参数优化问题，涉及分块、嵌入、检索、重排、生成等多个相互依赖的环节。现有优化方法（如贝叶斯优化、遗传算法）仅使用聚合分数，忽略了每次试验中检索与生成失败的细粒度证据，导致搜索效率低。此外，多目标优化（准确率与成本）需要额外的先验知识。

### 5. 方法概览

- 任务 / 环境: 多跳问答基准（HotpotQA、MuSiQue、MultiHop-RAG）和真实医疗语料（UniDoc-Bench）
- 变量 / 干预设计: 对比随机搜索、MO-TPE（带/不带热启动）、无知识库和诊断的智能体消融，以及知识库贪心基线
- 评价指标: 验证集准确率、测试集准确率、成本（每查询美元）、Pareto前沿
- 模型比较: Agentic AutoRAG 与随机搜索、MO-TPE、消融变体对比，在三个基准上均达到更高准确率，且成本更低
- 我的理解: 该方法将优化过程分解为诊断和提议两个阶段，诊断器分析失败原因，提议器基于知识库和诊断信息选择下一配置，从而在探索和利用之间取得平衡。

### 6. 关键发现

- 更高的准确率与样本效率: 在三个多跳QA基准上，Agentic AutoRAG 在10次试验内达到或超过基线30次试验的准确率，最终准确率显著高于所有基线。
- 成本显著降低: 在医疗语料上，成本感知模式下达到77%的中位准确率，成本仅为最强基线（71.5%）的58%；匹配基线准确率时成本仅为22%。
- 诊断与知识库的贡献: 消融实验表明，移除诊断和知识库后性能下降，证明两者对优化效果有重要贡献。

## 3. ParanoiaEval: Benchmarking Unnecessary Defensive Work in Agentic Coding

**Topics:** AI Agent, Coding Agent, Software Engineering, Risk Management
**Authors:** Hanjun Luo, Xiucheng Zhang, Zhuoning Xu, Zhimu Huang, Yingbin Jin, Xinfeng Li, Hanan Salam
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.08662v1) | [PDF](http://arxiv.org/pdf/2610.08662v1.pdf) | [Code](https://github.com/ZhuoningXu/ParanoiaEval_release)

### 1. 一句话结论

ParanoiaEval 是首个统一评估编码智能体风险处理能力的基准，通过 200 个证据控制的任务对，发现不必要的防御性行为普遍存在且与任务能力解耦。

### 2. 为什么重要

随着编码智能体自主执行真实任务，判断其风险处理是否过度变得至关重要。现有评估多关注功能正确性，忽略了风险处理的合理性。ParanoiaEval 首次将软件工程中的 ATMA 框架引入智能体评估，为衡量智能体的风险判断能力提供了统一基准，有助于提升智能体的可靠性和用户信任。

### 3. 研究问题

1. 编码智能体在何种情况下会进行不必要的防御性工作？
2. 智能体的任务完成能力与其风险处理能力是否相关？
3. 不必要的风险处理对开发者体验有何影响？

### 4. 背景与问题设定

LLM 驱动的编码智能体正从代码生成工具发展为自主完成多步骤软件工程任务的系统。在执行任务时，智能体需要决定如何探索仓库、验证结果、处理不确定性以及采取何种预防措施。然而，主流评估仍以功能正确性为中心，忽略了风险处理的合理性。现有研究从不同角度（如过度行动、过度编辑、冗余步骤）描述了类似行为，但缺乏统一框架。软件工程领域已有成熟的风险管理理论（如 ATMA 框架），但尚未系统应用于智能体评估。

### 5. 方法概览

- 任务 / 环境: 基于 50 个开源仓库（34 个 Python、16 个 Go），每个仓库固定于 2026 年 7 月 1 日之后的提交，并预装依赖。任务为 SWE 风格，包含问题描述、参考补丁和可执行测试。
- 变量 / 干预设计: 构建 200 个证据控制的任务对，每对包含两个变体：E+ 包含治疗定义证据，E- 移除或反转该证据。两个变体仅证据不同，其余条件相同。任务覆盖四种风险治疗（规避、转移、缓解、接受）下的 44 种具体情境。
- 评价指标: 引入两个指标：风险治疗违规（Risk-Treatment Violation）和证据响应性（Evidence Responsiveness），使用人类校准的智能体裁判进行评估。
- 模型比较: 在 Claude Code 和 Codex 两个框架上评估了 8 个代表性模型，共 9600 次运行。
- 我的理解: 该方法通过严格控制证据变量，将风险治疗行为从任务完成中分离出来，从而能够单独评估智能体的风险判断能力。这种设计类似于心理学中的对照实验，使得观察到的行为差异可归因于证据的存在与否。

### 6. 关键发现

- 不必要的风险治疗普遍存在: 即使证据明确存在，智能体在 11.2% 到 58.7% 的运行中仍会进行不必要的风险治疗，表明该问题具有普遍性。
- 任务能力与风险治疗能力解耦: 更强的任务完成能力并不保证更合适的风险治疗，说明风险治疗是一个独立的能力维度，需要单独评估和优化。
- 风险治疗违规损害开发者体验: 不必要的风险治疗显著降低开发者的满意度评分（5 分制中降低 1.27 分），表明过度防御性行为对用户体验有负面影响。

- 图来源: Figure 1: ParanoiaEval 使用证据控制的任务对展示相同防御行为何时适当或不必要。
- 为什么重要: 该图直观展示了 ParanoiaEval 的核心设计：通过对比 E- 和 E+ 变体，同一防御行为在证据缺失时是适当的，在证据存在时则是不必要的。这体现了基准如何精确控制变量来评估风险治疗能力。

ParanoiaEval 填补了编码智能体评估中风险处理能力的空白，其证据控制的任务对设计非常巧妙。研究结果提示，智能体的风险判断能力与任务能力独立，这为未来智能体设计提供了新方向：不仅要提高任务完成率，还要优化风险决策。未来工作可扩展至更多语言和任务类型，并探索如何通过训练或提示来减少不必要的防御行为。

## 4. Agentic RCA for Internet-Scale Services Using Constrained Creativity

**Topics:** 根因分析, LLM智能体, 网络服务可靠性, 领域特定语言, 约束创造力
**Authors:** Sayan Sinha, Vipul Harsh, B. Aditya Prakash, Vyas Sekar, Hui Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.08622v1) | [PDF](http://arxiv.org/pdf/2610.08622v1.pdf)

### 1. 一句话结论

E4通过约束创造力范式，将LLM的分析过程限制在DSL定义的程序空间内，在提升根因分析准确率的同时大幅降低成本，并保持可解释性。

### 2. 为什么重要

互联网规模服务的故障根因分析（RCA）需要在表达性、效率、可解释性和低人力投入之间取得平衡。现有方法（专用算法、结构化框架、LLM智能体）难以同时满足所有要求。E4提出了一种新的智能体设计范式，通过DSL约束LLM的创造性，在保持可解释性的同时实现高准确率和低成本，为构建可靠、实用的RCA系统提供了新思路。

### 3. 研究问题

1. 如何设计一个RCA系统，使其同时具备高表达性、高效率、高可解释性和低人力投入？
2. 如何利用LLM的探索能力，同时避免其产生不可验证或不可解释的分析过程？
3. 如何自动引导操作符库以适应新部署，并在现有操作符不足时安全地扩展？

### 4. 背景与问题设定

互联网规模服务（如视频流、电商）依赖复杂的客户端、网络、第三方服务和后端组件，故障频发。系统管理员需要快速定位根因（RCA）。理想系统应具备四个特性：表达性（覆盖已知和未知故障）、效率（成本可控）、可解释性（提供可操作的洞察）和低人力投入。现有方法各有局限：专用算法（如Sage、Murphy）效率高但表达性差；结构化框架（如SQL、ExplainIt!、MoCE）需要人工编写查询；LLM智能体（如Terminus-2、RCAgent）表达性强但成本高、可解释性差。E4旨在通过约束创造力的范式，在表达性和可解释性之间取得平衡。

### 5. 方法概览

- 任务 / 环境: RCA任务：给定KPI异常告警（含时间窗口），系统分析遥测数据（客户端属性、网络指标、后端日志等），返回排序的根因假设列表。环境为互联网规模服务，数据量大、维度多。
- 变量 / 干预设计: E4采用DSL（领域特定语言）定义分析程序的结构。DSL包含一组操作符（如生成候选假设、评分、过滤）和语法（操作符组合成无环数据流图DAG）。LLM被限制只能生成符合DSL的程序，不能编写任意代码。系统分为三个阶段：1) 引导（Bootstrap）：根据部署的遥测模式、领域知识和示例playbook，生成初始操作符库和验证过的playbook；2) 运行时适应（Runtime adaptation）：针对每个故障，LLM在DSL约束下组合操作符生成DAG，执行并验证；3) 演进（Evolve）：如果现有操作符不足以解决问题，LLM可以编写新操作符（需符合DSL类型），并重新运行。
- 评价指标: 主要指标：根因识别准确率（top-3命中率）和每次故障的平均成本（美元）。
- 模型比较: 对比基线：LLM-only（直接让LLM回答）、RCA-Agent（编码智能体）、Terminus-2（工作流智能体）。E4在四个数据集（合成+真实）上准确率更高，成本更低（最高12倍）。
- 我的理解: E4的核心思想是“约束创造性”：通过DSL限制LLM的探索空间，既保留了LLM的灵活性，又保证了程序的可验证性和可解释性。这类似于给LLM提供乐高积木（操作符），而不是让它自由捏造。这种设计降低了LLM幻觉的风险，同时通过操作符复用和DAG执行优化了成本。

### 6. 关键发现

- E4在准确率和成本上均优于现有智能体方法: 在四个数据集上，E4的top-3根因准确率比最强基线（Terminus-2）高62%，平均成本降低5.4倍，最高降低12倍。
- 约束创造性是提升可解释性和效率的关键: 通过DSL限制LLM的输出，E4的分析过程是结构化的DAG，易于验证和解释，同时避免了LLM的无效探索，降低了token消耗。
- E4对低能力LLM也有效: 即使使用较弱的推理模型，E4仍能保持较高的准确率，表明DSL约束降低了对LLM能力的依赖。

### 11. 局限性

## 5. RSJEV: Discriminative Remote Sensing Scene Classification with Multimodal Large Language Models

**Topics:** 遥感场景分类, 多模态大语言模型, 判别式决策, 高效推理
**Authors:** Dongchen Si, Di Wang, Mingzhen Xu, Jing Zhang, Bo Du, Liangpei Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.08539v1) | [PDF](http://arxiv.org/pdf/2610.08539v1.pdf) | [Code](https://github.com/Dongtcs/RSJEV)

### 1. 一句话结论

RSJEV 通过单次前向传播的判别式决策框架，在遥感场景分类中实现了优于生成式 MLLM 的精度与效率平衡。

### 2. 为什么重要

该工作针对生成式 MLLM 在分类任务中因自回归解码导致的推理开销大、效率低的问题，提出了一种无需自回归解码的判别式决策方法，为多模态大模型在高效分类任务中的应用提供了新思路。

### 3. 研究问题

1. 如何在不进行自回归解码的情况下，利用多模态大模型实现高效的遥感场景分类？
2. 如何将视觉表示、任务指令和候选类别语义联合建模，以提升分类精度？

### 4. 背景与问题设定

遥感场景分类是地球观测中的基础任务。现有方法包括基于 CNN/Transformer/Mamba 的视觉分类器、基于 CLIP 的视觉-语言相似度匹配，以及生成式多模态大模型。然而，视觉分类器依赖固定标签空间，缺乏语义先验；CLIP 方法仅通过静态相似度匹配，缺乏动态交互；生成式 MLLM 需要自回归解码，推理成本高。因此，需要一种既能保留多模态交互又能高效决策的分类框架。

### 5. 方法概览

- 任务 / 环境: 遥感场景分类，输入为遥感图像和包含候选类别的任务提示，输出为类别标签。
- 变量 / 干预设计: 提出 RSJEV 框架，将分类任务重构为候选条件判别式决策问题。通过 OnePass Decider 提取答案槽的隐藏状态，并复用预训练语言模型头对候选选项打分，直接估计类别概率。
- 评价指标: 使用精确率（P）、召回率（R）、F1 分数和总体准确率（OA）作为评估指标。
- 模型比较: 与 CNN（ResNet、DenseNet、EfficientNet）、Transformer（DeiT、Swin、ViT）、Mamba（VMamba、Vision Mamba、RSMamba）、视觉语言模型（Open-CLIP、MaPLe、OSCLIP）以及生成式 MLLM（Qwen3-VL、InternVL3、LHRS-Bot-Nova、GeoChat）进行比较。
- 我的理解: RSJEV 的核心创新在于将分类问题转化为判别式决策，通过设计一个特殊的答案槽 [RSSC]，在单次前向传播中直接计算候选类别的概率，避免了生成式模型逐 token 解码的耗时过程。同时，通过复用预训练语言模型头，无需额外训练分类头，保持了模型的泛化能力。

### 6. 关键发现

- 分类性能优越: 在 UC Merced、AID 和 NWPU-RESISC45 三个基准上，RSJEV 的 F1 分数分别达到 97.72%、96.30% 和 94.58%，优于所有对比方法，包括生成式 MLLM。
- 推理效率显著提升: 由于消除了自回归解码，RSJEV 的推理延迟和 GPU 内存消耗显著降低，吞吐量更高，实现了精度与效率的更好权衡。具体而言，与生成式 MLLM 相比，推理延迟降低约 80%，GPU 内存占用减少约 50%，吞吐量提升约 4 倍。
- 参数效率高: 仅使用 0.8B 参数的骨干模型，就超越了 2B 到 8B 参数的生成式 MLLM，展示了判别式决策框架的优越性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: RSJEV 的高效判别式决策机制可应用于需要快速响应的智能体系统，如实时遥感监测和地理空间分析，减少推理延迟。
- 对 Skill: 该方法展示了如何将生成式 MLLM 改造为判别式分类器，为其他分类任务提供了可借鉴的范式，可能推动多模态模型在高效分类场景中的应用。
- 对 Memory: 通过消除自回归解码，RSJEV 降低了 GPU 内存占用，使得在资源受限的设备上部署多模态分类模型成为可能。
- 对评测: RSJEV 的评估指标（P、R、F1、OA）全面，且对比了多种方法，为遥感场景分类提供了新的基准。

### 11. 局限性

- 实验仅在三个公开数据集上进行，未涵盖更多样化的遥感场景，泛化性有待进一步验证。
- 方法依赖预训练 MLLM 的质量，若骨干模型性能不足，可能影响分类精度。
- 论文虽提及推理延迟、GPU 内存和吞吐量的对比，但具体数值未在摘要中详述，需查阅原文获取量化结果。

### 12. 我的看法 / 个人笔记

RSJEV 提出了一种新颖的判别式决策框架，有效解决了生成式 MLLM 在分类任务中的效率瓶颈。其核心思想——通过答案槽直接计算类别概率——具有通用性，可推广到其他分类任务。然而，论文在实验部分对效率提升的量化不足，且未讨论在更大规模数据集上的表现。未来工作可探索如何将该框架扩展到开放集分类或动态类别场景。
