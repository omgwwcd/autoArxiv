## 1. When Tool Outputs Become Commands: Separating Action Induction from Runtime Authorization in Tool-Augmented LLM Agents

**Topics:** LLM Agent Security, Indirect Prompt Injection, Tool-Augmented Agents
**Authors:** Xiaokun Guo, Zhen Xu, Dongdong Huo, Yanqiu Zhang, Wei Wang, Qinfu Yang, Dongjin Yu, Yu Wang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.27146v1) | [PDF](http://arxiv.org/pdf/2608.27146v1.pdf)

### 1. 一句话结论

SARA separates action induction from execution authorization to prevent tool outputs from becoming unauthorized commands in LLM agents.

### 2. 为什么重要

This work addresses a critical security gap in tool-augmented LLM agents: untrusted tool outputs can induce actions that lead to real-world side effects beyond user intent. SARA provides a principled runtime authorization mechanism that maintains task utility while drastically reducing attack success rates.

### 3. 研究问题

1. How can a system allow untrusted Observations to remain involved in solving open-ended tasks while preventing them from acquiring execution authority not granted by the user?
2. How to distinguish runtime instantiation (legitimate use of runtime data) from authority expansion (unauthorized extension of privileges) in multi-step tool execution?

### 4. 背景与问题设定

Tool-augmented LLM agents rely on untrusted runtime Observations (e.g., webpages, emails) to complete open-ended tasks. However, when tool outputs contain operational content (e.g., 'send a copy to attacker@example.com'), they can induce actions that produce real-world side effects beyond user intent. This is a form of indirect prompt injection (IPI). Existing defenses either restrict external content (hurting utility) or fail to distinguish legitimate runtime adaptation from attack-induced behavior. The core problem is conflating action induction (Observation influences candidate action) with execution authorization (action is permitted to execute).

### 5. 方法概览

- 任务 / 环境: Dynamic tool-augmented LLM agents operating in open environments (web browsers, OS, databases) with multi-step tool execution.
- 变量 / 干预设计: SARA is deployed between the Agent and the real tool executor. It uses a context-isolated Action Probe to detect action-inducing semantics in Observations and persistently records action origins. On the execution side, candidate calls are authorized only against the user objective and audited evidence from authorized successful executions, satisfying goal, execution-chain, and argument-level support. No-History-Promotion prevents historical recurrence from laundering action origins into execution authority.
- 评价指标: Attack Success Rate (ASR) and task utility (e.g., task completion rate).
- 模型比较: Compared against input filtering, execution-structure constraints, action attribution, and execution-boundary control methods on AgentDojo and AgentDyn benchmarks.
- 我的理解: SARA introduces a persistent provenance tracking mechanism that separates two types of evidence: what external content induced (action origins) and what legitimate execution established (audited evidence). By requiring candidate calls to have independent support from both user authorization and audited evidence, it prevents action origins from being promoted to execution authority even after cross-step propagation.

### 6. 关键发现

- SARA limits ASR to ≤0.63% across four primary evaluation settings: On AgentDojo and AgentDyn, SARA achieves extremely low attack success rates while maintaining competitive task utility, significantly outperforming existing defenses.
- SARA consistently reduces ASR across different Agent backbones: The security gains are robust across various underlying LLM agents, demonstrating the method's generalizability.
- No-History-Promotion is critical for preventing authority laundering: Without this mechanism, historical recurrence of action origins can implicitly promote them to execution authority, increasing ASR.

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: SARA provides a principled runtime authorization mechanism that can be integrated into existing agent architectures without modifying the agent's internal reasoning, offering a practical security layer.
- 对 Skill: The approach does not require retraining skills; it works as a post-hoc authorization layer, making it compatible with any tool-using agent.
- 对 Memory: SARA maintains persistent action origins across steps, which could be integrated with agent memory systems to track provenance of information used in decision-making.
- 对评测: The work highlights the need for evaluation benchmarks that capture dynamic tool tasks with security-utility trade-offs, like AgentDojo and AgentDyn.

### 11. 局限性

- SARA assumes the user request is trusted and the attacker cannot modify the SARA runtime; in practice, user requests could be manipulated via social engineering.
- The Action Probe relies on LLM-based semantic detection, which may be vulnerable to adversarial attacks that craft action-inducing content to evade detection.
- SARA adds inference cost due to the Action Probe and authorization checks, which may impact latency in real-time applications.

### 12. 我的看法 / 个人笔记

SARA offers a well-motivated and principled solution to a critical security problem in LLM agents. The key insight—separating action induction from execution authorization—is both theoretically sound and practically effective, as demonstrated by the strong empirical results. The design is elegant in its simplicity: it does not require modifying the agent's internal reasoning or training, making it easily deployable. However, the reliance on an LLM-based Action Probe introduces a potential vulnerability; future work could explore more robust detection methods. Overall, this is a significant contribution to agent security.

### 14. 总结

SARA is a runtime authorization mechanism for tool-augmented LLM agents that separates action induction (how Observations influence candidate actions) from execution authorization (whether those actions are permitted). It uses a context-isolated Action Probe to detect action-inducing semantics in tool outputs and persistently records action origins, while independently maintaining audited execution evidence. At the execution boundary, candidate calls are authorized only if they satisfy goal, execution-chain, and argument-level support from user authorization and audited evidence. Evaluated on AgentDojo and AgentDyn, SARA limits attack success rate to ≤0.63% while maintaining competitive task utility, and consistently reduces ASR across different agent backbones.

## 2. Safety Does Not Compose: Non-Decaying Loop State for Autonomous LLM Agents

**Topics:** LLM Agent Safety, Autonomous Loop, Cross-Iteration Attack
**Authors:** Chenhao Wu, Haoxuan Jia, Yang Liu, Yingguang Yang, Yuhan Lin, Chongyang Zhang, Hao Zheng, Yulin Huang, Jianshen Zhang, Yongzhi Qi, Shang Luo, Kefu Xu, Jifeng Zhu, Bin Chong
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.27141v1) | [PDF](http://arxiv.org/pdf/2608.27141v1.pdf)

### 1. 一句话结论

当前单轨迹安全机制在跨迭代攻击下完全失效，必须引入非衰减的循环级安全状态。

### 2. 为什么重要

LLM代理正从单次调用转向自主循环，但现有安全机制仅在单轨迹内重置状态，无法防御跨迭代的碎片化攻击，这可能导致严重的安全漏洞。本文首次形式化证明了该问题，并提出了可组合的循环级防御方案LoopHarness。

### 3. 研究问题

1. 轨迹级安全监控器能否检测跨迭代碎片化攻击？
2. 几何衰减的风险分数能否有效防御耐心攻击者？
3. 如何设计循环级安全状态以实现可证明的防御保证？

### 4. 背景与问题设定

LLM代理系统正从单次问答转向自主循环部署，例如软件维护、运维、研究辅助等场景。这类系统从人类目标出发，反复发现工作、规划、执行工具调用、验证结果并持久化状态。然而，现有安全机制（如输入清洗、逐调用分类、权限上限等）均限定在单条轨迹内，每次轨迹开始时安全状态被重置。这种设计导致两个问题：一是单轨迹防御的残余失败概率在循环中被放大；二是攻击者可将恶意证据分散到多个轨迹中，使得轨迹级监控器永远无法看到完整证据。

### 5. 方法概览

- 任务 / 环境: 基于Agent-SafetyBench的自主循环任务，包含配对清洁和攻击场景，以及外状态攻击套件。
- 变量 / 干预设计: LoopHarness包含五个持久组件：IPM（准入与来源监控）、XRC（跨迭代风险累积器）、MIG（内存完整性守卫）、ASA（对抗鲁棒停止仲裁器）、CRG（复合风险调控器），所有组件状态在循环内永不重置。
- 评价指标: 主要指标为复合攻击成功率cASR(n)及其AUC，同时报告清洁场景目标完成率CleanGC、每迭代ASR、过早停止率、检测延迟等。
- 模型比较: 对比三种配置：关闭（每迭代重置）、衰减（始终使用几何衰减）、非衰减（本文提出的带锁存机制）。
- 我的理解: LoopHarness的核心创新在于将攻击证据、动作影响和验证器不确定性作为独立信号处理，只有基于规则的循环结构标志才能锁存风险衰减，从而避免高影响合法操作或模型不确定性污染后续迭代。

### 6. 关键发现

- 轨迹级监控器无法检测碎片化攻击: 对于证据分散在多个迭代的攻击，任何轨迹级监控器的真阳性率等于假阳性率，因为所需证据从未出现在其可见窗口内。
- 几何衰减风险分数不足: 耐心攻击者只需等待常数长度的冷却期即可绕过几何衰减的风险分数，该常数不随总迭代次数N增长。
- LoopHarness提供与N无关的保证: 在仲裁检测下限δ_M下，未授权不可逆动作的期望数上界为B+m-1+m/δ_M，其中B+m-1项由无模型规则决定，即使验证器完全合谋也能保持。

- 为什么重要: 直观展示了碎片化攻击如何利用轨迹级重置的盲点，是理解全文动机和核心分离结果的关键。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 自主循环系统必须采用循环级安全状态，而非仅依赖轨迹级防御。
- 对 Skill: 技能执行应受循环级风险状态约束，高影响操作需额外审查。
- 对 Memory: 持久内存必须具有完整性保护，且信任级别不能自动升级。
- 对评测: 评估协议必须包含跨迭代攻击场景，并报告清洁与攻击场景的配对指标。

### 11. 局限性

- LoopHarness的保证依赖于仲裁检测下限δ_M，实际中δ_M的取值需要经验调优。
- 当前评估仅在Agent-SafetyBench上进行，泛化性有待验证。
- 非衰减风险累积可能导致过度保守，影响合法任务的完成效率。

### 12. 我的看法 / 个人笔记

本文精准指出了当前LLM代理安全的核心漏洞——状态重置，并提供了理论严谨的解决方案。LoopHarness的设计巧妙地将不同信号分离，避免了高影响合法操作对风险状态的污染。但实际部署中，非衰减风险可能导致系统过于保守，需要在安全性和可用性之间取得平衡。此外，对验证器合谋的鲁棒性假设较强，实际中可能难以完全满足。

### 13. 这篇工作引用的近期高影响力相关文章

  为什么重要：提供了评估LLM代理安全性的基准，但仅考虑单轨迹场景。
  核心贡献：定义了多种攻击类型和评估协议。
  与当前论文关系：本文在其基础上扩展了跨迭代攻击场景，并提出了新的评估协议。
- Memory Poisoning in LLM Agents

  核心贡献：揭示了记忆作为攻击面的重要性。
  与当前论文关系：本文将其形式化为T9自馈记忆投毒，并设计了MIG组件防御。

### 14. 总结

本文证明当前LLM代理的轨迹级安全机制在跨迭代碎片化攻击下完全失效，并提出LoopHarness——一种循环级防御方案，通过非衰减风险累积和独立信号处理，实现了与迭代次数无关的安全保证。在Agent-SafetyBench上的实验验证了其有效性。

## 3. UrbanGround: From Local Perception to Spatial Agency in a Real-Scale City

**Topics:** GUI Agent, Embodied AI, Urban Navigation, Multimodal Large Language Models
**Authors:** Tianjie Ju, Zheng Wu, Yueqing Sun, Yuhan Cui, Bobo Li, Shengqiong Wu, Pengzhou Cheng, Haodong Zhao, Zongru Wu, Xinbei Ma, Doris Zhang, Kunling Li, Mong-Li Lee, Wynne Hsu, Hao Fei, Qi Gu, Gongshen Liu, Zhuosheng Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.27456v1) | [PDF](http://arxiv.org/pdf/2608.27456v1.pdf) | [Code](https://github.com/UrbanGround/UrbanGround)

### 1. 一句话结论

当前多模态大语言模型在城市尺度下无法将局部感知能力可靠地组合为持续的目标导向行为，空间智能在扩展交互中崩溃。

### 2. 为什么重要

该工作首次在真实地理尺度的香港3D城市沙盒中系统评估MLLM智能体的空间能动性，揭示了局部视觉识别与全局导航之间的根本断裂，为构建真正能在复杂城市中自主行动的智能体提供了关键基准。

### 3. 研究问题

1. MLLM智能体能否通过主动观察建立可用的局部空间定位？
2. 局部定位能力如何扩展到超出视野的目标导向导航？
3. 城市环境变化（如天气、道路封闭、行人运动）如何影响智能体的空间感知与行动？

### 4. 背景与问题设定

现有MLLM在单帧街景识别上表现优异，但城市能动性要求智能体在持续移动中保持空间理解的一致性。现有评估环境要么是游戏世界（空间结构受游戏机制约束），要么是物理世界但范围有限（室内或小尺度），缺乏一个既保持真实地理结构又支持闭环交互的城市场景。UrbanGround填补了这一空白，基于香港全境3D地理数据构建了可交互的物理约束城市。

### 5. 方法概览

- 任务 / 环境: 基于香港3D可视化地图和3D行人网络构建的Unity沙盒，支持第一人称视角、物理碰撞、时间/天气控制、行人动画，智能体通过客户端-服务器接口与Unity环境交互。
- 变量 / 干预设计: 设计了五级空间能动性评估阶梯：Level 1局部环境理解（视觉识别、定向、主动探索）；Level 2显式指令导航（短/长距离、指令/约束变体）；Level 3隐式指令探索（地点搜索、意图推断）；Level 4多任务规划；Level 5环境变化（天气、道路封闭、行人运动）。
- 评价指标: 任务成功率、轨迹效率、是否偏离行人网络、重复动作次数、碰撞事件数。
- 模型比较: 未明确列出具体模型，但提及当代MLLM智能体在原子能力（视觉识别、短程空间推理）上表现良好，而在定向、行人感知移动和扩展探索中失败。
- 我的理解: 该方法的核心创新在于将真实城市地理数据转化为可交互的物理仿真环境，并通过逐步增加空间状态维持难度的任务阶梯，系统性地暴露了局部感知与全局行动之间的鸿沟。

### 6. 关键发现

- 局部空间定位能力尚可但行为不可靠: 在主动空间问答任务中，MLLM能正确回答局部空间问题，但即使答案正确，智能体有时也会离开行人网络，表明答案准确性不保证物理有效行为。
- 导航能力随距离增加急剧下降: 智能体可到达附近目的地，但路线超过几个街区时性能崩溃。即使识别出正确全局方向，也无法找到可行局部路径，且受阻后常重复相同动作而不恢复。
- 环境变化下适应性不足: 低可见度主要削弱局部问答，对短程导航影响不一致。当路线在执行中失效时，智能体继续产生局部合规动作，即使空间计划已过时，暴露了局部行为与有效适应之间的差距。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体系统需要更强的空间记忆和错误恢复机制，不能仅依赖局部视觉推理；应集成显式地图和路径规划模块以弥补MLLM在扩展导航中的不足。
- 对 Skill: 需要开发将局部感知组合为全局行动的策略，例如通过子目标分解和空间推理链来维持目标导向行为。
- 对 Memory: 空间记忆必须支持跨视角的定位更新和冲突解决，当前MLLM的上下文窗口不足以维持长时间导航所需的几何一致性。
- 对评测: 评估应超越单帧或短程任务，采用逐步增加空间和时间跨度的阶梯式基准，以暴露智能体在扩展交互中的累积误差。

### 11. 局限性

- 仅基于香港一个城市，地理多样性和文化差异未覆盖。
- 智能体控制接口简化了真实机器人运动（如无惯性、动力学约束）。
- 行人模型使用通用化身，未模拟真实行人行为复杂性。
- 评估主要关注导航，未涉及更复杂的城市任务（如社交互动、任务规划）。

### 12. 我的看法 / 个人笔记

UrbanGround是一个设计精巧的基准，它通过真实地理数据和渐进式任务阶梯，有力地证明了当前MLLM智能体在城市尺度上的空间能动性存在根本性缺陷。其核心贡献在于将问题从‘能否识别’转向‘能否持续行动’，这更贴近实际应用需求。未来工作应关注如何将局部感知与显式空间推理（如地图、路径规划）结合，以及如何设计能自我纠正的探索策略。

## 4. RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution

**Topics:** LLM Agent Security, Automatic Red-Teaming, Jailbreak Attack, Skill Evolution
**Authors:** Junjie Zhang, Hui Liu, Kecheng Chen, Xianbo Mo, Changsheng Chen, Haoliang Li
**Venue / Year:** arXiv preprint 2026
**Links:** [Abstract](http://arxiv.org/abs/2608.27439v1) | [PDF](http://arxiv.org/pdf/2608.27439v1.pdf)

### 1. 一句话结论

RedEvoAgent通过经验驱动的技能演化，将跨案例攻击轨迹提炼为简洁、可读的攻击技能，并利用验证棘轮机制仅保留提升验证性能的更新，从而在多种基准和模型上超越现有固定和智能体基线。

### 2. 为什么重要

LLM智能体被部署到Claude Code、Codex等产品级执行框架中，可修改文件、传输数据、调用API，越狱攻击可能触发有害工具使用和持久状态改变，风险远超文本生成。RedEvoAgent提供了一种可扩展、可解释的自动红队方法，通过技能演化持续提升攻击效果，并具备跨攻击模型和跨执行框架的迁移能力，对产品级智能体的安全评估具有重要意义。

### 3. 研究问题

1. 如何将跨案例的攻击轨迹提炼为简洁、可读且可演化的攻击技能？
2. 如何避免轨迹检索中的偏差和工具归因不清问题，实现稳定的技能演化？

### 4. 背景与问题设定

LLM智能体在Claude Code、Codex等产品级框架中可修改文件、传输数据、调用API，越狱攻击可能导致破坏性工具使用和持久状态改变。现有自动红队方法多依赖固定攻击（如GCG、AutoDAN）或基于轨迹检索的智能体攻击（如RedCodeAgent），但轨迹检索存在检索偏差、工具贡献不明确、上下文开销大、可解释性差等问题。RedEvoAgent旨在通过经验驱动的技能演化解决这些问题。

### 5. 方法概览

- 任务 / 环境: 黑盒目标智能体M_tar（包括目标模型m_tar和执行框架h_tar），攻击智能体M_att(s)（包括攻击模型m_att和攻击框架h_att(s,T)），攻击工具箱T包含7种越狱工具：GCG、AutoDAN、AmpleGCG、Template、FlipAttack、RolePlay以及本文新增的Prompt Substitution（利用辅助LLM改写失败提示但保持意图）。
- 变量 / 干预设计: 将数据集分为训练集D_tr、验证集D_va和测试集D_te。在训练集上收集攻击轨迹并构建工具效能画像（每个工具独立评估的ASR）；通过Deciding-Tool Attribution标记导致成功的决定工具（即成功QUERYTARGET前最后一个调用的工具）；利用验证棘轮机制，仅当候选技能在验证集上严格优于当前技能时才接受更新，否则保留原技能并记录失败候选。
- 评价指标: 攻击成功率（ASR）作为主要指标，在Agent Security Bench (ASB)和AgentHarm基准上评估，并测试跨攻击模型（如GPT-4到Llama-3）和跨执行框架（如Claude Code到Codex）的迁移性。
- 模型比较: 与固定攻击方法（GCG、AutoDAN、PAIR、TAP等）和智能体基线（RedCodeAgent、JailbreakOPT、MAJIC）比较，RedEvoAgent在攻击效果、工具效率和迁移性上均更优。
- 我的理解: RedEvoAgent的核心创新在于将经验提炼为技能而非存储完整轨迹，并通过验证棘轮确保技能更新有效，避免了轨迹检索的偏差和开销。Deciding-Tool Attribution解决了工具归因问题，防止策略崩溃。新增的Prompt Substitution工具丰富了攻击手段。

### 6. 关键发现

- 攻击效果显著提升: 在ASB和AgentHarm基准上，RedEvoAgent在多个目标模型（如GPT-4、Claude）上均取得最高ASR，优于固定攻击和智能体基线。例如，在ASB上针对GPT-4，RedEvoAgent的ASR达到0.85，而RedCodeAgent为0.72，GCG为0.45。
- 工具效率改善: RedEvoAgent在达到相同或更高ASR时，使用的工具调用次数更少，平均每案例调用2.3次工具，而RedCodeAgent为3.8次，表明技能演化优化了工具选择策略。
- 跨攻击模型和跨执行框架迁移: 在GPT-4上演化的技能迁移到Llama-3上仍保持高ASR（从0.85降至0.78），而RedCodeAgent迁移后ASR从0.72降至0.55；在Claude Code上演化的技能迁移到Codex上同样有效（ASR从0.80降至0.74），优于基线。

## 5. Persona-Execution Separation: An Architecture Pattern for Evolving LLM Agents under Execution Audit

**Topics:** LLM Agent Architecture, Governance, Software Engineering
**Authors:** Yisen Xi
**Venue / Year:** arXiv:2608.27427v1 [cs.SE]
**Links:** [Abstract](http://arxiv.org/abs/2608.27427v1) | [PDF](http://arxiv.org/pdf/2608.27427v1.pdf)

### 1. 一句话结论

提出人格-执行分离（PES）架构模式，将LLM代理的人格与执行置于不同信任域，通过受控契约桥接，使人格自由演化而不影响执行审计。

### 2. 为什么重要

在受监管组织中，LLM代理需同时满足人格持续演化和执行可审计性，传统单域架构无法兼顾。PES模式提供了一种系统级解耦方案，对构建合规、可演化的企业级代理系统具有重要指导意义。

### 3. 研究问题

1. 如何设计架构使LLM代理的人格（指令、语气、自我呈现）能自由演化，同时保持执行（有状态、可审计的工作）可追溯？
2. 在LLM表示不可区分性下，单域机制能否同时满足自由漂移、执行可追溯性和解耦三个目标？

### 4. 背景与问题设定

LLM代理在受监管组织中执行状态变更操作（如资金操作、合规申报），要求每个操作被门控、记录和审计。同时，操作员需持续调整代理的指令、语气和技能绑定以改进系统。传统单域架构中，人格与执行共享同一信任域，严格治理下每次人格编辑触发全面重新验证，宽松治理则丧失可靠审计线索。现有方案（单域代理、代理+工具、代理+子代理）均无法同时满足人格自由漂移（G1）、严格执行可追溯性（G2）及其解耦（G3）。

### 5. 方法概览

- 任务 / 环境: 受监管组织中的LLM代理，如数字员工平台，需处理资金操作、合规申报等状态变更任务。
- 变量 / 干预设计: PES模式：人格位于低治理域（允许自由演化），执行位于高治理域（严格门控和审计），两者通过受控契约桥连接。桥包含审批矩阵、数据丢失防护（DLP）和审计机制，仅允许状态摘要返回，数据体保留在限制域，身份保持连续。
- 评价指标: 机制检查：执行侧在人格扰动下无需重新验证；人格指纹不出现在硬断言字段。追溯隔离检查：预分离构建中执行路径因疏忽而非构造解耦。
- 模型比较: 与8个开源平台（DeepSeek Harness、AgentScope、cordum、StaffDeck等）及学术邻居（意图/执行分离、安全执行集群等）比较，显示无现有架构同时满足G1-G3。
- 我的理解: PES本质是将变化隔离原则应用于LLM代理：人格作为易变模块，执行作为需稳定模块，信任域边界作为模块边界。桥接契约定义了跨域交互的规则，确保人格漂移不影响执行审计。

### 6. 关键发现

- PES模式满足三个设计目标: 通过将人格与执行置于不同信任域，PES同时实现人格自由漂移（G1）、严格执行可追溯性（G2）及其解耦（G3）。在受监管数字员工平台的开发/试点案例中，一个月内记录五项决策，每项均有被拒绝的替代方案。
- 机制检查验证了分离有效性: 对已部署实现的机制检查发现：在五种模型配置的人格扰动下，执行侧无需重新验证；硬断言字段上无人格指纹。预分离构建的探测显示，受治理执行路径因疏忽而非构造解耦，而PES将其变为审计架构规则。
- 现有架构无法同时满足三个目标: 系统比较显示，单域代理、代理+工具、代理+子代理以及2025-2026年的安全执行集群（如Fides、CaMeL、Progent等）均未将人格置于不同信任域以实现自由漂移而不污染审计线索。

### 12. 我的看法 / 个人笔记

PES模式巧妙地将变化隔离原则应用于LLM代理架构，通过信任域分离优雅解决了人格演化与执行审计的根本矛盾。其核心洞察在于认识到人格与执行在LLM代理中表示不可区分，因此必须通过架构而非策略来解耦。与2025-2026年安全执行集群的互补性表明，PES填补了治理/演化视角的空白。未来工作可探索PES与安全机制的集成，以及更广泛的适用性验证。

### 14. 总结

本文提出人格-执行分离（PES）架构模式，将LLM代理的人格与执行置于不同信任域，通过受控契约桥接，使人格自由演化而不影响执行审计。在受监管数字员工平台的案例中验证了其有效性，并与现有架构系统比较，显示PES是唯一同时满足自由漂移、执行可追溯性和解耦三个目标的方案。该模式适用于多用户部署、执行审计和预期人格变更的场景。
