## 1. PASTABench: Proactive Assessment of Sequential Trajectories for Agent Safety

**Topics:** GUI Agent, LLM Agent Safety, Proactive Safety Monitoring
**Authors:** Jiapeng Sun, Yujin Zhou, Han Zhu, Pengcheng Wen, Jiayi Zhou, Sirui Han, Yike Guo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.28197v1) | [PDF](http://arxiv.org/pdf/2609.28197v1.pdf)

### 1. 一句话结论

PASTABench 基准测试表明，当前 LLM 在主动安全监控方面表现不佳，最佳模型仅有 40.74% 的完美干预率，且普遍存在词汇过拟合问题。

### 2. 为什么重要

随着 LLM 代理在现实世界中执行多步骤任务，其安全性至关重要。现有评估方法要么忽略风险的累积性，要么事后评估，无法及时干预。PASTABench 首次提出解耦式主动安全监控框架，并引入最优干预窗口（OIW）指标，为代理安全评估提供了新的范式。

### 3. 研究问题

1. 如何形式化定义代理轨迹中的主动安全监控任务？
2. 当前 LLM 在主动安全监控中的表现如何？
3. 模型是否真正理解风险，还是仅依赖表面词汇线索？

### 4. 背景与问题设定

LLM 代理能够改变现实世界状态，其安全性至关重要。现有安全评估多为单轮或事后评估，无法捕捉多步骤任务中风险的累积和演变。PASTABench 旨在解决这一问题，通过多轮轨迹模拟风险逐步显现的过程，并评估代理在风险早期信号出现时能否及时干预。

### 5. 方法概览

- 任务 / 环境: 包含 1,139 条多轮轨迹，覆盖 5 个主要风险类别（直接健康与身体危害、程序安全差距、物理环境与基础设施损害、信息与网络安全、经济与数字资产破坏）和 13 个子类别，涉及数字和物理环境。
- 变量 / 干预设计: 每个轨迹标注了最早信号轮次（tes）和触发轮次（ttrigger），定义最优干预窗口（OIW）。评估模型在每一步决定是否干预，并输出风险类别。
- 评价指标: 使用完美干预（Perfect Interruption）、过早干预（Early）、过晚干预（Late）和准时率（On-Time Rate）等指标。
- 模型比较: 评估了 16 个 LLM，包括 GPT-4o、Gemini 系列、Grok-3、DeepSeek-R1、Qwen 系列和 Llama 系列。
- 我的理解: 该方法将安全监控视为一个序列决策问题，要求模型在每一步基于历史信息判断是否干预，并识别风险类型。通过时间锚点定义最优干预窗口，量化干预的及时性和准确性。

### 6. 关键发现

- 主动安全监控性能普遍较低: 最佳模型（GPT-4o）的完美干预率仅为 40.74%，平均准时率约为 52.95%，表明当前 LLM 在主动安全监控方面仍有很大提升空间。
- 词汇过拟合现象普遍: 当风险词汇被中和后，许多模型（尤其是较小的开源模型）的主动干预能力大幅下降，表明它们依赖表面词汇而非真正的风险理解。
- 诊断精度差距显著: 许多模型能识别风险大类（Level-1），但无法准确分类具体子类别（Level-2），导致有效干预率远低于良好干预率。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 代理系统需要内置主动安全监控机制，能够在风险早期信号出现时及时干预，而非事后补救。
- 对 Skill: 模型需要提升对风险的理解能力，而非依赖表面词汇，这要求更强的推理和情境理解能力。
- 对 Memory: 监控器需要维护历史上下文，以识别风险的累积效应，这需要有效的记忆机制。
- 对评测: 评估应包含时间维度，衡量干预的及时性和准确性，而不仅仅是最终结果。

### 11. 局限性

- 基准测试仅覆盖有限的风险类别和场景，可能无法全面代表真实世界的复杂性。
- 轨迹合成依赖 LLM，可能引入偏差，影响评估的客观性。
- 评估指标主要关注干预时机，未充分考虑干预后的行动效果。

### 12. 我的看法 / 个人笔记

PASTABench 提出了一个重要的评估框架，将安全监控从静态转向动态，并引入时间维度。其发现揭示了当前模型的不足，尤其是词汇过拟合问题，为未来研究指明了方向。然而，基准测试的构建和评估方法仍有改进空间，例如增加更多真实场景和考虑干预后的影响。

### 14. 总结

## 2. Agent-Editing World Model: Rethinking World Modeling for LLM Agents

**Topics:** LLM Agent, World Model, Action Judge, State Revision, Task-State Contamination
**Authors:** Shuang Sun, Guoxin Chen, Fanzhe Meng, Jia Deng, Huatong Song, Jinhao Jiang, Wayne Xin Zhao, Hongteng Xu, Ji-Rong Wen
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.28416v1) | [PDF](http://arxiv.org/pdf/2609.28416v1.pdf)

### 1. 一句话结论

提出Agent-Editing World Model (AEWM)，通过Action Judge和State Revision编辑智能体的推理-动作对，建模决策对任务进展的影响，而非预测环境观测，从而缓解任务状态污染并提升长程任务性能。

### 2. 为什么重要

传统语言世界模型预测高熵、依赖执行的环境观测，价值有限且可能引入虚构信息。AEWM直接建模决策效果并编辑智能体状态，为提升LLM智能体在长程任务中的可靠性提供了新范式，且通过AEWM-RFT可将编辑模式内化到智能体中，无需在线指导。

### 3. 研究问题

1. 语言世界模型应预测什么才能有效支持长程LLM智能体？
2. 如何识别并纠正智能体推理-动作中的任务状态污染？

### 4. 背景与问题设定

LLM智能体在长程任务中常因任务状态污染（如接受未经验证的假设、保留过时计划）而失败。现有语言世界模型预测环境观测，但观测高熵且依赖执行，预测困难且对决策帮助有限。因此需要重新思考世界模型的目标：从预测观测转向建模决策效果并编辑智能体状态。

### 5. 方法概览

- 任务 / 环境: 跨域环境：Search（BrowseComp, DeepSearchQA）、Terminal（Terminal-Bench 2.0）、软件工程（SWE-Bench Pro, Doc2Repo, NL2Repo）。
- 变量 / 干预设计: AEWM包含Action Judge（将决策分类为critical/exploratory/noisy）和State Revision（对noisy决策生成新的推理-动作对）。EditAct在真实执行前选择性编辑智能体提议的推理-动作。训练数据：52B tokens中训练，120K示例（60K Action Judge + 60K State Revision）。
- 评价指标: Action Judge评估：准确率和宏F1；智能体性能：各基准的准确率、F1、解决率或平均测试通过率。
- 模型比较: 与ReAct、Step-level Best@3、Trajectory-level Best@3比较；Action Judge与Gemini-3-Pro、GLM-5.2、Qwen3.7-Max、GPT-5.5、DeepSeek-V4-Pro比较。
- 我的理解: AEWM的核心创新在于将世界模型从观测预测转变为决策效果预测，并通过编辑智能体状态来主动干预，而非被动预测。这种'编辑'机制直接修正智能体的推理和行动，从而避免错误累积。

### 6. 关键发现

- AEWM在Action Judge上显著优于前沿模型: AEWM在Action Judge基准上达到70.5%宏F1，超过最强基线（Gemini-3-Pro等）10.6个百分点，表明其能有效区分关键、探索性和噪声决策。
- EditAct提升智能体在六个基准上的性能: 在三个不同规模的智能体上，EditAct相比ReAct平均提升3.2-6.7分，尤其在BrowseComp和Terminal-Bench上提升显著。
- AEWM-RFT无需在线指导即可迁移性能: 通过拒绝采样微调，AEWM-RFT在三个领域上比Self-RFT提升2.2-2.6分，表明编辑模式可被内化到智能体中。
- 消融实验支持直接替换优于重采样和提示: 消融实验表明，EditAct超越智能体重采样和推理提示，支持直接替换当前推理-动作连续体，而非仅提供批评或引导重新生成。

## 3. EmbodiedMemory-Bench: Benchmarking Embodied Memory for Long-Horizon Embodied Tasks

**Topics:** 具身智能, 多模态大语言模型, 记忆系统, 长时程任务
**Authors:** Lizhou Liang, Xinyu Zhong, Miao Pan, Xiaohe Zhou, Xuanyu Liu, Qinfeng Li, Peng Li, Jintao Chen, Xuhong Zhang, Wenqi Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.28236v1) | [PDF](http://arxiv.org/pdf/2609.28236v1.pdf)

### 1. 一句话结论

提出 EmbodiedMemory-Bench 基准和 Embodied-Memorizer 外部记忆系统，系统评估并提升具身智能体的记忆能力。

### 2. 为什么重要

现有具身智能体在长时程任务中常因记忆缺陷而失败，该工作首次系统性地将记忆能力分解为四个维度，并提供了大规模基准和有效基线，为具身记忆研究奠定基础。

### 3. 研究问题

1. 当前多模态大语言模型在长时程具身任务中的记忆能力存在哪些具体缺陷？
2. 如何构建一个能够全面评估具身记忆能力的基准？
3. 外部记忆系统能否有效提升具身智能体的记忆表现？

### 4. 背景与问题设定

长时程具身交互要求智能体持续记忆并更新环境信息，但现有智能体在视觉记忆、动态状态跟踪、交互结果记录和经验泛化方面存在明显不足。现有基准未直接评估这些记忆能力，导致该问题未被充分研究。

### 5. 方法概览

- 任务 / 环境: 基于 AI2-THOR 和 ProcTHOR 构建的多房间虚拟家庭环境，支持导航、交互和状态变化。
- 变量 / 干预设计: 基准包含四个任务族：被动观察、动态跟踪、交互失败和经验泛化，每个任务族设计特定的记忆线索和干扰轨迹，要求智能体从历史交互中提取信息并完成后续任务。
- 评价指标: 主要指标为成功率（SR），并引入错误复发率（ERR）衡量智能体重复犯错的倾向。
- 模型比较: 评估了 16 种开源和专有 MLLM，以及多种多模态记忆系统，包括 GPT-5.4-mini、Gemini-3-Flash、Qwen3-VL 系列等。
- 我的理解: 该基准通过精心构造的交互历史，将记忆能力分解为可独立评估的维度，并利用模拟器验证智能体是否真正利用记忆信息，而非仅依赖当前感知。

### 6. 关键发现

- 现有模型记忆能力普遍薄弱: 最强专有模型 Gemini-3-Flash 平均成功率仅 64.2%，开源模型大多低于 45%，且错误多源于记忆与历史矛盾。
- 记忆缺陷可归为四类: 细粒度视觉记忆遗忘（35%）、动态状态跟踪失败（18%）、交互结果未记录（31%）、经验泛化不足（7%），合计占失败原因的 91%。
- 外部记忆系统有效提升性能: 提出的 Embodied-Memorizer 将交互历史组织为空间、事件和场景记忆，在开源和专有模型上分别提升 16.4 和 23.6 个百分点。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 具身智能体需要显式记忆管理机制，外部记忆系统可显著提升长时程任务表现。

- 对 Memory: 记忆系统需支持空间、事件和场景的层次化组织，并能够更新和泛化。
- 对评测: 基准设计应覆盖多种记忆类型，并采用成功率与错误复发率结合的综合指标。

## 5. Can LLMs Reason About Runtime Behavior? A Repository-Level Dynamic Benchmark

**Topics:** 代码执行推理, 仓库级基准, LLM评估
**Authors:** Hamed Taherkhani, Mohammad Abdollahi, Melika Sepidband, Hridya Dhulipala, Tien N. Nguyen, Hadi Hemmati
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.28449v1) | [PDF](http://arxiv.org/pdf/2609.28449v1.pdf) | [Code](https://github.com/HamedTaherkhani/SWE-Flux/tree/master)

### 1. 一句话结论

SWE-FLUX是一个仓库级动态执行推理基准，包含480个实例，最佳模型准确率仅37%，揭示了LLM在运行时行为推理上的显著不足。

### 2. 为什么重要

该基准填补了现有仓库级QA基准仅评估静态代码理解、而执行推理基准局限于片段或函数的空白，为评估LLM在真实仓库环境中的动态执行推理能力提供了系统化、执行接地且确定性评估的工具。

### 3. 研究问题

1. 开源和专有LLM在仓库级动态执行推理任务上的表现如何？
2. LLM在不同运行时行为类别上的失败模式和根本原因是什么？
3. 基于输入扰动的自动基准变体生成方法能否产生更难的实例？

### 4. 背景与问题设定

LLM在编码任务中应用广泛，但其对代码执行推理的能力尚不明确。现有基准要么评估静态代码理解，要么局限于函数级执行推理，缺乏仓库级动态行为评估。SWE-FLUX通过自动从插桩测试执行中提取金标准答案，避免了人工编写或LLM评判的主观性，覆盖控制流、循环、程序状态、数据流、异常和程序不变量等七类运行时行为。

### 5. 方法概览

- 任务 / 环境: 12个真实Python仓库（如sympy、matplotlib等），固定提交版本，使用Docker容器和pytest测试执行。
- 变量 / 干预设计: 基准包含480个实例，分为单测试和多测试问题，覆盖七类运行时行为。金标准答案通过插桩测试执行自动提取，确保客观性。
- 评价指标: 准确率（accuracy），即模型回答与金标准答案的匹配程度。
- 模型比较: 评估了5个LLM，包括开源和专有模型，如GPT-5.4、Gemma4、GPT-OSS等。
- 我的理解: 该方法通过系统化分类和自动提取答案，构建了一个可扩展的基准，能够生成新变体以持续评估模型。

### 6. 关键发现

- 最佳模型准确率仅37%: 在SWE-FLUX上，表现最好的模型（GPT-5.4）准确率仅为37.71%，表明仓库级动态执行推理对当前LLM极具挑战性。
- 数据流推理最难: 运行时数据流是准确率最低的类别，仅6%，而程序不变量和局部控制流表现相对较好。
- 失败多为语义错误: 对299个错误答案的人工分析显示，93%是实质性语义失败，而非格式或数值偏差，说明模型在理解执行语义上存在根本缺陷。
- 自动变体生成有效: 输入扰动方法成功为89.7%的选定实例生成了有效变体，且这些变体对模型更具挑战性，降低了GPT-5.4的准确率至43.1%。
