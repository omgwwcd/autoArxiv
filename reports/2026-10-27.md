## 1. MiRL: Error-Targeted Reinforcement Learning for Correcting Terminal Agent Misbehaviors

**Topics:** Terminal Agent, Reinforcement Learning, Error-Targeted Learning
**Authors:** Runchu Tian, Zaid Khan, Zun Wang, Justin Chih-Yao Chen, Mohit Bansal
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.35697v1) | [PDF](http://arxiv.org/pdf/2610.35697v1.pdf) | [Code](github.com/runchu-tian/MiRL)

### 1. 一句话结论

MiRL通过错误画像识别通用错误行为，并从错误前缀开始强化学习，以数据高效的方式显著提升终端代理的任务成功率。

### 2. 为什么重要

该研究首次将错误定向学习应用于长时程终端代理任务，通过识别和纠正通用错误行为，大幅减少训练所需的rollout数量，为数据高效的代理训练提供了新范式。

### 3. 研究问题

1. 如何识别终端代理的通用错误行为？
2. 如何从错误前缀开始进行强化学习以高效纠正这些错误？

### 4. 背景与问题设定

终端代理需通过自然语言指令与命令行交互完成长时程任务。现有训练方法依赖大规模环境采样，成本高昂。错误定向学习虽在单轮任务中有效，但难以直接应用于多步终端任务，因为错误步骤常与任务特定相关，且从任务开始训练效率低下。

### 5. 方法概览

- 任务 / 环境: 终端环境：包含自然语言指令、容器和测试套件，代理通过执行shell命令完成任务。
- 变量 / 干预设计: MiRL首先对策略进行错误画像，识别通用错误行为；然后从错误前缀开始rollout，并引入行为奖励，要求rollout既通过测试又避免错误行为。
- 评价指标: 任务成功率（Terminal-Bench Lite和Terminal-Bench 2.1）以及错误行为重复率。
- 模型比较: 与TMax-4B（全量训练）、TMax-189、PivotRL和RaR+进行比较。
- 我的理解: MiRL的核心在于将错误分析结果直接融入RL训练，通过从错误点开始rollout和额外的行为奖励，使训练聚焦于纠正具体错误，从而提升数据效率。

### 6. 关键发现

- 错误行为集中性: 8种通用错误行为覆盖了52.1%的错误步骤，表明少量错误类型主导了失败。
- 性能提升: MiRL在Terminal-Bench Lite上达到51.8%的成功率，超过TMax-4B的47.4%，且仅使用35%的rollout。
- 错误行为减少: 训练后，策略重复错误行为的频率降低43%至57%。
- 基线对比: MiRL在Terminal-Bench Lite上至少领先TMax-189、PivotRL和RaR+ 4.2个百分点，在Terminal-Bench 2.1上至少领先2.2个百分点。
- 消融实验: 从错误前缀开始和添加行为奖励分别贡献了7.9和6.5个百分点的提升（Terminal-Bench Lite）。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: MiRL提供了一种可解释的代理改进方法，通过识别和纠正特定错误行为，可系统性地提升代理性能。
- 对 Skill: 错误定向训练可针对特定技能缺陷进行强化，提高技能学习的效率。
- 对 Memory: 从错误前缀开始训练可视为一种记忆重放机制，有助于代理记住并避免历史错误。
- 对评测: 错误画像可作为评估代理弱点的新维度，补充传统成功率指标。

### 11. 局限性

- 依赖LLM进行错误定位和修正，可能引入额外成本和不准确性。
- 错误行为分类可能受限于标注质量，且仅覆盖部分错误。
- 实验仅在单一基座模型（Qwen3.5-4B）上验证，泛化性未知。

### 12. 我的看法 / 个人笔记

MiRL是错误定向学习在长时程代理任务中的成功应用，其数据效率提升显著。未来可探索更自动化的错误画像方法，并扩展到更多代理类型。

## 2. VibeVideoBench:Evaluating Multimodal Agents on Code-Driven Video Generation

**Topics:** 多模态智能体, 代码驱动视频生成, 视频生成评估, 基准测试
**Authors:** Muxi Diao, Wenbin Xu, Lele Yang, Xuyang Ma, Yuzhe Chen, Jiankang Chen, Kaiyu Jiang, Changyi Liu, Haoyu Zhang, Hongyi Fu, Jianxiong Wang, Tianke Zhang, Haonan Fan, Yingxin Li, Bingyi Li, Xu Wang, Xuanyu Zheng, Bin Wen, Tingting Gao, Han Li, Wentao Zhang, Weiran Xu, Kongming Liang, Zhanyu Ma
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.35864v1) | [PDF](http://arxiv.org/pdf/2610.35864v1.pdf) | [Code](https://vibevideobench.github.io)

### 1. 一句话结论

VibeVideoBench 是首个针对通用多模态智能体在开放域代码驱动视频生成任务上的基准，包含239个任务和三层评估体系，实验表明现有前沿智能体系统远未解决该问题。

### 2. 为什么重要

该基准填补了现有视频生成评估的空白：传统像素生成模型无法保证精确文本、规则一致性和音画同步，而代码驱动视频生成通过程序化渲染实现这些属性。VibeVideoBench 首次系统评估了多模态智能体在真实场景下（如课堂讲解、论文解读、数据故事）自主生成完整带声音视频的能力，为智能体系统在视频创作领域的进步提供了关键测试平台。

### 3. 研究问题

1. 通用多模态智能体在代码驱动视频生成任务上的表现如何？
2. 现有前沿智能体系统在视频生成中的主要失败模式是什么？
3. 如何设计一个可扩展、证据驱动的评估协议来评判生成的视频？

### 4. 背景与问题设定

扩散视频模型能生成惊艳片段，但无法可靠渲染精确公式、正确图表、规则一致的游戏或与屏幕事件同步的旁白。代码驱动视频生成通过编写程序控制渲染器、TTS和ffmpeg，能实现精确、可编辑、可控时长和声音的视频。然而，现有评估要么针对短时无声片段，要么针对单一程序或静态视觉产物，缺乏对通用智能体端到端生成完整视频的评估。VibeVideoBench 旨在填补这一空白。

### 5. 方法概览

- 任务 / 环境: 每个任务在一个全新的Docker沙箱中运行，提供通用渲染工具链（Python、Node、无头浏览器、ffmpeg）和TTS命令行工具，限时1小时，所有网络流量被记录。
- 变量 / 干预设计: 任务由自然语言规范、可选只读资产包、机器可读交付规范、音频策略和创意自由声明组成。智能体需在截止时间前交付MP4视频、可编辑源项目和时序表。禁止调用图像或视频生成模型。任务来源包括四种真实世界来源：用户对代码视频工具的真实请求、真实视频的密集字幕、真实资产包（如3D扫描、游戏精灵）、讲座笔记和研究论文。
- 评价指标: 三层评估：L1程序检查（交付规范合规性）、L2任务特定rubric检查（通过率、严格成功率）、L3质量评分（五个维度：视觉质量、美学、内容逻辑、时序与运动、音频质量与音画同步）。
- 模型比较: 评估了9个前沿智能体系统（如GPT-6 Astra、Claude Opus 5.5等），每个系统在239个任务上各运行一次，共2151次评分运行。
- 我的理解: 该基准强调证据驱动的评估，L2检查要求时间戳证据，L3评分有任务特定的锚点描述。通过三层分离，可以区分交付失败、内容错误和质量差异。

### 6. 关键发现

- 基准远未解决: 即使最好的系统（GPT-6 Astra和Claude Opus 5.5）也在约四分之一的任务上失败于核心要求，表明代码驱动视频生成对当前智能体仍是重大挑战。
- 交付率是关键瓶颈: 视频是否生成（交付）与生成质量同等重要；约四分之三的丢失视频是由于最终渲染开始太晚、运行太慢或从未开始，而非内容错误。
- 评估协议有效: 三个独立的VLM评审小组在系统排名上达成一致，并与人类盲评偏好相符，但单个视频的评分仅中等一致，表明需要进一步改进评审一致性。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体需要更强的规划和时间管理能力，以确保在截止时间前完成渲染；同时需要改进自我检查机制，以发现和修复内容错误。
- 对 Skill: 代码驱动视频生成要求智能体掌握多种技能：编程、图形渲染、音频合成、视频编辑，以及跨模态的自我评估。
- 对 Memory: 长视频生成需要智能体在长时间内保持上下文一致性，这对记忆机制提出更高要求。
- 对评测: 该基准的评估协议（程序检查+rubric+质量评分）可推广到其他多模态生成任务，强调证据驱动和人类验证。

### 11. 局限性

- 任务规范可能无法完全覆盖真实用户需求的多样性。
- VLM评审在单个视频上的评分一致性中等，可能影响细粒度比较。
- 基准仅评估了代码驱动方法，未与像素生成方法直接对比。

### 12. 我的看法 / 个人笔记

VibeVideoBench 是一个设计精良的基准，填补了代码驱动视频生成评估的空白。其三层评估协议和证据驱动方法值得借鉴。然而，评审一致性问题提示我们需要更可靠的自动评估方法。未来工作可探索更细粒度的任务分解和更鲁棒的评审机制。

## 3. Profiling a Frontier Agent with EBench: From Direct Control to Harness with Policy

**Topics:** GUI Agent, 机器人操作, 多模态大语言模型, 视觉-语言-动作模型, 世界动作模型
**Authors:** Yifei Yao, Yude Zou, Guanbo Jiao, Xing Gao, Ning Gao, Yukai Wang, Jiantong Chen, Zihou Zhu, Xinyu Li, Ningyu Yan, Shuai Wang, Jianming Ma, Haoyu Guo, Weinan Zhang, Chunhua Shen
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.35832v1) | [PDF](http://arxiv.org/pdf/2610.35832v1.pdf) | [Code](https://internrobotics.github.io/EBench-Astra-Tech-Report/)

### 1. 一句话结论

GPT-6-Astra 在直接控制下与后训练策略性能相当，但通过策略调用（harness with policy）可显著提升整体成功率并降低 token 成本。

### 2. 为什么重要

该研究首次系统对比了前沿 MLLM 智能体与后训练 VLA/WAM 策略在统一基准上的表现，揭示了直接控制与策略调用两种模式的互补性，为设计更高效的机器人智能体框架提供了实证依据。

### 3. 研究问题

1. 在统一观测协议下，GPT-6-Astra 智能体直接控制与后训练 VLA/WAM 策略相比，性能如何？
2. 在 harness with policy 模式下，调用后训练策略能否弥补直接控制的不足，并带来哪些新的失败模式？

### 4. 背景与问题设定

前沿多模态大语言模型（MLLM）无需机器人特定训练即可控制机器人，但其能力与后训练策略（如 VLA 和 WAM）的对比尚不明确。现有研究多单独评估直接控制或策略调用，缺乏系统性对比。本文在 EBench 基准上，以 GPT-6-Astra 为核心，在相同观测协议下评估直接控制与 harness with policy 两种配置，覆盖 26 个任务、510 个测试片段。

### 5. 方法概览

- 任务 / 环境: EBench 仿真基准，基于 GenManip 和 Isaac Sim，使用 ARX Lift 2 双臂移动机器人，包含 26 个任务，覆盖家庭、零售、工业场景，测试泛化维度包括未见物体、背景、指令改写及混合扰动。
- 变量 / 干预设计: 两种配置：直接控制（智能体直接生成 EEF 路点）和 harness with policy（智能体可调用后训练 VLA π0.5 或 WAM InternW0-∆ 执行动作）。智能体通过工具调用控制机器人，观测仅包括 RGB 图像和本体感觉状态。
- 评价指标: 任务成功率（SR）和阶段完成分数（score），按任务平均后取平均。
- 模型比较: 对比 GPT-6-Astra 智能体（直接控制、harness with π0.5、harness with InternW0-∆）与八种后训练策略（包括 OpenWAM-α、InternW0-∆、Qwen-RobotManip、π0.5 等）。
- 我的理解: 该研究通过统一的观测协议和工具接口，将 MLLM 智能体与后训练策略置于同等条件下比较，并引入策略调用机制，探索两者协同的可能性。

### 6. 关键发现

- 直接控制下智能体性能与后训练策略相当: GPT-6-Astra 直接控制达到 46.7% 的整体成功率，优于多数后训练策略，且在短时任务上领先（73.2%），但长时任务、桌面操作和高精度接触丰富任务上表现较弱。
- 策略调用提升整体性能并降低 token 成本: harness with InternW0-∆ 达到 56.0% 成功率，超过所有后训练策略；token 成本降低超过一半。
- 智能体与策略互补但协调不足: 策略调用弥补了直接控制在长时任务上的不足，但存在策略调用过度、子目标传递缺失、抓取中断等问题，导致性能低于组件上限。

## 4. FOCUS: Active Critic Learning for Long-Horizon Language Model Agents

**Topics:** GUI Agent, Reinforcement Learning, Long-Horizon Language Model Agents
**Authors:** Zhengping Jiang, William Jurayj, Liaoyaqi Wang, Chunsheng Zuo, Anqi Liu, Benjamin Van Durme
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.35801v1) | [PDF](http://arxiv.org/pdf/2610.35801v1.pdf) | [Code](https://github.com/zipJiang/FOCUS)

### 1. 一句话结论

FOCUS通过主动学习式选择性分支，在有限预算下高效训练评论家网络，显著提升长程智能体在多个基准上的性能。

### 2. 为什么重要

长程语言模型智能体面临稀疏奖励和信用分配难题，现有方法要么评论家不准确，要么采样成本高昂。FOCUS提出一种主动评论家学习框架，通过选择性分支优化价值估计，在同等预算下显著超越GRPO和VinePPO，为长程智能体强化学习提供了新范式。

### 3. 研究问题

1. 如何高效分配有限的采样预算以改进评论家网络的价值估计？
2. 如何利用压缩诱导的段边界进行有效的信用分配？
3. FOCUS在长程任务上相比无评论家方法（如GRPO）和基于树的方法（如VinePPO）的优势如何？

### 4. 背景与问题设定

长程语言模型智能体在复杂任务中需要多步决策，但最终奖励稀疏，难以对早期动作进行信用分配。评论家网络可提供中间状态的价值估计，但训练评论家需要大量采样，成本高昂。现有方法如GRPO使用组相对奖励，但无法提供细粒度信用；VinePPO通过树搜索采样但均匀分配预算，效率低。FOCUS旨在通过主动学习选择最有价值的节点进行分支，以最小化评论家误差。

### 5. 方法概览

- 任务 / 环境: 长程智能体任务，包括数学推理（MATH）、法律推理（DeonticBench）、深度搜索（BrowseComp-Plus）和代码定位（LocBench）。智能体通过工具调用与环境交互，如搜索、打开、读取等。
- 变量 / 干预设计: FOCUS在每次迭代中，根据评论家预测和已观测结果，计算每个候选节点的期望误差减少量，选择最优节点进行额外采样（分支）。采样结果用于更新评论家训练目标，并通过TD(λ)优势进行策略更新。
- 评价指标: 主要指标为任务准确率（如DeonticBench的准确率、BrowseComp-Plus的准确率、LocBench的Acc@1和Acc@5）。同时评估训练过程中的奖励、生成token数、评论家误差等。
- 模型比较: 与GRPO和VinePPO对比，使用相同的基础模型（Qwen3.5-9B和27B）和训练预算。
- 我的理解: FOCUS的核心创新在于将评论家学习视为主动学习问题，通过选择信息量最大的状态进行采样，从而在有限预算下最大化评论家精度。其使用压缩段作为状态边界，使得价值估计和信用分配更高效。

### 6. 关键发现

- FOCUS在多个长程基准上取得最优性能: 在Qwen3.5-9B规模下，FOCUS在DeonticBench整体准确率56.5%，比GRPO高4.1个百分点；在BrowseComp-Plus上55.4%，比GRPO高7.2个百分点；在LocBench上File@1和File@5分别为72.4%和81.6%，均优于基线。
- FOCUS训练效率更高: 在MATH初步实验中，FOCUS在相同更新次数下准确率提升更快，且生成token数更少，表明其价值估计更准确，减少了无效探索。
- 评论家误差随预算增加而降低: 诊断实验显示，随着分支预算增加，评论家的价值估计误差显著下降，而均匀采样的VinePPO误差下降较慢。

## 5. EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation

**Topics:** LLM路由, 多智能体系统, 自进化, 在线策略蒸馏, 强化学习
**Authors:** Yitao Xiao, Xu Zhang, Ye Cheng, Shaoyong Guo, Yan Sun, Ziyue Zhu, Sitao Xie, Guo Tong, Haoran Luo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.35690v1) | [PDF](http://arxiv.org/pdf/2610.35690v1.pdf) | [Code](https://github.com/CenYangtze/EvoRouter)

### 1. 一句话结论

EvoRouter通过洞察引导的在线策略蒸馏，将跨任务执行经验转化为条件化路由规则，在提升多智能体配置准确率的同时大幅降低推理成本。

### 2. 为什么重要

多智能体系统在真实Web服务中面临组合爆炸的配置空间和稀疏奖励，EvoRouter提供了一种自进化框架，能够从历史轨迹中提炼可复用的条件化路由知识，并通过在线蒸馏与成本感知强化学习实现性能与成本的联合优化，为大规模智能体路由提供了高效且可扩展的解决方案。

### 3. 研究问题

1. 如何从多智能体配置与执行结果中提炼可复用的条件化路由知识？
2. 如何将提炼出的洞察内化到路由策略中，以改善预执行规划决策？

### 4. 背景与问题设定

随着LLM智能体在Web服务中的广泛应用，多智能体系统（MAS）的配置空间（如模型选择、协作模式、智能体数量、交互轮次、技能分配等）呈组合爆炸式增长。现有路由方法要么仅优化模型选择，要么依赖稀疏的最终奖励，难以对相互依赖的配置决策提供细粒度监督。因此，需要一种机制从跨任务的历史轨迹中提取条件化路由规则，并将其内化到路由策略中，以在性能和成本之间取得平衡。

### 5. 方法概览

- 任务 / 环境: 多智能体系统（MAS）路由环境，涵盖数学、代码、多模态问答、知识、通信等21个场景，每个任务需配置模型、协作模式、智能体数量、交互轮次和技能。
- 变量 / 干预设计: EvoRouter包含两个阶段：初始化阶段通过SFT学习基础路由协议；进化阶段通过洞察蒸馏专家周期性地从在线轨迹中提炼条件化路由规则，并利用在线策略蒸馏（OPD）和成本感知强化学习（RL）联合优化路由策略。
- 评价指标: 任务成功率（Accuracy）、推理计算成本（MAS FLOPs）、以及性能-成本联合效用（Utility）。
- 模型比较: 与多种基线比较，包括RouteLLM、Router-R1、MasRouter、DAAO、MAS-Orchestra、Skill-MAS、RSI-Router等，覆盖单模型选择、多轮调用、MAS配置等不同路由方法。
- 我的理解: EvoRouter的核心创新在于将经验提炼与策略学习结合：洞察蒸馏专家从历史轨迹中提取条件化规则（如任务类型与资源扩展的匹配），而在线策略蒸馏则将这些规则转化为token级别的监督信号，配合成本感知的组相对策略优化，使路由策略在预执行阶段就能做出更优的配置决策。

### 6. 关键发现

- 性能提升: 在21个场景中，EvoRouter平均准确率达68.69%，比最强路由基线高出7.23个百分点。
- 成本大幅降低: 相比基线，EvoRouter将推理计算成本降低50.95%，同时保持或提升准确率。
- 跨域泛化: 在域外基准上，EvoRouter展现出更强的鲁棒性和泛化能力，优于现有路由方法。
