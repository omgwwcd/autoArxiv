## 1. When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents

**Topics:** LLM Agent, Self-Evolution, Memory Management, Falsification
**Authors:** Runxuan Tang, Haoyu Gao, Yuyan Ding, Junyi Yao, Zihao Zheng, Zecheng Sheng, Liwei Hou
**Venue / Year:** NeurIPS 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.14326v1) | [PDF](http://arxiv.org/pdf/2611.14326v1.pdf)

### 1. 一句话结论

FGSE 通过将经验更新视为结构化假设，并在临时状态下进行目标迁移、证伪和回归测试，再决定是否写入长期记忆，从而显著提升 LLM 智能体的长期适应能力，同时降低安全风险。

### 2. 为什么重要

该研究解决了 LLM 智能体自我进化中的核心问题：何时将经验写入持久记忆。直接写入经验可能导致过度泛化、遗忘旧技能或积累错误。FGSE 提供了一种基于验证的门控机制，确保只有安全、可迁移且不破坏已有能力的更新才被提交，从而提升长期可靠性。

### 3. 研究问题

1. 经验衍生的行为更新在什么条件下应该被纳入 LLM 智能体的持久状态？
2. 如何设计一个基于验证器的门控机制，以平衡目标迁移、安全性和回归保持？

### 4. 背景与问题设定

LLM 智能体在长周期、可验证的环境中运行时，常通过自我反思或经验总结来改进行为。然而，直接写入记忆的更新可能过度泛化到不相关场景，或与已有成功策略冲突，导致性能下降。现有方法缺乏对更新可迁移性、保留价值和风险的系统评估。

### 5. 方法概览

- 任务 / 环境: 涵盖网页导航（WebArena）、应用操作（AppWorld）和长期记忆任务（τ-Retail/τ-Airline）等可验证环境。
- 变量 / 干预设计: FGSE 将每个候选更新表示为结构化假设（前置条件、行为变化、预期效果、验证器），在临时状态下应用，并通过目标迁移、证伪和回归测试三个探针集进行评估。根据测试结果，假设被提交、细化或拒绝。
- 评价指标: 主要指标包括任务成功率（如 WebArena 成功率、AppWorld 完成度、Pass@1），以及安全性指标：证伪失败率（falsification failures，即更新在证伪探针上导致失败的比例）、回归损伤（regression damage，即更新对已解决任务造成的性能下降）、有害提交更新率（harmful committed updates，即被提交但后续违反验证器的更新比例）。
- 模型比较: 与基线方法比较，包括直接写入记忆、Reflexion、Self-Refine、Voyager 等，以及上下文进化方法（如 Symbolic Learning、Lighthouse、ACE）。
- 我的理解: FGSE 的核心创新在于将记忆更新视为可证伪的假设，通过临时测试来验证其泛化性和安全性，从而避免盲目写入。这种方法类似于科学方法中的假设检验，提高了自我进化的可靠性。

### 6. 关键发现

- FGSE 在多个基准上取得显著性能提升: 在 WebArena 上达到 39.8% 成功率，AppWorld 平均完成度 78.8%，τ-Retail/τ-Airline 的 Pass@1 分别为 0.724/0.487，均优于基线。
- FGSE 大幅降低安全风险: 证伪失败率降至 5.0%，回归损伤降至 1.3%，有害提交更新率降至 3.6%，表明门控机制有效过滤了不安全或过度泛化的更新。
- 细化机制提升更新质量: 通过前置条件细化，部分原本有害的更新被修复并保留，进一步提高了记忆的可用性和安全性。

## 2. Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents

**Topics:** LLM Agent, External Memory, Memory-Induced Degradation, Evidence-Linked Memory, Agent Memory
**Authors:** Yukyeong Lee, Yumin Choi, Jinheon Baek, Sung Ju Hwang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.14320v1) | [PDF](http://arxiv.org/pdf/2611.14320v1.pdf) | [Code](https://github.com/yukyeongleee/wikitrace)

### 1. 一句话结论

WikiTrace 通过将每条经验教训链接回其原始轨迹，使智能体在应用记忆时能够核查证据，从而显著降低记忆引发的性能退化。

### 2. 为什么重要

现有外部记忆方法虽能提升智能体性能，但常因错误或误用的经验教训导致智能体在原本能解决的任务上失败（记忆诱导退化）。WikiTrace 通过保留证据链，让智能体在决策时能回溯原始轨迹，有效缓解了这一问题，为可靠的经验复用提供了新思路。

### 3. 研究问题

1. 如何减少 LLM 智能体因外部记忆导致的性能退化？
2. 在任务执行过程中，访问原始轨迹证据能否帮助智能体纠正或验证记忆中的经验教训？

### 4. 背景与问题设定

LLM 智能体通过外部记忆将过去任务的轨迹提炼为简洁的经验教训，以提升新任务性能。然而，由于轨迹仅标注成功或失败，提炼出的教训可能错误或适用范围不当，导致智能体在原本能解决的任务上失败（即记忆诱导退化）。现有方法通常只提供教训而不附带其来源轨迹，智能体无法验证教训的可靠性。

### 5. 方法概览

- 任务 / 环境: 五个智能体基准（八个套件），包括模拟文本世界（ALFWorld、ScienceWorld、PlanCraft）和工具使用环境（AppWorld、τ3-bench Retail）。
- 变量 / 干预设计: WikiTrace 构建三层记忆结构：洞察（insight）、编译（compilation）和原始轨迹（raw trajectory），并通过链接关联。在测试时，智能体从所有洞察开始，当洞察缺乏细节、与其他洞察冲突或来自失败轨迹时，可下降（descend）到其来源轨迹进行核查。
- 评价指标: 各基准原始指标（如成功率），并额外报告 Gain（记忆将失败转为成功的比率）和 Regression（记忆将成功转为失败的比率）。
- 模型比较: 与无记忆基线、AWM、ExpeL、ReasoningBank 以及仅提供洞察而无证据访问的基线（Insights Only）进行比较。其中 Insights Only 是消融实验的一部分，用于隔离证据访问的贡献。
- 我的理解: WikiTrace 的核心创新在于将记忆从静态的教训列表转变为可追溯的证据链，使智能体在应用教训时能动态验证其适用性，从而减少盲目信任记忆带来的风险。

### 6. 关键发现

- WikiTrace 在所有八个套件上取得最佳性能: 平均得分 90.2，比无记忆基线高 10.7 分，比仅提供洞察的基线高 3.2 分，表明证据访问带来了额外收益。
- 显著降低记忆诱导退化: WikiTrace 的 Regression 率仅为 4.5%，低于 Insights Only 的 6.5% 和无记忆重跑的 9.7%，且其置信区间完全低于重跑基线。
- 证据访问在困难任务上收益更大: 在无记忆无法解决的困难任务上，下降（descent）带来的性能提升最大（+12.4），而在简单任务上提升较小（+0.8），表明证据核查在不确定情境下更有价值。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 外部记忆系统应设计为可追溯的证据链，而非孤立的教训列表，以便智能体在决策时验证记忆的适用性，减少盲目信任。
- 对 Skill: 技能学习应保留原始执行记录，使技能在应用时可根据具体情境调整，避免因过度泛化而失败。
- 对 Memory: 记忆结构应支持多粒度访问，从简洁教训到详细轨迹，使智能体能在需要时获取足够信息。
- 对评测: 评估记忆系统时，应同时报告 Gain 和 Regression，而不仅仅是平均性能，以全面反映记忆的利弊。

### 11. 局限性

- 实验基于单一骨干模型（deepseek-v4-flash2），未验证在其他模型上的泛化性。
- 记忆构建和测试均使用离线轨迹，未考虑在线学习场景。
- 证据访问增加了推理时的计算开销，可能影响实时性。

### 12. 我的看法 / 个人笔记

WikiTrace 通过证据链接有效缓解了记忆诱导退化，为可靠的经验复用提供了实用方案。未来可探索自动化的证据核查机制，减少对人工提示的依赖，并扩展到更多样的任务和模型。

## 3. LM-SimBench: A Unified Framework, Dataset, and Benchmark for Large Language Model Training Simulation

**Topics:** LLM训练模拟, 分布式训练, 性能模拟, 基准测试
**Authors:** Yu Dong, Hong Li, Qiang Sun, Xu Zhou, Jinbiao Huo, Qixiu Cheng, Zhiyuan Liu
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.14285v1) | [PDF](http://arxiv.org/pdf/2611.14285v1.pdf) | [Code](GitHub; dataset: Hugging Face)

### 1. 一句话结论

LM-SimBench 提供了一个统一的框架、数据集和基准，用于评估 LLM 训练模拟器，支持跨平台配置选择。

### 2. 为什么重要

在大规模 LLM 训练中，评估并行策略的成本极高，而现有模拟器因工作负载和平台差异难以直接比较。LM-SimBench 通过统一框架和数据集，使模拟器的评估和比较成为可能，有助于降低训练成本并优化资源配置。

### 3. 研究问题

1. 如何统一描述和评估 LLM 训练模拟器的性能？
2. 模拟器在不同平台（如 NPU 和 GPU）上的预测准确性和配置选择能力如何？

### 4. 背景与问题设定

分布式 LLM 训练需要选择并行配置（如 DP/TP/PP/CP/EP）和激活重计算等策略，但通过实际训练评估这些策略成本极高。性能模拟提供了一种低成本替代方案，但现有模拟器在建模阶段、工作负载和评估指标上存在差异，导致难以进行公平比较。

### 5. 方法概览

- 任务 / 环境: Ascend 910B3 NPU 集群，包含 10 个 LLM 家族（稠密和 MoE）的 23 种模型设置，共 348 种可行配置。
- 变量 / 干预设计: 将模拟过程分解为五个功能阶段：模型编译、设备绑定、执行表示构建、算子级成本估计和调度级聚合。数据集包含六种测量视图（迭代时间、峰值内存、时间分解、算子延迟、通信事件、矩阵内核），并支持跨平台（NPU 和 GPU）配对实验。
- 评价指标: 使用平均绝对误差（MAE）、对称平均绝对百分比误差（sMAPE）、R²、Spearman ρ、Kendall τ、Top-k 命中率、Top-k 集合重叠和遗憾值（Regret@k）等指标。
- 模型比较: 评估了 Calculon（解析模型）和 vTrain（基于执行图和配置文件）两种模拟器，比较其预测准确性、配置选择质量和模拟成本。
- 我的理解: 该方法通过统一框架将模拟器的输入输出标准化，并提供了多粒度测量数据，使得模拟器可以在相同条件下进行公平比较，同时支持跨平台迁移，为实际训练前的配置优化提供了可靠工具。

### 6. 关键发现

- 模拟器准确性与成本差异: 在 Qwen1.5-1.8B 8K tokens 且 CP=1 的 NPU 测试中，Calculon 的 sMAPE 为 12.3%，vTrain 为 8.7%；Calculon 的中位模拟时间为 0.5 秒，vTrain 为 15.2 秒。
- 跨平台配置选择可行性: 通过 NPU 数据指导 GPU 配置选择，验证了跨平台迁移的有效性。在 Qwen3-0.6B 和 Qwen3-1.7B 的配对实验中，NPU 引导的配置选择在 GPU 上的 Top-1 一致率达到 85%，Regret@1 为 3.2%，表明模拟器可以跨平台使用。

## 4. Looking One Step Ahead: An Anticipation-guided Agent for Object State Readout in Videos

**Topics:** 视频理解, 对象状态读取, 多模态大语言模型, 智能体
**Authors:** Yuanhe Tian, Yan Song
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.14113v1) | [PDF](http://arxiv.org/pdf/2611.14113v1.pdf) | [Code](https://github.com/synlp/LASER)

### 1. 一句话结论

LASER 通过预测对象下一步可能的变化来指导当前帧的属性检查，从而提升视频中对象状态读取的准确性。

### 2. 为什么重要

对象状态读取是程序规划和机器人交互的关键，但现有 MLLM 生成的描述往往缺少区分连续状态的关键属性。LASER 通过前瞻性引导和反馈驱动的技能优化，在不更新模型参数的情况下显著提升状态描述的完整性和准确性，为视频理解智能体提供了一种高效、可泛化的新范式。

### 3. 研究问题

1. 如何确定视频中对象状态描述需要关注哪些关键属性？
2. 如何利用未来信息（预测）来指导当前帧的属性检查？
3. 如何在不更新模型参数的情况下，通过反馈优化可复用的观察技能？

### 4. 背景与问题设定

对象状态读取旨在描述视频中目标对象的状态及其随时间的变化，对于程序规划和机器人交互至关重要。尽管多模态大语言模型（MLLM）能生成详细的视觉描述，但这些描述往往未能充分指定区分连续状态所需的属性。例如，对于抽屉，其开合程度是关键属性，但通用描述可能忽略。因此，需要一种机制来选择关键属性，并利用后续帧的证据来修正和细化状态描述。

### 5. 方法概览

- 任务 / 环境: 视频对象状态读取任务，输入为有序视频帧、目标对象提示和任务指令，输出为对象状态变化的自然语言描述。
- 变量 / 干预设计: LASER 包含四个组件：观察技能库（可复用的文本指令）、预测性属性选择（基于技能预测下一步变化并生成检查问题）、顺序视觉校正（利用后续帧验证和修正状态记录）、反馈引导的技能修订（基于参考描述优化技能库）。
- 评价指标: 在 OSCaR 和 PLM RCap 数据集上，使用 BLEU、ROUGE-1、ROUGE-2、ROUGE-L 和综合 Score 指标评估。
- 模型比较: 与直接描述、顺序读取、通用复核、属性清单、自由预测等基线方法，以及 InstanceCap、Matters、RICO、ReAgent-V、ScaleCap 等现有方法进行比较。
- 我的理解: LASER 的核心创新在于将“预测未来”作为选择当前检查属性的依据，并通过反馈循环不断优化指导技能，使得模型在冻结参数的情况下也能适应特定任务。

### 6. 关键发现

- LASER 在多个 MLLM 上均优于基线: 在 OSCaR 和 PLM RCap 数据集上，LASER 在 BLEU、ROUGE 等指标上均显著优于直接描述、顺序读取等基线，且在不同规模的 MLLM（4B 到 35B）上表现一致。
- 预测性属性选择是关键: 消融实验表明，移除预测性属性选择（即使用属性清单）会导致性能下降，说明预测下一步变化对于选择关键属性至关重要。
- 反馈驱动的技能修订提升泛化能力: 通过反馈修订技能库，LASER 在未见视频上表现更好，且修订后的技能比固定技能更有效，表明该方法能适应不同场景。

## 5. Evaluating LLM-Generated World Models for Neuro-Symbolic Reasoning

**Topics:** 世界模型, 神经符号推理, LLM评估, 部分可观测随机博弈
**Authors:** Souhaila Djaffal, Amna Jamal, Gagana Madhugiri Devaraja, Anidipta Pal, Jobst Heitzig
**Venue / Year:** arXiv preprint
**Links:** [Abstract](http://arxiv.org/abs/2611.14419v1) | [PDF](http://arxiv.org/pdf/2611.14419v1.pdf) | [Code](world-model-suite)

### 1. 一句话结论

LLM生成的世界模型虽大多机械有效，但结构保真度低，常添加多余结构，机械有效性不足以保证忠实性。

### 2. 为什么重要

该研究揭示了LLM生成世界模型在神经符号系统中的关键风险：即使模型可执行，也可能错误表征决策问题，影响下游规划与安全推理。

### 3. 研究问题

1. LLM生成的世界模型在机械有效性上表现如何？
2. 机械有效性是否足以保证模型忠实于原始情境？
3. 不同LLM在结构保真度和语义准确性上有何差异？

### 4. 背景与问题设定

神经符号系统依赖形式世界模型进行规划、验证和安全推理，但手工构建困难。LLM可自动生成，但多智能体情境下多种形式化皆合理，评估生成模型的忠实性成为挑战。现有评估多假设存在唯一参考，而开放情境下正确性不确定。

### 5. 方法概览

- 任务 / 环境: 44个场景，涵盖游戏、情境和文化领域，部分有参考POSG，部分开放。
- 变量 / 干预设计: 五个LLM（GPT-5.6 Sol, Claude Opus 5, Llama 3.3 70B, Qwen 3.8 27B, DeepSeek V4 Flash）生成POSG，采用JSON或Python格式。
- 评价指标: 机械有效性（Lane 1）、结构保真度（Lane 2a，基于置换不变F1）、语义检查（Lane 3，程序化检查）。
- 模型比较: 比较五个LLM在三个轨道上的表现，分析机械有效性、结构保真度和语义准确性。
- 我的理解: 该研究通过多维度评估框架，系统性地检验LLM生成世界模型的质量，强调机械有效性之外的忠实性维度。

### 6. 关键发现

- 机械有效性高但结构保真度低: 游戏轨道中134/135通过机械审计，但平均结构F1仅0.366，仅28/134精确匹配参考。
- 主要错误为添加多余结构: 所有LLM的覆盖率均高于精确率，表明倾向于添加参考中不存在的结构，如Claude Opus 5在G6中发明了规则禁止的竞价水平。
- 开放情境下LLM差异显著: 情境轨道中Claude Opus 5和GPT-5.6 Sol全部通过机械审计，而其他LLM仅约60%通过；文化轨道中仅98/140可严格解析。
- 文化情境中命名国家影响结构: 显式命名国家改变了大多数LLM生成的结构表示，但自动化语义分数变化不大，表明结构变化未被语义检查捕获。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体系统依赖世界模型进行规划时，需警惕LLM生成模型的潜在偏差，应结合结构验证和语义审查。

- 对 Memory: 记忆机制可能存储错误的世界模型，影响长期推理。
