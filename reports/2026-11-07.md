## 1. Agent-R$^2$: Scaling Agents for Realistic Productivity Work via Real-Source Data Synthesis

**Topics:** GUI Agent, 数据合成, 生产力任务, 智能体训练
**Authors:** Teng Pan, Zixuan Wang, Yuchen Yan, Qifei Wu, Yao Chen, Yingqi Qu, Ruiqing Zhang, Yongliang Shen
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.08219v1) | [PDF](http://arxiv.org/pdf/2611.08219v1.pdf) | [Code](https://github.com/ZJU-REAL/Agent-R2)

### 1. 一句话结论

Agent-R2通过从真实网络来源合成训练数据，使4B参数模型在GDPval和OfficeQA上超越235B模型，并缓解了智能体的捷径行为。

### 2. 为什么重要

当前智能体在真实生产力任务中表现不佳，主要因为缺乏反映真实工作意图、文件环境和交付物标准的训练数据。Agent-R2提出了一种可扩展的真实数据合成框架，显著提升了小模型的性能，为智能体训练数据构建提供了新范式。

### 3. 研究问题

1. 如何从真实网络来源合成反映真实工作流程和文件环境的训练数据？
2. 基于真实来源合成的数据能否提升智能体在生产力任务上的端到端性能？
3. 训练数据如何影响智能体的行为，特别是能否减少捷径行为并促进持续探索？

### 4. 背景与问题设定

大型语言模型在智能体推理和工具使用方面取得进展，但在完成长期专业工作流程、理解异构文件上下文和生成符合细粒度要求的交付物方面仍存在困难。现有训练数据要么依赖人工编写的工作流（扩展性差），要么使用LLM生成的文件（缺乏真实复杂性）。因此，需要一种可扩展的数据合成方法，能够反映真实工作意图、真实文件环境和交付物级评估标准。

### 5. 方法概览

- 任务 / 环境: 持久沙箱环境，提供bash、web_search、web_fetch、view_image等工具，任务涉及多步骤工作流和异构文件处理。
- 变量 / 干预设计: 数据合成流程分为三个阶段：1) 从网络语料中提取面向文件的工作流蓝图；2) 检索并验证真实公开文件作为附件；3) 合成指令和细粒度评分标准。训练采用SFT和基于评分标准的强化学习（GRPO）。
- 评价指标: GDPval和OfficeQA上的Pass@1和Pass@3，以及行为分析（如捷径行为频率、探索步数）。
- 模型比较: 与GPT-4.1、Gemini-2.5-Pro、Claude-Opus-4.5等闭源模型，以及DeepSeek-v3.1、GLM-4.7、Qwen3系列等开源模型对比。
- 我的理解: 该方法的核心在于利用真实网络数据作为数据源，通过自动化流程生成高质量训练样本，避免了人工标注的瓶颈，同时保证了数据的真实性和多样性。

### 6. 关键发现

- 性能显著提升: Agent-R2-4B在GDPval上达到51.0% Pass@1，超过Qwen3-235B-A22B-Thinking-2507（48.0%），在OfficeQA上达到14.8% Pass@1，同样超越该大模型（13.8%）。
- 缓解捷径行为: 训练后的模型减少了在未充分理解文件或验证信息的情况下生成表面合理交付物的行为，促进了更深入的探索和验证。
- 泛化能力: 在OfficeQA上的表现表明，训练不仅提升了交付物生成能力，还增强了文件检查、证据整合和数值提取等基础能力。

## 2. Terminal-style Mathematical Modeling Bench: The First Agentic and Verifiable Benchmark for Mathematical Modeling

**Topics:** 数学建模, 智能体基准, 可验证评估
**Authors:** Xiaojun Wu, Cehao Yang, Xuhui Jiang, Chengjin Xu, Jia Li, Jian Guo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.08237v1) | [PDF](http://arxiv.org/pdf/2611.08237v1.pdf) | [Code](https://github.com/wxj630/terminal-bench-math-modeling)

### 1. 一句话结论

TB-MathModel 是首个将完整数学建模竞赛题转化为智能体终端任务，并通过方向感知单侧评分与双层可行性验证（程序门+Lean 4）实现可复现、可机器检查的基准。

### 2. 为什么重要

现有数学建模基准要么只评估求解器片段，要么用 LLM 评判报告，导致数值正确性和物理可行性未被验证。TB-MathModel 首次将完整竞赛题、智能体终端、可执行验证器和物理可行性检查结合，为长时程建模能力提供了可复现的量化信号，并支持收集智能体轨迹。

### 3. 研究问题

1. 如何将完整的数学建模竞赛题转化为智能体可执行的终端任务，并实现自动化评分？
2. 如何设计评分机制，使其既奖励接近人类优秀论文，又不惩罚超越锚点的结果？
3. 如何独立于锚点验证答案的物理可行性，避免看似合理但违反约束的答案？

### 4. 背景与问题设定

数学建模竞赛（如 CUMCM、MCM/ICM）要求将开放的现实问题转化为可辩护的定量答案，其交付物是假设-模型-求解-敏感性-建议的链条。现有基准要么只评估求解器片段（如 Mamo），要么用 LLM 评判报告（如 ModelingBench、MM-Bench），均未同时具备智能体性、可验证性和终端环境。TB-MathModel 填补了这一空白，将 18 个真实竞赛题（2023-2025）转化为容器化终端任务，要求智能体返回结构化 JSON，并针对数值核心进行评分和可行性验证。

### 5. 方法概览

- 任务 / 环境: 每个任务包含官方陈述、附件（xlsx/csv/pdf）、从 PDF 裁剪的 21 张图片，以及一个网络隔离的容器终端。智能体需在终端内操作，最终返回符合给定 schema 的单个 JSON 文件。
- 变量 / 干预设计: 评分采用方向感知的单侧评分：每个指标有明确语义方向（higher_is_better、lower_is_better、target_value、exact_value），达到或超过锚点（优秀论文复现值）即得满分，不惩罚超越。多参考评估使用所有可用的优秀论文作为参考面板，取平均得分；对于文献分裂任务（如 mcm-2024-c-tennis-momentum），明确标记并排除在排名之外。
- 评价指标: 主要指标为 O-EVAL（绝对得分，归一化到 [0,1]）和 MULTI-BO（相对于 Flash 基线的多参考增益指数，1.0 表示与基线持平）。可行性验证通过程序门（覆盖六种可判定不变量形式）和 Lean 4 证书层（624 个义务）实现，硬性失败将任务得分置零。
- 模型比较: 评估了七个多模态模型/工具链组合，包括 GPT-6 Astra + codex、Fable 5.1 + claude-code、DeepSeek V4.1 Flash + opencode 等，每个组合运行三个种子，报告均值和标准差。
- 我的理解: 该方法的核心创新在于将建模问题分解为可验证的数值核心，并通过多参考锚点和可行性门控，使评分既公平又严格。单侧评分避免了锚点偏差，而可行性验证则防止了看似合理但违反物理约束的答案。

### 6. 关键发现

- 最强模型达到 64.58% O-EVAL: GPT-6 Astra + codex 组合在三个种子上平均 O-EVAL 为 64.58±2.93，MULTI-BO 为 1.132；Fable 5.1 + claude-code 紧随其后（63.11±1.33，1.081）。
- 低成本模型性价比突出: DeepSeek V4.1 Flash + opencode 成本仅 2.54 美元，却达到 59.81±1.25 O-EVAL，约为最强模型性能的 92.6%，而成本仅为 1/100。
- 模型比锚点更正确: 在龙舞问题中，模型给出的答案被证明是正确的，而人类优秀论文的锚点有误，这凸显了独立可行性验证的重要性。
- 评分规则修正影响排名: 通过修正退化带和未固定单位等规则，某些任务的得分发生变化（如 stair-wear 从 72.67 变为 73.52），表明细致的评分设计对公平性至关重要。

## 3. RM-VLM: From Natural-Language Task Descriptions to Vision-Grounded Reward Machines

**Topics:** Reinforcement Learning, Reward Machines, Vision-Language Models, LLM
**Authors:** Roko Parac, Christos Ziakas, Leo Ardon, Alessandra Russo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2611.08308v1) | [PDF](http://arxiv.org/pdf/2611.08308v1.pdf)

### 1. 一句话结论

RM-VLM 利用 LLM 从自然语言任务描述自动生成奖励机，并以 VLM 作为标注函数，在三个非马尔可夫视觉任务上取得了比现有 VLM 奖励方法更高的成功率。

### 2. 为什么重要

该工作解决了奖励机在视觉环境中应用的关键瓶颈——标注函数的手工设计问题，通过 LLM 自动生成奖励机结构、VLM 自动进行视觉标注，使得奖励机能够直接用于图像观测的强化学习任务，显著提升了非马尔可夫任务的自动化程度和泛化能力。

### 3. 研究问题

1. RM-VLM 能否在没有预定义标注函数和任务特定奖励机的情况下解决非马尔可夫任务？
2. 将任务分解为奖励机是否比直接使用 VLM 提供更好的奖励和更快的学习？
3. RM-VLM 对 VLM 标注误差的鲁棒性如何？

### 4. 背景与问题设定

许多强化学习任务具有非马尔可夫奖励，即奖励依赖于历史状态和动作。奖励机通过有限状态自动机显式建模任务的时间结构，但传统方法需要人工设计标注函数来将观测映射到原子命题，这在图像观测或真实世界环境中难以实现。现有方法如 ARM-FM 依赖环境源码，GCR 需要人工标注，ISA 等方法假设标注函数可用。因此，如何自动从自然语言任务描述中生成奖励机并自动将视觉观测与原子命题关联，是一个亟待解决的问题。

### 5. 方法概览

- 任务 / 环境: 三个环境：GeoGrid（8x8 网格世界，符号视觉）、OGBench-Scene（连续控制机器人操作，渲染场景）、MiniWorld-Pickup（第一人称 3D 部分可观测环境）。任务包括序列、循环、逻辑、安全等非马尔可夫结构。
- 变量 / 干预设计: RM-VLM 使用 LLM 从自然语言任务描述生成原子命题和奖励机结构；使用 VLM 作为标注函数，预测图像中哪些命题成立；通过 RM 状态信念（概率分布）处理标注噪声；结合生成值学习（GVL）提供密集奖励信号。
- 评价指标: 任务成功率（task success rate），并与现有 VLM 奖励方法（如直接使用 VLM 打分）进行比较。
- 模型比较: 与直接使用 VLM 作为奖励模型的方法对比，以及消融研究（如去除状态信念、去除 GVL 等）。
- 我的理解: 该方法的核心创新在于将奖励机的生成和标注函数都自动化：LLM 负责结构生成，VLM 负责视觉语义理解，并通过概率信念和密集奖励增强鲁棒性和学习效率。

### 6. 关键发现

- RM-VLM 在三个领域均取得更高成功率: 在 GeoGrid、OGBench-Scene 和 MiniWorld-Pickup 上，RM-VLM 的任务成功率均高于现有 VLM 奖励方法，表明其有效性。
- 奖励机分解优于直接 VLM 奖励: 将任务分解为奖励机结构，相比直接使用 VLM 对整体任务打分，能提供更准确的奖励信号，从而提升学习性能。
- 状态信念机制增强鲁棒性: 通过维护 RM 状态信念而非确定性状态，RM-VLM 对 VLM 标注误差具有更好的鲁棒性，减少了错误标注对策略学习的负面影响。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: RM-VLM 使得智能体能够从自然语言指令中自动构建奖励结构，并利用视觉信息进行学习，适用于需要理解复杂任务顺序的领域，如机器人操作和导航。
- 对 Skill: 通过奖励机分解任务，可以更清晰地定义子目标，有助于技能学习和迁移。
- 对 Memory: RM 状态信念提供了一种记忆机制，使智能体能够跟踪任务进度，处理部分可观测环境。
- 对评测: 提供了一种无需人工标注的奖励生成方法，可用于自动评估智能体在非马尔可夫任务上的表现。

### 11. 局限性

- VLM 标注的准确性仍有限，在复杂视觉场景中可能出错。
- LLM 生成的奖励机可能不完美，需要人工验证。
- 实验环境相对简单，真实世界应用仍需进一步验证。

### 12. 我的看法 / 个人笔记

RM-VLM 是一个很有前景的方向，它结合了 LLM 和 VLM 的优势，实现了奖励机的自动化生成和标注。未来可以探索更复杂的任务分解和更鲁棒的信念更新机制，以及扩展到真实机器人平台。

## 4. NPCBench: A Clinical Apprenticeship Benchmark for Multimodal Care-Pathway Reasoning in Nasopharyngeal Carcinoma

**Topics:** 医学人工智能, 多模态推理, 临床路径推理, 鼻咽癌, 基准测试
**Authors:** Pengkai Wang, Wei-Wei Zhang, Yan Li, Min Tang, Zhitian Hou, Zeyu Liu, Guanghao Zhu, Yuanyi Wang, Yanggan Gu, Wenjun Wang, Minheng Ni, Congkai Xie, Zhijie Sang, Jianmin Wu, Ying Sun, Hongxia Yang
**Venue / Year:** NeurIPS 2026 (Track on Evaluations and Datasets)
**Links:** [Abstract](http://arxiv.org/abs/2611.08369v1) | [PDF](http://arxiv.org/pdf/2611.08369v1.pdf) | [Code](https://github.com/)

### 1. 一句话结论

NPCBench 通过临床学徒制框架评估多模态大模型在鼻咽癌诊疗路径中的综合能力，发现模型在独立任务上表现良好，但在整合视觉证据与纵向决策时存在显著“组合鸿沟”。

### 2. 为什么重要

现有医学基准多聚焦于孤立问题或静态病例，无法反映真实临床中模型需整合多模态证据并随时间调整决策的复杂性。NPCBench 首次以鼻咽癌为场景，构建了从指南知识到纵向护理路径的渐进式评估体系，揭示了模型在组件技能与整体路径成功之间的差距，为医学AI的临床适用性评估提供了新范式。

### 3. 研究问题

1. RQ1: 模型能否将指南知识转化为病例层面的规划能力？
2. RQ2: 模型的分期预测是否真正基于准确的视觉证据解读？
3. RQ3: 模型在纵向护理路径中能否保持决策的一致性和正确性？
4. RQ4: 自动化咨询评分与医生评估的一致性如何？

### 4. 背景与问题设定

医学大语言模型（LLM）和多模态大模型（MLLM）在考试型基准上表现优异，但临床实践要求医生综合专科知识、多模态证据和患者随时间变化的状态进行决策。现有基准无法评估这种纵向整合能力。鼻咽癌（NPC）诊疗依赖病理、MRI、EBV-DNA等多模态信息，且治疗决策随病情演变，是理想的评估场景。

### 5. 方法概览

- 任务 / 环境: NPCBench 包含 4,777 个组件和咨询项目，以及 100 名患者的 CarePath 队列（417 个评分任务）。任务分为六个渐进级别（L1-L6）和开放式咨询（O1），覆盖指南记忆、原子应用、多模态证据基础、病例规划、纵向修订和完整路径评估。
- 变量 / 干预设计: L1-L2 基于 CSCO/NCCN 指南；L3 包含病理和 MRI 图像任务；L4-L6 使用真实患者记录构建病例规划和纵向决策场景。CarePath 评估要求模型在给定临床背景下依次做出诊断和治疗决策，并计算严格路径成功率（Strict），即所有诊断和治疗答案均正确。
- 评价指标: 主要指标包括各任务准确率、Care 准确率（所有治疗决策正确）、Strict 成功率（病理、MRI T 分期和治疗决策均正确）。此外，还报告了平衡准确率、结构识别准确率、联合结构-侵犯正确率等。
- 模型比较: 评估了 30 个医学和通用模型，其中 21 个多模态模型完成图像任务。模型包括 HuatuoGPT-o1、Lingshu、Qwen、GPT-OSS 以及 GPT 和 Gemini 系列。
- 我的理解: NPCBench 的设计核心在于“组合鸿沟”的测量：通过将组件任务与患者级路径绑定，能够识别模型在孤立任务上的高分是否掩盖了在真实临床流程中的失败。严格成功率（Strict）是衡量模型能否像医生一样整合多模态证据并做出连贯决策的关键指标。

### 6. 关键发现

- 指南知识与病例规划之间存在显著差距: Gemini-3.1-Pro-Preview 在指南记忆（L1）和原子应用（L2）上分别达到 94.0% 和 92.5%，但在病例规划（L4）上仅为 71.9%。类似地，GPT-5.1 和 DeepSeek-V3.1 在 L1/L2 上分数相近，但在 L4 上相差 11.7 个百分点（63.5% vs 51.8%）。
- 视觉证据基础不完整: 在 400 例 MRI T 分期任务中，最高准确率仅为 43.5%，而多数类基线为 37.5%。在 100 例解剖面板中，完整侵犯正确率最高仅 5.0%，表明模型常能猜对分期标签但缺乏准确的解剖学支持。
- 纵向路径中的组合鸿沟: Gemini-3.1 在 Care 准确率上达到 89.9%，但严格成功率（Strict）仅为 11.0%；Claude-4.6 的严格成功率最高，也仅 23.0%。这表明模型在单个决策上表现良好，但无法在完整路径中保持所有决策的正确性。
- 咨询安全性问题: GPT-5.1 在咨询任务中得分最高，但仍有 14.6% 的响应触发重大错误标准。自动化评分器与医生评估存在敏感性-特异性不平衡，提示需要更可靠的评估方法。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: NPCBench 表明，即使单个任务准确率高，智能体在完整临床路径中的表现可能很差。这提示开发医学智能体时，需要关注决策的时序一致性和多模态证据的整合，而非仅优化局部任务。
- 对 Skill: 模型在视觉证据基础（如 MRI 结构识别）上的不足，说明需要专门训练多模态模型在医学图像上的细粒度感知能力，而不仅仅是分类标签。
- 对 Memory: 纵向路径评估要求模型记住并利用先前的决策和患者状态，这凸显了记忆机制在医学智能体中的重要性。
- 对评测: NPCBench 提供了一种可复用的评估框架，将组件任务与患者级结果绑定，可推广到其他疾病领域，以更全面地衡量医学AI的临床适用性。

### 11. 局限性

- NPCBench 仅覆盖鼻咽癌单一病种，其框架在其他疾病上的泛化性有待验证。
- CarePath 评估中，模型在回答每个决策时可能无法访问完整的真实临床记录，导致信息不完整。
- 自动化评分器与医生评估存在不一致，可能影响咨询任务评分的可靠性。
- 模型评估基于固定提示模板，可能未充分探索模型的最佳性能。

### 12. 我的看法 / 个人笔记

NPCBench 是医学AI评估的重要进步，它揭示了“组合鸿沟”这一关键问题：模型在孤立任务上的高分可能掩盖其在真实临床路径中的失败。严格成功率（Strict）是一个强有力的指标，它要求模型在诊断和治疗上同时正确，更贴近临床实际。未来工作应扩展该框架到更多疾病，并改进自动化评估方法以减少与医生判断的偏差。

### 14. 总结

NPCBench 是一个针对鼻咽癌的多模态临床路径推理基准，包含 4,777 个组件任务和 100 个患者路径。评估 30 个模型发现，尽管模型在指南记忆上表现良好（最高 94%），但在病例规划（最高 71.9%）和严格路径成功（最高 23%）上显著下降，表明存在组合鸿沟。视觉证据基础尤其薄弱，完整侵犯正确率仅 5%。该基准为医学AI的临床适用性评估提供了新范式，强调了多模态整合和纵向一致性的重要性。

## 5. Benchmarking Large Language Models on Heterogeneous Cognitive and Biomedical Knowledge Graphs: The Role of Graph Grounding in Multi-Hop Reasoning and Hallucination Mitigation

**Topics:** Large Language Models, Knowledge Graphs, Multi-Hop Reasoning, Hallucination Mitigation, Biomedical Informatics, Cognitive Neuroscience
**Authors:** Ali Sarabadani, Kheirolah Rahsepar Fard, Tahereh Jeirani
**Venue / Year:** 
**Links:** [Abstract](http://arxiv.org/abs/2611.08315v1) | [PDF](http://arxiv.org/pdf/2611.08315v1.pdf)

### 1. 一句话结论

通用前沿模型（GPT-5.1、Gemini 2.0 Pro）在异构生物医学知识图谱上的多跳推理优于领域专用模型，且图谱接地能显著降低幻觉率。

### 2. 为什么重要

该研究首次系统比较了通用与领域专用LLM在多个异构生物医学知识图谱上的推理能力，揭示了图谱接地对减少幻觉的关键作用，为神经符号系统在个性化医疗和认知障碍诊断中的应用提供了实证基础。

### 3. 研究问题

1. 通用与领域专用LLM在异构生物医学知识图谱上的多跳推理能力如何？
2. 图谱接地（KG grounding）能否降低LLM的幻觉率？
3. 模型性能随查询复杂度增加如何变化？

### 4. 背景与问题设定

大型语言模型（LLM）在生物医学和认知神经科学中应用日益广泛，但其在异构知识图谱（KG）上的可靠推理能力尚不明确。现有基准多局限于单一图谱或通用领域，缺乏对多图谱、多跳推理和幻觉行为的联合评估。

### 5. 方法概览

- 任务 / 环境: 五个异构知识图谱：DrugBank、NeuroSynth、Cognitive Atlas、Brain Map和GDPKG-LLM，涵盖药物、脑区、认知概念等。
- 变量 / 干预设计: 双模式评估：KG感知（图谱接地）模式，LLM生成SPARQL/Cypher查询并执行；KG不可知（无接地）模式，LLM直接回答。查询分为单跳（50）、多跳（70）和高层推理（30）三类，共150个查询。
- 评价指标: 精确匹配（EM）、宏F1、解析率（ParseRate）、结果等价率（EquivRate）、幻觉率（HallucRate）和延迟。
- 模型比较: 比较GPT-5.1、Gemini 2.0 Pro、Llama 3、Qwen和BioGPT五个模型。
- 我的理解: 该研究通过精心设计的双模式对比，隔离了查询翻译错误与内部推理错误，从而清晰评估了图谱接地对推理和幻觉的影响。

### 6. 关键发现

- 通用模型优于领域专用模型: GPT-5.1和Gemini 2.0 Pro在多跳和高层推理任务上持续优于BioGPT等领域专用模型，即使在没有图谱接地的情况下也是如此。例如，在KG感知模式下，GPT-5.1的宏F1为0.91，而BioGPT仅为0.65。
- 图谱接地降低幻觉率: 所有模型在KG感知模式下幻觉率均显著降低，表明结构化知识约束有助于减少事实错误。具体降低幅度因模型而异，但整体趋势一致。
- 性能随查询复杂度下降: 所有模型在从单跳到多跳查询时性能均下降，但通用模型下降幅度较小。例如，GPT-5.1的多跳EM为88%，而BioGPT仅为45%，显示出更强的组合推理能力。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 图谱接地可作为减少智能体幻觉的关键机制，尤其在需要可靠事实推理的领域（如医疗诊断）中，建议集成结构化知识源。
- 对 Skill: 通用模型在组合推理上的优势表明，领域专用训练可能不足以弥补推理能力的不足，应注重提升模型的泛化推理技能。
- 对 Memory: 图谱接地可视为外部记忆的一种形式，帮助模型访问结构化事实，减少对参数化记忆的依赖。
- 对评测: 该基准提供了多图谱、多跳推理和幻觉评估的框架，可用于未来模型选择和系统设计。

### 11. 局限性

- 基准查询数量有限（150个），可能不足以全面覆盖复杂推理场景。
- 仅评估了五个模型，未涵盖更多最新模型。
- 图谱接地依赖SPARQL/Cypher查询生成，可能受限于模型对查询语言的掌握。
- 注释者间一致性（Cohen's kappa=0.781）虽为实质性一致，但仍存在一定主观性，可能影响错误分类的准确性。

### 12. 我的看法 / 个人笔记

该研究提供了有价值的实证证据，表明通用模型在结合结构化知识时能有效提升推理可靠性。未来工作可扩展更多图谱和模型，并探索动态接地机制。
