## 1. MintAct: A Unified Visual Agent for Digital Environments

**Topics:** GUI Agent, 视觉语言模型, 强化学习
**Authors:** Mingfei Gao, Rui Tian, Haiming Gang, Bohan Zhai, Le Zhang, Yuanzheng Gong, Di Feng, Ege Özsoy, Kaixin Ma, Vishwesh Kirthivasan, Oğuzhan Fatih Kar, Roman Bachmann, Anders Boesen Lindbo Larsen, Afshin Dehghan
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.22083v1) | [PDF](http://arxiv.org/pdf/2609.22083v1.pdf)

### 1. 一句话结论

MintAct 通过多阶段训练（高分辨率单步 SFT、低分辨率多步 SFT、领域专家 RFT 蒸馏、联合异步 RL）在 2B/4B/8B 规模上统一了 UI 定位、跨移动/桌面/网页的多步导航和视觉工具使用，且性能匹配或超越领域专家模型。

### 2. 为什么重要

该工作首次在紧凑模型规模上实现了跨数字环境的统一视觉智能体，解决了以往各领域（移动、桌面、网页、工具使用）模型碎片化的问题，为端侧通用数字助手提供了可行路径。其异步 RL 框架和可扩展环境基础设施也为后续研究提供了重要参考。

### 3. 研究问题

1. 一个单一模型能否在不牺牲各领域性能的前提下，统一 UI 定位、多步导航和视觉工具使用？
2. 如何设计训练流程和环境基础设施，以支持跨异构领域的稳定且可扩展的强化学习？

### 4. 背景与问题设定

当前视觉语言智能体在 GUI 定位、移动导航、桌面控制、网页导航和视觉工具使用等方面已有显著进展，但这些能力通常由各自领域的专用模型实现，导致维护和扩展成本高昂，尤其不适合端侧部署。MintAct 旨在解决这一碎片化问题，通过统一模型实现多种数字环境下的通用视觉智能体。

### 5. 方法概览

- 任务 / 环境: 移动端（AndroidWorld）、桌面端（OSWorld）、网页端（Weblica-Cache 和 Weblica-Synth）、视觉工具使用（MM-ToolSandBox），以及自建的合成环境。
- 变量 / 干预设计: 多阶段训练：1) 高分辨率单步 SFT 建立 UI 定位能力；2) 低分辨率多步 SFT 学习导航和工具使用；3) 各领域 RL 专家通过拒绝采样蒸馏回单一模型；4) 联合异步 RL 优化整体策略。
- 评价指标: 在 OSWorld-Verified、Online-Mind2Web、AndroidWorld 等基准上的任务成功率，以及 UI 定位准确率等。
- 模型比较: 与各领域的专用模型（如 Ferret-UI Lite、MAI-UI、UI-TARS、OpenCUA、Scale-CUA、Weblica 等）以及同规模通用模型进行比较。
- 我的理解: MintAct 的核心创新在于其训练流程：先用 SFT 打好基础，再用领域专家 RL 提升各领域能力，最后通过蒸馏和联合 RL 融合，同时通过异步框架和平衡采样控制跨域训练分布，避免领域间干扰。

### 6. 关键发现

- 统一模型达到或超越专家性能: MintAct-8B 在 OSWorld-Verified 上达到 48.9，Online-Mind2Web 上 39.1，AndroidWorld 上 67.0，均匹配或超过同规模专用模型。
- 多阶段训练的有效性: 消融实验表明，每个训练阶段（高分辨率 SFT、多步 SFT、RFT、联合 RL）都对最终性能有贡献，缺一不可。
- 异步 RL 框架的稳定性: 异步框架在异构环境后端下能保持稳定的训练分布，并有效处理噪声反馈和 off-policy 漂移，支持数百个并发实例。

## 2. Supporting Industrial Test-Failure Analysis with LLM-Based Systems: An Experience Report

**Topics:** 软件工程, LLM智能体, 根因分析, 工业测试
**Authors:** Eric Jansson, Per Strandberg, Thomas Sörensen, Eduard Paul Enoiu, Wasif Afzal
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.21843v1) | [PDF](http://arxiv.org/pdf/2609.21843v1.pdf)

### 1. 一句话结论

在工业测试失败根因分析中，单智能体系统比多智能体系统更快、更便宜，且两者在从业者感知质量上无一致优势。

### 2. 为什么重要

该研究提供了LLM智能体在真实工业测试失败分析中的实证评估，挑战了多智能体架构必然更优的假设，为实际部署提供了成本、速度和一致性方面的关键数据。

### 3. 研究问题

1. 单智能体与多智能体LLM系统在工业测试失败根因分析中的质量、成本和速度表现如何？
2. 从业者对LLM生成的根因分析报告的可信度、清晰度和实用性有何感知？

### 4. 背景与问题设定

Westermo公司的夜间测试会产生大量异构测试数据和日志，目前需要从业者手动跨多个来源检查，耗时且依赖经验。LLM智能体有望自动化这一过程，但缺乏在真实工业环境中的对比评估。

### 5. 方法概览

- 任务 / 环境: Westermo网络设备公司的夜间回归测试，涉及控制器和多个被测设备（DUT），数据包括测试元数据、设备映射和日志。
- 变量 / 干预设计: 设计了两种LLM系统：单智能体（直接调用工具）和多智能体（编排者+专业子智能体），两者使用相同的数据源、工具和报告格式。在真实失败场景下运行，收集120次执行数据，并通过调查和焦点小组收集6名从业者的反馈。
- 评价指标: 从业者感知的正确性、推理质量、修复现实性、清晰度、有用性和信任度；系统层面的成本、持续时间和一致性（语义稳定性）。
- 模型比较: 单智能体 vs 多智能体（编排者+子智能体）
- 我的理解: 该研究通过混合方法（定量测量+定性反馈）对比了两种智能体架构，强调了在工业环境中评估LLM系统时，不仅需要关注质量，还需考虑成本和速度等实际因素。

### 6. 关键发现

- 单智能体更高效: 单智能体系统每次分析约需40秒，而多智能体约需130秒；单智能体成本约0.75瑞典克朗，多智能体为1.5-1.75瑞典克朗。
- 质量无一致优势: 两种架构在从业者感知质量上无一致优势，结果因场景而异：场景1中单智能体评分更高，场景2中多智能体评分更高。
- 报告内容需改进: 从业者认为报告冗长重复，根因部分有时重复证据，推理步骤不自然，但下一步行动部分有用。
- 有用性取决于经验: 报告对经验丰富的从业者价值有限，但对新手或处理不熟悉故障时可能更有用。
- 错误结论风险: 看似合理但错误的结论可能误导从业者，使其忽略真正的原因，且错误的时间戳会加剧问题。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 智能体架构的选择应基于任务复杂度和资源约束，简单任务可能不需要多智能体。
- 对 Skill: LLM生成的报告应更简洁，避免重复，并明确区分证据和推理。
- 对 Memory: 多智能体系统需要管理上下文和协调，可能增加开销，需权衡。
- 对评测: 评估LLM系统时，应结合客观指标（成本、速度）和主观感知（信任、有用性），并考虑场景依赖性。

### 11. 局限性

- 仅基于两个真实失败场景，样本量小，结果可能不具普遍性。
- 从业者数量有限（6人），且来自同一公司，可能存在偏差。
- LLM模型和工具版本固定，未探索不同模型的影响。
- 一致性评估使用LLM评判，可能引入主观性。

### 12. 我的看法 / 个人笔记

该研究提供了宝贵的工业实证数据，表明多智能体架构并非万能。未来研究应探索更复杂的场景，并改进报告的可解释性和简洁性。

### 14. 总结

## 3. DRT: Dense Reasoning Trace for Efficient and Grounded Multimodal Reasoning

**Topics:** 多模态推理, 链式思维, 视觉锚定, 强化学习
**Authors:** Wan Xu, Yuanfan Guo, Kevin Han, LaLa Chen, Wangmeng Zuo
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.21675v1) | [PDF](http://arxiv.org/pdf/2609.21675v1.pdf) | [Code](https://github.com/HIT-leaderone/DRT)

### 1. 一句话结论

DRT 用紧凑结构化轨迹替代自然语言 CoT，实现 5.5 倍 token 效率提升和 1.3 个准确率点提升。

### 2. 为什么重要

当前多模态推理依赖冗长自然语言 CoT，导致信息稀释和视觉锚定弱化。DRT 通过改变推理表达空间，在保持甚至提升准确率的同时大幅降低计算开销，为下一代多模态大模型提供更高效的推理范式。

### 3. 研究问题

1. 如何在不牺牲推理准确性的前提下，减少多模态推理中的 token 开销？
2. 如何通过结构化推理轨迹增强模型对视觉证据的锚定，减少幻觉？

### 4. 背景与问题设定

多模态大模型（MLLMs）在复杂推理任务中常采用链式思维（CoT）范式，但自然语言表达空间存在冗余，导致信息稀释和视觉锚定不足。现有高效推理方法（如 token 剪枝、早期停止）仍局限于自然语言空间，未从根本上解决表达效率问题。

### 5. 方法概览

- 任务 / 环境: 多模态推理基准测试，包括视觉数学推理、逻辑推理和视频理解等任务。
- 变量 / 干预设计: 提出 DRT 范式，将推理过程分解为 <visual>（视觉证据）、<thinking>（逻辑推理）和 <answer>（结论）三部分，使用符号连接符（如 →）压缩表达。训练分为两阶段：Dense Trace Initialization（SFT 初始化）和 Trace-Grounded Reinforcement Learning（RL 优化）。
- 评价指标: 准确率（Accuracy）、token 效率（token 数量）、以及推理质量（通过人工评估或自动指标）。
- 模型比较: 与 Qwen3-VL-8B-Instruct 基线及多种高效推理方法（如 token 剪枝、早期停止）对比，评估准确率与 token 效率的权衡。
- 我的理解: DRT 的核心创新在于将推理从自然语言空间转移到结构化符号空间，通过显式分离视觉观察和逻辑推理，既减少了冗余表达，又增强了推理的可验证性。强化学习阶段通过三视角验证和过程奖励，确保生成的轨迹既简洁又逻辑严谨。

### 6. 关键发现

- token 效率大幅提升: DRT 在多个基准上实现 5.5 倍 token 效率提升，同时准确率提升 1.3 个点，优于现有高效推理方法。
- 视觉锚定增强: 通过显式分离视觉证据和逻辑推理，DRT 减少了幻觉，提高了推理对视觉输入的忠实度。
- 强化学习有效性: Trace-Grounded GRPO 通过过程奖励和探索激励，进一步提升了推理准确性和轨迹质量。

- 为什么重要: 该图直观展示了 DRT 在准确率和 token 效率上的优势，以及其结构化推理轨迹的示例，是理解 DRT 核心贡献的关键。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: DRT 可显著降低多模态智能体的推理延迟和计算成本，使其更适合实时交互场景。
- 对 Skill: 结构化推理轨迹有助于技能的可解释性和可复用性，可促进技能库的构建。
- 对 Memory: 紧凑的推理表示可减少记忆存储开销，同时保留关键逻辑链，有利于长期记忆管理。
- 对评测: DRT 的 token 效率指标可作为评估推理质量的新维度，推动更全面的评估体系。

### 11. 局限性

- 依赖 GPT-5.1 生成高质量参考轨迹，可能引入额外成本。
- 结构化表示可能不适用于所有任务类型，如需要自由形式推理的开放域任务。
- 实验仅在 Qwen3-VL 上验证，泛化性需进一步测试。

### 12. 我的看法 / 个人笔记

DRT 是高效多模态推理的重要探索，通过改变表达空间而非仅压缩 token，实现了效率与准确率的双赢。未来可探索自适应轨迹长度和跨模型泛化，并考虑与模型架构结合。

  核心贡献：构建了高质量多模态推理数据集，并展示了冷启动 RL 的有效性。
  与当前论文关系：DRT 基于该数据集进行 SFT 和 RL 训练，并扩展了数据来源。
- DAPO: 开放 LLM 强化学习系统
  为什么重要：提供了 DRT 使用的文本推理数据，补充了纯文本推理能力。

  与当前论文关系：DRT 使用 DAPO 数据增强文本推理样本。

### 14. 总结

DRT 提出用紧凑结构化轨迹替代自然语言 CoT，通过两阶段训练（SFT 和 RL）实现高效且锚定视觉的多模态推理。实验显示 5.5 倍 token 效率提升和 1.3 准确率提升，为下一代多模态推理提供了新方向。

## 4. Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design

**Topics:** GUI Agent, Graphic Design, Procedural Memory, Continual Learning
**Authors:** Hongyang Du, Lan Yan, Christian Flores, Asim Kadav
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.22086v1) | [PDF](http://arxiv.org/pdf/2609.22086v1.pdf)

### 1. 一句话结论

通过外部程序性记忆的持续演化（加宽与加深），冻结的视觉模型在图形设计任务中的执行成功率显著提升，且无需更新模型权重或人工标注。

### 2. 为什么重要

该工作展示了在缺乏可靠程序化评估信号的长周期智能体任务中，如何通过外部记忆的持续演化实现模型能力的提升，为无法更新基础模型的场景提供了一种实用路径。

### 3. 研究问题

1. 如何从用户流量中自动发现并提炼可复用的设计技能？
2. 在无可靠程序化评估的情况下，如何安全地更新外部技能库以避免性能回退？
3. 技能库的扩展（加宽）与精炼（加深）如何协同作用以提升整体性能？

### 4. 背景与问题设定

专业图形设计是长周期智能体任务，需要生成可编辑的结构化设计稿，但缺乏可靠的程序化评估标准。现有方法依赖人工演示或强化学习，但基础模型通常托管在外部，难以更新。本文提出将外部程序性记忆作为学习目标，通过从用户流量中积累经验，在不改变模型权重的情况下持续改进智能体性能。

### 5. 方法概览

- 任务 / 环境: 图形设计智能体，控制超过230个工具（模拟Photoshop、Illustrator、InDesign），处理真实用户设计请求。
- 变量 / 干预设计: 对比有技能库（EVOLVE）与无技能库（BASE）的智能体，在多个基础模型（Claude-Opus-4.6, Claude-Sonnet-4, Qwen3.6-27B）上评估。
- 评价指标: 使用GenEval2、DPG-Bench、OneIG等基准的生成质量和成功率，以及内部基准的完整性分数和成对胜率。
- 模型比较: EVOLVE智能体与BASE智能体（无技能库）对比，保持其他条件一致。
- 我的理解: 该方法通过外部技能库的持续演化，在不改变模型权重的情况下，使冻结的视觉模型适应新任务，类似于给模型配备一个不断更新的操作手册。

### 6. 关键发现

- 技能库演化显著提升执行成功率: 在Claude-Sonnet-4上，GenEval2执行成功率从72.7%提升至99.3%，生成质量提升11.99点。
- 加宽与加深机制互补: 单独使用加宽或加深效果有限，但组合使用在内部基准上胜率显著提升（58.5% vs 49.4%/48.6%）。
- 技能库持续增长且覆盖新意图: 从76个初始技能增长至139个，新技能与初始技能在语义空间上距离较远，表明覆盖了初始未覆盖的意图。

## 5. CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

**Topics:** 代码智能体, 强化学习, 代码生成, 软件工程
**Authors:** Bowen Ye, Lei Li, Shicheng Li, Zihao Yue, Linghao Zhang, Hanglong Lv, Yuanxin Liu, Wenhan Ma, Hao Tian, Rang Li, Jinhao Dong, Yikai Zhao, Xiangwei Deng, Hailin Zhang, Liang Zhao, Qi Liu, Lingpeng Kong, Tong Yang, Fuli Luo
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2609.22068v1) | [PDF](http://arxiv.org/pdf/2609.22068v1.pdf)

### 1. 一句话结论

CodeMidas 提出了一种仅以源代码为输入的智能体流水线，自动从开源代码库构建可执行的强化学习环境，显著提升了代码智能体在多种软件任务上的性能。

### 2. 为什么重要

该工作解决了强化学习训练中任务多样性和验证器可靠性难以兼得的瓶颈，通过自动化构建大规模、可验证的编码任务，为训练通用代码智能体提供了可扩展的数据来源，推动了代码智能体在真实软件工程场景中的应用。

### 3. 研究问题

1. 如何仅从源代码自动构建多样且可验证的强化学习任务？
2. 基于源代码构建的训练任务能否提升代码智能体在多种下游基准上的表现？

### 4. 背景与问题设定

训练代码智能体进行强化学习需要大量多样化的任务和可靠的奖励信号。现有方法通常依赖开发工件（如 issue、PR、commit、测试或文档），这限制了任务覆盖范围。CodeMidas 旨在直接从源代码中提取任务，以扩大任务多样性并确保验证器的可靠性。

### 5. 方法概览

- 任务 / 环境: 每个任务包含一个任务描述、一个容器化的开发环境（基于源代码改编，移除目标实现）和一个隐藏的可执行验证器。
- 变量 / 干预设计: 使用智能体流水线：1) 任务设计：智能体分析代码库，识别功能并生成任务描述和代码边界；2) 测试构建：基于参考实现执行生成测试；3) 执行一致性检查：在六个容器中验证起始代码失败、参考代码通过；4) 后滚动过滤：通过对抗性滚动检查泄漏、审查验证器一致性，并保留有成功和失败案例的任务。
- 评价指标: 在五个外部基准上评估：SWE-bench Pro、DeepSWE、ProgramBench、RepoZero C2Rust、Terminal-Bench v2.1，以及内部 CodeMidas Val。主要指标为通过率（ProgramBench 为 Almost Solved）。
- 模型比较: 使用 MiMo-V2.5 作为基础模型，对比初始策略与经过 CodeMidas RL 训练后的策略。训练使用 GRPO，batch size 32，每个任务 32 次 rollout。
- 我的理解: 该方法的核心在于利用智能体自动化任务构建和验证，通过多阶段过滤确保任务质量，从而使得从源代码中提取的任务能够有效训练代码智能体。

### 6. 关键发现

- 性能全面提升: 在五个外部基准上均取得显著提升：DeepSWE 从 10.0% 提升至 21.7%（+11.7个百分点），ProgramBench Almost Solved 得分从 4.5 提升至 21.5（+17.0个百分点），Terminal-Bench v2.1 从 63.7% 提升至 72.2%（+8.5个百分点）。
- 任务规模与质量: 构建了包含 5,545 个训练任务的数据集，覆盖 23 种编程语言和 15 个技术领域。消融实验显示，增加高质量任务数量可提升性能，且 3k 子集优于 8k 未过滤基线，表明任务质量比数量更重要。
- 行为改进: 轨迹分析显示，RL 训练后的智能体在代码库探索（如访问更多文件）和自验证（如执行更多样化的测试命令）方面表现出更优的行为，且这些行为变化也出现在外部任务上。
