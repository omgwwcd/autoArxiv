## 2. A Baseline Assessment for the Agentic Web Technology Stack

**Topics:** GUI Agent, Agentic Web, Multi-Agent Systems, LLM Agents, Agent Protocols
**Authors:** Vagner Figueredo de Santana, Diogo Cortiz
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.13703v1) | [PDF](http://arxiv.org/pdf/2610.13703v1.pdf)

### 1. 一句话结论

通过MASTIF框架对3种LLM、3种协议和4种框架组成的Agentic Web技术栈进行基准评估，发现针对特定任务选择技术栈可显著提升任务完成率、效率和稳定性。

### 2. 为什么重要

该研究为快速演进的Agentic Web技术栈提供了首个系统性基准评估，帮助开发者和组织在众多协议、框架和模型中选择合适组合，降低入门门槛，促进多智能体系统的设计与部署。

### 3. 研究问题

1. RQ1: 在评估条件下，哪种Agentic Web技术栈的任务完成率最高？
2. RQ2: 哪种技术栈在任务完成率、收敛时间和冗长度方面效率最高？
3. RQ3: 哪种技术栈最适合Web上的工具调用？
4. RQ4: 哪种技术栈在通信中嵌入的社会价值观方面最稳定？

### 4. 背景与问题设定

随着LLM-based agents的兴起，Web正从人类用户主导的生态转变为智能体参与的Agentic Web。然而，协议、框架和技术快速涌现，导致技术栈碎片化，开发者难以选择最佳组合。现有研究缺乏对不同技术栈组合的系统评估，因此需要建立基准来指导实践。

### 5. 方法概览

- 任务 / 环境: 使用Mind2Web基准测试中的300个任务，涵盖多种真实网站和交互模式，模拟智能体作为用户执行Web任务的环境。
- 变量 / 干预设计: 构建MASTIF框架，系统评估3种LLM（如GPT-4、Claude等）、3种协议（如MCP、A2A、ACP）和4种实现框架（如LangChain、CrewAI、LangGraph、Semantic Kernel）的组合，共形成多种技术栈。每个技术栈在相同任务集上运行，记录任务完成率、效率、冗长度和社会价值稳定性等指标。
- 评价指标: 任务完成率（TCR）、效率分数（结合完成率和资源消耗）、收敛时间、冗长度（输出文本量）、社会价值稳定性（基于价值观嵌入的一致性）。
- 模型比较: 比较不同LLM、协议和框架的单独及组合效果，识别最优技术栈。
- 我的理解: 该方法通过控制变量和标准化任务集，系统性地分离了各组件对整体性能的影响，为技术选型提供了实证依据。

### 6. 关键发现

- 任务特定技术栈带来显著性能提升: 选择针对任务类型优化的技术栈，相比通用组合，任务完成率可提升高达20%，效率分数提升15%，同时降低冗长度和完成时间。
- 协议选择影响工具调用能力: 不同协议在工具调用场景下表现差异明显，例如MCP在标准工具集成上更稳定，而A2A在跨智能体协作时更高效。
- 框架的编排能力影响多智能体协作: LangGraph和CrewAI在复杂任务分解和子智能体协调上优于其他框架，但资源消耗更高；Semantic Kernel在轻量级任务中效率更优。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 技术栈的选择应基于任务特性，而非盲目追求最新组件；多智能体系统设计需考虑协议与框架的兼容性。
- 对 Skill: 开发者需要掌握多种协议和框架的优缺点，以便针对不同场景进行组合优化。
- 对 Memory: 不同框架对记忆管理的支持差异可能影响长任务表现，未来可探索记忆机制与技术栈的交互。
- 对评测: MASTIF框架提供了一套可复用的评估方法，可扩展到更多任务和组件，推动标准化评估。

### 11. 局限性

- 评估仅基于Mind2Web的300个任务，可能无法覆盖所有Web交互场景。
- 技术栈组合数量有限，未包含所有可能的协议和框架。
- 社会价值稳定性指标基于LLM判断，可能存在主观性。
- 实验环境为模拟，真实世界中的网络延迟、API变化等未考虑。

### 12. 我的看法 / 个人笔记

该研究为Agentic Web技术选型提供了宝贵基准，但需注意其结论的时效性，因为技术栈组件快速迭代。未来可扩展至更多任务类型和真实环境，并纳入成本指标，以提供更全面的指导。

## 3. A Multi-Agent LLM System for Automated Tuning of Specialized Neural Network Models

**Topics:** 多智能体系统, 大语言模型, 自动调参, 脉冲神经网络, 物理信息神经网络
**Authors:** Ivan Moloshnikov, Dmitry Kunitsyn, Alexander Sboev, Maksim Skorokhodov, Roman Rybka, Yuanchao Liu
**Venue / Year:** 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.13663v1) | [PDF](http://arxiv.org/pdf/2610.13663v1.pdf)

### 1. 一句话结论

提出一种多智能体LLM框架，通过分析师、编码员和记录员三个角色协作，自动调整专用神经网络的特定功能模块，在五个不同任务上显著提升性能。

### 2. 为什么重要

该框架解决了专用神经网络中关键组件手动选择耗时且不可复现的问题，提供了一种跨模型、跨任务的自动调参方法，无需改变框架内部结构即可应用于脉冲分类和物理信息神经网络等多种场景，展示了LLM作为元优化器的潜力。

### 3. 研究问题

1. 如何利用多智能体LLM系统自动调整专用神经网络的功能模块？
2. 该框架能否在不同类型的任务（如SNN分类和PINN求解）中通用？
3. 详细提示（含方法类别的覆盖图）能否提升较弱LLM的性能？

### 4. 背景与问题设定

许多机器学习方法采用两级流程：专家选择方法类别，然后手动调整关键组件（如输入编码、解码器、损失函数等），这一过程耗时且难以复现。现有自动化方法（如NAS）通常搜索整个架构或优化整个脚本，而本文聚焦于在固定架构下调整特定功能模块。作者提出一个多智能体LLM框架，通过角色分工和实验日志记忆，在开放但语义狭窄的搜索空间中生成和评估假设，从而自动调优模块。

### 5. 方法概览

- 任务 / 环境: 五个任务：MNIST和Digits上的脉冲分类（SNN），以及广义非线性薛定谔方程（GNLSE）和Kuramoto-Sivashinsky（KS）方程的边界值问题（PINN）。
- 变量 / 干预设计: 框架包含三个LLM角色：分析师（生成假设和技术规格）、编码员（实现代码）、记录员（记录实验日志）。实验在Docker沙箱中执行，先进行功能测试，再评估性能。有两种提示模式：标准模式和详细模式（后者提供方法类别列表和动态覆盖图）。
- 评价指标: 分类任务使用准确率；PINN任务使用相对误差（针对有解析解的GNLSE）或守恒误差（如质量漂移）作为指标。
- 模型比较: 与基线（argmax解码器、原始输入输出变换）比较，并比较不同LLM（如GPT-4o-mini、GPT-4o、DeepSeek等）在标准/详细提示下的性能。
- 我的理解: 该框架的核心在于将调参问题转化为一个受限的代码生成与评估循环，通过实验日志和覆盖图引导搜索，避免重复尝试，并利用LLM的领域知识提出有意义的假设。

### 6. 关键发现

- 跨任务性能提升: 在MNIST上准确率提升13个百分点，Digits上提升6个百分点；GNLSE单孤子解的相对误差降低约2491倍；守恒误差降低约325倍（选定的高斯扰动运行），KS问题质量漂移降低14倍。
- 详细提示增强较弱模型: 提供详细提示（含方法类别和覆盖图）显著提升了较弱LLM（如GPT-4o-mini）的性能，使其接近更强模型（如GPT-4o）的水平。
- 框架通用性: 同一框架无需修改内部结构即可应用于不同任务，表明其作为通用调参工具的潜力。

**Authors:** Zhengyang Zhang, Jing Xiong, Hongzhou Lin, Juihui Chung, Zijian Zhang, Song Han, Sihao Liu, Ligeng Zhu

HOA 通过独立审查、结构化维基和客观验证三个反馈通道，在多个奥林匹克竞赛和形式化数学基准上达到或超越金牌水平，并显著提升开放模型的性能。

### 2. 为什么重要

该工作展示了系统化反馈机制（独立审查、知识维基、客观验证）能够弥补基础模型能力的差距，使开放模型在复杂推理任务上接近甚至超越闭源模型，为构建可复现、鲁棒的智能体工作流提供了重要范式。

### 3. 研究问题

1. 如何通过多会话协作和反馈机制减少长程推理中的错误传播和问题误解？
2. 系统化的知识检索和客观验证能否显著提升智能体在奥林匹克级问题上的表现？

### 4. 背景与问题设定

大型语言模型智能体在长程科学和奥林匹克任务上进展迅速，但单一会话在困难问题上表现脆弱：早期错误可能传播、缺失领域知识会阻碍进展、表面成功可能掩盖对问题的误解或奖励黑客行为。现有系统往往不公开完整推理栈，难以复现。

### 5. 方法概览

- 任务 / 环境: 涵盖高中奥林匹克（IMO、IPhO、IChO、IOI）、大学数学竞赛（PutnamBench）和研究级形式化数学（Lean-Eval）。
- 变量 / 干预设计: HOA 框架包含三个反馈通道：独立审查者提供语义反馈，结构化维基提供知识反馈，验证器提供客观反馈。工作-审查循环迭代直到所有门控通过。
- 评价指标: 对于数学任务，使用 Lean 内核验证的证明通过率；对于竞赛，使用官方评分标准和金牌分数线；对于编程，使用隐藏测试用例。
- 模型比较: 比较了 GPT-5.6-Sol 和开放模型（Kimi-K3、GLM-5.3、DeepSeek-V4-Pro）在有无 HOA 框架下的表现，并与现有系统（如 Seed-Prover、AxiomProver）对比。
- 我的理解: HOA 的核心在于将生成、审查、验证分离，通过外部知识库和客观验证器提供可靠信号，避免自我修正的失效，从而提升长程任务的鲁棒性和最终性能。

### 6. 关键发现

- 全面达到金牌水平: HOA 在 IMO、IPhO、IChO、IOI 2026 上均达到或超过金牌分数线，并在 PutnamBench 上解决全部 672 个问题。
- 显著提升开放模型性能: 使用 Kimi-K3 的 HOA 在 IMO、IPhO、IOI 上获得满分，IChO 上获得 97.1%，接近或超过闭源 GPT-5.6-Sol 基线。
- Lean-Eval 排行榜第一: HOA 在 Lean-Eval 上解决 251/304（82.6%），相比 GPT-5.6 官方结果 112/304（36.8%）提升 45.7 个百分点。

## 5. SafeDiSTL: Decomposing Joint Constraints for Safe Multi-Agent Reinforcement Learning

**Topics:** 多智能体强化学习, 约束优化, 信号时序逻辑
**Authors:** Hongrui Zheng, Aditya Singh, Rahul Mangharam
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.13737v1) | [PDF](http://arxiv.org/pdf/2610.13737v1.pdf)

### 1. 一句话结论

SafeDiSTL 通过信号时序逻辑鲁棒性梯度分解共享约束，实现多智能体安全强化学习，显著提升安全成功率与吞吐量。

### 2. 为什么重要

在多智能体协同任务中，共享约束的信用分配是核心难题。SafeDiSTL 提供了一种基于 STL 鲁棒性梯度的分解机制，无需假设个体约束，可有效处理联合约束，提升安全性与任务性能，对实际多智能体系统（如仓储机器人、交通控制）具有重要意义。

### 3. 研究问题

1. 如何将共享约束的违反成本分解到各个智能体及其决策时刻？
2. 如何利用分解后的成本信号优化多智能体策略，同时保持任务性能？

### 4. 背景与问题设定

多智能体强化学习（MARL）在协同任务中常面临共享约束（如碰撞避免、连通性保持），但现有方法通常假设个体约束可解耦，难以处理联合约束。团队级违反成本无法区分各智能体责任，导致策略更新冲突。SafeDiSTL 利用信号时序逻辑（STL）的鲁棒性度量，通过梯度敏感性实现约束的细粒度分解。

### 5. 方法概览

- 任务 / 环境: 三个协同任务：负载运输（避障）、连通导航（保持通信）、交通控制（避免核心过载）。
- 变量 / 干预设计: 对比 SafeDiSTL 与 MAPPO、MACPO、MAPPO-L 基线，在相同训练预算下评估安全成功率、任务回报等指标。
- 评价指标: 安全成功率（任务完成且无约束违反）、任务回报、交通场景中的无过载完成率。
- 模型比较: SafeDiSTL 在安全成功率上优于基线，交通场景吞吐量提升 50-68%，运输场景安全成功率提升 1.6-5.1 倍。
- 我的理解: SafeDiSTL 的核心创新在于利用 STL 鲁棒性对整条轨迹的梯度，将每个时间步的约束违反增量按各智能体动作的敏感性加权分配，从而为每个智能体提供个性化的约束惩罚信号，同时保持总成本不变。

### 6. 关键发现

- 约束分解有效性: SafeDiSTL 在三个任务中均显著提升安全成功率，运输场景提升 1.6-5.1 倍，导航提升 11.1%，交通吞吐量提升 50-68%。
- 任务性能保持: SafeDiSTL 在提升安全性的同时，任务回报与无约束策略相当，表明分解机制未损害任务完成能力。

- 对 Agent 系统: SafeDiSTL 为多智能体系统提供了一种处理共享约束的通用框架，可应用于协同搬运、编队控制、交通管理等场景，提升集体安全性。
- 对 Skill: 该方法可帮助智能体学习更精细的协作技能，如根据自身对约束的影响调整行为，避免盲目规避。
- 对 Memory: 方法依赖完整轨迹的梯度计算，需要存储轨迹数据，但分解过程不依赖额外记忆结构。
- 对评测: 提供了安全成功率等评估指标，可推广到其他多智能体安全强化学习研究。

### 11. 局限性

- 方法依赖可微分的动力学模型，对于不可微或黑盒环境可能不适用。

- 实验仅在仿真环境验证，实际部署需考虑传感器噪声和模型误差。
