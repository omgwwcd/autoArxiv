## 1. MMSearch-OPD: Easy Made Hard, Hard Made Learnable for Long-Horizon Multimodal Search Agents

**Topics:** GUI Agent, 多模态搜索, 长程推理, 强化学习, 知识蒸馏
**Authors:** Huanyao Zhang, Jiepeng Zhou, Jiaye Lin, Ontai Tang, Jingtian Hao, Mugeng Liu, Ru Peng, Lang Mei, Xiaohan Yu, Liyan Liu, Chong Chen, Wentao Zhang
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.22240v1) | [PDF](http://arxiv.org/pdf/2610.22240v1.pdf)

### 1. 一句话结论

提出MMSearch-OPD，通过可控数据精炼和联合强化学习与在线策略蒸馏，显著提升长程多模态搜索智能体的能力。

### 2. 为什么重要

长程多模态搜索智能体需要持续获取证据，但训练数据稀缺且过程反馈不足。MMSearch-OPD提供了一种可扩展的数据增强和训练方法，使模型能够处理更复杂、更长的搜索任务，推动多模态智能体向更实用方向发展。

### 3. 研究问题

1. 如何利用现有简单多模态问题生成高质量的长程搜索训练数据？
2. 如何结合强化学习和在线策略蒸馏，为长程搜索提供有效的过程反馈？

### 4. 背景与问题设定

多模态搜索智能体通过交错推理和外部检索回答知识密集型视觉问题。现有数据集多为简单问题，难以训练长程搜索能力；同时，终端奖励稀疏，无法提供过程反馈。

### 5. 方法概览

- 任务 / 环境: 长程多模态搜索环境，智能体需结合文本搜索、网页浏览、图像搜索和视觉推理，逐步收集证据并最终回答复杂问题。
- 变量 / 干预设计: 数据精炼（Refine）通过Expand、Blur、Visualize三种操作控制搜索深度、实体消歧和视觉证据需求，生成难度可控的训练问题；训练阶段采用联合RL和OPD，其中OPD根据奖励差距对失败轨迹提供token级指导，并指数衰减。
- 评价指标: 在多个基准（如MMSearch、LiveVQA等）上的准确率，以及消融实验验证各组件贡献。
- 模型比较: 与直接回答模型（GPT-5.5等）和现有智能体（MMSearch-R等）对比，MMSearch-OPD在长程搜索任务上表现更优。
- 我的理解: 该方法通过数据增强解决训练数据稀缺问题，并通过混合训练策略缓解奖励稀疏问题，使模型在复杂搜索任务中更稳健。

### 6. 关键发现

- 数据精炼显著提升性能: 使用Refine生成的高难度问题训练后，模型在长程搜索基准上的准确率大幅提升，表明可控数据增强有效。
- 联合RL和OPD优于单独使用: 联合训练比单独RL或单独OPD效果更好，且OPD的指数衰减有助于模型最终超越教师。
- 跨基准泛化能力增强: 在多个未见过的基准上，MMSearch-OPD也表现出更好的泛化性，说明其学习到了更通用的搜索策略。

## 2. OS-Helix: Unifying GUI Interaction and Code Execution in Native Computer-Using Agents

**Topics:** GUI Agent, Computer-Using Agent, GUI/Code Coordination, Reinforcement Learning
**Authors:** Bowen Yang, Kaiming Jin, Zichen Ding, Zhenyu Wu, Zehao Li, Zhoumianze Liu, Kanzhi Cheng, Fangzhi Xu, Yanan Sun, Qiushi Sun, Yu Qiao
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.22234v1) | [PDF](http://arxiv.org/pdf/2610.22234v1.pdf) | [Code](https://os-copilot.github.io/OS-Helix/)

### 1. 一句话结论

OS-Helix通过端到端训练统一GUI交互与代码执行，提出应用-工件组合、解耦指令/评估器生成和Step-balanced GSPO，显著提升桌面自动化性能。

### 2. 为什么重要

该工作解决了真实桌面自动化中GUI与代码协调的难题，通过训练内化路由而非简单工具组合，为构建更强大的计算机使用智能体提供了新范式。

### 3. 研究问题

1. 如何让单一策略原生学习GUI与代码动作的协调，而非通过提示级工具组合？
2. 如何规模化生成可验证的混合GUI/代码训练数据？
3. 如何在强化学习优化中平衡异构动作（短GUI动作与长代码动作）的贡献？

### 4. 背景与问题设定

真实桌面自动化需要同时理解用户界面和操作文件、脚本等程序化状态。现有方法要么纯视觉（GUI-only），要么纯代码（code-only），各有局限。简单地在GUI智能体上添加代码工具会降低性能（如Qwen3-VL从34%降至32%），因为模型未学习何时使用哪种模态。因此，需要端到端训练来内化GUI/代码路由能力。

### 5. 方法概览

- 任务 / 环境: Ubuntu桌面虚拟机环境，通过应用-工件组合构建可执行状态，任务基于这些状态生成。
- 变量 / 干预设计: 数据基础设施：应用-工件组合构建环境，探索代理生成指令，评估代理生成验证器。训练：SFT冷启动 + 在线RL（Step-balanced GSPO）。
- 评价指标: OSWorld-Verified成功率，WindowsAgentArena跨平台迁移测试。
- 模型比较: 与Qwen3.5混合基线对比，OS-Helix-27B和35B-A3B分别提升35.0%和33.7%，RL版本进一步提升42.9%。
- 我的理解: 核心创新在于数据生成和训练策略：通过应用-工件组合创造多样可执行状态，解耦指令和评估器生成确保任务可验证，Step-balanced GSPO解决动作长度不平衡问题。

### 6. 关键发现

- 端到端训练优于提示级工具组合: 简单添加代码工具会降低GUI智能体性能（Qwen3-VL从34%降至32%），而通过SFT和RL训练内化路由可显著提升成功率。
- Step-balanced GSPO有效平衡异构动作优化: 按动作步而非token数聚合重要性权重，防止长代码动作主导优化，提升整体性能。
- 跨平台迁移能力: 在WindowsAgentArena上展示跨平台迁移，表明学习到的协调能力具有泛化性。

## 3. HTN-Orchestrate: A Hierarchical Task Network Framework for Multi-Agent Orchestration

**Topics:** Multi-Agent Orchestration, Hierarchical Task Network, LLM Agents
**Authors:** Yanchen Deng, Jianguo Huang, Yao Long Teng, Yixuan Li, Handuo Zhang, Ning Wang, Liangcai Su, Xinyu Wang, Bo An
**Venue / Year:** arXiv preprint, 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.22195v1) | [PDF](http://arxiv.org/pdf/2610.22195v1.pdf) | [Code](https://github.com/ycdeng-ntu/htn-orchestrate)

### 1. 一句话结论

HTN-Orchestrate 通过分层任务网络将全局规划与局部执行解耦，在多个基准上显著优于现有方法。

### 2. 为什么重要

该框架解决了多智能体系统中全局规划与局部执行之间的根本矛盾，通过结果驱动的规划和重建机制，提升了复杂任务的完成质量，为多智能体协作提供了新的范式。

### 3. 研究问题

1. 如何在不牺牲执行灵活性的前提下，显式建模子任务之间的层级和依赖关系？
2. 如何利用执行过程中的中间结果来动态调整任务分解，并在失败时有效重建任务网络？

### 4. 背景与问题设定

现有方法要么采用固定工作流，缺乏适应性；要么采用动态调度，但未显式建模任务层级和依赖。HTN-Orchestrate 提出两层架构：Planner 负责全局任务网络，Orchestrator 负责局部子任务执行，通过 AND 语义向上合成结果，并在必要时重建网络。

### 5. 方法概览

- 任务 / 环境: 涵盖网页研究、科学推理和研究工作流等五个基准测试，包括 BrowseComp 和 SUPERChem。
- 变量 / 干预设计: Planner 根据前置结果逐步展开任务网络，Orchestrator 调度多个 worker 执行叶子任务，结果按 AND 语义向上合成，失败时基于已有证据重建网络。
- 评价指标: 准确率（Accuracy），与 ReAct、Agent Team、DeepSeek Harness 对比。
- 模型比较: 在相同基础模型下，HTN-Orchestrate 在 BrowseComp 上达到 89.73%，在 SUPERChem 上达到 73.44%，分别超过 Agent Team 2.45 和 4.69 个百分点。
- 我的理解: 该框架的核心在于将任务分解与执行解耦，通过结果反馈动态调整规划，同时保留层级结构，既保证了全局一致性，又具备局部灵活性。

### 6. 关键发现

- 性能提升: 在五个基准上均优于现有方法，尤其在 BrowseComp 和 SUPERChem 上表现突出。
- 消融实验: 结果驱动的规划、局部多智能体编排和任务网络重建均对最终性能有显著贡献。

## 4. PROBE: Learning to Audit Policy Compliance in Tool-Using LLM Agents

**Topics:** LLM Agent, Policy Compliance, Red-Teaming, Reinforcement Learning, GUI Agent
**Authors:** Kshitij Mishra, Abhijith Sharma, Nils Lukas, Salem Lahlou
**Venue / Year:** NeurIPS 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.22124v1) | [PDF](http://arxiv.org/pdf/2610.22124v1.pdf) | [Code](https://github.com/Mishrakshitij/PROBE)

### 1. 一句话结论

提出PROBE算法，通过训练小型LLM审计器与冻结的目标智能体进行多轮工具交互，以发现其违反预设策略的行为，显著优于零样本基线。

### 2. 为什么重要

现有评估主要关注能力与内容安全，忽略了智能体在合法任务执行中是否遵守操作策略（如定价、隐私、确认等）。PROBE填补了这一空白，为自动化策略合规审计提供了可扩展的方法，对部署安全至关重要。

### 3. 研究问题

1. 如何训练一个LLM审计器，使其能够通过多轮对话主动探测目标智能体的策略违规行为？
2. 不同的强化学习优化算法（GRPO、DPO、GFlowNet）在策略审计任务中的效果如何？
3. 奖励设计如何影响审计器的探索多样性和违规发现效率？

### 4. 背景与问题设定

现代智能体系统通过外部工具执行复杂任务，但可能违反预设策略（如价格、隐私、确认等）。现有评估方法（能力基准、内容安全红队）无法检测此类违规，因为违规可能隐藏在多轮工具调用中。因此，需要一种新的评估维度：策略合规审计。

### 5. 方法概览

- 任务 / 环境: SKYASSIST：确定性航班预订环境，包含35个机场、120条航线、643个航班、8个工具（4个查询、4个变更）和20条策略（业务、安全、隐私、运营）。
- 变量 / 干预设计: 审计器（Qwen3-4B）与冻结的目标智能体（Qwen3-30B）进行多轮对话，审计器扮演客户或测试者，通过自然语言引导目标执行任务，目标可调用工具。审计器只能看到公开对话，无法访问内部状态。
- 评价指标: 策略覆盖率（发现的不同策略违规数）、违规产出（加权违规数）、多策略违规事件比例、以及人类研究验证的验证器可靠性。
- 模型比较: 比较了三种优化算法：GRPO（组相对策略优化）、DPO（直接偏好优化）、GFlowNet（基于流的生成网络），以及两个基线：随机场景和零样本Qwen3-30B。
- 我的理解: PROBE将审计建模为部分可观测的马尔可夫博弈，通过复合奖励（违规发现、进度、新颖性、合理性）引导审计器探索多样化的违规路径，并采用课程学习逐步增加对话轮数。

### 6. 关键发现

- PROBE显著提升策略违规发现能力: 在50个保留场景中，PROBE训练的审计器（4B参数）发现的策略违规数量是零样本30B模型的2倍以上，策略覆盖率从35%提升至60%。
- 多轮交互是发现复杂违规的关键: 通过课程学习逐步增加对话轮数（4→14），审计器能够触发需要多步操作才能暴露的违规，例如先查询再预订时绕过确认。
- 奖励设计对优化算法影响显著: GRPO和GFlowNet对奖励幅度敏感，而DPO对单调奖励变换更稳定。GFlowNet的覆盖模式有助于探索多样性，但需要仔细校准奖励以避免过度探索。
- 审计器可迁移至其他环境: 在τ-bench基准上，PROBE训练的审计器也表现出较好的策略违规发现能力，表明其泛化性。

## 5. Grounding Generative Verification in 3D Content

**Topics:** 3D 内容验证, 多模态大语言模型, 生成式验证
**Authors:** Shuanglin Li, Jiaying Lin, Shuquan Ye
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2610.22360v1) | [PDF](http://arxiv.org/pdf/2610.22360v1.pdf)

### 1. 一句话结论

当前最强的多模态大语言模型在3D内容验证上仍与人类存在21.6个百分点的差距，尤其在身份保持和细粒度几何验证上表现薄弱。

### 2. 为什么重要

该工作首次系统评估了MLLMs在3D内容验证中的能力，并提供了大规模训练数据和基准，为构建可靠的3D生成系统提供了关键反馈机制，推动模型从单纯生成走向可验证、可反思的闭环。

### 3. 研究问题

1. 当前多模态大语言模型在3D内容验证任务上与人类水平的差距有多大？
2. 如何通过数据构建和监督信号提升MLLMs的3D验证能力，并支持生成后的反思与修正？

### 4. 背景与问题设定

尽管MLLMs和3D生成技术取得了显著进展，但生成内容往往在视觉上逼真却可能违反具体任务要求。现有评估多关注偏好或质量，缺乏对显式需求满足情况的验证。因此，需要一种能够识别未满足需求并解释违规原因的验证反馈，以支持模型反思和改进。

### 5. 方法概览

- 任务 / 环境: 3DVerifierBench基准，包含10个任务，共2581个示例，覆盖物体属性、部件、关系、可抓取区域、抓取有效性、身份保持、细粒度几何和运动理解等。
- 变量 / 干预设计: 通过受控反事实构造（Spec-CF和Cand-CF）、参数化数据合成（身份）和专家引导数据构造（细粒度几何和运动）生成训练数据，共14126个样本，确保与基准无源组重叠。
- 评价指标: 使用平衡准确率（BA）和总体准确率（OA），并引入解释感知的联合指标（ExpBA）和链接反事实三元组成功率。
- 模型比较: 评估了GPT-6 Astra、Gemini-3.8-Flash、GPT-5.6-Sol、Qwen系列、GLM-4.6V、Gemma-4-31B、InternVL3.5、Qwen2.5-VL和OmniVerifier-7B等模型。
- 我的理解: 该方法通过构建多样化的验证任务和高质量训练数据，使模型学习如何将判断与具体证据关联，从而提升验证的可靠性和解释性。

### 6. 关键发现

- 人类与模型存在显著差距: 人类总体准确率为87.8%，而最强模型GPT-6 Astra仅为69.4%，差距达21.6个百分点。
- 特定任务表现薄弱: 所有模型在身份保持（最高59.0%）和细粒度几何（最高53.3%）任务上表现不佳，说明这些任务需要更精细的3D证据理解。
- 解释质量影响验证可靠性: 即使模型正确拒绝，其解释也可能未指向正确的矛盾点，说明仅判断正确性不足以支持有效的反思。
