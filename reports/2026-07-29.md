## 1. VetClaw: An Edge-Cloud Multimodal Agentic System for Veterinary Disease Screening

**Topics:** GUI Agent, Edge-Cloud Computing, Multimodal AI, Veterinary Disease Screening
**Authors:** Syed Mhamudul Hasan, Anas AlSobeh, Hussein Zangoti, Abdur R. Shahid
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.26042v1) | [PDF](http://arxiv.org/pdf/2607.26042v1.pdf)

### 1. 一句话结论

VetClaw 是一个边缘-云多模态智能体系统，通过将图像与症状文本结合，利用零样本视觉语言模型进行兽医疾病筛查，并采用 OpenClaw 和 LangGraph 分离交互与工作流编排，显著提升了分类性能。

### 2. 为什么重要

该系统展示了如何将静态图像分类模型转化为一个协调、安全感知的智能体系统，能够使用工具、管理工作流、处理故障并升级不确定病例，为实际兽医诊断中的早期筛查提供了可行方案。

### 3. 研究问题

1. 如何将边缘设备（如树莓派）与云端视觉语言模型结合，实现兽医疾病的零样本筛查？
2. 多模态输入（图像+症状文本）相比单一模态（仅图像或仅文本）能否提升疾病分类性能？

### 4. 背景与问题设定

动物生物安全措施旨在减少传染病传播，但兽医诊断面临动物无法口头描述症状、疾病表现因物种而异等挑战。现有AI系统多依赖单一数据模态，缺乏协调推理和故障处理能力。VetClaw 旨在通过边缘-云架构和多模态智能体工作流，实现早期疾病筛查。

### 5. 方法概览

- 任务 / 环境: 兽医疾病筛查任务，使用两个公开数据集：Pet Disease Images（1736张图像，22类）和 Dogs Skin Disease Dataset（443张图像，4类）。
- 变量 / 干预设计: 系统包括边缘层（树莓派+摄像头+OpenClaw+LangGraph）和服务器层（FastAPI+VLM）。OpenClaw 管理调度、工具和通知；LangGraph 控制状态化工作流（验证、路由、安全检查等）。
- 评价指标: 准确率、精确率、召回率、F1分数。
- 模型比较: 比较 Qwen3-VL-32B 和 InternVL3-38B 在三种输入设置下的零样本性能：仅图像、仅文本、文本+图像。
- 我的理解: VetClaw 的核心创新在于将智能体交互（OpenClaw）与工作流编排（LangGraph）分离，使系统能够灵活处理多模态输入、执行安全规则并处理异常，而不仅仅是简单的图像分类。

### 6. 关键发现

- 多模态输入显著提升零样本分类性能: 在 Dogs Skin Disease 数据集上，仅图像 F1 为 0.31，文本+图像 F1 提升至 0.69；在 Pet Disease Images 上，仅图像 F1 为 0.49，文本+图像 F1 达 0.86。
- 文本引导的推理优于纯视觉预测: 仅文本设置下，InternVL3-38B 在 Dogs Skin Disease 上达到 100% 准确率，表明症状描述提供了关键线索，但也可能引入标签泄露风险。
- 边缘-云架构实现实时可行性: 系统在树莓派上完成图像捕获和预处理，云端 VLM 推理延迟约 925ms，总端到端延迟在数秒内，适合实际部署。

VetClaw 提出了一种边缘-云多模态智能体系统，用于兽医疾病早期筛查。通过树莓派捕获图像，结合症状文本，利用云端 VLM 进行零样本分类，并由 OpenClaw 和 LangGraph 分别管理交互和工作流。实验表明，多模态输入显著优于仅图像或仅文本，但零样本性能仍有限。该系统为实际兽医诊断中的智能体应用提供了有价值的参考。

## 2. Interactive Reward Agent: GUI Task Evaluation via Environment-State Verification

**Topics:** GUI Agent, Task Evaluation, Reward Signal, Environment-State Verification
**Authors:** Chenrui Shi, Yuwei Wu, Yang Liu, Ruining Feng, Zirui Shang, Zhi Gao, Lifeng Fan, Che Sun
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.25904v1) | [PDF](http://arxiv.org/pdf/2607.25904v1.pdf)

### 1. 一句话结论

IRA通过先提出任务完成条件、再交互式验证环境状态的方法，在GUI任务评估中达到86.9%准确率，并可作为有效奖励信号用于强化学习训练GUI智能体。

### 2. 为什么重要

现有GUI任务评估方法要么依赖人工脚本（精确但不可扩展），要么仅基于截图（忽略隐藏状态）。IRA结合两者优势，通过交互式工具调用验证文件、配置等环境证据，为自动化评估和训练提供了可靠且可扩展的解决方案。

### 3. 研究问题

1. 如何设计一个能同时利用截图和环境状态证据的GUI任务评估器？
2. IRA提供的奖励信号能否有效用于训练GUI智能体？

### 4. 背景与问题设定

GUI任务评估旨在判断智能体是否完成用户指令。现有方法分为脚本式（需人工标注，精确但不可扩展）和VLM式（仅基于截图，忽略文件、配置等隐藏状态）。IRA将评估视为交互过程：先提出条件，再通过工具调用从环境中收集证据进行验证。

### 5. 方法概览

- 任务 / 环境: Ubuntu桌面环境，包含10类应用（办公、图形、浏览器、通信、媒体、开发、系统配置等），共321条任务轨迹，其中成功轨迹约50%，失败轨迹约50%。
- 变量 / 干预设计: IRA采用“提出-验证”框架：首先基于指令和截图生成一组完成条件（如文件存在、配置值正确），然后对每个条件通过ReAct循环调用系统工具、应用工具和GUI工具收集证据，直到能做出二元判断。
- 评价指标: 准确率、精确率、召回率、F1分数，以及TP/FP/TN/FN。奖励>0.8视为成功。
- 模型比较: 对比WebRL、ZeroGUI、DigiRL、DistRL等被动VLM评估器，以及IRA使用Qwen3.6-35B、GPT-5.4、GPT-5.5的变体。
- 我的理解: IRA的核心创新在于将评估从被动观察变为主动验证：它不直接判断任务是否完成，而是先分解出可验证的条件，然后像智能体一样与环境交互获取证据。这类似于将评估问题转化为一个子任务完成验证问题。

### 6. 关键发现

- IRA在GUI-RewardBench上达到86.9%准确率，显著优于被动VLM评估器: IRA（GPT-5.5）准确率86.9%，F1 84.9%，而最佳被动方法DistRL仅78.8%准确率、76.7% F1。在隐藏状态任务上提升尤为明显：VLC类别中IRA准确率85.7% vs DistRL 64.3%（提升21.4个百分点），Thunderbird类别中IRA准确率92.3% vs DistRL 69.2%（提升23.1个百分点）。
- IRA提供的奖励信号可用于强化学习训练GUI智能体: 使用IRA作为奖励函数训练GUI智能体，在OSWorld上达到34.0%成功率，与使用真实评估脚本的效果相当（脚本基线为35.2%），验证了IRA作为训练信号的实用性。
- IRA的判断与人类标注者高度一致: 在100个自动生成任务上，IRA的判断与人类标注者强对齐（Cohen's Kappa = 0.84），验证了其可靠性。

### 7. 最重要的图

- 图来源: 图2：IRA整体流程
- 为什么重要: 该图清晰展示了IRA的“提出-验证”框架：从指令和截图生成条件，再通过工具调用循环验证每个条件，最后聚合为奖励。这是理解IRA核心机制的关键。

### 8. 如何读这张图

从左到右：输入任务指令和初始/最终截图，IRA首先生成一组完成条件（如“文件res.png存在于桌面”）。然后对每个条件，IRA进入ReAct循环：推理→选择工具（系统/应用/GUI）→获取观察→更新历史，直到能给出二元判断（满足/不满足）。最后将所有条件判断聚合为最终奖励。

### 9. 次重要图

- 为什么也重要: 图1对比了IRA与VLM评估器在需要验证输出文件的任务上的表现，直观说明了仅靠截图无法判断文件是否存在，而IRA通过工具调用能获取环境状态证据。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: IRA提供了一种可扩展的奖励信号生成方法，可用于训练更可靠的GUI智能体，特别是在需要验证文件、配置等隐藏状态的任务上。
- 对 Skill: IRA的“提出-验证”框架可泛化到其他需要环境状态验证的技能评估中，如机器人操作任务。
- 对 Memory: IRA的交互历史可视为一种短期记忆，用于追踪每个条件的验证进度，未来可结合长期记忆存储常见验证模式。
- 对评测: GUI任务评估应从被动观察转向主动验证，IRA为此提供了有效范式，可推动更可靠的自动化评估基准。

### 11. 局限性

- IRA依赖VLM生成完成条件，可能遗漏某些条件或生成不准确的条件，例如在复杂多步骤任务中条件覆盖不全，导致评估偏差。
- 交互式验证可能改变环境状态（如GUI工具点击），影响后续验证或导致状态漂移，尤其在多次验证同一环境时，需谨慎设计只读操作。
- 当前仅支持Ubuntu桌面环境，泛化到其他操作系统（如Windows、macOS）需适配工具集和系统命令。
- GUI-RewardBench规模较小（321条轨迹），且轨迹由特定智能体（UI-TARS-1.5和EvoCUA-8B）生成，可能引入偏差，需在更多智能体上验证。

### 12. 我的看法 / 个人笔记

IRA巧妙地将评估问题转化为条件验证问题，通过工具调用弥补了VLM仅依赖截图的不足。其“提出-验证”框架具有通用性，未来可扩展到更多需要环境状态验证的场景。但条件生成的质量和交互对环境的扰动是潜在风险，需进一步研究更鲁棒的条件生成和状态恢复机制。

### 14. 总结

IRA是一种基于“提出-验证”框架的交互式GUI任务评估器，通过先提出完成条件、再调用系统/应用/GUI工具验证环境状态，在GUI-RewardBench上达到86.9%准确率，优于现有被动VLM评估器（最佳DistRL为78.8%）。在隐藏状态任务上提升显著，如VLC类别准确率提升21.4个百分点（85.7% vs 64.3%），Thunderbird类别提升23.1个百分点（92.3% vs 69.2%）。IRA的判断与人类标注者高度一致（Cohen's Kappa = 0.84）。IRA提供的奖励信号可用于强化学习训练GUI智能体，在OSWorld上达到34.0%成功率，与脚本基线（35.2%）相当。该方法结合了脚本式评估的精确性和VLM评估的可扩展性，为可靠自动化评估提供了新范式。

## 3. Runtime Uncertainty Monitoring for LLM-Based Multi-Agent Systems Using Bayesian Networks

**Topics:** 多智能体系统, 不确定性量化, 精算风险建模, 大语言模型
**Authors:** Bart Custers, Koorosh Aslansefat
**Venue / Year:** arXiv 2026
**Links:** [Abstract](http://arxiv.org/abs/2607.25877v1) | [PDF](http://arxiv.org/pdf/2607.25877v1.pdf)

### 1. 一句话结论

提出一种基于贝叶斯网络和令牌级对数概率的运行时不确定性监控框架，用于LLM多智能体系统在精算工作流中的安全监测。

### 2. 为什么重要

精算工作流是高风险的决策支持场景，LLM的不确定性和智能体间依赖可能导致错误传播。该框架首次将贝叶斯网络与校准后的对数概率结合，实现了对多步工作流不确定性的结构化建模和运行时监控，为高可靠性AI系统提供了可解释的安全机制。

### 3. 研究问题

1. 如何量化LLM多智能体系统中每个智能体输出的不确定性？
2. 不确定性如何在多步工作流中传播，并如何建模这种传播？
3. 基于贝叶斯网络的运行时监控能否有效识别工作流中的不安全状态？

### 4. 背景与问题设定

精算风险建模依赖准确预测，但LLM的随机性和幻觉引入不确定性。现有方法缺乏对多智能体工作流中不确定性传播的系统建模。本文提出一个中心化星型拓扑的多智能体框架，包含数据准备、建模、审查和解释四个专用智能体，并利用贝叶斯网络捕获任务间依赖，将令牌级对数概率转换为校准后的任务级置信度，实现不确定性传播的可视化和量化。

### 5. 方法概览

- 任务 / 环境: 精算风险建模工作流，包括数据准备、模型开发、验证和解释。使用三个开源LLM后端（Llama 2 7B, Llama 3.1 8B, Qwen2.5 7B）在本地运行。
- 变量 / 干预设计: 中央枢纽协调四个专用智能体（数据准备、建模、审查、解释），通过消息传递避免直接通信。审查智能体可触发修订或终止。解释智能体评估概念对齐（TCAV）和公平性。
- 评价指标: 任务成功率、RMSE（与基线模型比较）、错误检测率、工作流不确定性（贝叶斯网络后验概率）。
- 模型比较: Llama 2 7B、Llama 3.1 8B、Qwen2.5 7B三个模型在原始数据集和20个扰动数据集上比较。Qwen在错误检测率（90%）和扰动下RMSE上最优，Llama 2任务成功率80%但错误检测率仅45%。
- 我的理解: 该方法的核心创新在于将LLM的令牌级对数概率（经长度归一化和校准）作为贝叶斯网络的先验证据，而非直接视为正确概率。贝叶斯网络通过条件概率表（如AND门）建模任务间依赖，从而量化不确定性传播。这类似于将每个智能体的“自信度”转化为概率图中的节点，然后通过图推理得到整体工作流的置信度。

### 6. 关键发现

- 贝叶斯网络有效量化不确定性传播: 在示例工作流中，单个智能体置信度约80%，但通过贝叶斯网络传播后，整体工作流置信度降至55%，表明不确定性累积效应显著。
- 温度设置直接影响工作流可靠性: 低温度（0.2）场景下工作流成功概率87.1%，高温度（1.2）场景下降至42.8%，验证了贝叶斯网络对随机性传播的敏感性。
- Qwen2.5 7B在错误检测和适应性上显著优于Llama系列: Qwen错误检测率90%，而Llama 2仅45%；Qwen在扰动数据集上更频繁地触发模型重训练或策略调整。

## 4. A Cost-Effective Multimodal LLM Reasoning Framework for Question Answering over Irregular Clinical Time Series

**Topics:** 多模态大语言模型, 不规则临床时间序列, 问答系统, 多尺度编码, 渐进对齐
**Authors:** Frank Nie, Ethan B Liu, Yuan Zhu, Wei Fan, Jindong Han
**Venue / Year:** 
**Links:** [Abstract](http://arxiv.org/abs/2607.25947v1) | [PDF](http://arxiv.org/pdf/2607.25947v1.pdf)

### 1. 一句话结论

ClinPRISM通过不规则感知多尺度编码器和渐进对齐策略，仅用16个时间序列令牌和0.15秒推理延迟，在不规则临床时间序列问答上达到最优性能。

### 2. 为什么重要

该工作解决了现有时间序列LLM难以处理临床数据稀疏、异步和不规则采样模式的问题，为高效、准确的临床决策支持提供了新范式。

### 3. 研究问题

1. 如何有效建模不规则临床时间序列中的稀疏、异步和多样时间尺度证据？
2. 如何将不规则时间序列表示高效对齐到大语言模型的语义空间，同时保持计算效率？

### 4. 背景与问题设定

不规则临床时间序列（ICTS）在医疗决策中至关重要，但现有时间序列大语言模型主要针对规则采样数据，难以处理临床记录的稀疏性、异步性和不规则采样模式。问题包括：不规则时间建模（需联合捕获时间动态和观测模式）、稀疏多尺度证据定位（证据分布不均且依赖不同时间尺度）、不规则时间-语言对齐（缺乏大规模配对数据）。

### 5. 方法概览

- 任务 / 环境: 训练数据：从去标识化ICU记录构建30,000条不规则临床轨迹（用于多尺度编码器预训练），41,000条指令微调实例（覆盖11种任务，包括趋势分析、事件检测、数值查询等）。
- 变量 / 干预设计: 提出ClinPRISM框架，包含三个模块：1) 不规则感知多尺度编码器（宏观、中观、微观三尺度，通过共享事件架构和有效性掩码避免重采样）；2) 时间证据蒸馏器（跨尺度融合并压缩为固定数量令牌，使用查询重采样器）；3) 渐进对齐策略（三阶段：自监督预训练编码器、冻结编码器和LLM的层次化字幕对齐、问答导向微调）。
- 评价指标: 在独立保留基准上评估问答性能（准确率等），同时报告时间序列令牌数（16个）和推理延迟（0.15秒/问题）。
- 模型比较: 与Qwen、ITFormer、ChatTS、t-PatchGNN等模型家族对比，ClinPRISM在11项任务中均取得最优，例如在TG任务上达87.0%，在MED任务上达96.7%（见图1(b)）。
- 我的理解: 该方法通过多尺度编码器分别捕获全局趋势（宏观）、事件动态（中观）和细粒度观测（微观），再通过蒸馏器融合为紧凑表示，最后用渐进对齐逐步将时间表示映射到LLM空间，避免了传统文本序列化带来的高令牌开销。

### 6. 关键发现

- 多尺度编码有效捕获稀疏临床证据: 宏观、中观、微观三尺度编码器分别处理全局趋势、事件动态和细粒度观测，通过共享事件架构和有效性掩码（基于观测支持度），避免了重采样或插值，保留了原始时间戳信息。中观尺度使用可学习软窗口自适应观测密度。
- 渐进对齐策略提升时间-语言语义一致性: 分三阶段训练：Stage 1自监督预训练多尺度编码器（各分支独立优化）；Stage 2冻结编码器和LLM，仅优化时间证据蒸馏器，通过层次化字幕对比学习（含双向对比损失和尺度正则化）对齐蒸馏器输出与LLM语义空间；Stage 3先调蒸馏器再联合LoRA优化，适应下游问答。
- 高效推理：16个令牌与0.15秒延迟: 仅使用16个时间序列令牌和4B参数LLM骨干，平均推理延迟0.15秒/问题，显著优于需要大量令牌的文本序列化方法（如Qwen家族）。

- 图来源: 图1(b)：现有模型家族在11项临床时间推理任务上的性能对比（柱状图）。
- 为什么重要: 直观展示了现有方法（Qwen、ITFormer、ChatTS、t-PatchGNN）在多种任务上的不足，例如Qwen在TG任务上仅26.5%，而ClinPRISM达87.0%；在MED任务上Qwen为22.8%，ClinPRISM为96.7%，凸显了ClinPRISM的全面优势。

### 10. 对 Agent / Skill / Memory 的启发

- 对 Agent 系统: 为医疗AI代理提供了高效处理不规则临床数据的接口，可集成到临床决策支持系统中，实现实时问答（如病情恶化检测、治疗效果评估）。

### 11. 局限性

- 依赖去标识化ICU数据（如MIMIC），可能无法直接泛化到其他临床环境（如门诊或急诊），需验证跨域迁移能力。

ClinPRISM在不规则时间序列问答上取得了显著进展，其多尺度编码和渐进对齐设计巧妙且高效。未来可探索更轻量的对齐策略（如端到端训练）、扩展到多模态临床数据（如影像、文本报告），或验证在非临床不规则时间序列（如金融）上的泛化性。

## 5. Evaluating VLMs for Autonomous Agent-Driven Geometry Clipping Detection in Video Game QA

**Topics:** GUI Agent, Automated Game Testing, Vision-Language Models, Anomaly Detection
**Authors:** Carlos Celemin, Benedict Wilkins, Adrián Barahona-Ríos, Saman Zadtootaghaj, Nabajeet Barman
**Venue / Year:** IEEE Conference on Games 2026

### 1. 一句话结论

当前VLM在游戏几何裁剪检测中作为高召回率候选过滤器有效，但无法独立作为bug检测器，尤其在视觉模糊帧上误报率高。

### 2. 为什么重要

该研究首次系统评估了多种VLM在自动化游戏QA管线中的实际表现，揭示了其作为高召回率预筛选器的潜力与作为独立检测器的局限性，为游戏开发中部署AI辅助测试提供了关键指导。

### 3. 研究问题

1. 通用VLM能否在零样本设置下有效检测游戏中的几何裁剪异常？
2. 不同VLM对提示词变体的敏感度如何，以及其精度-召回率权衡特性？

### 4. 背景与问题设定

游戏QA中手动测试难以覆盖复杂状态空间，现有自动化方法依赖游戏特定数据或小规模监督数据集，泛化能力有限。VLM结合视觉理解与自然语言推理，但此前缺乏针对几何裁剪这一常见bug的系统评估。

### 5. 方法概览

- 任务 / 环境: 基于Godot引擎的第三人称射击演示项目，使用自定义探索代理收集帧数据，并通过修改引擎生成几何裁剪的二进制掩码标签。
- 变量 / 干预设计: 构建包含2420正常帧和516裁剪帧的数据集，并划分易、难、随机三个正常帧子集；评估6种VLM（Gemini、GPT、Qwen、Gemma、Llama、Ministral）在4种提示词变体下的零样本检测性能。
- 评价指标: 平衡数据集上的准确率、精确率、召回率。
- 模型比较: Gemini-3.1-Flash在准确率和精确率上最优，且对提示词变化最鲁棒；开源模型如Ministral和Gemma召回率高但精确率低，Llama精确率高但召回率低。
- 我的理解: 该实验设计巧妙地将探索代理与VLM检测解耦，通过人工标注的难易子集揭示了VLM在空间推理上的根本局限——依赖局部表面邻近性而非深度理解，导致对近接触几何和部分遮挡的误报。

### 6. 关键发现

- VLM在易分帧上表现良好，但在难分帧上精确率显著下降: 在易分帧子集上，Gemini准确率达85.0%，精确率87.2%；但在难分帧子集上，所有模型精确率均大幅下降，Gemini降至57.5%，表明VLM无法区分真实几何相交与视觉邻近。

- 仅评估了单帧检测，未考虑时序上下文，而许多裁剪bug具有时空连续性。
- 仅覆盖一种bug类型（几何裁剪）和单一游戏环境，泛化性未知。
- 未与人类测试者性能进行对比，难以判断VLM的绝对有效性。

### 12. 我的看法 / 个人笔记

该工作扎实地揭示了VLM在游戏QA中的实际能力边界，其核心贡献在于通过精心设计的难分帧子集和提示词敏感性分析，证明了VLM的误报源于空间推理缺陷而非随机噪声。这为未来研究指明了方向：需结合深度估计或时序推理来提升VLM的细粒度视觉理解。
